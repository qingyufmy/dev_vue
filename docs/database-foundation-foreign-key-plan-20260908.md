# 基础域外键补齐

139步当前库只读检查7组目标关系。其中5组无孤立引用：Bridge会话用户、默认模型配置的模型、能力配置的模型及验证用户、用量日志的模型。追加这5个冻结目标外键，使用默认RESTRICT/NO ACTION，不级联删除或更新。MySQL需为验证用户和用量模型引用建立两个辅助索引，纳入DDL指纹和索引增量核验。

user_model_defaults.user_id有1条孤立记录；ai_model_usage_logs.user_id有11787条孤立记录。两条用户外键延期，原值及历史记录完整保留，不删除、虚构用户或改成NULL。由模型配置/用量归档迁移合同明确历史来源及新写入口后再处理，当前DDL不掩盖这些差异。

第一轮复审：只补父子ID类型一致且现有值全量有效的目标关系。模型删除采用软删除，FK防止带历史引用的物理删除；不改变用户权限，不让模型owner=0被用户FK误伤。服务端按用户授权仍需独立校验，引用完整不等于权限完整。

第二轮复审：恢复副本逐DDL后异常恢复、重复0DDL与全量业务数据/其它结构/自增值保持后再执行开发库。继承已有索引显示顺序规范化，保留所有历史步骤checksum。新增FK与自动辅助索引都必须精确匹配，不关闭foreign_key_checks，不回写历史孤立记录。全局约束语义核对仍须继续，名称相同不足以证明动作或表达式相同。
