## 执行顺序

1. 保留现有64步，追加10张独立表及1条后置外键，共11个结构步骤：手动分析冷却、outbox、全局风险控制、策略记忆库/版本/注入记录、历史迁移checkpoint、观摩管理版本/操作审计、V4配对请求。沿用既有目标DDL，不复制业务数据、不激活风险政策、不生成任务、配对码或记忆。
2. 在唯一恢复副本实际执行相同11条DDL，记录每一步之前/之后SHOW CREATE及hash；临时参考表始终为空并精确清理。冻结回执后接入现有升级协调器，逐条DDL中断、journal恢复、重复执行和原有数据/结构/自增值不变通过，才对当前库执行。
3. 汇总所有同名表的字段/类型差异，以及新旧业务权威表的映射。不能把暂存表视为已经切换，也不能仅因读写方未接入就跳过可以独立完成的结构改造。
4. 对剩余缺口逐项确定：可独立升级、需要数据合同/迁移、需业务切换配合、仅保留旧来源。仍可独立实施的继续执行；配合项列明表、字段、依赖模块、恢复条件和验证，不用一个总豁免代替审查。
5. 最终核对源字段覆盖、目标必填列来源、强软关系、UTC/精确数值/机器键/查询索引、完整升级历史、恢复及重复执行，形成已完成与配合待办两张明确清单。没有这些证据不宣称数据库结构优化完成。

## 已明确的配合边界

`trading_accounts.id` 当前 INT 与目标 BIGINT UNSIGNED、`strategy_subscriptions.id` 同类冲突、`inference_snapshots.id` BIGINT 与目标 CHAR(36)、`ai_model_tasks` 旧主键与目标 id 缺口，共同阻断69张下游目标。现有账户/归属/订阅构建表不能直接替代正式同名表；旧消费者仍可能使用旧ID和旧字段。这些需要对应领域的映射、权威入口切换及消费者验收。

新增 `global_risk_controls` 的真实控制值必须由旧风险控制迁移合同确定，不能套用空库 seed 将停机状态默认为关闭。`observer_management_registry` 的初始revision必须随旧观摩事实迁移/切换一致建立。此轮只补结构，两项初始化不等于已完成，随风控和观摩领域补齐。

## 第二轮复审：兼容、恢复与数据

同名根表不能用修改类型后直接安装下游的方式绕过ID和历史归属迁移。11步DDL不能包在一个事务后宣称整体回滚；复用现有同连接升级锁、checksum、before/after结构与journal恢复。DDL前后核对所有既有业务表，不仅原165表；参考清理限制本轮空表，原表、旧SQL和旧证据不改。风险/观摩种子延期有具体数据语义原因，不能由安装默认值隐式开启业务。

剩余风险：完整源字段转换与目标反向覆盖仍不齐，四类根实体切换尚未验收，特权对象可见性待补。新增结构通过不代表旧数据已可由新API访问；用户已允许后者随对应业务阶段接续。
