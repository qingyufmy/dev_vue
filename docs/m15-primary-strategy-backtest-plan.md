# M15 主判策略提示词与隔离回测方案

## 1. 目标与边界

本实验新增一份独立策略提示词，不覆盖线上 v39，不修改服务端通用缠论算法、输出合同、风险控制或 Bridge。策略周期重构为：

> M15 趋势主判 → 仅在 M15 不明确或结构不可用时由 H1 降级备判 → M15 机会分类 → M5 闭合 K 线触发 → M1 EMA34 最终时机过滤 → 保护价、净风险收益与订单合法性

目标不是用未来数据“命中每一个波峰波谷”，而是在可执行确认延迟内提高有意义 M15/M5 拐点和延续段的召回率，同时控制假信号、不可成交挂单和连续亏损。所有策略输入只允许使用检查点当时已经闭合、系统已经提供的数据；未来行情只用于标签和结果评估。

## 2. 冻结与对照

- 代码基线：本地 `dev_codex` 当前提交与虚拟机同提交。
- 策略基线：虚拟机 active platform XAUUSD 策略 v39，只读导出并保存哈希。
- 行情来源：本地 MT5 `DooTechnology-Demo` 账户，只读取行情，不发送交易。
- 时间口径：同时保存原始终端服务器时间、转换后的 UTC、校准偏移和闭合状态。
- 对照组：当前 v39 规则在相同检查点、相同 K 线和相同成交模拟上的结果。
- 实验组：M15 主判候选版本。每轮变更记录版本、理由和指标，不回写线上。

## 3. 机会状态机

### 3.1 方向裁决

1. M15 `local_structure_usable=true` 且能给出唯一方向时，以 M15 为唯一主判。
2. M15 已确认趋势与 `reversal_watch` 必须区分；后者只是反转观察方向，不能直接下单。
3. M15 不明确、方向不唯一或本地结构不可用时，才允许 H1 降级备判。
4. M15 已明确时，H1 只作为风险背景和目标空间证据，不得以旧趋势直接否决 M15。
5. H1 降级形成的方向属于临时方向，必须由更严格的 M5 触发确认。

### 3.2 反转机会族

用于提高波段端点召回率，至少满足一个结构证据和一个独立触发证据：

- 结构证据：系统确认的 M15 背驰、三类买卖点、M15 `reversal_watch`、系统中枢边界反应。
- 价格证据：M15 裸 K 反转、假突破回收、关键位拒绝；同根 K 线或同一价格事件只能计一次。
- 触发证据：M5 扫破回收完整生命周期，或 M5 已确认局部反转后首次同向闭合触发。
- 禁止仅凭 RSI、MACD 正负、单根普通 K 线或 M1 EMA34 直接反转。

### 3.3 延续机会族

用于覆盖趋势中的第二、第三类买卖点和回踩恢复：

- M15 已确认方向、系统三类买卖点或有效离开中枢后的回抽不回中枢。
- M5 同向双 K 突破，或首次回踩关键位后重新同向闭合。
- 形成中结构只可作为观察，不得替代确认触发。

### 3.4 最终过滤

- M1 EMA34 只在唯一候选方向和 M5 触发已经成立后检查。
- EMA34 同向时可评估市价；不同向时不得伪造通过，可等待一次系统回踩价或返回观察。
- 止损读取采用路径对应的系统结构锚点，并使用系统 ATR 做最小距离校验；不得由模型重算。
- 推荐执行档位净风险收益至少 1.5；市价不足时只检查一次合法回踩 Limit。
- 信号识别率与真实订单率分别统计，不能为了提高订单数删除保护价和风险收益门槛。

## 4. 标签与评价指标

### 4.1 无未来函数标签

未来窗口只用于生成评估标签，不进入策略输入。使用两类标签：

- 方向变化标签：M15 方向变化后，未来达到预设 ATR 倍数且先未触及对称反向阈值。
- 可交易波段标签：在确认点后存在足够空间覆盖结构止损、成本和至少 1.5 净风险收益。

每个标签保存端点、最早可确认时间、允许延迟、未来 MFE/MAE 和是否可成交。小于交易成本与最小结构止损空间的噪声波动不计作“必须下单”的买卖点。

### 4.2 核心指标

- 拐点召回率：有效标签中在允许确认延迟内被识别的比例。
- 精确率：产生候选的检查点中，最终对应有效标签的比例。
- 可执行率：通过保护价、净风险收益、报价与挂单方向检查的比例。
- 成交率：挂单在有效期内实际触发的比例。
- 交易结果：胜率、平均 R、期望 R、Profit Factor、最大连续亏损、最大回撤。
- 时机质量：相对标签端点的延迟、价格滑移、MFE/MAE。
- 稳定性：不同日期、时段、波动状态和滚动窗口的指标分布。

## 5. 实验流程与停止规则

1. 读取至少 30 个可用交易日的 M1/M5/M15/H1/H4 数据；不足时明确缩小结论范围。
2. 按时间顺序划分开发段、验证段和最终留出段；最终留出段只运行一次。
3. 先用确定性证据引擎筛选候选，再在候选点、临界点和负样本上运行真实模型，避免对每根 K 线进行高成本调用。
4. 每轮只修改一个规则族，记录试验次数；不得按单个亏损样本追加专用例外。
5. 使用滚动窗口和按交易时段分层结果检查稳定性。
6. 若留出段召回提升但精确率、期望 R 或回撤明显恶化，则拒绝该版本。
7. 若样本量不足、行情缺口未闭合、成本不可得或模型输出无法复现，结论标记为部分，不宣称“完全可用”。

建议验收门槛：相对 v39，有效拐点召回率明显提高；精确率不低于 55%；成交后 Profit Factor 大于 1.2；平均期望为正；最大回撤和连续亏损不显著恶化；所有可交易信号字段、方向、止损、止盈与净风险收益一致；最终留出段无未来函数和结构安全违规。

## 6. 第一轮方案复审：需求与设计

### 检查结论

- 已覆盖 M15 主判、H1 降级、缠论、裸 K、M5 精确入场、M1 EMA34 和订单风险要求。
- 不直接对调原策略周期，而是拆分反转与延续机会，避免 M15 主判后只会抓一种行情。
- 复用现有 `computeChan`、系统指标和输出合同，不在提示词内新增公式或要求模型重算客观数据。
- 保留线上 v39 作为对照，不改变生产配置。

### 本轮调整

- 将“每次涨跌都下单”拆成“拐点识别”和“可执行交易”两个指标，防止为了召回率交易噪声。
- 将 H1 从常态否决者改为严格降级备判和风险背景。
- 将 M1 EMA34 放到唯一候选方向之后，避免它提前污染方向判断。
- 增加反转、延续两个机会族，防止仅靠统一两票门槛漏掉结构完备的单一路径。

### 剩余风险

- 缠论确认天然晚于真实极值，无法保证在最低点或最高点成交。
- 频繁尝试规则会产生数据窥探，需要记录全部试验并保留最终留出段。
- 模型输出存在随机漂移，确定性规则通过不等于模型每次都能正确表达。

## 7. 第二轮方案复审：兼容、安全与验证

### 检查结论

- 无数据库迁移、服务端策略专用分支或 Bridge 改动；与其他策略兼容。
- 回测按闭合 K 线和终端服务器时间运行，形成中 K 线不能进入证据。
- 候选、订单和结果使用稳定事件键去重；同一行情检查点不会重复计为多笔独立交易。
- 模型回放不持久化生产信号、不发送订单、不消耗订阅用户风控额度。
- 输出和回测产物不保存 API Key、账号隐私或完整模型密钥配置。
- 失败、超时和不完整响应单独计入，不自动重复成功请求。

### 本轮调整

- 增加订单成交率，防止“回测上有信号、实际挂单永不成交”被计为成功。
- 增加最终留出段一次性运行和滚动稳定性检查。
- 增加模型临界负样本，验证提高召回后是否产生大量假反转。
- 明确不自动部署；最终提示词作为独立 Markdown 交付，由用户决定是否配置。

### 剩余风险

- 历史 Bid/Ask、动态滑点和真实成交队列可能不完整，只能进行保守近似。
- 单一品种和有限月份无法证明未来市场状态下长期有效。
- 若最终版本需要关闭或改变平台 EMA34 硬约束，必须另行修改策略配置并重新验证，不能只靠提示词绕过。

## 8. 回滚与交付

实验失败时直接保留线上 v39，不做任何回滚操作。最终交付包括：

1. 完整可复制的 M15 主判策略提示词 Markdown；
2. v39 与候选版本的同样本指标对比；
3. 每轮修改、接受或拒绝理由；
4. 留出段结果、模型回放结果和剩余风险；
5. 是否建议上线及上线前必须完成的影子验证。
