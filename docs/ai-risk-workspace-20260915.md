# AI 风控师完善记录

## 范围与顺序

本轮先收口页面状态、规则编辑、记录详情、账户切换和缺数据展示；后续仍须补齐账户风险汇总生产。不得把页面可用表述为日初资金、净值峰值及成交统计已经上线。

第一轮复核：沿用账户作用域及现有接口，使用共享组件；状态概况、六项风险用量、规则设置和记录是主要信息层级。不额外创建交易开关或浏览器风控执行器。

第二轮复核：缺数据不能隐藏已知暂停；过期或未确认时区不能显示正常；切换账户关闭编辑与解除窗口；保留原保存请求的幂等恢复。真实规则仍由服务端逐笔校验，未修改任何账户配置。

## 日内计算模块

已依据旧版 account-risk-auto-recovery-fix-plan 和只读参考 risk-state.js 核对口径：日亏损为当日已实现净损益加负浮动盈亏；正浮盈不抵扣已实现亏损。日初基准由完整当日损益、浮盈亏和资金流反推。当日高水位随净资金变动校正，日切以首个完整快照重建，不沿用昨日峰值。

实现 daily-risk-metrics.ts，金额用八位定点整数，风险百分比向上取至六位小数。输入是完整当日累计值，重复读入不会重复累计资金。账户与所有权区间不匹配、历史不完整、时间倒退、非法金额拒绝计算。这里不签发交易权限，不重置人工解除记录。

复核一：沿用已确认的日内口径，不改为跨日回撤，不引入第二套风控政策。复核二：金融定点运算、日切、入出金、重复输入、缺数据、账户隔离均有定向用例；数据库事务与历史覆盖证明仍由后续生产适配负责。

10 项计算测试及服务端构建通过。该模块尚未接入运行生产者，不能视作页面已有真实汇总。下一步添加日基准持久化迁移及生产事务，接入历史覆盖与完整成交数据；不通过页面刷新查询全量终端历史。未执行数据库变更、重启或交易。

## 真实历史采集接线与排障

开发库现场核对发现 history_collection_tasks_v4 与 terminal_history_deals_v4 均为空，账户风险汇总亦为空。已运行本地历史调度器并用既有 outbox 通道登记采集任务，没有发送交易指令。

修复以下实际阻塞：

- 普通账户指标没有携带新校准样本时，将仍在 24 小时有效期内的原始校准保留为已确认；校验账户、归属区间和终端，原始时间不随指标刷新续期。
- 账户时区读取误将旧字符串 connection_epoch 与 V4 数字 epoch 比较，改用 connection_epoch_v4。真实开发库读取已返回 calibrated / 180。
- 历史采集使用当前账户已确认时区，避免继续使用连接建立时保存的空时区。
- 本地缓存刷新和查询繁忙采用固定窗口、固定游标及有上限的退避，不把每次缓存预热都立即判为任务失败。
- Bridge 原有 ProjectionSyncCoordinator 没有接入运行生命周期，现由连接所属后台线程串行处理；共享暂停/停止和在途操作计数，退出先等待同步线程再释放数据库与终端句柄。
- MT5 密集历史窗口触发数量上限时，对尚未开始分页的窗口有界二分；已有游标分组不跳过，不裁掉交易记录。
- 新历史请求复用已完整覆盖的前缀，只把后续缺口放入本地同步队列；相同请求复用在途任务，避免窗口末端前移后重新扫描全部年份。
- 构建前拒绝清理仍被进程使用的输出目录。本次验证曾遇到 review 目录被 Python 使用导致清理中断，停止相关 Bridge 子进程后已重新完整构建恢复运行目录。
