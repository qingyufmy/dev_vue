# 当前核心需求偏离检查

日期：2026-09-11。范围：核对用户要求、现行架构和交付清单、近期实现；不是全仓功能审计，也没有重新运行数据库或交易验证。

## 结论

总体技术路线仍符合要求，但实施优先级和完成口径已经发生偏离。近期持续加深复盘子系统，延后后端主流程和全域模块/API 收口；不能继续把每个细节当作独立阶段推进。

当前核心是：服务端和 API 完全模块化并形成后续新增功能的统一规则；数据库规范化且当前 dev_vue 可保留数据直接升级；既有主要业务能力在新架构下接通。前端和 Bridge 的具体可用性细节后置。开发应用在本地，数据库和 Redis 使用虚拟机，不涉及公网部署。

## 收口调整建议

1. 暂停复盘子系统的进一步边缘扩展，保留已有实现和已执行迁移；只处理阻断主流程、数据正确性、权限隔离或重复副作用的问题。
2. 优先核对 D3 主流程：账户与订阅 → 分析任务 → 风控 → 执行状态与结果。以实际接线和开发依赖验证标记完成；真实模型和终端尚未验证的部分单列，不伪装成通过。
3. 同步关闭 D8：逐域列出功能、数据所有权、公开端口、HTTP 合同、实际路由与消费者，明确统一认证、错误、分页、时间和新增模块规则。现有标准先核验覆盖，避免再造框架。
4. 将缺项分为“阻断后端核心”“前端/Bridge 联调”“后续增强或上线验收”。日/月复盘的必要基本能力仍在范围内，迟到费用修订、复杂历史边界和容量优化按实际影响安排，不能一概删除或全部升为阻断项。
5. 后端核心结束依据是完整主流程和全域对账，不再以单张表、单个脚本或测试数量宣布新阶段。当前不宣称核心已完成。
