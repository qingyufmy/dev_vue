# 终端路由增量结构与初始事实合同

本包追加036的两张表及150步注册定义，当前不提供执行入口。前提为035账户根正式提升完成、原148步校验和当前库身份匹配。旧表、历史ID映射、旧迁移checksum不修改。

## 结构与所有权

terminal_account_bindings及bridge_connection_sessions由Bridge路由注册用例写入，trading查询读取；不是账户模块新增第二写入口。引用的terminal_profiles与users采用现有正式结构，账户外键必须指向提升后的V4 trading_accounts。

连接会话结构合并空库设计003、010和023的最终语义：opaque connection_epoch继续保留终端/opaque唯一键；numeric connection_epoch_v4为可空安全整数，由user/profile/epoch普通索引支持档案级最大epoch查询。严格单调性仍在锁定profile行的事务内验证，不能用终端/numeric唯一索引代替。

## 初始事实

两表初始为空，明确表示尚未建立V4可信绑定与连接，不表示旧账户被删除。不得将V3心跳、旧terminal session或历史绑定复制为在线V4会话。首次经过有效凭据、档案、账户归属、额度及epoch校验的Bridge握手，在既有同连接事务中注册新事实；旧来源继续保留供迁移追溯。

本包不默认授予额度、开放观摩或解除风控；已有容量表与凭据、终端事实仍需分别验证。空的新会话事实不要求清除旧终端档案，也不允许自动启动或登录终端。

## 协调与恢复要求

原035协调器核对完成后的完整表集合，因此不能直接在副本执行036再期待原148步检查自动通过。新增协调器先验证完整150步注册历史，对精确登记的两张新增表分别校验结构与状态，再以原表集合及原148条历史调用旧只读验证。不能忽略任意新表、任意日志或改变旧证据。

两个CREATE各自记started/completed。表不存在且无日志才可开始；同名表无日志拒绝接管；started且表符合固定定义才能补完成日志；结构漂移拒绝；结果未知不在同次调用重试。重入时完整保护原有表结构和数据，新表开始接收业务写入后不自动DROP回退。

已实现离线协调器terminal-route-coordinator.mjs：校验完整历史、新表日志与结构状态后，用原148条历史和严格剔除两张已校验新表后的快照调用原035只读验证；默认不写，写入前逐步重查，三类未知响应均立即退出。适配器必须持有同连接升级锁、核对持久化计划、比较新表完整规范结构，并在未全部完成时保护冻结的旧数据。

已增加mysql-terminal-route-migration.mjs适配器：复用原账户根同连接锁/身份检查和日志存储；持久化计划绑定数据库、原根证据、150步注册摘要、旧表快照、新表规范DDL和工具清单。准备函数校验并复制输入，文件采用独占创建及fsync，禁止覆盖原计划。未完成时保护旧行摘要，完成后继续保护旧结构，原协调器另行保护legacy根行。

14项适配器测试验证计划篡改、来源SQL/DDL绑定、缺表/视图/结构漂移、锁丢失传播、步骤拒绝、旧行保护和文件不可覆盖。MySQL连接、原账户适配器及日志调用使用测试替身，不能据此声称实际数据库锁或DDL已验收。

待实现：准备计划的执行入口、来自真实MySQL的规范SHOW CREATE证据及恢复副本演练；不能用手写格式或宽松归一化推测MySQL表定义。完成后才准备当前dev_vue执行。当前SQL、注册表、适配器和离线状态机不代表MySQL已增加表或150步已完成。

## 两轮复核

第一轮检查职责与需求：保留Bridge唯一注册写入口；将终端路由与账户根、行情、观摩分组，不创建不必要的通用迁移框架。第二轮检查兼容和异常：采用当前profile epoch语义、保留旧事实、显式空会话初态，并处理旧完整表集合校验与新表冲突；未设计逆向删除新业务事实的回退。
