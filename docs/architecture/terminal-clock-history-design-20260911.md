# 历史终端时钟证据

当前账户快照覆盖旧值，无法支持日/月复盘引用历史时区。本次在既有账户投影事务内追加原始时钟观察记录，归 trading 模块所有。UTC 时间和终端偏移分开保存，不改写历史交易时间。

第一轮复审（职责与覆盖）：保存全部原始状态，包括 stale/unavailable，而非只保存 calibrated，避免掩盖证据中断。既有实时展示继续使用当前快照。复盘通过明确的读取端口引用记录，不读取最新快照推测历史。记录是观察证据，不宣称其间整个时间段已校准。

第二轮复审（数据与异常）：076 只新增表，不回填或修改旧行。账户、所有权区间、终端、连接 epoch、投影 revision 一起冻结；与已接受投影同事务写入，重复或旧 revision 不新增记录，失败整体回滚。原始时区与 carry-forward 后的有效时区分开保存。保留原始 observedAt 和服务端接收时间；历史边界选择仍需独立验证，时钟观察不能填补离线间隙或证明未知 DST 规则。

验收：定向覆盖原始过期状态、路由身份、非法时间与 revision、写入失败传播；真实隔离库验证表约束、事务回滚；完整 schema 克隆、恢复副本演练、当前 dev_vue 增量升级检查旧数据哈希及重放。未完成的读取、自然日/月调度仍列为核心待办。

实施调整：原恢复副本已不存在，因此本次以一次性当前 DDL + journal 演练验证恢复协调器；不复制业务数据，演练后删除。当前库升级独立核对全部旧表数据哈希，结果通过。此替代不等同从加密备份完整恢复验证。


边界读取 v1 复核：采用显式的有界观察策略，最多向边界前后各查五分钟，选择最近记录，要求 calibrated、同所有权 revision/终端/连接/epoch/偏移，且原始证据哈希匹配。不得预先过滤 stale/冲突连接来跳过较近的无效记录；记录必须在采集 asOf 前收到。该策略不是经纪商 DST 规则证明，不跨离线缺口外推；首尾边界分别验证，因此允许周期中间发生 DST 变化。

职责复审：trading 拥有证据读取端口，bootstrap 组合历史归属、时钟、全量交易库存和 reviews 写入；reviews 不导入 trading 内部实现。数据复审：从服务器记录产生新的 evidenceRef，替换调用者字符串；授权失败/证据缺失在案件写入前返回 unresolved。范围不扩展到自动发现周期、调度和迟到证据刷新，这些仍待实现。

自然周期入口复核：午夜候选偏移只从同账户/归属区间历史观察读取，最多 16 种；再逐一执行既有边界证明。零解/多解均不选择。观察查询不等于授权，collectCalendar 解析后仍必须通过完整历史所有权检查才能读取库存并写案件。当前入口属于服务端任务组装，不作为直接公开 HTTP 操作。
