# 合成账户归属退役设计

状态：设计与只读预检完成，归属写入能力尚未实现。基线7256488c。

## 已验证的边界

当前没有完整撤销账户归属的application用例。真实开发库预检见local-account-retirement-preflight-20260909.json：账户4/5属于合成用户31，账户6属于合成运营者32；每个账户有一条当前owner和开放区间，来源为runtime/bridge-first-account。用户31上下文仍为full/account4/revision47。账户6被已关闭的observer_sources和observer_channels引用，保留这些引用符合历史追溯要求。

15项声明外键只能证明已声明关系，不能涵盖JSON回执、Redis、旧表映射或无外键查询。禁止以计数为零认定可删除。既有trading_context_changes_v4仅允许select_account/enter_observer/leave_observer，不允许把系统退役冒充用户上下文命令。

## 实现范围

在trading建立独立、受限的“未使用归属退役”应用能力，初期仅由本地夹具工具组装，不增加面向用户的删除按钮或通用任意SQL接口。输入必须包括精确账户、用户、预期ownership revision、预期interval、固定request ID与原因。auth负责主体身份能力；Bridge、execution、strategies分别提供阻断事实，不能由trading写它们的表。

用例只结束指定当前归属，保留账户、区间、映射、上下文历史、策略及交易证据。对活跃档案/绑定、未结束会话、持仓/挂单、待决或uncertain命令、启用订阅与观摩入口拒绝操作。缺失依赖表/能力返回未就绪，不当作“没有依赖”。当前缺少部分推理/执行表，需明确对应能力的兼容语义后才能执行。

成功事务以同一UTC时间设置ownership.revoked_at及interval.ended_at/end_reason，按比较版本更新账户归属版本；必须验证开放区间与当前归属完全一致，且结束时间不早于起始时间。引用该账户的当前上下文转为blocked并推进版本，其他账户上下文保持原样。新增专用幂等回执保存原请求指纹及结果，不能扩写已执行的上下文迁移或覆盖历史回执。

权限失效事件由同事务outbox登记，提交后发布；消费方丢弃旧账户作用域、重拉权威上下文。未知提交保留原request/body查询回执，不生成新请求或回滚数据库版本。删除账户、关闭终端和交易命令均不属于此用例。

## 实施前必须解决的锁与兼容问题

现有Bridge注册是账户→归属→用户；上下文命令先用户、后账户。不能宣称已经存在覆盖所有写入者的统一锁序。实现前列出参与事务及实际锁类型，收敛锁序或采取有证明的冲突重试机制，使用双连接验证账户切换、Bridge注册和归属退役交错。不能把预检之后的一段空闲时间当作并发保护。

先盘点SQL-only/JSON/缓存依赖及现有缺表，再确定专用回执与outbox合同的追加迁移；迁移编号在实施时按当前目录分配。保持冻结的321个输入和已执行迁移不变。回退只能停止后续退役，恢复权限需要新的授权命令及新区间，不倒退revision或清除撤销记录。
