# 首次账户登记的事务端口收口

范围：总体方案 P0/P1 的账户写入所有权；只改源码组装，不执行数据库迁移、连接注册或终端操作。

trading 拥有账户实体、归属区间及当前归属的写入。Bridge 保持 hello、凭据、档案、epoch、绑定和连接会话的编排。运行入口将 trading 的事务适配器工厂注入 Bridge 组装入口；工厂接收已经开始事务的连接，只向 Bridge 提供首次账户创建和首次归属登记能力。MySQL 类型只出现在 infrastructure/composition/entrypoint，应用端口不接受连接、不提供 commit/rollback。

Bridge 消费端与 trading 提供端各自定义最小结构合同，由入口赋值进行类型兼容检查，避免模块为适配器实现互相导入。存储影响行数异常与非法 BIGINT 返回值通过明确的结果原因传回 Bridge，再映射既有错误码；SQL 驱动异常仍由外层事务回滚并使用现有分类。trading 不依赖 Bridge 的错误类或 hello DTO。

保留顺序：验证 hello → 开始事务 → 查询账户 → 缺失时创建账户 → 核对已有归属 → 重查凭据 → 档案校验 → 缺失时登记归属 → epoch 校验 → 绑定 → 会话 → 一次提交。中途任何错误整体回滚；原锁序、服务器登记时间、legacy origin 引用、字符串 BIGINT 和重复身份冲突保持。端口仅承载已验证的首次登记写入，现有账户读取/授权投影后续单独收口。

第一轮复审（职责与复杂度）：不引入通用事务容器或跨域 SQL 接口，只为真实流程提供两个受限方法；SQL 迁移到唯一业务所有者，工厂只在运行组装处连接。禁止保留 Bridge 内的默认 SQL 实现，否则注入只是可选旁路。

第二轮复审（兼容与异常）：不能让交易适配器获取第二条连接或独立提交；保留第一次账户 INSERT 与后续凭据/归属/会话失败的回滚。旧错误码不能因移动错误类改变；采用结构化失败原因映射。既有并发冲突、孤儿/已撤销/其它所有者、货币、时效、BIGINT 与后续失败场景通过实际组装工厂重跑，并验证端口失败也进入同一回滚路径。

剩余风险：当前测试使用有事务状态的 SQL double，不是 MySQL 真实并发与回滚证据；账户创建后的读取与跨域锁查询仍有未收口内容。验收不能将三张表写入归位等同于账户模块或数据库迁移完成。

实施记录：trading/application声明AccountRegistration，Bridge声明最小消费端口；两个composition由bridge-gateway入口组装，Bridge仓储构造器不保留默认实现。原首次登记SQL文件已移除，三张账户表写入位于trading/infrastructure/mysql-account-registration.ts。Bridge业务index不再导出具体路由仓储，删除对应1条真实消除的依赖例外。

验证：26项路由登记事务测试与3项账户登记适配器测试通过；原失败回滚、冲突及归属隔离通过新的组装路径，新增登记/归属端口两种失败原因的映射回滚、异常影响行数及字符串BIGINT验证。完整服务端类型检查与构建通过，239文件边界扫描无新增，存量143条；SQL清单确认三表仅由trading写入。未连接真实依赖，未执行首次登记或迁移。
