# 自动复盘证据收集与建案实施方案

日期：2026-09-11。属于已授权的本地核心重构；未完成实现，不代表生成链已接通。

## 已核实的断点

- `reviews/MysqlReviewRepository.createManualCase` 是当前 runtime 唯一的新建 case 路径；日、月、系统单笔 case 没有生产器。
- `manual_review_candidates_v4` 尚无 runtime 生产器。候选列表和手工建案可用不等于候选有来源。
- `trade-history` 有独立读取、采集、归因模块；记录提供 closed/partial、exact/unresolved、evidenceStatus、货币来源和 evidenceHash。
- `TradeHistoryFreshness.ready` 及记录 `evidenceStatus=complete` 不能单独证明费用稳定。当前终端解析仍存在缺费用字段补零的行为，必须区分“明确为零”与“字段缺失”。
- 命令 `succeeded` 只证明对应动作的结果。挂单创建成功不能当成已平仓、已结算交易。
- 已实现的复盘 Worker、不可变版本、确认、记忆候选、恢复机制继续复用。归档历史永不重新入队。

## 职责与接口

1. `trade-history` 提供专用 ReviewTradeEvidenceReader 应用端口，经公开 index 暴露合同；SQL 适配器留在本域。一次一致快照返回有界稳定游标、所有权区间、采集 revision/范围/完成回执、记录与关联成交、费用字段存在性、精确来源及原始摘要。分页未完成不得声明集合完整。
2. `inference` 提供冻结分析/决策读取；`execution` 提供精确 intent/outcome 来源；`strategies` 提供历史订阅和策略版本。复盘不能跨模块直接 JOIN 这些业务表，也不能以当前策略覆盖历史正文。
3. `reviews` 的 collector 应用服务决定等待、拒绝或冻结，SQL writer 仅写本域 case/source/evidence/job/事件/outbox。领域资格判断不依赖数据库、Redis、模型。
4. 独立 review scheduler 只登记收集任务；收集 Worker 从所属域读取证据，完成后以短事务提交。模型 Worker 只消费完整冻结 case，不能采集行情或交易历史。

## 建案资格

### 系统单笔和手工候选

- 同一历史所有权区间、terminal instance、账户标识和精确交易 ID。
- 已平仓且入场/出场手数守恒；未决成交、混合来源、冲突、费用缺失或未证明币种时等待证据，不以零值或推测补齐。
- 明确归因为 system 的交易建立 trade case；明确 manual 的交易只建立候选，用户选择后复用现有手工建案。other_ea/mixed/unknown 不进入这两种路径。
- 保存费用/成交采集截止时间和完整性证明；后续更正形成新的 evidence revision，不覆盖已确认正文。
- 手工候选 token 继续使用现有 `id.revision.evidenceHash` 协议及 SHA256 校验。已消费交易不得重复生成经验样本。

### 日、月周期

- 根据冻结的历史终端时区证据确定半开区间 `[start,end)`。只收集已经结束的周期。
- 不把今天的终端偏移追溯到过去。跨时区变化时需要边界处的历史证明；无法确定周期边界则等待。
- 按用户、所有权区间、账户、品种、订阅 revision、分析/交易策略版本划分范围，防止跨用户或策略切换串线。
- 交易、分析、决策、风控拒绝及未执行结果分别保留；没有交易不能推导没有信号或机会。
- 月复盘依据完整原始范围，日复盘只作关联材料；不能拼接若干日结论冒充全月证据。
- 默认 UTC+3 仅用于用户已要求的显示兜底，不构成自动建案的历史时间证据。

## 持久化、幂等和恢复

- 稳定 scope key 不包含每次扫描时间或随机 ID；包含 kind、用户、所有权区间、历史业务范围。
- 首次建案原子写 case、来源引用、canonical evidence、job、事件及 outbox。相同 scope/相同证据返回原记录；改变证据进入显式 revision 更新流程。
- 收集和模型执行不在同一数据库事务；跨域证据携 revision/hash，提交前逐域复核 token。源变化重收集，不提交混合快照。
- 初版分页与载荷均设硬上限；达到上限返回需要继续收集，不能截断后标 complete。大证据采用已有摘要/分块经验，具体 schema 变化只追加迁移。
- 未就绪保存稳定原因和重试游标，避免每次扫描重新遍历全历史。重启/重复投递只推进原任务。
- 修改或替换既有 evidence 时不自动覆盖已确认版本、不自动更新策略记忆。

## 实施顺序及交付判据

1. 费用字段存在性与证据资格：补终端解析的 missing/explicit 区分和回归；提供 ReviewTradeEvidenceReader 实际 SQL 实现。缺字段、部分成交、归属变化、分页缺口均不能返回 ready。
2. 手工候选生产：当前本地参考库跑实际采集到候选再到 createManualCase；并发、选择过期、改 revision、旧所有者拒绝、重复消费全部验证。
3. 系统单笔建案：通过真实领域端口冻结分析→决策→风控→执行→历史交易，生成一个完整 case；合成模型验证正文版本，不调用真实模型。
4. 周期建案：历史终端日/月边界、策略切换、夏令时边界、空交易但有决策、跨日平仓、月缺日、补费用后 revision 更新。
5. scheduler/collector/recovery 接入独立角色、配置与健康检查，验证自然队列推进。新增 schema 先完整参考外键和恢复库升级，再按既有授权升级 dev_vue。

## 第一轮复审：覆盖与模块职责

- 调整：撤销“execution outcome succeeded 即可自动建案”的捷径，改由交易历史闭合证据触发。
- 调整：先补证据端口与手工候选生产，再扩大到周期；三个复盘种类仍保留在目标中，不能以单笔代替周期。
- 调整：复盘不拥有交易归因和费用真相；这些能力归 trade-history，跨模块只传公开证据合同。
- 结论：范围完整，现有 Worker/版本机制复用，不增加第二套复盘工作流。

## 第二轮复审：兼容、并发、故障和验证

- 调整：稳定费用必须有字段和采集证明，不能任意等待几分钟后宣告稳定。
- 调整：原用户历史所有权和历史时区必须冻结；当前账户设置不覆盖旧事实。
- 调整：收集完成与模型生成分离；用 revision/hash 提交复核处理跨域一致性，拒绝把长网络请求包进 SQL 事务。
- 调整：旧表/归档/确认正文保持，schema 仅追加；只有完整对账才允许切换读路径。
- 剩余风险：现有终端事实未必携带足够费用字段/历史时区证明；需先实现并验证能力，缺证据任务可持续等待，但不得伪造 ready。真实终端、模型和公网验证仍分别记录，不由本地夹具替代。

## 人工单笔时间语义修订及两轮复审（2026-09-11）

依据用户已明确的“数据库所有时间存UTC、AI实验室显示终端时间”要求，人工候选按精确交易ID、UTC生命周期和所有权区间确定范围。此前给人工候选强制要求覆盖开平仓全区间的历史时区证明，混入了日/月周期分组的前置条件，应移除。此修订不改变实际成交、完整采集回执、费用、源revision与当前授权要求，不降低日/月周期的历史时间边界要求。

第一轮（范围和职责）：人工候选没有终端自然日/月分桶，因此UTC事实足以确定交易集合、排序和金额；交易记录携带的终端偏移只作为冻结的显示元数据，标注 collected_record_offset、historical_interval_verified=false。不得根据该值推导历史夏令时或周期归属。历史归属仍需当前所有者与原精确区间双重校验。系统单笔按同一UTC原则处理，日/月边界仍单独实现。

第二轮（兼容和验证）：新候选authority保存UTC语义及偏移来源，不覆盖旧候选版本。撤销/跨用户/归属变更、UTC格式异常、未来或倒序成交、越界偏移必须拒绝。删除尚未使用的 HistoricalClockReader 空合同，避免一个没有数据源的抽象阻塞人工流程。073表结构及已执行迁移不变；真实MySQL组装应接入实际ActivePrincipalAccess/OwnedHistoryAccess，终端数据合成边界继续标注。剩余风险是记录偏移可能并非历史实际偏移，必须保持显示用途标记，不得转用为日/月周期时间证据。


## 候选任务持久化复审（2026-09-11）

第一轮：任务归reviews所有，以完成的history task ID作稳定唯一来源。每次最多20条，在同一MySQL短事务内锁定任务行、生成候选、写下一页游标/结果；不新增网络调用或模型调用。pending/waiting/succeeded描述扫描进度，不是模型任务状态。未就绪记录所在页不前进，保留逐项原因；队列只负责唤醒。

第二轮：使用数据库行锁串行化同一来源任务，事务结束即释放，不在短SQL页处理中另设可过期应用lease。崩溃回滚整页，COMMIT回执未知通过重读任务/候选恢复；已完成任务重跑不生成新版本。next_attempt_at使用数据库UTC，waiting返回明确重试时刻。页游标和候选必须同事务，不能先提交候选再单独推进游标。后续outbox完成事件、注册、恢复扫描和BullMQ接线仍为必要交付，单独实现表或run函数不视为自动任务上线。
