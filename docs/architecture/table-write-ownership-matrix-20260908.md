# 全表写入所有权矩阵与接续

> 历史基线，不能用本页表数量判断当前进度。当前源码差异见 [2026-09-11 写入归属复核](data-write-ownership-review-20260911.md)：新增写入表已补列，风险预留及其事件当前归 execution 管理；全数据库目录和间接 SQL 的当前对账仍待关闭。

本批将当前开发库表名与现有V4结构计划、旧表迁移矩阵和源码写入清单对齐。它是所有权设计底稿，尚未完成所有权验收。

证据：[当前222表只读目录](database-table-catalog-20260908.json)、[291表逐项矩阵](table-write-ownership-matrix-20260908.json)、[结构延期目录v10](../migration/dev-vue-structure-remaining-work-20260908-v10.json)、[旧表业务迁移矩阵](../database-table-migration-matrix.md)。本次只读访问env指定的dev_vue并核对数据库身份，没有读取业务行、运行迁移或改动配置；表名存在不证明字段兼容。

所有114张目标字段清单中的表都有建议所有者。另纳入24张现有附加表，包含学习、支付、设置及7张构建表；构建表建议由迁移工具管理，不能代替缺失的正式业务表。没有源码写入者的表不等于无用表，不删除数据，也不把旧服务写入覆盖情况标成已核验。

94张源码静态/动态写入目标中，有66张在当前库尚不存在。这与既有根实体延期一致，说明离线服务端验证不能代替真实全功能联调；应先完成账户等根合同和增量升级，再逐模块验证，不能关闭外键或建立占位表让启动通过。

| 建议所有者 | 表数 | 需落实的职责 |
| --- | ---: | --- |
| auth | 3 | 身份根与会话；users会员和资料字段继续按原合同拆分 |

| trading | 19 | 账户、归属、交易上下文、观摩和终端行情投影 |
| inference | 16 | 模型配置/用量、推理任务、快照与决策事实 |

| trade-history | 8 | 终端历史、归因、同步与账户统计 |
| market | 11 | 宏观/日历数据；这是待落实的领域建议，不表示已有独立模块 |

这里没有将“当前唯一写入者”直接转换为完成状态。例如risk预留目前由execution/trading写入，目标归risk；Bridge命令表虽然带bridge前缀，状态机归execution；outbox虽有多个事件生产者，SQL追加实现仍需集中到受限事务端口。

## 两轮复审

第一轮核对范围与职责：检查222个现有表、69个延期表、165个旧源表及92个静态写入目标均进入矩阵；补入动态两表及24张附加表。151张尚未定责的旧源表保持待定，不能通过表名前缀自动批准。market领域及subscription_schedules所有权仍是建议，需要对应阶段落实。

第二轮核对数据与事务：表名只读证据不替代字段/约束兼容；构建表不冒充正式表；跨域写入保留同连接事务，特别是risk预留、决策关联、订阅游标及outbox追加。源码写入不存在的正式表被显式列出，不能声称当前数据库已支持完整V4运行。

下一批优先处理账户样板所依赖的根ID、归属和投影表合同，同时继续逐旧域定责。所有者确定后再接入写入边界检查；当前矩阵不作为自动豁免基线。
