# 周期复盘持久流程

归 reviews 所有。每个用户、账户、历史归属区间、日/月 key 只有一个周期工作项；工作项持久保存 planning/history/succeeded 进度、固定时钟与窗口、历史请求 ID、尝试次数和结果案件 ID。已有 review worker 执行具体模型任务，不把模型 I/O 放进工作项事务。

第一轮复审：工作项承担周期级恢复，history_collection_tasks_v4 承担终端分页和连接租约，review_jobs_v4 承担模型执行，不合并三种状态机。日/月生成的策略版本案件仍由既有周期写入器管理。发现、窗口推导和真实端口组装必须补齐，不能把持久表视为自动运行已完成。

第二轮复审：077 只加表，不改业务旧行。scope 唯一键防重复登记；先锁账户再锁工作项，与历史注册保持顺序。进度 JSON 与哈希一起保存，读取核验。每次进度与内部 SQL 副作用同事务提交，提交回执不确定沿用 review_commit_unknown。新历史尝试 ID 先随进度提交，下一次再登记历史任务；失败退避上限一小时。进度不得覆盖已完成项或改变 scope。固定窗口不随着重试时间滑动。测试需覆盖 SQL 事务回滚、同 scope 重放和已完成流程不重复；源码端口替身结果不替代真实依赖整链路。

剩余：自然到期发现、历史生命周期最早边界证明、具体端口组装、迟到证据与大样本。未启动常驻服务或授权真实终端操作。


运行接线复审：scheduler-trade-history 只按真实归属/时钟候选登记工作项，每轮至多 20 个 scope；重启游标丢失时依靠 scope 唯一键重放。worker-review 增加独立低并发周期队列，恢复器按 MySQL next_attempt 时间唤醒，队列只载 workflowId。规划以已授权历史归属区间起点作为完整生命周期采集下界，避免只请求本日/月而漏掉跨期持仓；该范围可能很大，现有库存分页上限仍须后续处理。

具体流程复用真实 auth/trading/history/reviews 组装，计划/请求/建案都在调用者短事务内。注册不依赖一次性外部投递成功，恢复器直接核对 MySQL 到期状态；history 与 model 外部 I/O 继续沿各自 outbox/worker 执行。未启动常驻角色；真实 SQL/Redis 参考测试的终端观察仍为合成输入。

库存分页复核：每页必须引用同一完成回执哈希，游标必须来自该回执事实集，后页缺失不可当作完整库存。周期消费者只累积期间平仓证据，但仍检验所有批次；现阶段同事务遍历，持久页检查点和模型样本分块尚未实现。one-shot 消费者维持原完整性上限，避免把局部页误认为全量。
