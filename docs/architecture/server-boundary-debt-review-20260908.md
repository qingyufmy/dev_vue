- 跨域内部导入按实际目标路径登记：Bridge/execution共享命令、inference依赖策略与交易内部服务、trade-history依赖Bridge查询类型/传输、交易认证适配器访问auth内部。应按所属域改为公开端口及组装注入，不能把全部内部实现重新导出规避检查。
- 公开实现导出按index转导出的具体infrastructure/transport目标登记，含同一路径的纯类型与运行导出；类型定义位于基础设施目录同样应迁到公开业务契约，不豁免整个文件。
- 领域层依赖主要在Bridge/execution/risk及历史投影之间；保持现有业务规则，先明确基础契约与应用端口后迁移，不能删除行为来打断依赖。

## 门禁行为

`pnpm run verify:server-boundary-delta`先运行真实静态扫描，再对比精确多重集；新增记录、同一边次数增加、类型改运行、导入改导出均失败。减少债务后必须同时移除陈旧记录。循环比较全部内部边，不仅比较成员或循环总数；行号移动不产生假差异。

配置必须有模块、阶段和理由，禁止通配符、重复记录及将未知规则/无法解析依赖加入豁免。没有自动更新基线命令。将新增问题手工加入JSON依然属于需要代码审查的规则变更，脚本不能代替该审查。

15项检测器测试通过，包括同数量替换、陈旧例外、运行属性变化、重复边、循环内部扩张及配置拒绝。实际在audit/application下创建一条指向trading/domain的临时依赖，CLI正确拒绝；探针已删除，之后类型检查通过。门禁已接入服务端类型检查和构建。
