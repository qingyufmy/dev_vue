133步库补齐冻结V4目标的6个索引：bridge_refresh_sessions两个可空迁移键唯一索引及设备复合索引；ai_model_profiles归属复合索引；ai_model_usage_logs额度及待恢复复合索引。用户邮箱/手机号已有唯一索引承担对应查找，保留，不为目标普通索引重复建索引。其余根实体缺列相关索引随对应领域承接。

第一轮复审：现有模型解析、额度检查和过期预约恢复查询已使用对应列；Bridge迁移键唯一约束防止重复迁移来源。索引来自目标DDL，保留所有旧索引、主键、CHECK、NULL、排序和历史行；不以增加索引数量证明查询变快。现有两个迁移键无非空重复，执行前重验。

第二轮复审：6条DDL分别绑定完整前后表定义，沿用同连接锁、journal、checksum和逐DDL中断恢复。模型表已有CHECK步骤与新增索引必须串联同一表状态，不误用旧中间定义。恢复副本全行业务摘要、其它DDL及自增值不变，重复0DDL后才开放当前库。EXPLAIN只证明当前数据分布下访问路径，不冒充压测或实际业务切换。

剩余风险：索引方向、前缀、隐含主键列和实际查询覆盖需在完整索引审查中区分，初步25项列签名差异不是25个都应新建。原表不同于目标根实体的部分不能仅加索引强行切换。
