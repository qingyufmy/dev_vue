# 同库升级第八批：稳定账户 ID 映射

2026-09-06。新增完整冻结账户集合上的确定性 ID 映射规则及真实只读复核；本批没有写入业务表或迁移账本，原库仍保持第六批结构状态。

## 实现与数据对应关系

`scripts/lib/v4-account-id-mapping.mjs` 复用已有账户候选工具，对完整来源主键集合建立映射：

- 同平台、服务器规范身份及登录号形成实体组，使用组内数值最小的来源 ID 作为计划目标 ID。按数值排序，不能把字符串 "10" 排在 "2" 前；登录号保留前导零。
- 每个来源 ID 生成一条符合现有迁移账本合同的 sourcePk→target 引用，不丢掉被合并的旧 ID。各用户的设置键分别保留。
- 必须一次基于完整冻结源规划，再持久化后供分页回填使用。来源主键集合不完整时拒绝，不能每批独立选代表 ID。
- 同用户的两个旧记录若合并后占用同一设置键，直接报告冲突，不采用最近记录覆盖。未解决的平台/币种证据、孤立当前绑定和目标 ID 冲突也拒绝。
- 输出 ownershipMap 与前一批归属转换器衔接。对方仍独立验证历史 user_id、账户身份、时间与区间不重叠，不能由当前设置用户替代历史所有者。

计划中尚不生成账户的 UTC 创建/更新时间，也不解除历史平台/币种覆盖、目标 ID 占用、实际实体转换及写入对账条件。persisted=false、readyForBusinessWrite=false；计划目标 ID 不表示已经存在规范化业务实体。

当前源库只读复核：4 账户、7 终端、3 当前绑定、274 归属区间（3 开放）。274 条区间均能匹配计划目标账户的规范身份，无新映射关系问题。新增孤立绑定检查后，再次从真实库读取并重算，除采集时间外与已记录证据完全一致。
