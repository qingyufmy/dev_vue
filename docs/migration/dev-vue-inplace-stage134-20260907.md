# 阶段 134：配置更新事务原语

本轮实现已有非秘密配置值的版本化更新。数据库结构仍沿用阶段129的57步，本轮没有连接或写入数据库，没有启动服务或切换消费者。

## 实现与边界

`server/src/modules/settings/infrastructure/mysql-setting-writer.ts` 在同一连接内锁定目标行，检查类型、敏感级别及 expectedRevision，再以 CAS 更新值、版本和 UTC 毫秒时间，并写入 system_setting_changes。版本保持十进制字符串，避免 JavaScript 精度损失。

审计摘要采用版本1固定15列 JSON_ARRAY，整数转文本、日期保留六位小数后由 MySQL SHA256 计算。摘要覆盖配置全部持久化字段；不会把配置正文写进审计。此格式与迁移来源八列摘要不同，不相互替代。

入口只更新已有 public/restricted 配置，不创建条目、不修改元数据、不接受 credential。基础类型检查之外，调用方必须提供同步逐键语义验证器，明确决定 NULL、范围、枚举、URL及内容等策略；必须严格返回 true。当前没有提供可公开调用的万能配置接口。

调用方负责 UTC 会话、认证授权、事务开始及任何错误后的完整回滚。原语不提交、不重试。现有审计仅存前后摘要，不能据此实现完整请求重放；管理服务接入前必须实现持久化请求幂等与未知提交恢复。任何提交未知不得直接重试此原语。

## 定向复核与验证

- 并发复核：使用 FOR UPDATE 当前读取得版本和类型，避免事务一致性快照导致陈旧判断；CAS 影响行数必须为1。
- 安全复核：秘密或类型不匹配的条目拒绝更新；验证器不得执行外部 I/O；审计失败向调用方传播。
- 离线：读写器共8项测试通过，覆盖大版本精度、版本冲突、秘密拒绝、类型/范围输入、语义拒绝和审计失败传播。
- `pnpm run typecheck:server`、`pnpm run build:server:v4` 通过。
