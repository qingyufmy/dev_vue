# 阶段 136：配置逐键运行时写入规则

新增 `server/src/modules/settings/domain/setting-value-policy.ts`，覆盖59个已分类全局配置键。运行时不导入迁移脚本；测试逐项比较冻结迁移注册表的类型、敏感级别、上下界和枚举，防止两个入口无意漂移。旧迁移文件和来源转换规则保持原样。

写入检查拒绝未知键、类型不匹配、NULL、无效UTF-8、长度超限、非规范整数及非法枚举/布尔值。字符串按Unicode码点计数，保留原文，不做trim、默认值或JSON重序列化。

凭据必须走后续专用安全写入用例。media_storage的local_root及qiniu_connection_test系列属于服务维护字段，通用配置更新拒绝这些字段。

地址、菜单项目、工具箱项目、更新正文、SMTP端点和身份、短信/七牛配置、存储可用性通过显式policyChecks交给各业务域。eligible仅表示基础规则通过，不表示完整语义已接受；validateSettingValueForWrite在缺少任何必需业务检查时返回false。调用方应提供已经取得的领域证据，不能在数据库事务中发起网络I/O。此策略尚未替代管理用例的权限、幂等和跨字段一致性检查。

## 定向复核与验证

- 需求复核：区分迁移原文保留和新写入规则；不得因旧值需要保留而让管理接口接受任意新值。
- 安全复核：秘密和服务状态不开放通用写入口；业务语义检查缺失时失败关闭；错误结果不含配置正文。
- 9项测试通过：59键合同一致性、不可借返回副本篡改注册表、敏感/未知/服务字段拒绝、整数边界、语义证据缺失、JSON及Unicode边界，并回归事务writer。
- 服务端类型检查与构建通过。本轮无数据库连接、迁移、回填、服务启动或消费者切换。

下一步补齐配置管理持久化请求收据与并发恢复，再接入经授权的管理用例。地址、菜单等业务校验的具体实现仍待所属域提供，不以回调接口存在宣称已经验证语义。整体自动升级和旧结构删除仍未完成。
