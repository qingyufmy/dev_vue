# U2 身份字段纯转换与逐值核对

范围：复用U1首批11表字段合同和源读取器hex信封，实现无数据库依赖的候选值转换及独立输入的目标值比较。候选值不是完整业务行，不接writer，不解除U1阻断。

第一轮复审（覆盖与职责）：逐一登记整行源字段，缺列、多列、重复列或源hash/PK不符即拒绝；只处理明确的exact、legacy-id、decimal规则。历史、时间、关系重映射及其它专用转换明确deferred，原值仍由源信封保留。没有确定目标的字段不能消失在成功计数中。

第二轮复审（数据与异常）：整数与DECIMAL仅使用字符串和BigInt；文本严格解码，不trim、不大小写归一、不替换非法编码；NULL/空串/零分开，目标NOT NULL与长度/精度冲突直接报告。比较器接收另行读取的目标值，不以writer返回hash作为对账；局部字段相等不能证明目标记录集合、关系、金额汇总或全库完整，结果始终不可回填。不会把时间NULL、已删除用户或旧在线字段解释为授权。

## 实施结果

`scripts/lib/v4-identity-values.mjs`提供三个纯函数：`representIdentityValue`校验可表示性，`inspectIdentityValues`登记完整源行并产生候选值/待处理/拒绝结果，`compareIdentityCandidates`比较独立输入的目标逻辑值。所有结果保持`readyForBackfill=false`，比较器始终`fullRowReconciled=false`。原U1的业务阻断逐字段保留，未修改冻结清单和SQL。

当前首批148列中25列采用exact/legacy-id/decimal规则，可以进入标量校验；是否实际生成候选值仍取决于目标声明、NULL/长度/精度及具体原值。其余123列的专用规则保持deferred。全部11表148列有输出登记，不能把候选字段子集当成完整行。目标默认值不会补源NULL，推荐余额采用DECIMAL定标字符串；仅允许去掉多余的零精度，不允许舍入。源hash保留原信封，定标后的候选值不取代原值证明。

调用者必须使用已由`review-v4-upgrade.mjs`验证的U1合同并绑定其hash；函数不认证任意传入合同，不提供公开API或写入入口。候选结果在内存中含密码哈希、用户联系方式等原值，不可直接输出到CLI日志/公开报告；差异结果只给字段定位和机器码。实际目标回读适配器尚未实现，测试使用单独构造的目标值输入，不能冒充真实数据库回读。

`pnpm exec vitest run tests/v4-`：31文件244项通过，本批8项包含全11表148列登记、原值保留、源hash/PK/字段覆盖篡改、整数边界、十进制拒绝舍入、NULL/超长、非法UTF-8及目标缺失/多余/改值。U1产物一致性和模块语法检查通过。没有连接数据库、执行DDL/DML、启动服务或部署。

## 下一步及剩余门

继续专用规则前，须逐项核实39列wall-clock、14列relation、8列state、17列observer、1列credential、3列epoch-ms、15列fresh-runtime和26列history的业务证据及目标承接，不能仅凭类型推出语义。用户删除态、密码认证兼容、推荐码关系、账户授权区间、唯一键排序规则冲突还需整行/集合级验证；字段相等不能解除这些门。之后实现受控领域writer、独立目标读取和计数/金额/关系对账，完成冻结源与真实依赖演练后才具备U3回填条件。
