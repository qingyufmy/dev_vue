# 阶段 170：学习域冻结清单与执行适配

新增 learning-manifest/v1，沿用已有 settings 清单模式，绑定来源 ID、来源集合摘要、转换摘要、run、批大小、外部审查证据、schemaHash、服务器 UUID、逻辑来源和同库目标。清单不嵌入课程/进度业务原行，不生成历史时区依据，不自动放行 admission。

读取清单时重新校验自摘要，重新读取的实际来源必须通过原转换校验并匹配全部 sourceIds/摘要。证据摘要必须与调用方独立提供的已审查目录一致；进度必须使用调用方提供的当前用户集合。来源课时映射保持绑定，跨域最终关系由已有 migrateLearningCore 核对。

清单文件采用 wx 独占创建、fsync 和回读确认。相同内容重复读取允许，已有冲突或半写文件不覆盖。文件自摘要用于发现意外改动，不是外部签名或审查授权的替代品。

executeLearningManifests 接入两个实际 MySQL repository 与父子编排。取得第一条连接前先解析两份清单和转换，仍由实际 repository 校验数据库身份、事务、回执及独立对账。默认 verify；连接不可用返回父域 unknown、progress=null，不自动重试或补写。

## 验证与限制

清单 6 项、执行适配 2 项和父子编排 5 项定向测试通过。覆盖序列化往返、来源/证据变化、清单重算摘要后仍不合法的 ID/转换绑定、用户缺失、admission 未通过、独占文件冲突与半写文件、真实 repository 连接失败路径。临时测试目录已清理。

适配测试最初错误地预期 verify 连接失败抛异常；核对恢复合同后改为断言返回 unknown 且不启动进度，未为满足测试改写既有恢复语义。

本轮没有真实 DB 连接、DDL/DML、服务恢复或部署。MySQL 启动故障与背景信息仍待解决，既有只读探针未完成。显式命令入口的环境/文件读取、真实恢复副本回填与中断演练仍需继续；不能把清单源码完成视为部署自动升级已交付。全域规范化目标继续保持未完成。
