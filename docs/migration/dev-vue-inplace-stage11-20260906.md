# 同库升级第十一批：事务回填的存储模式

现有回填框架要求源库与目标库不同，并依赖新版 schema_migrations 布局；当前 dev_vue 保留旧日志，不能直接使用。新增明确的 inplace-account-v1 模式与 MySQL 账户适配器，复用原事务、映射、回执、检查点和未知提交恢复流程。

## 两轮复核

第一轮（范围与职责）：不修改原异库模式，不把当前库伪装成别的源库身份。新模式要求 sourceDatabase 与 targetDatabase 相同、mirrorDatabase 不同；只接受 trading_accounts 和 mt5_account_ownership_history 两种源流。逻辑目标固定为账户实体、归属区间、授权投影、个人设置四张表，对应同库四张 _v4_build 物理表。映射继续使用最终逻辑表名，避免切表后 ID map 指向已经消失的临时名字。

第二轮（误写与恢复）：运行规范、目标身份与 writer 都必须携带匹配的 storageMode；通用 writer 在进入事务之前即被拒绝，防止把逻辑目标 trading_accounts 当成可写的旧物理表。物理表名解析只有固定白名单。原事务提交不确定时仍销毁连接并走锁定账本核对，不新增盲重试。当前只接通框架，专用业务 writer 尚待实现，不通过此模式自动开放业务回填。

## 身份检查

专用适配器读取独立升级日志，复核全部 22 个步骤完成、首批九列及九张基础表和四张账户工作表实际结构，并复核 users、旧账户、归属历史的结构摘要。不读取不兼容的旧 schema_migrations 新版字段。目标库仅允许 dev_vue 或既定恢复副本命名；实际实例 UUID、数据库和 schemaHash 由原事务 runner 与绑定证据核对。

结构摘要忽略 AUTO_INCREMENT 当前计数，但保留列、默认值、生成表达式、字符排序规则、索引、外键及 CHECK，避免正常插入改变身份摘要。该摘要只覆盖本账户回填所需结构，不能当成全库结构、源行内容或金额对账证明。后续执行入口仍须冻结输入、持有升级锁、验证备份和真实回填演练。

## 验证与后续

32 项定向测试通过，包括新增 4 项同库范围/错误源流/越界目标/错误 writer/错误适配器回归，以及原事务恢复、MySQL 适配器和账户转换测试。使用当前 dev_vue 执行真实只读身份检查，两次摘要一致，见 [身份证据](dev-vue-inplace-backfill-identity-20260906.json)。没有 DDL、DML、运行开关或公网操作。

下一步实现账户专用批次和 writer：使用固定物理表路由，在同一事务写目标行、稳定映射和逐源回执；共享实体必须验证内容一致，不能重复覆盖。历史 DATETIME 的实际 UTC 转换仍等待明确来源时区；随后执行副本回填、故障恢复和源库回填。全域自动升级与已替代结构删除仍未完成。
