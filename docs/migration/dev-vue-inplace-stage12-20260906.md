# 同库升级第十二批：账户批次写入器

实现账户实体与个人设置的专用批次生产器和 writer，接入现有 executeBackfillBatch 事务协议。完整冻结集合先转换、再按稳定源 ID 分页；每条源记录携带公共实体、对应个人设置、最终逻辑目标引用及源到目标 ID map。共享实体的时间聚合不会随批次大小变化。

## 两轮复核

第一轮（覆盖与职责）：一条旧账户记录产生一个逐源回执和一个稳定实体映射；公共实体可由多条来源引用，个人设置分别保存。目标引用保留正式逻辑表名，writer 只解析到固定 _v4_build 表。来源全字段在转换 payload 中携带，但现有账本只保存来源/转换摘要与目标引用，因此 sourceProvenancePersisted 明确为 false；完整来源持久化和历史逐字段回读仍须在清理旧表前解决，不能把摘要当原文。

第二轮（事务与异常）：writer 使用 runner 传入的同一事务连接，先锁定读取，已有内容逐字段一致才复用；不存在则参数化 INSERT 并完整回读。不存在 UPDATE、REPLACE、INSERT IGNORE 或覆盖式 upsert。整数按字符串回读，日期验证毫秒精度，登录号前导零、NULL/空字符串及文本精确保留。writer 闭包保存权威预期行，调用方即使修改公开 payload 并重算 hash 也会在 SQL 前被拒绝。失败由外层事务回滚目标行、ID map、回执和检查点；未知提交继续使用现有恢复流程。

## 验证

6 项新增离线测试覆盖分页前全集合聚合、共享实体只插一次、最终逻辑映射、固定物理表范围、参数化值、锁定回读、冲突拒绝、输入篡改、存储值转换检测。新增事务组合测试在第二条来源写入时故意失败，验证第一条业务行及映射/回执/检查点全部不提交；成功后 3 条目标行、2 条映射、2 条回执一起提交，再次执行无变化。加上同库模式与原恢复测试共 25 项通过。

本批没有真实数据库写入，也没有执行 DDL。Mock 事务结果不是 MySQL 实际回滚或断线恢复证据。下一步在恢复副本执行专用 writer 的真实事务演练，并补齐完整来源持久化、归属/权限回填、历史时区证据，再开放源库业务回填及最终切表。全域自动升级与旧结构清理未完成。
