# 返佣规则规范化合同

当前范围是 `referral_rules` 五字段的同库保留与约束补齐，不生成佣金、不回放支付、不调整用户余额。读取证据为 [当前库报告](dev-vue-referral-rule-source-review-20260907.json)；两次独立只读事务结果一致。

## 已核实来源与转换

当前四行完整覆盖 Plus/Pro 的 monthly/yearly，全部 enabled=1、rate_bps=1000。来源散列 `6fce5f71912f8beeb223a44bb5479c814bd25177eeb0431a0acd6e278eed6a4f`。现有主键与 plan/period 唯一键均保留，无时间字段，无历史时区依赖。

| 源字段 | 主处置 | 验收 |
| --- | --- | --- |
| id | 原表原值保留，不重新编号 | 逐行 ID 与完整五字段散列一致 |
| plan | 保留原字符串，允许 plus/pro | 大小写、空格或未知值阻断，不自动修剪 |
| period | 保留 monthly/yearly | 不把订单 month/year 别名写回规则表 |
| rate_bps | 保留整数基点，0–10000 | 0 与 NULL 不等价；不经过浮点比例转换 |
| enabled | 保留 0/1 | 不把停用推导成零返佣；其它数值阻断 |

拟追加变更：原表增加正整数 revision（已有行初始化 1，表示新并发协议基线而非历史修改次数），增加 rate_bps、enabled 的 CHECK。保留现有唯一键及文本排序规则，避免无收益的重建和排序规则漂移。是否添加 plan/period CHECK 随产品合同确定；应用校验已有明确范围。迁移 SQL 尚未创建或执行，须先在恢复副本验证新约束及已有行保留，然后纳入版本化升级器。

## 运行行为与兼容边界

参考旧 `server/utils.js`：month/year 查询别名转换到 monthly/yearly；仅查询 enabled=1 的记录。没有命中（包括停用）时回退 1000 基点。规则存在且 rate_bps=0 时仍为零。这是源代码证据，不代表已执行真实返佣。

新读取应分别返回 found、disabled、missing，保留规则 ID 和 revision；佣金用例显式承担最终策略，不能在 repository 中隐藏回退或把 missing 当零。尚未切换该业务，不能在结构迁移中顺便修正旧的停用语义。当前四行均启用，数据保留不需要等待此产品决策；覆盖 missing/disabled 的消费者切换仍需明确兼容策略。

新写事务按固定规则 ID 顺序锁定；比较调用方 revision；同事务更新规则、递增 revision 并写审计。旧管理接口逐条 upsert 不能继续作为切换后的另一写入口。上线前验证并发冲突、整批回滚、无重复审计和精确金额计算。规则变化不得重新计算已有佣金；新佣金事实冻结采用的规则 ID/revision/rate_bps。

## 两轮复核

第一轮（覆盖与职责）：五字段均保留，当前配置无需复制成历史版本表；revision 用于并发，不虚构历史。保持原表和唯一键，不为命名或减少表数搬数据。

第二轮（兼容与异常）：新增约束前阻断非法率/标记及未知范围；原主键、默认值、唯一键和四行数据逐项对账。禁用规则的旧回退行为已单独登记，不偷偷修改财务结果。DDL 自动提交及恢复需要既有升级器处理，应用代码回退不能删除已产生的审计或递减 revision。

当前已交付：源检查器、四项行为测试、真实只读全列与索引报告。剩余：恢复副本约束演练、追加迁移与当前库升级、运行仓储和业务接入验收。本合同不证明该域已完成，也不授权删除规则表。
