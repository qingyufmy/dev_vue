已在恢复副本与当前 dev_vue 建立 data_migration_source_rows，作为逐源回执的关联证据。SQL inplace/005 已执行，后续不得修改。当前源库 180 张表、23 条完成升级记录、旧 schema_migrations 214 条保留；来源证据表为空，尚未执行真实业务来源回填。

## 两轮复核

第一轮（保留范围）：公共实体合并会压缩逐来源创建时间及原始身份拼写，单纯保存哈希不足以支持删除旧字段后的精确回查。来源表只保存已明确转换的账户/归属两种记录，包含完整源字段、sourceTable、格式版本和时间依据哈希；不扩展成任意业务 JSON 存储，不替代规范化业务表。来源数据与逐源回执通过 run_id、stream_id、source_pk_sha256 的组合外键关联。

第二轮（事务与校验）：引入显式 inplace-account-v2 模式。规范、writer 与 MySQL 适配器必须一致；v2 必须验证第23步来源表结构。adapter 在同一事务中先校验源字段覆盖、ID、源内容哈希与时间依据哈希，再写回执和完整来源，精确回读后才允许外层提交。失败回滚业务行、映射、回执和来源；不存在孤立的来源记录。旧 v1 仍用于历史证据，不代表具备完整来源承接。

## 实现与证据

账户和归属批次创建器通过 preserveSource:true 显式选择 v2，其 transformHash 同时变化；没有静默提升旧批次。MySQL 适配器使用 sourceEvidence:true，目标身份检查覆盖全部23步。源证据限定账户15字段、归属10字段，保留精确字符串、NULL、前导零和原始墙钟；不从 MT5 默认时区推导旧时间。

恢复副本实际 CREATE 后主动中断连接，重连识别已建成结构并补记完成；总计1次DDL，重复运行不建表。源 dev_vue 实际新增1表，独立重复执行DDL为0；原165表271007行原有列哈希均与备份一致。证据：[副本建表演练](dev-vue-source-evidence-rehearsal-20260906.json)、[源库执行](dev-vue-source-evidence-apply-20260906.json)、[独立重复执行](dev-vue-source-evidence-repeat-20260906.json)。执行文件和步骤哈希已绑定。

34项定向测试通过：来源存储4项、同库范围4项、账户writer6项、归属writer5项、事务runner15项。新增测试覆盖字段缺失、原文修改、ID不匹配、回读差异，以及来源INSERT失败时同连接回滚已写回执。当前v2目标身份已在源库只读检查通过。
