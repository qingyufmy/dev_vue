# dev_vue 同库直接升级：第一批实施结果

2026-09-06。用户已明确开发期不涉及公网，只要求当前dev_vue保留现有数据并能直接升级。由此调整实施路径：同一数据库内增量兼容、必要的过渡结构和转换，不要求用户改连一个空库。历史A/B仅供验证，不替代本库升级交付。

## 已完成

实现只读检查器 `scripts/review-dev-vue-inplace.mjs`，仅从server/.env读取配置，强制数据库名称为dev_vue。连接后再次核对DATABASE()；不打印主机、用户、密码或业务行。使用只读事务读取元数据，两次连续结构结果一致才生成本地清单；不能据此认为MySQL元数据被事务冻结，也不代表备份。

- [实际源元数据](dev-vue-inplace-source-20260906.json)：表/列定义、索引、关键引用、版本、sql_mode、会话时区、旧迁移ID。
- [同库覆盖报告](dev-vue-inplace-review-20260906.json)：165张源表、2,598列，对照113张SQL计划声明表，12张同名、101张仅目标存在、153张仅源存在。
- 113不含runner管理的两张迁移控制表，因此不与历史A/B共115表的结果矛盾。计划声明不是本次实际目标安装检查。
- 所有同名表均标记需要语义/类型/约束复核，即便列名完全相同也不自动通过；源多余列全部保留在待处置清单，不生成DROP或自动删除建议。
- `--verify`离线重算与产物比较，不连接数据库；源和目标计划均有指纹，修改源文件、目标SQL或结果会导致产物校验失败。

元数据权限可见性、触发器/例程/事件/视图完整性、业务内容和备份恢复仍需后续核查；本批不是全对象审计完成证明。

## 同库实施前两轮复核

第一轮：用户要求改变了原旁路目标方案。修正为现库直接升级；相同库名不意味着必须原位修改每一张表，必要时可以在dev_vue内建有明确生命周期的过渡表，转换后在停写门完成切换。字段相同不作为兼容证明，12张业务表与journal分别处理。当前仅产出只读差异，不拿空库SQL绕过保护强行执行。

第二轮：过渡结构必须有容量预算、源行追踪、幂等转换、异常隔离和独立对账。涉及改名/索引切换的DDL须逐条可恢复；外键、视图、触发器和应用引用必须先完整枚举。切换前源行保留，切换后新写入仍需要恢复路径；不允许仅恢复旧表丢弃新写入。真实数据时间和身份歧义仍不默认转换。
