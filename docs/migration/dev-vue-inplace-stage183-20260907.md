# 阶段 183：统一 UTC 存储与前端时区

用户决定：所有时刻存 UTC；AI 交易实验室显示终端时间，其它应用显示北京时间。详见[权威时间规则](../time-storage-and-display-policy.md)。

## 实现

- V4 连接池保留驱动 UTC 序列化，同时在新连接首次查询前设置 SQL UTC 会话，失败关闭连接。
- 实验室分析、策略版本、复盘、审计和挂单显示统一格式化；账户快照 ID 不匹配时不沿用旧账户偏移。缺省显示 UTC+3，页头标识默认/校准状态。
- 复盘保留合同中的冻结偏移，UTC 边界先转换为终端日期，避免前一天/前一月错误。
- 挂单创建及编辑输入终端时间、输出 UTC 毫秒；冻结表单账户和偏移，不把默认时区写入指令，未修改到期值不重写，保留原毫秒精度。
- 应用级账户运行状态移至 trade/lib，旧 home 路径仅作兼容导出，不跨应用共享业务状态。
- 共享无状态格式化入口提供固定北京时间，禁止浏览器本地时区解析无偏移 API 字符串。目前其它三个应用尚无日期显示消费者。

## 定向复核

第一轮：检查全部现有前端日期格式化入口，补入挂单输入；明确业务日期和时长不按时间戳处理。没有新增通用控件或服务。

第二轮：检查账户切换、冻结历史偏移、UTC+0、负偏移、跨日、无效日期和默认显示边界；补入 SQL 会话初始化及失败关闭。未对旧表执行统一减 8 小时，未修改已执行 SQL。

## 验证

- trade 原有及时间策略测试 24 文件、108 项通过；随后新增到期表单 5 项组件行为测试通过，合计 113 项。
- 连接池初始化成功/失败测试 1 项通过；服务端类型检查、构建通过。
- 四应用前端类型检查、构建及边界检查通过；到期表单补充后 trade 再构建通过。
- 本地运行新编译连接池，使用现有 env 连接 dev_vue：两个并行新连接 session_timezone=+00:00、NOW 与 UTC_TIMESTAMP 秒差为 0；释放后复用仍为 UTC。仅 SET SESSION 和 SELECT，不修改持久数据。
- 初次探针将 BIGINT 文本 `0` 与数字 0 严格比较导致探针断言失败，修正为文本比较后验证通过；非数据库时间异常。

旧课程/进度及其它遗留表回填仍按原值、来源证据和 manifest 执行。统一目标口径不等于旧数据已转换。本轮不启动网站、Redis、Bridge、终端，不涉及公网及真实交易；未执行浏览器视觉验收。
