# 同库升级第十批：账户全字段转换

完成账户实体与个人设置纯转换器，以及当前 dev_vue 的全字段只读校验。真实 4 条旧账户记录对应 3 个公共实体、4 条个人设置，每条源记录 15 个字段完整覆盖；再次读取后的摘要一致。证据见 [源字段审查](dev-vue-account-conversion-review-20260906.json)。尚未进行业务回填、持久化 ID 分配或表名切换。

## 字段去向

| 旧字段 | 目标用途与保留方式 |
| --- | --- |
| id | 稳定实体 ID 映射；每条设置转换记录保留 sourceId |
| user_id | 个人设置联合主键，验证原用户存在；不作为公共实体身份 |
| broker_server、login_account | 公共实体身份；复核已计划的大小写规范化与精确登录号，保留原始拼写到逐行来源 |
| margin_mode | 公共实体字段；同实体各来源必须完全一致，冲突时拒绝转换 |
| nickname | 个人设置，区分 NULL 和空字符串 |
| review_status、observe_status、anomaly_code | 个人设置原值，不据此生成新归属授权 |
| is_deleted | 个人设置 hidden 与 legacy_is_deleted；不推导公共实体删除 |
| created_at | 实体创建时间取同实体最早来源时间；每个原始时间另保留在逐行来源 |
| updated_at | 个人设置更新时间保留逐源值；公共实体更新时间取最晚来源值 |
| observed_until、identity_verified_at、first_verified_at | 对应个人设置 UTC 时间字段；保留 NULL 与原始墙钟 |

来源中没有平台和币种，需要继续使用前批终端/绑定候选证据。实体 deleted_at_utc 初始 NULL；个人设置 connection_paused 初始 0，属于新字段默认值，不代表交易权限已开放。revision、ownership_revision 初始 1；真实授权、风控与运行状态必须单独对账。

## 两轮复核与实现

第一轮（语义与覆盖）：旧删除入口只删除用户自己的账户记录，并停用相关订阅，因此不能把 is_deleted 变成公共实体删除。旧昵称、审核、观察、异常标记按用户保留。原始逐行来源由转换产物携带，不能只保留合并后的最早/最晚日期；这些来源仍需进入正式迁移回执。转换器拒绝未知字段和缺失来源，避免静默遗漏新增列。

第二轮（数据与异常）：校验完整源集合、计划摘要、源到目标映射、用户存在、精确字符串长度、删除标记、时间合法性、个人设置键冲突及公共保证金模式冲突。复查时将逐记录搜索改为 Map 索引，避免大集合二次方扫描。未确认时区时只允许 inspect；convert 要求明确 trading_accounts 时区证据，不能借用 MT5 终端时区或归属历史表的证据。转换不执行 SQL，也不激活业务。

## 验证与剩余工作

5 项新增测试涵盖跨用户合并、删除语义、NULL/空字符串、日期跨日、输入顺序稳定、缺少时区、保证金冲突、部分来源、额外字段、超长文本、非法删除值、缺失用户及被篡改的映射；加上原 ID 映射 5 项共 10 项通过。真实只读审查与 --verify 均通过。

入口为 `node scripts/review-dev-vue-account-conversion.mjs --read-only|--verify`；已记录的报告使用 --verify，不覆盖证据。业务日期尚未转换，当前报告不能证明历史平台/币种覆盖或业务可用性。下一步接入事务回执与映射持久化、账户归属和权限对账，取得历史时区依据后执行恢复副本回填与源库回填，再做正式表名切换。全域升级、自动部署升级入口及旧结构删除继续进行。
