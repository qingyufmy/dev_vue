# 同库升级第二十二批：历史金额查询、合同与页面

历史金额汇总链路已接通第二十批规则。repository 在完整授权筛选集合上检查明确币种覆盖率和唯一性，输出 comparable / unknown / mixed / empty；仅 comparable 返回金额合计和盈利因子。其它状态的金额为 NULL，保留笔数。日统计通过同一条 SQL 的完整范围 CTE 检查单位，不能把每天各自单币种的跨日混币记录连成一条收益曲线。累计值用定点小数相加，日查询单位与摘要不一致时也抑制曲线。

记录和成交详情携带 account_currency / currency_evidence；summary 携带 account_currency / money_status。领域、HTTP DTO、OpenAPI 和共享 Zod 合同已同步，空态金额也为 NULL。OpenAPI 与共享合同禁止不可比较状态返回金额或币种，不能用数值零表示未知。明细原值继续保留。

交易页摘要、曲线、桌面/移动列表和详情停止使用当前账户币种贴历史标签。摘要显示缺少证据或混合币种的原因，明细显示逐记录币种或“币种未知”，曲线仅在全范围可比较时创建。修复初始空态之后加载数据无法创建图表的问题；不可比较时移除图表，屏幕阅读器表格的缺失值显示 --。沿用现有 shadcn-vue Card、Table、Sheet 及设计令牌，未调整导航和页面布局。

- 服务端类型检查/构建、前端各应用类型检查、交易端构建、前端边界检查通过。
- 使用构建后的实际 repository，在当前开发MySQL 8.4.8执行5组合成CTE：同币种、跨日混币、部分未知、全部未知、空集合。两条真实聚合SQL均经过SQL引擎；同币种净额-0.10000000、盈利因子0.50000000，其它金额和累计值NULL。记录见 [SQL回执](trade-history-money-sql-20260906.json)，复验命令为构建服务端后运行 `node scripts/verify-trade-history-money-sql.mjs`。

SQL验证使用只读事务，CTE覆盖查询中的表名；不创建临时表、不修改结构或业务行。它证明聚合表达式和结果转换，不是实际历史表索引、全量性能、真实终端或迁移数据的端到端验收。页面证据来自组件挂载与构建，尚未做浏览器尺寸视觉验收。
