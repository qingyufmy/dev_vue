# 配置管理请求收据合同 v1

## 职责与结构

追加021_system_setting_requests.sql，不修改已执行018–020。六列：actor_user_id、request_id、request_sha256、setting_id、revision、recorded_at_utc。主键为(actor_user_id,request_id)，唯一(setting_id,revision)，外键引用既有配置变更审计。请求正文不入库，凭据不经过此用例。

请求SHA256输入为UTF-8 JSON有序数组：版本setting-update/v1、actorUserId、requestId、namespace、key、expectedType、expectedRevision、value。不转换文本、不填默认值。返回结果只含setting_id、revision及replayed。

## 事务与恢复

锁顺序为管理员用户行、请求收据、配置行。先检查真实用户仍为admin、active且未删除；包括重放请求也重新授权。同一个管理员的写入在用户行锁上串行化。不同管理员仍由配置版本和行锁防止覆盖。

已有收据：核对请求摘要、关联审计的actor/request及版本，再返回原始结果；不依赖配置当前版本，也不重复更新。缺少收据：运行逐键语义检查，调用配置更新及审计原语，再插入请求收据，同一事务提交。

提交前失败完整回滚；回滚失败销毁连接。commit已尝试但报错时销毁连接并返回setting_commit_unknown，不自动重试。客户端保留原始请求重新查询/提交时，同样先锁用户再查持久化收据；存在即恢复，不存在才在原expectedRevision约束下执行。

运行时语义回调只消费已有领域证据，不在事务内进行外部网络调用。管理HTTP尚未接入，不能绕过CSRF、会话认证等接口层规则直接对外开放。

## 第一轮复审：需求与职责

审计前后摘要无法还原任意历史请求，因此增加六列独立收据，不把配置正文复制进另一份历史表。收据直接关联审计版本，避免通用万能操作表及重复状态机。请求主键包含actor，恢复不能凭requestId越权读取其他管理员结果。

## 第二轮复审：兼容、并发与恢复

追加DDL不改历史；新表必须先在参考库验证并加入显式升级器，安装前不可启用管理入口。现有审计可能没有请求收据，不能虚构旧收据或把旧审计自动视作精确重放。

权限检查在收据读取之前，提交未知不回滚/重放，锁用户行序列化同actor的并发请求。数据库外键保证审计版本存在；代码另核对审计actor/request，防止不一致收据。SHA摘要不是可逆变更历史，也不能替代恢复备份。
