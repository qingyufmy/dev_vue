# 阶段 78：运行余额与账本写入原语

新增 commerce infrastructure 的 `postReferralCreditInTransaction`。外层用例必须先验证权限并锁定订单/佣金来源，再在同一事务调用该原语；失败必须整事务回滚。它不自行提交、不提供 HTTP 入口、不接受 opening 类型，也不替代来源业务授权。

锁定推荐账户后，核对最后账本 revision/余额与账户相同，再查业务事件键。已存在且金额与源证据 hash 完全相同的事件返回原事件结果，即使账户已有更高 revision，也不重复入账；相同事件键变更内容拒绝。新事件必须匹配期望 revision，使用精确金额规则计算，插入账本并条件 UPDATE 余额/版本，二者由调用方事务一起提交。

19 项定向测试、服务端类型检查与构建通过。覆盖精确扣款、历史事件重试、改金额重用键、账本漂移、版本冲突、透支和 UPDATE 失败抛错。测试没有证明真实事务原子性或并发，下一步必须实际 MySQL 回滚/并发验收，不能将 mock 写入列表当作数据库证明。

当前库没有执行任何新扣款、返还或佣金入账，仍只有已验证的期初账本。应用层订单/佣金状态、返还义务、outbox 与认证授权尚未接入。全库迁移、部署自动升级及旧字段删除门仍未完成。
