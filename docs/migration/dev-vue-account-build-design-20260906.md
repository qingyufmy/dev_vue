# 同库账户结构承接

当前旧 trading_accounts 是逐用户设置记录，目标表是公共账户实体；4 个旧 ID 对应 3 个实体候选。仅修改主键类型不能完成业务拆分。

实施采用同一个 dev_vue 内的四张 `_v4_build` 暂存表：账户实体、归属区间、当前/最近授权投影、用户账户设置。完整定义来自只读核实的 V4 参考结构；子表外键指向暂存账户/区间，users 仍引用现有原用户 ID。已有父键的类型与用户数据不改动。

本批只建结构。回填、逐源 ID/字段/归属对账及业务验收完成后，才在停写范围内将旧账户表保留为有明确来源的 legacy 名称，并将四张完成的暂存表切换到正式表名。旧表最终删除仍以全部原字段去向、来源回执和引用清理为前提。最终数据库不保留这些 `_v4_build` 名称作为另一套业务权威表。

迁移期间不修改 V4 repository 去长期双读/双写临时名字，不启用运行开关。正式表名切换之前旧查询仍指向原结构；只有完整升级完成后才能恢复新版本业务写入。部署最终入口须整合这些阶段并检查工作表的中断状态，不能把本批当成独立完成的上线。

第一轮复核（业务与职责）：保留旧表及原主键，先建立规范化目标，避免把逐用户记录硬改成公共实体；四张暂存表仅用于迁移，不新增长期业务域。账户 ID 映射、个人设置和归属区间分别对账，不能以聚合行数下降代替无损证明。

第二轮复核（恢复与约束）：沿用同一升级日志与命名锁，前18步必须已完成；四个 CREATE 分别记账、完整结构比对、断线后识别实际表。保留生成列、唯一开放 owner、组合区间 FK、时间 CHECK、用户外键。先检查约束名冲突，不关闭 foreign_key_checks。建表无源数据写入，恢复演练先在现有副本执行；真实业务日期仍等待历史时区依据。

剩余条件：历史时间、完整实体属性/设置转换、目标数据回读、ID map 与 row receipt 写入、最终原子表名切换及切换后恢复尚未完成。方案不授权遗漏这些步骤或保留两套活动账户权威。
