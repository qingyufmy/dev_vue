# 同库升级第二十一批：历史币种采集与投影

按第二十批纠正规则接通服务端采集与入库。MT4 历史交易和 MT5 成交只在逐条原始记录同时声明 account_currency 与 currency_evidence=explicit_record 时采用该单位；缺少证据保留 NULL/unknown，拒绝非法显式币种及未知证据类型。单独的 currency/account_currency 字段不能证明历史单位，原始 evidence_json 继续完整保留。

MT5 组成成交全部具有相同明确单位时，交易投影继承该单位；部分未知则保持未知；明确单位冲突则标记 evidence_status=conflicted。MT4 单条记录继承自身证据。raw deal INSERT 和 trade projection UPSERT 同步绑定两个新字段，仍在既有事务中执行，历史归属判定没有改用当前采集用户。

验证：35 项定向测试通过，服务端类型检查通过。覆盖同币种、部分未知、无证据、混合币种、非法标记、MT4 原始来源保留，以及离线 MySQL adapter 的金额单位绑定、占位符数量和历史归属字段位置。测试发现新增字段使旧测试的末尾参数位置失效，已改为检查实际归属参数与新增单位参数。adapter 测试使用离线 fixture，不是真实 SQL 引擎验证。

定向复核：没有从当前账户或终端时区推导历史币种，没有修改旧金额和已执行迁移。026 仍未执行，当前 dev_vue 没有两张对应 V4 历史表；新采集代码要求目标结构先具备026字段，不能在旧目标结构上启动。现有 Bridge 记录没有明确币种声明时仍为 unknown，本批不宣称真实终端已提供证据。

尚未完成：查询汇总依然需要按完整筛选结果验证单位并抑制未知/混合金额，API/OpenAPI/前端也尚未接通。投影保留的原数值不能当作混合单位的有效金额统计；本批不是历史金额问题的完整验收。整体同库升级、真实历史回填和旧结构清理继续进行。本批无数据库写入或部署。
