# 钱包地址元数据规范化合同

## 当前真实来源

[两次只读核对报告](dev-vue-wallet-address-source-review-20260907.json)确认 dev_vue 的 wallet_keys 有五字段、四条记录，全部 TRON，派生索引连续覆盖 0–3。现有主键 id，以及 chain/index、chain/address 两个唯一键。

数据库没有私钥、助记词或加密密钥字段。旧源码由环境中的 HD_WALLET_MNEMONIC 获取派生种子，数据库保存的只是索引和地址。本次只阅读源码，不访问助记词内容、不加载钱包模块、不派生密钥或地址、不请求链上、不归集资金。报告保留完整来源行散列及非地址摘要；实际地址原值留在原表及已有完整备份中。

## 五字段主处置

| 源字段 | 目标职责 | 转换与阻断 |
| --- | --- | --- |
| id | payment_wallet_addresses 的稳定内部 ID/legacy 映射 | 原 ID 可追溯，不依赖排序重编号 |
| chain | 链标识 | 当前 TRON 可原样承接，未知链不猜测；不能把 TRON 与 TRC20 资产/协议名称混为一列 |
| address_index | 派生索引 | 精确保留整数，不由行数重新生成、不跨链复用身份 |
| address | 公开收款地址 | 原字符串完整保留；按链定义身份比较，不能全局转小写。当前检查只验证可表示性，不证明 checksum 或控制权 |
| created_at | 历史创建时间事实 | 原墙钟完整保留，明确时区依据后转 UTC；不能用导入时间、终端默认偏移或 NULL 替换未知来源时间 |

目标命名沿用总矩阵的 payment_wallet_addresses，后续 SQL 实施前固定密钥来源引用、可用状态及旧时间证据的具体字段。密钥引用仅是托管位置/版本的标识，不得保存明文助记词或私钥；也不能把配置项名称本身当作地址归属已经验证。

## 依赖与运行行为

旧 sweep.js 使用 COUNT(wallet_keys WHERE chain='TRON') 并遍历索引 0..count-1，当前四行没有缺口，但这个算法不能承担新结构的地址清单读取。新扫描应按明确登记的地址及派生索引分页读取，不能派生不存在的记录或跳过稀疏索引。归集、签名和发送交易另属副作用流程，本次数据库规范化不触发。

钱包与订单/监控的引用需逐条按链、实际 recipient、索引和历史证据核对。共享收款地址可能由旧主地址派生逻辑提供，不能按记录顺序把一个钱包行分配给一个订单。未知引用保留原事实并阻断自动关联。

新实体可先建立结构和来源承接工具；历史时间与密钥控制关系未核实前，不得标为 operational/verified，也不得启用新签名或归集路径。不能把所有活动钱包仅放入归档后称为钱包域迁移完成。

## 两轮复核

第一轮（覆盖与职责）：五字段全部有主处置，地址记录与密钥托管独立；数据库不成为私钥管理器。当前资产仅 TRON，不提前按未出现的链扩建多个钱包框架。

第二轮（兼容与异常）：保留地址大小写及索引；跨链相同文本不能误合并；来源时间、控制权、关联、导入重复和原资金可访问性需分别验收。表名含 keys 不证明有私钥，地址语法也不证明控制权。旧表删除必须等待地址引用、只读/写入消费者、备份恢复和独立对账完成。

已交付来源检查器与真实结构/索引/五字段散列报告，四项测试通过。检查器拒绝额外字段及重复身份，对大跨度索引仅做有界排序扫描，不按最大索引分配数组。四行均登记 created_time_basis_required 和 custody_binding_unverified，尚未执行钱包 DDL/DML。当前库继续为 203 表/53 步。
