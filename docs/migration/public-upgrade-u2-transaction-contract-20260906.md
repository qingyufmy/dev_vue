# U2 批次迁移与恢复合同

2026-09-06，U1之后的源码/离线工作包，事务框架首批实现完成。当前没有获准的可执行业务波次，本批不运行真实DDL/DML，不把U1的`executable=false`改为可执行。

## 实施前两轮复审

第一轮：复用独立Node迁移工具，不接入应用/队列。追加025保存run、stream checkpoint、batch、ID map和逐源行receipt；数据转换在目标事务外准备，只允许经审核的领域writer在同一目标事务里写业务数据。框架不接收任意SQL清单，不自带用户/交易回填器，不调用正常业务API。

第二轮：run绑定源逻辑身份、原库/冻结镜像、快照、目标实例/库、schema/manifest/transform指纹与作用域。目标库不得为源/镜像；目标连接身份在事务内核对。批次按run锁串行化，旧checkpoint、批次内容变化、ID映射冲突、重复源行处置均拒绝。映射业务身份不随run/snapshot生成新ID。数据、映射、receipt、batch和checkpoint共同提交；提交响应丢失标记结果未知，通过新事务锁同一run并读取批次回执判定，禁止直接重放。真实MySQL锁/断网行为需另行演练。

## 精确接口与界限

- run由调用者提供稳定UUID；bindings字段固定并生成canonical hash，未知字段拒绝。作用域是源表和处置角色组成的stream。源主键采用有序带类型字符串元组，整数/金额不通过JS Number转换；稳定游标由后续源读取器按冻结主键和实际排序规则提供，框架只验证精确前后衔接，不假装证明数据库分页顺序。
- 批次最多500源行、canonical UTF-8载荷不超过2 MiB；超大单行明确拒绝，后续独立有界路径实现前不能截断。空批次不推进checkpoint；整域完成须由后续覆盖对账证明，批次成功不标记全库完成。
- 每行有source PK、source bytes hash、transform结果hash、目标引用、经审核writer需要的payload及ID映射。payload只在内存传给writer；迁移元数据只存hash/主键与目标定位，不保存密码/正文。主键/定位可能仍为敏感数据，元数据不对外暴露。
- ID map以逻辑源+实体类型+源表+规范PK为键；相同目标重复确认，不同目标拒绝。不因新增snapshot/run另起映射。多源到同目标须由领域合同明确批准；框架不从账号相近或名字相似自动合并。
- run创建和批次执行均需要调用者提供已批准波次的声明及零阻断；该声明只是内部前置条件，不是安全授权凭证。后续真实CLI必须从受控预检和人工授权证据构造，不接受浏览器请求/U1清单直接放行。当前没有apply CLI或生产领域writer。
- SQL仅在repository内；业务writer显式收到同一事务连接，调用者不得自行提交/回滚或发网络请求。writer职责由后续领域模块审查及真实事务测试保证；框架不能拦截任意JavaScript插件的外部副作用。
- 当前`schemaHash`绑定目标已完成迁移记录及纠正事件指纹，能够发现登记版本变化；它不是实际字段/约束指纹，不能发现绕过迁移记录的手工DDL。受控预检必须另行核对实际结构并冻结无DDL窗口。当前没有实现该真实预检入口，不能以journal hash相同宣称结构验收完成。
- 只对确认回滚的死锁做有上限整批重试；commit异常先报告unknown。恢复返回committed/not_committed，确认not_committed后才允许显式重试；无法确认时保持unknown。非幂等DDL不用此恢复规则。

## 验证门

用事务替身验证目标身份/绑定漂移、原子回滚、映射与receipt冲突、复合主键/大整数、批次限额、旧cursor拒绝、同批重复确认、commit前后丢响应及恢复。SQL适配器验证参数化与锁序；025仅离线计划解析，不安装。真实源读取器、业务转换、受控apply入口、实际数据库约束/锁、全域对账及切换仍在后续阶段。

## 首批实现结果

- `scripts/lib/v4-backfill-contract.mjs`：严格run/批次合同、规范化hash、带类型复合PK、500行/2MiB上限；主键中的大整数和业务十进制保持字符串，拒绝非整数JS Number。金额是否误用安全整数仍由领域转换合同核验，不把通用JSON校验当作金融语义校验。
- `scripts/lib/v4-backfill-runner.mjs`：prepare/execute/recover三个内部入口；复制输入防止异步期间被外部修改。批次先锁run，重复同内容回传已提交结果，不同内容拒绝；映射限定本源行和已声明目标。writer收到副本，确认hash不符则全部回滚。
- `scripts/lib/v4-backfill-mysql-repository.mjs`：显式目标连接、UTC会话、有界锁等待、参数化SQL、当前锁定读取与checkpoint CAS。确认回滚的死锁最多三次总尝试；提交或rollback结果未知时销毁连接，不还池复用。恢复查询同run的锁与回执，不受旧一致性快照误判影响；不可查询时返回unknown。
- 新增025：`data_migration_runs/checkpoints/batches/id_maps/row_receipts`五张表。没有业务种子、队列、级联删除或状态激活；没有自动标记run全量完成。ID map唯一键不含run/snapshot，旧身份映射不能随新快照被覆写。批次`recorded_at_utc`是事务内记录时刻，不冒充精确数据库commit时刻。
- U1机器清单仅刷新SQL计划指纹和新出现的候选元数据表；11表148列合同、52项更新和81项声明定位不变，仍不可执行。20260905冻结输入和既有001–024/纠正SQL未改。

`pnpm exec vitest run tests/v4-`：29文件223项通过，其中本批23项为批次框架与SQL适配器定向回归；其余覆盖既有schema runner、备份、字段清单和合同。新增025后同步更新历史测试对“全计划数量”的预期，保留前25文件159语句断言；当前离线计划为26文件164语句，另有既有1个correction。U1产物一致性、三个新模块语法检查和diff检查通过。

证据边界：事务原子性/并发/丢响应使用可回滚状态替身和SQL调用替身，不是真实MySQL约束或网络故障证明。逐行receipt表示声明的源hash、writer确认的转换hash及目标定位已与该批一起提交，不证明目标业务值已经独立回读对账。未接真实业务writer，没有对任何源行进行迁移。

## 接续工作

下一步继续U2配套的只读波次预检与稳定源读取器：核对既有冻结镜像/A/B实例与schema，验证主键分页及源行hash来源，设计批准波次的可验证输入；对未关闭时间/关系/历史去向保持阻断。然后按领域实现纯转换、同事务writer与独立目标回读对账。只有这些证据齐备且精确DDL/DML获准，才进入U3首批真实回填；不是现在安装025并灌入旧表。

接续进展：只读预检和源读取器的源码/替身测试已完成，见[读取合同与当前缺口](public-upgrade-u2-reader-contract-20260906.md)。实际结构核对模块已存在，真实预检入口和源内容证明仍未完成；以上首批验收数字保留为历史结果。
