# 同库升级第二十七批：合并账户后的订阅候选

原策略来源入口新增--write-scopes/--verify-scopes。在同一只读事务读取完整4账户、终端、当前绑定及5订阅，复用稳定账户ID映射，随后组合逐品种转换结果。没有使用当前页局部账户分配ID，未写入映射或业务表。

新增reviewSubscriptionAccountScopes核对订阅用户与来源账户/个人设置映射的一致性，并检查两个不同的候选键：用户+目标账户+来源策略+品种的身份键，以及目标账户+品种的潜在执行占用键。身份重复连已删除历史也报告，因为目标唯一键不按删除状态豁免；旧execution_enabled=1且未删除的记录用于发现潜在占用冲突。该开关不是V4运行许可，不能据此启用trader或trade_send。

真实结果：4旧账户→3计划实体，5条品种候选，2个潜在执行占用，无本轮范围内的用户不一致、身份键重复或执行占用冲突。[回执](dev-vue-subscription-account-review-20260907.json)保留来源、账户映射、候选键摘要以及旧执行/删除标记；不输出账户登录信息。策略仍以来源身份参与候选键，最终analysis/trader拆分映射完成后必须重新检查目标唯一性。

5项新增测试和15项品种/来源回归通过。覆盖跨旧账户/跨用户合并冲突、停用订阅保留、已删除身份重复、用户不一致、显式空集合/缺父引用。真实独立verify-scopes一致，前批verify-symbols仍通过。

此批只完成结构候选，不是权限验收：当前及历史所有权、会员/风险/时段/记忆配置、策略角色版本、历史时间仍待转换对账。structuralCandidatesConsistent=true不能覆盖executable=false和runtimePermissionGranted=false。本批没有DDL/DML、任务或交易指令。

下一步将订阅配置、策略版本与归属条件接入转换器，再进入有来源回执的业务演练；完整旧库自动升级与旧表清理目标仍未完成。
