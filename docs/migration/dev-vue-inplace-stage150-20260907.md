# 阶段 150：配置凭据转换与真实恢复验证

已追加独立迁移辅助模块 `v4-settings-credential-conversion.mjs`。不修改已执行 SQL、历史转换器或运行时推理模块；模块不执行数据库 I/O。

## 转换规则

调用者必须明确指定 empty/encrypted/plaintext，不能遇到解密失败就回退明文。空值保留未配置，NULL 仍待语义处理。疑似 JSON 的文本不得自动当明文保护；超长值和无法精确保留的 Unicode 拒绝。

已有封装验证四字段、规范 Base64、12 字节 IV、16 字节认证标签、32 字节密钥及 AES-GCM 认证后原字节保留。旧文本使用活动密钥和随机 IV 加密；再次解密，按字节验证与来源一致。已存在目标必须解密匹配；不匹配拒绝覆盖。重试传入已保存目标，复用同一密文，不能每次重新生成随机密文后假称转换确定。

调用者仍须将来源摘要、格式决策和生成的目标密文绑定并持久化到受控迁移批次后再写库。当前模块不代表这一集成已经完成。返回值含待保存密文，不含解密正文；内部明文 Buffer 在 finally 清零，但不宣称 JavaScript 字符串或运行时内存可被完全擦除。

## 当前 dev_vue 真实验证

新只读脚本绑定当前 58 步结构、数据库 UUID 和五项原八字段摘要，用 server/.env 的既有密钥在内存中转换。数据库正文只在进程内使用，输出和报告不含正文、密文或密钥。

- sms 的 access_key_id/access_key_secret 和 smtp/pass：认证解密成功，旧封装字节不变。
- qiniu 的 access_key/secret_key：按明确的旧文本格式通过歧义检查，加密后认证解密与来源字节一致。
- 五项已生成目标的复用校验通过。--write 与独立 --verify 报告一致；转换代码 SHA-256 记录于报告。

这证明当前 .env 密钥可以处理所选五项数据，不证明异机密钥备份恢复、供应商可用性或真实批次恢复。新生成密文没有持久化，未写数据库。五项 created_at/updated_at 的历史时间依据仍待解决。

## 验证与定向复审

13 项转换/配置行/值合同测试通过。覆盖未配置与 NULL、明确格式、Unicode/空白原文、随机 IV、已存目标重试复用及冲突、旧格式字节保留、损坏标签、缺失密钥、错误 Base64/长度、未知字段、超长和非法 Unicode。只读验证执行两次一致。

第一轮检查格式边界与复用：不以宽松封装形状当认证结果，不覆盖目标、不修改旧 proof 文件；生成与持久化职责明确。

第二轮检查异常与数据保留：严格认证后才成功，失败输出固定错误码，原数据摘要核对不省略。真实密钥和数据仅进程内使用，不进入仓库。剩余工作是转换计划持久化、58 步批次接入、提交响应丢失/恢复演练及历史时间处理；尚无真实回填或消费者切换。
