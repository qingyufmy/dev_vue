# 同库升级第五批：新表依赖与四项根结构冲突

2026-09-06。本批新增可重复运行的依赖检查器，覆盖编号迁移及 bootstrap 中全部 101 张目标专有表；没有执行新的数据库写入。前一批已执行九列增量保持有效，全面规范化仍在进行。

## 已定位的根冲突

| 原有父表字段 | 原结构 | 目标外键类型/字段 | 直接受影响的新表数量 |
| --- | --- | --- | --- |
| trading_accounts.id | INT | BIGINT UNSIGNED | 38 |
| strategy_subscriptions.id | INT | BIGINT UNSIGNED | 4 |
| inference_snapshots.id | BIGINT（有符号） | BIGINT UNSIGNED | 5 |
| ai_model_tasks.task_id | CHAR(36)，没有 id | 引用 ai_model_tasks.id | 3 |

数量按不同子表计算，存在交集，不能相加当成总数。沿所有外键传播后，68 张新表被上述冲突直接或间接阻断。其余 33 张通过本轮外键列存在性、类型和排序规则检查；它们只是下一批候选，还没有证明唯一键、CHECK、初始化行和业务迁移已完成。

实际旧结构还存在指向 `ai_model_tasks.task_id` 的三个外键，来自 `ai_manual_analysis_jobs`、`ai_model_task_attempts`、`ai_model_task_events`。不能直接把 task_id 改名或删除，破坏旧任务证据链。账户、订阅与推理快照未在这份基线发现入站物理外键，不代表不存在业务代码和逻辑引用。

## 检查器与证据

- `scripts/review-inplace-table-dependencies.mjs --write` 生成 [依赖清单](./dev-vue-inplace-table-dependencies-20260906.json)；`--verify` 离线重算并比对。
- 绑定原始源元数据和当前完整迁移计划的摘要；每个子表记录语句来源、SQL 摘要、完整外键、直接原因或被阻断的父表。
- 区分建表时外键和后置 ALTER 外键。先创建互相引用的实体，再追加后置约束的合法流程，不会被错误认定为建表循环。
- 13 项定向回归通过，清单重新计算一致。检查器明确 `executable:false`，不能把筛出的 CREATE/ALTER 直接当升级脚本。

源元数据是首批增量前的冻结基线；已追加的九列不涉及这里的四项父键，且未改动现有键。后续实际执行前仍需读取当时的源结构，不能把这份离线清单当成持续有效的数据库观测。

## 后续实施顺序

1. 优先落地未被根冲突阻断的身份、认证、容量与迁移账本新表；核对父唯一键、追加约束和初始化控制行后，在现有演练副本验证，再推进开发库。
2. 账户先完成公共账户实体、个人设置和历史归属的拆分与 ID 映射。仅把 INT 扩成 BIGINT UNSIGNED 不能解决旧的逐用户账户与新的公共账户实体之间的差异；已有账户映射候选工具继续复用。
3. 订阅按用户级分析与账户级执行的粒度转换，推理快照保留来源和载荷，任务保留旧 task_id 与尝试/事件引用。逐项解决根冲突后重新计算依赖清单，开放后续表。
4. 全部旧事实有可用去向及对账、代码与约束引用解除后，执行已被替代结构的删除。不能通过只建空表、删除外键或把全部活动业务转为 JSON 归档来绕过本轮目标。

剩余检查明确包括迁移纠正脚本、语句中间状态、父唯一键、CHECK、初始控制行、真实升级与恢复、全部业务字段映射。目标空库已有的编号迁移正文保持冻结，同库结构变更继续追加独立步骤。
