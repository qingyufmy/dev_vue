# U2 账户身份候选映射合同

第一轮复审：在既有11表源审计后增加候选映射，复用已验证完整行及sourceHash。平台必须来自同用户、同server/login的终端记录，不能从mt5表名推定或借用另一用户终端；币种只作为绑定的当前证据。保留每个源账户ID及其设置用户，不创建目标ID、owner、设备或会话。

第二轮复审：此次现场证明只有ASCII服务器大小写差异，候选归一仅允许ASCII大小写；空白、非ASCII、前导零或平台冲突不能被偷偷修正。多源账户落入同一候选身份时保留全部成员，标记必须复核合并；同用户多源设置还需解决目标复合主键冲突。候选key绑定逻辑源、平台、服务器候选值及原样login，不绑定snapshot/run，不把随机生成ID当稳定映射。所有候选保持不可执行，时间/归属/原文历史证据及完整源校验仍为后续门。

## 实现与验证

`scripts/lib/v4-account-mapping-candidates.mjs`已实现有界候选生成：分别按同用户终端和当前binding收集平台/币种证据，缺失、矛盾、非法字符和超长币种明确拒绝或标记。不同平台不会合并；当前binding必须能回指本次源账户集合中的账户与用户。候选只提供稳定分组key、各源账户ID、设置用户ID及证据hash，不分配真实目标ID、不复制在线状态或授予owner。输入每类最多10,000行，通过索引映射查找。

`v4-identity-source-audit.mjs`已接入该模块，先验证完整源信封再生成候选。对外诊断只输出定位hash、证据hash、候选key和阻断，用户ID、服务器/login与终端ID原文不进入报告。底层候选对象含内部ID，调用者不能直接公开；源hash由前置读取/清单验证保证，候选函数不认证任意传入hash。

`pnpm exec vitest run tests/v4-`：35文件268项通过，本批新增7项候选行为测试、1项源信封接入测试、3项真实事务演练脚本的离线范围/目标保护测试。候选测试包含不同用户设置保留、平台缺失/冲突、MT4/MT5分离、账号前导零、ASCII大小写/空白边界、币种与binding矛盾、输入顺序稳定和逻辑源隔离。没有对现场274条归属记录运行本模块，没有把候选key提升成实际ID map。

后续必须在完整冻结源上核对候选合并组、历史平台/币种覆盖、各用户设置和归属区间，保留源ID与原文字节证据；unknown DATETIME及历史处置仍阻断业务回填。本批未连接数据库、未执行测试DML或改动018–025等既有SQL。

后续现场结果见[11表完整读取](public-upgrade-u2-identity-read-report-20260906.md)与[时间/归属承接合同](public-upgrade-u2-time-ownership-contract-20260906.md)：4账户形成3候选组，重复组为不同用户；274条归属墙钟区间无倒置或重叠。候选实体与4份用户设置、274条历史及3份当前owner分别承接，仍未执行实际合并、时间转换或授权创建。
