# 同库升级第十三批：账户 writer 的真实事务演练

已在备份恢复副本 dev_vue_m1_source_20260906_01 完成专用账户 writer 的 MySQL 真实事务演练。使用两条明确标记的合成账户来源，引用副本内两个已有用户，仅写入账户工作表及本次迁移账本；不修改原用户或旧账户，不写源 dev_vue。

## 真实结果

- 第二条合成来源写完后故意抛出异常：两条来源产生的业务行、ID map、回执和批次全部回滚。
- 再执行时实际 COMMIT 成功，随后主动关闭连接并向调用方模拟响应丢失。适配器返回 backfill_commit_unknown；新连接锁定读取账本，恢复为 committed。
- 重复执行同一批次时，没有再次调用 writer。
- 已提交结果为 1 条公共实体、2 条个人设置、2 条映射、2 条逐源回执和 1 个批次。另一次事务通过 writer 的锁定精确回读复核已提交业务字段。
- 演练成功后，按固定 runId、logicalSourceId、合成账户 ID、服务器名、登录号和用户键清理本次数据。五张账本表及四张账户工作表恢复为空。
- 演练前后，165 张原表、271007 行原有列内容哈希与备份证据一致；账户回填结构摘要保持一致。

这证明当前 writer 与事务账本能在真实 MySQL 上协作。它不证明历史业务数据已经转换，也不证明网络设备真正丢包；故障方式是数据库已确认提交后，测试包装层关闭连接并向上层隐藏成功响应。

## 修正与证据

首次尝试在写入前的原数据校验处停止：控制连接遗漏显式 SET SESSION time_zone='+00:00'，驱动 timezone 选项不能替代 MySQL 会话时区。补齐后，在新的 recovery-01 工具目录执行完整流程并通过。原工具目录保留，未覆盖。

两次尝试均要求九张相关目标表最初为空；首次没有进入 prepareBackfillRun。成功演练没有执行 DDL。暂存账户的 AUTO_INCREMENT 计数可能因合成显式 ID 插入而提高，清理不通过 ALTER 重置；目标 ID 由稳定映射显式指定，结构摘要本来就排除当前自增计数。源 dev_vue 的自增计数和数据未改变。

证据：[演练回执](dev-vue-account-writer-rehearsal-20260906.json)、[75 个工具文件 SHA-256](dev-vue-account-writer-tools-20260906.json)。收集时逐文件核对本地代码哈希与实际执行工具一致。远端目录为 /www/backup/aurum-v4/m1/20260906-01/account-writer-rehearsal，凭据通过匿名内存文件传入，报告不包含账户值或密码。
