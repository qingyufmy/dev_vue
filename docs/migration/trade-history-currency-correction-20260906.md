# 历史交易币种纠正规则

核查发现 V4 account_trade_records_v4 和 terminal_history_deals_v4 没有金额币种字段，mysql-trade-history-repository.ts 的金额汇总直接 SUM；TradeSummaryCards 和 TradePnlChart 使用当前账户币种标签。账户范围过滤不能证明跨历史期间币种相同，因此缺少历史币种时该汇总没有充分依据。

## 两轮复核

第一轮（业务语义）：金额必须保留记录自己的单位。当前账户currency只用于当前账户上下文，不为历史deal、trade或汇总补币种。原金额保留，即便币种未知也不丢弃历史行。币种不明或不同币种的记录不能汇成一个金额；笔数仍可计数。

第二轮（升级和兼容）：026只追加nullable account_currency和currency_evidence，旧行默认NULL/unknown，不改金额、归属、时间或原始证据。CHECK保证unknown与NULL成对、explicit_record非空；该标记只允许来自记录明确声明的币种，不允许采集器把当前会话币种伪装成历史记录币种。现有013迁移不修改。当前dev_vue还未建立这两张V4历史表，026作为后续安装/同库表承接的纠正迁移，不能对当前旧库直接执行全部根迁移。

## 连续实施要求

1. 采集与投影：只从明确的逐记录币种证据生成account_currency；没有此证据则unknown。复合trade只有所有金额来源币种已知且一致才有明确币种；冲突保持可解释状态。
2. API与领域：每条历史记录暴露币种及证据状态；汇总增加金额可比较状态与币种。混币或未知时，金额汇总及profit factor为NULL，不能用0表示；禁止跨币种累计曲线。没有历史行时保持空态。
3. repository：相同筛选范围内同时检查币种完整性与唯一性，再输出金额SUM；明细原金额仍保留。分页之外的汇总必须基于相同完整筛选集合，不能仅检查当前页。
4. 消费者：更新OpenAPI、共享contracts、HTTP DTO、前端适配与展示。金额不可比较时显示原因和未知单位，不贴当前账户币种标签，也不把NULL格式化为0。
5. 验证：同币已知、混币、部分未知、全部未知、空集合、跨页混币、数据库存量默认值、记录币种缺失的采集输入都要覆盖。完成实际表承接后再做MySQL验证。

本文件和026只是结构纠正的起点。采集、查询、API和前端尚未同步，当前问题未修复完成；旧查询仍存在无币种求和行为。完成上述联动前不得宣称历史金额语义已经规范化。
