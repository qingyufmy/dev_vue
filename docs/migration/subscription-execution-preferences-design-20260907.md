# 订阅止盈偏好存储设计

目标是承接旧 strategy_subscriptions.take_profit_mode 的四种值。V4 当前订阅表没有对应字段，交易员输出只有通用 action.parameters，最终执行读取已确定的 take_profit；不能把旧档位偏好直接解释成价格。

新增 subscription_execution_preferences_v4，以 subscription_id 为主键并外键引用 V4 strategy_subscriptions。显式保存 take_profit_mode、contract_version、revision 和 UTC 毫秒创建/更新时间。不设置模式隐式默认，不自动给历史订阅补行，不修改旧表或已执行迁移。新订阅与偏好行在原创建事务内一起写入 ai_recommended、版本1；读取按 subscription + user + account 授权范围，缺行返回 null，禁止拿当前默认填补历史证据。

追加根迁移027，仅针对已经是 V4 结构的数据库；旧 dev_vue 同名表仍为旧版，禁止直接运行根迁移。旧库须先经同库计划完成账户/订阅实体切换，再创建本表并由逐行转换器插入原模式、对账。根迁移不包含历史数据 DML。本轮不启用偏好控制执行；后续必须冻结偏好 revision/内容以及模型三档价格证据，由确定性选择器生成最终价格，并在执行前验证配置仍匹配。

第一轮复审（覆盖与职责）：偏好属于订阅，不属于平台策略版本或账户共享设置，不能让一名订阅者的选择影响其他用户。独立一对一表避免改写冻结基础表迁移；风险档案与记忆模式未证实属于相同生命周期，本表不混入这些字段。修订为没有默认值的显式行，避免缺失记录被解释为有效配置。

第二轮复审（兼容与异常）：外键无级联删除；主键保证单一配置来源；版本和 revision 有正值约束；读取必须匹配用户和账户；初始化失败由调用者原事务回滚。历史缺行不修补，旧迁移文件不变。验证包括完整迁移顺序解析、非法模式/版本/缺行/越权读取行为，以及服务端类型检查。真实建表和物理并发尚待同库切换演练；仅有新存储不构成止盈语义已承接或可删除旧字段的证据。

## 确定性选择合同（第四十二批）

冻结 TraderInputSnapshot.executionPreferences 可显式包含版本1、模式和十进制字符串 revision。出现该字段时，模型的新开仓/挂单 parameters 必须含 take_profit_prices（三个十进制字符串或null）和 recommended_take_profit_tier（1/2/3/null）。AI模式缺推荐使用第一档；固定模式按1/2/3档；选中价格缺失或为零时最终值null，不改选其他价格。最终价格保持字符串原精度，并记录模式、推荐/请求/使用档、偏好revision和原模型价格。服务端完成决策时生成此结果，输入对象不被修改。

覆盖复核：规则只影响开仓和挂单，不覆盖修改保护、平仓或撤单；没有冻结偏好的历史输入沿用原路径，不补默认模式。异常复核：新合同拒绝数值价格、指数/负数/非数字文本及不合法推荐档；旧记录不能直接投喂此严格合同，迁移适配器仍需显式处理旧Number容错差异并保存来源。冻结字段的生产读取、同事务核对和最终执行版本检查尚未接通，在此之前不启用生产偏好输入。配置缺失兼容只用于既有路径，不代表允许已迁移的新任务省略配置。
