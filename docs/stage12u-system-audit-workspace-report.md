# 阶段 12U：系统审计与执行链路工作区验收记录

> 日期：2026-09-04
> 状态：源码实现与离线验证完成；数据库迁移、旧数据回填、真实 MySQL/Redis、浏览器登录态和 Bridge/MT 联调均未执行

## 1. 本阶段结果

本阶段将 AI 交易实验室的 `/audit` 从占位页替换为当前用户可用的系统审计工作区，用于查看操作日志、自动分析状态、交易员判断、确定性风控、执行操作、Bridge 指令和终端交易事实。

审计页面不是新的事实来源。服务端直接从 V4 权威业务表投影事件摘要，并在详情中围绕同一 operation 精确连接：

```text
AI 分析师运行
  → AI 交易员账户评估
  → 确定性风控决策
  → operation
  → execution intent
  → Bridge command
  → terminal outcome / trade fact
```

事件列表按发生时间倒序，支持当前用户的全部账户或单一账户、分类、状态、操作者、UTC 日期和关键词筛选，以及冻结范围的 keyset 分页。详情只返回经过白名单整理的摘要、原因代码、关联 ID 和精确链路，不向浏览器暴露模型原始载荷、终端命令参数、内部堆栈或数据库 JSON 正文。

## 2. 权威数据边界

新 V4 事件不再复制到一张新的“万能审计日志表”。当前列表从以下权威记录做只读 `UNION ALL` 投影：

- `ai_analysis_runs`：自动或手动行情分析运行；
- `ai_trader_runs`：账户级 AI 交易员评估；
- `risk_decisions_v4`：确定性风控结果；
- `operations`：用户或系统发起的业务操作；
- `bridge_commands_v4`：终端指令状态；
- `risk_policy_change_items_v4`：账户风控规则变更项；
- `risk_manual_releases`：用户手动解除风控限制；
- `account_trade_records_v4`：终端已封口交易事实。

历史 `trade_audit_logs` 仍属于必须保留的数据。其现有 9,660 行将在后续获得迁移授权后按 checkpoint 迁入 `trade_audit_events` 作为旧版归档；这只服务于旧数据保全，不会成为新 V4 事件的重复写入目标。完成逐用户计数、时间、主体、动作和关联 ID 对账之前，旧表不能删除。

## 3. HTTP、分页与访问控制

新增只读 HTTP V4：

- `GET /api/v4/audit/events`
- `GET /api/v4/audit/events/{source_kind}/{source_id}`

列表与详情的每个权威表分支都以认证后的 `user_id` 收窄。选择交易账户时，服务会先核实当前用户仍持有有效 owner 权限，再执行列表查询；详情不会只按来源 ID 查询，因此另一个用户即使猜到 ID 也无法读取记录。

列表默认读取最近 7 天，最大查询窗口 90 天，每页默认 50 条、最多 100 条。游标绑定完整筛选哈希、首次查询的 `captured_end`、最后一条时间和稳定来源键；修改账户或筛选条件后复用旧游标会返回明确错误，避免翻页漂移或跨筛选串页。

日期输入明确标为 UTC。终端事件如果保留了已校准时区偏移，页面会同时显示对应终端时间；它不会用浏览器本地时区猜测终端时间。

## 4. WebSocket 边界

实时协议新增用户级 `audit.changed` 和 `audit/all` 订阅目标。WebSocket 只携带来源事件类型和来源 ID，作用是通知页面重新拉取 HTTP 快照；事件列表、详情链路、模型正文和终端参数都不会进入实时帧。

审计订阅固定为当前用户范围：`trading_account_id=null`、`observer_channel_id=null`。账户筛选只改变 HTTP 查询，不建立账户级审计 socket，也不会把 owner 的审计数据投递给观摩用户。

失效事件使用 outbox 自增 ID 作为可用时的单调 revision，浏览器连接继续使用独立 sequence 检测丢帧。发生序列缺口或服务端要求 resync 时，页面会关闭旧连接、先重新读取 HTTP，再按有界退避重连；连续事件以 350ms 合并刷新，避免列表闪烁和请求风暴。

## 5. 前端工作区

页面按普通外汇交易者的阅读顺序组织：

1. 当前审计范围和实时状态；
2. 总事件、处理中、成功、拒绝、失败和不确定摘要；
3. 账户、分类、状态、主体、日期和关键词筛选；
4. 桌面事件表格或移动端事件卡片；
5. 右侧详情 Sheet，依次展示事件摘要、执行链路、关键证据和相关业务入口。

实现统一复用项目 shadcn-vue 的 Alert、Badge、Button、Card、Empty、Field、Input、ScrollArea、Select、Separator、Sheet、Skeleton 和 Table。桌面表格支持点击、Enter 和 Space 打开详情；小屏切换为整行可触控卡片，不依赖横向滚动。加载、空态、错误、恢复中、离线快照和观摩只读状态分别呈现，不使用本地模拟数据填充空白。

## 6. 第一轮复审：职责、安全与实时语义

复审重点：是否重复存储事实、跨用户访问、WebSocket 范围、原始证据泄漏和执行链准确性。

发现并调整：

- 初版曾让审计 WebSocket 随当前交易账户切换，这会把用户级分析事件错误拆分并增加无意义重订阅；最终固定为当前用户级失效，账户只作为 HTTP 过滤条件。
- 初版考虑按不同领域的 revision 在浏览器去重，但不同表 revision 不能互相比较；最终删除跨领域 revision Map，仅以连接 sequence 识别缺口，并用 HTTP 作为恢复真相源。
- SQL 列表投影改为明确列清单，禁止 `SELECT f.*`；浏览器 DTO 只允许摘要字段，不返回 `payload_json`、`params_json`、模型推理正文或内部异常。
- 详情链路只在同一用户拥有的 operation 上连接分析、交易、风控、意图、Bridge 和终端结果；无精确 operation 关联时只展示当前事件，绝不按时间邻近猜测。
- 旧 `trade_audit_logs` 与新 V4 事实分开治理：旧数据后续归档迁移，新事件不再双写通用日志。

第一轮结论：审计模块是权威事实的只读索引与解释层，不参与策略判断、风控、交易执行或 Bridge 控制。

## 7. 第二轮复审：查询成本、分页与响应式体验

复审重点：大范围查询、无效参数、全部账户视图索引、URL 状态和移动端可用性。

发现并调整：

- 查询窗口增加 90 天硬上限，非法或非数字分页大小安全回退到 50，避免无界聚合或 `NaN` 进入 SQL 参数。
- 迁移补充分析、交易员、风控、operation、Bridge、风控变更、手动解除和终端交易的用户时间覆盖索引；默认全部账户视图不再依赖以 account/status 开头的旧索引。
- 搜索框文案调整为服务端真实支持的“动作、原因、品种或关联 ID”，不误导用户可以搜索前端计算出的中文标题。
- 筛选、账户和详情来源写入 URL；刷新或分享链接会恢复同一范围，关闭详情时只移除详情参数。
- 移动端不用压缩桌面表格，而是使用 shadcn-vue Button 组成完整事件卡片；所有主要操作保持至少 44px 触控高度，详情 Sheet 内部独立滚动。

第二轮结论：当前实现具备有界查询、稳定分页、用户隔离和清晰的响应式阅读路径；没有为了审计页面引入新的写链路或后台任务。
