# V4 重构统一交付清单

更新：2026-09-11。用户已要求恢复核心实施，前端交互与细节可用性后置。以本清单确定交付顺序，以原功能矩阵保留全部需求，以专项报告保存证据。

## 1. 保留的目标与约束

- 保留 Fastify/TypeScript 模块化单体、公开业务入口与受限 composition、数据唯一写入所有者、独立任务角色、MySQL outbox 和统一 execution。
- 保留 www/trade/admin/auth 四应用、Nuxt/Vue、shadcn-vue、统一身份与独立应用会话，以及 `/api/v4` 和独立实时/Bridge 合同。
- dev_vue 原地追加升级，历史数据保留，已执行迁移不得改写。数据库保存 UTC，旧时间按 UTC 原值迁移；实验室显示终端时间，其它页面北京时间。休市默认 UTC+3 仅用于展示，不作为交易有效性证据。
- 市场状态面向用户只显示开市/休市；连接、权限、风险拒绝在各自语义下解释。
- 应用与测试在本地，MySQL/Redis 使用虚拟机 192.168.1.254。公网发布、旧数据删除、真实终端交易仍按原独立边界执行。
- Bridge 暂保留现有 .NET/Win7 目标，不因另一方案采用 Rust 而变更支持范围；原型不等于客户端正式交付。

吸收 Workbuddy 的需求追溯、事故回归、版本双轴、可观测与恢复验收组织方法，不引入它的旧 API/共享令牌、组件库替换或预设多机部署。

## 6. 两轮复审与调整

第一轮：需求与复杂度。保留原功能矩阵全部范围；区分已有基础与可交付成果；将细粒度候选实现合并为 D1 用户流程。主站与后台按业务同步交付；前端只等待自己依赖的后端合同，不等全系统完成。不建设另一套任务、身份或数据访问平台。

第二轮：数据、异常与验证。保留追加迁移、历史归属、未知结果对账及外部 I/O 不入事务；不因加快交付把未知费用补零或把 UTC+3 显示值当执行证据。数据库恢复不能丢切换后的新增事实；真实依赖参考测试不冒充实机验证。

剩余风险：旧策略语义、真实终端费用/时区事实、客户端支持矩阵、完整模型调用和资源预算尚未闭合；分别留在 D2/D3/D7/D9，不额外扩大本轮操作授权。

整理时仅调整交付组织；用户随后授权恢复核心实施，从 D1 完整流程开始，技术栈保持。
