## 2. 最终结论

采用“**结构化数据声明 + 界面使用指导 + 运行时中性身份说明**”三层设计：

1. 策略编辑器用开关和少量选择项声明模型需要的数据；
2. 开关下方直接解释系统会提供什么、不会替用户做什么；
3. 运行时只告诉模型“这是什么数据”，不告诉模型“应该如何交易”；
4. 策略正文继续拥有唯一分析权威，具体周期职责、方向条件、过滤逻辑和冲突处理只能来自用户策略；
5. 系统不得静默改写策略正文；使用示例只能由用户主动复制或插入；
6. 不再向普通用户暴露 `{{MTF...}}`、`{{ATF...}}`、`{{CTF...}}`、`{{USE_CHAN}}` 等旧控制标签；
7. EMA34 简单开关必须转换为现有通用指标声明，不能继续依赖没有运行作用的旧布尔字段。

一句话目标：

> **开关负责让数据出现，界面负责教用户描述用途，策略正文负责决定怎么交易。**

## 3. 需求边界

### 3.1 必须实现

- 普通用户不编辑 JSON 也能启用缠论和 EMA34 数据；
- 开启后立即看见简短中文说明、实际周期和模型将收到的数据摘要；
- 关闭后，新鲜推理不得继续携带对应可选数据或对应身份说明；
- 缠论结构继续按 `chan-model-payload-v1` 原样投影，不恢复可靠性解释、方向归纳或观望指令；
- EMA34 由通用指标注册器按声明周期和已收盘 K 线计算；
- 手动分析、自动分析、新鲜模型比较使用相同的数据声明；
- 历史模型比较继续使用历史冻结声明和历史冻结输入；
- 用户端和统一管理后台的策略编辑能力保持一致；
- 保存时保护已有高级策略声明，禁止简单开关覆盖不认识的高级配置；
- 所有用户可见文案使用自然中文，不暴露内部字段码和错误码。

### 3.2 明确不做

- 不把“EMA34 上方只做多”“结构不完整必须观望”等交易规则写入服务端；
- 不根据策略 ID、策略名称或当前策略正文建立服务端专用分支；
- 不自动给缠论周期分配“方向周期、确认周期、入场周期”等职责；
- 不自动把示例文字追加到策略正文末尾；
- 不在本阶段建设完整可视化策略 DSL 编辑器；
- 不删除历史字段、历史标签解析器或历史快照；
- 不因新增界面开关重新生成历史信号；
- 不执行策略数据库批量回填或自动转换。

## 4. 当前能力与问题清单

| 当前配置或声明 | 当前作用 | 是否进入新鲜模型输入 | 当前问题 |
| --- | --- | --- | --- |
| `symbols_json` | 限制策略可分析的品种 | 是 | 用户理解基本清楚 |
| `market_data_plan_json` | 声明周期、K 线数量和主周期 | 是 | 未说明每周期会附带哪些系统摘要 |
| `use_chan_analysis` | 为策略周期计算缠论结构 | 是 | “启用缠论指标”容易被理解为系统自动使用缠论交易 |
| `include_portfolio_context` | 私有策略读取当前持仓和挂单 | 是 | 当前说明基本完整 |
| `entry_methods_json` | 限制模型允许输出的订单类型 | 间接 | 属于输出能力，不是行情数据，界面应继续分区展示 |
| `use_ema34_filter` | 历史审计字段 | 否 | 字段名暗示会过滤，但当前运行时明确不计算、不注入、不执行 |
| `strategy_policy_json.indicators` | 声明 EMA/SMA、周期、价格字段和 K 线范围 | 是 | 后端已支持，用户端和管理端没有编辑入口 |
| 统一策略记忆库 | 传入完整冻结版本 | 是 | 自动能力，不需要策略标签 |
| `{{MTF...}}` 等旧标签 | 旧版提示词解析回退 | 仅兼容 | 保存时会剥离，不适合作为新用户合同 |

### 4.1 每个启用周期当前自动提供的基础数据

当前 `calculateMarketData()` 会生成：

- 原始压缩 K 线；
- 最新价格、涨跌幅、近期高低点和区间位置；
- SMA20、SMA50、EMA12、EMA26；
- MACD、RSI14、布林带、ATR14；
- 动量、波动率、支撑阻力、K 线形态和成交量摘要。

第一阶段不删除这些兼容字段，避免已有策略突然缺数据；界面必须把它们概括为“随周期提供的基础行情与技术摘要”。后续若要精简为完全按声明提供，应另立版本化模型输入合同，不能在本方案中静默移除。

### 4.2 EMA34 当前语义断层

`parseStrategyPolicy()` 已明确将 `use_ema34_filter` 视为只读历史元数据：它不能创建运行时策略、增加数据窗口、渲染提示词或启用执行限制。

真正负责 EMA34 的现有通用链路是：

```text
strategy_policy_json.indicators
  -> compileStrategyPolicy()
  -> indicatorRequiredHistory()
  -> calculatePolicyIndicators()
  -> strategy_context.indicators
  -> 模型输入
```

因此，恢复一个只写 `use_ema34_filter=true` 的界面开关是错误实现。新界面必须写入通用指标声明，并将旧布尔值仅作为兼容镜像和审计信息。

## 5. 核心产品模型

### 5.1 将“技术分析开关”改为“提供给模型的数据”

策略编辑器第 02 区改名：

> **提供给模型的数据**

内部按顺序组织：

1. 行情周期与 K 线数量；
2. 附加结构和指标；
3. 当前策略将收到的数据摘要。

“允许的入场方式”继续独立存在，避免把输入数据和输出权限混在一起。

### 5.2 缠论开关

用户文案：

> **提供缠论结构数据**
>
> 为已选的支持周期计算笔、线段、中枢、背驰和买卖点候选，并把结构原样提供给模型。开启不会自动决定方向，也不会强制观望或交易。

展开内容：

- 当前可计算周期：从已启用的 M5、M15、H1、H4 中自动列出；
- M1、M30、D1 仍可作为普通行情周期，不因缠论开启而阻止保存；
- 如果没有任何支持周期，开关不可保存并给出中文原因；
- 高级说明只展示模型字段路径，不展示内部诊断字段；
- 不提供“方向周期”“入场周期”等服务端默认选择。

#### 缠论周期语义调整

当前保存校验会在缠论开启时拒绝任何包含不支持周期的行情方案。应调整为：

- 普通行情周期可以包含 M1、M30、D1；
- 缠论只计算已启用周期中的 M5、M15、H1、H4；
- 至少存在一个支持周期才能开启；
- 冻结快照明确保存本次实际计算的 `chan_timeframes`。

这样可以避免用户为了使用 D1 普通行情而被迫关闭全部缠论。

### 5.3 EMA34 开关

用户文案：

> **提供 EMA34 数据**
>
> 按所选周期的已收盘 K 线计算 EMA34，并把数值和证据时间提供给模型。开启不会自动把 EMA34 作为开仓过滤条件，具体用途由策略正文决定。

展开配置：

- 计算周期：只能选择当前行情方案中已启用的周期；
- 价格字段：第一版固定为收盘价；
- K 线范围：第一版固定为已收盘 K 线；
- 周期参数：第一版固定为 34；
- 预热目标：60 根，实际取数仍由通用指标历史计算器决定；
- 高级信息：可展开查看 `ready`、数据周期、最后证据时间和算法版本含义。

界面名称禁止使用“EMA34 过滤开关”。“过滤”属于策略逻辑，不属于数据能力。

### 5.4 策略写法助手

每个已开启能力下提供“如何在策略中使用”区域，但默认不改策略正文。

缠论模板：

```text
【缠论结构用途】
- 使用周期：{当前实际缠论周期}
- 用途：{方向判断 / 入场确认 / 风险参考 / 其他，请填写}
- 有效结构条件：{请填写}
- 多周期冲突处理：{请填写}
```

EMA34 模板：

```text
【EMA34 用途】
- 使用周期：{所选周期}
- 用途：{趋势过滤 / 入场确认 / 仅作参考 / 其他，请填写}
- 多头条件：{请填写}
- 空头条件：{请填写}
- 不满足条件时：{请填写}
```

仅提供：

- `复制写法模板`；
- `插入到光标位置`。

禁止：

- 开启开关后自动追加模板；
- 保存时自动补写；
- 后端修改用户 `system_prompt`；
- 在模板中预填具体方向、周期职责或观望规则。

### 5.6 UI/UX 分析结论与设计取舍

本方案已使用 UI/UX Pro Max 对复杂表单、渐进披露、状态反馈、无障碍和响应式进行专项分析。工具生成的紫色高对比配色和“多步骤漏斗”样式不适合 AURUM，正式实施不得照搬，原因如下：

- AURUM 已有稳定的深色专业工作台和稀缺金色焦点体系，另建紫色体系会破坏产品一致性；
- 策略编辑属于高频回访和局部修改，不是一次性注册流程，多步骤向导会增加来回导航和上下文丢失；
- 当前编辑器同时承载基础信息、数据声明、策略正文和运行配置，用户需要快速对照而不是被强制逐页推进；
- 普通用户的主要困难是“不知道开启后得到什么、怎么写进策略”，不是缺少更多页面或装饰。

正式吸收以下分析结论：

1. 使用渐进披露：默认展示能力名称、开关、简短说明和当前状态，开启后才展开周期与写法帮助；
2. 使用明确标签和就地校验，不用占位符代替字段名称；
3. 每个异步动作具备加载、成功、失败和可恢复状态；
4. 全流程支持键盘、清晰焦点、屏幕阅读器和减少动画偏好；
5. 状态不能只靠颜色表达，必须同时有图标、中文文字或控件状态；
6. 移动端最小触控目标为 44×44px，表单输入字号不小于 16px；
7. 页面只保留一个主操作“保存策略”，复制、插入、取消等均为次级操作；
8. 不堆叠多层卡片，不用装饰性渐变、霓虹、高频动画或过度圆角。

### 5.7 策略编辑器信息架构

保留现有策略编辑器的单页编辑模型，按用户决策顺序组织：

```text
01 基础信息
   名称、品种、可见性

02 提供给模型的数据
   行情周期与 K 线数量
   缠论结构数据
   EMA34 数据
   持仓与挂单上下文
   本策略将收到的数据摘要

03 允许的输出方式
   市价、限价、止损限价等

04 策略正文与分析设置
   策略正文
   已启用数据的写法助手
   模型、计划任务和其他运行配置

底部操作
   取消                      保存策略
```

设计约束：

- “提供给模型的数据”与“允许模型输出什么”必须分区，避免用户把数据开关理解为交易规则；
- 数据能力采用连续表单行和 1px 分隔线，不为每个开关再嵌套一张卡片；
- 实时摘要紧跟数据配置，用户无需滚动到策略正文后才知道最终结果；
- 写法助手靠近策略正文，但按已启用能力生成，不在每个开关下重复放置大型编辑区；
- 桌面端可使用“配置 + 摘要”双栏，但 DOM 顺序必须先配置后摘要；
- 低于 1040px 自动单列，摘要位于能力配置之后；
- 不采用会遮挡最后一项内容的悬浮保存条；如使用粘性操作区，必须预留等高底部空间。

### 5.8 控件与状态合同

| 状态 | 用户看到的内容 | 可执行操作 | 保存行为 |
| --- | --- | --- | --- |
| 关闭 | 开关关闭、简要能力说明、无周期详情 | 开启、查看说明 | 正常保存 |
| 已开启且就绪 | 开关开启、实际周期、模型输入摘要 | 调整周期、查看写法 | 正常保存 |
| 已开启但配置不完整 | 橙色警示图标、中文原因、首个问题字段 | 补充配置、关闭能力 | 阻止保存并聚焦问题字段 |
| 旧 EMA 布尔值但无声明 | “旧配置未产生 EMA34 数据”中性提醒 | 重新开启并配置 | 不伪装为已生效 |
| 已存在高级声明 | “高级配置”状态和只读摘要 | 查看详情 | 简单开关锁定，避免覆盖 |
| 能力目录加载中 | 稳定尺寸的骨架或加载文字 | 取消编辑 | 不允许修改未知高级配置 |
| 能力目录加载失败 | 中文错误和重试入口 | 重试、取消 | fail-closed，不覆盖原配置 |
| 正在保存 | 主按钮显示加载状态并禁用重复点击 | 取消不可用 | 单次提交 |
| 保存成功 | 就地成功反馈，更新版本基线 | 继续编辑或关闭 | 草稿标记清除 |
| 保存失败 | 保留全部输入和错误位置 | 修改、重试、取消 | 不关闭编辑器 |
| 版本冲突 | 显示“策略已在其他位置更新” | 刷新对比、复制草稿 | 禁止自动覆盖 |

异步响应必须与当前策略 ID、编辑会话 generation 和请求版本绑定。用户已切换策略、关闭编辑器或继续修改后，旧响应不得覆盖当前界面。

### 5.9 正式界面文案

能力名称和说明固定使用中性中文：

**缠论**

> **提供缠论结构数据**
>
> 为已选的支持周期计算并提供原始结构。不会自动决定方向，也不会强制观望或交易。

**EMA34**

> **提供 EMA34 数据**
>
> 按所选周期的已收盘 K 线计算并提供。不会自动作为开仓过滤条件。

辅助区域统一使用：

- 摘要标题：`本策略将收到`
- 写法助手标题：`如何在策略中使用`
- 主按钮：`保存策略`
- 次级按钮：`复制写法模板`、`插入到光标位置`
- 高级状态：`高级配置`、`查看详情`

用户可见界面禁止出现：

- `use_chan_analysis`、`strategy_policy_json`、`indicator_declarations` 等内部字段名；
- `chan-model-payload-v1`、算法 hash 和内部错误码；
- “过滤通过”“结构可靠”“必须观望”等越权结论；
- 用 `enabled/disabled/ready` 等英文代替中文状态。

技术字段只允许在明确的“查看技术字段”区域展示，并默认折叠。

### 5.10 视觉、交互和无障碍规范

#### 视觉规范

- 继续使用 AURUM 现有深色层级：页面背景、工作面、输入面和边框按现有 token 组织；
- 金色仅用于当前步骤、开启状态、焦点和主操作，不作为大面积卡片底色；
- 中性说明使用现有蓝灰文字，配置警告使用橙色，错误使用红色，但都必须配合图标和中文；
- 圆角沿用 6px、10px、14px 层级，不将所有容器做成胶囊；
- 图标统一使用现有 Lucide 图标，不新增 emoji 或自绘风格不一致的图标；
- 标题、字段名、辅助文字形成明确字号和字重层级，说明文字不使用过低对比度。

#### 交互规范

- 开关基于原生 checkbox 语义实现，并关联 `aria-describedby`；
- 展开详情的控件声明 `aria-expanded` 和对应内容 ID；
- 表单组使用可识别的 label，周期选择组使用 fieldset/legend 或等价语义；
- 错误紧邻字段显示，提交失败摘要使用 `role="alert"`，实时数据摘要使用 `aria-live="polite"`；
- 键盘 Tab 顺序与视觉顺序一致，所有操作均有 2–4px 清晰 `:focus-visible`；
- 开关、按钮、复选框点击区至少 44×44px；
- 开关展开只使用 150–200ms 的 opacity/transform 过渡，不使用高度弹跳和循环动画；
- `prefers-reduced-motion: reduce` 下关闭非必要动画；
- 开启能力不得自动改写策略正文，复制或插入必须由用户点击；
- 插入成功应短暂提示，但不得夺走策略正文光标。

#### 响应式规范

- 1440px：完整桌面布局，允许配置与摘要双栏；
- 1024/1040px：检查双栏向单栏切换，无横向溢出；
- 720/768px：控件单列，按钮文字不截断，摘要不使用横向表格；
- 375px：输入字号至少 16px，触控目标至少 44px，开关说明和错误不挤成窄列；
- 任何宽度下都不得因加载、校验或展开造成主操作跳出可视区域或产生明显布局抖动。

## 6. 运行时提示词边界

### 6.1 允许注入的内容

运行时仅按实际存在的数据生成中性身份说明：

```text
## 系统提供的数据
以下内容只标识系统提供的数据，不构成交易规则。分析方法、周期职责、方向判断和交易条件均以当前策略正文为准。

- strategy_context.timeframes 各周期 summary.chan 为系统计算的缠论结构，请仅按当前策略正文自行分析。
- strategy_context.indicators.ema34 为系统根据策略声明计算的 EMA34 数据，请仅按当前策略正文自行分析。
```

规则：

- 对应数据不存在时，不生成对应说明；
- 说明文本来自能力类型，不来自策略 ID 或策略正文匹配；
- 缠论继续只保留现有一句身份说明，不恢复字段字典；
- EMA34 不注入“上方/下方”“多头/空头”“过滤/确认”等使用方法；
- 系统提示词不得比策略正文新增任何交易判断。

### 6.2 禁止注入的内容

- “价格在 EMA34 上方只做多”；
- “EMA34 下方禁止开仓”；
- “H1 判断方向、M5 负责入场”；
- “缠论结构不可靠时必须观望”；
- “多周期冲突时降低置信度”；
- 固定的指标权重、置信度分档、盈亏比、止盈倍数或方向结论。

### 6.3 为什么不会与现有策略冲突

中性身份说明只回答“字段是什么”，不回答“字段应该怎么用”。即使策略明确写“EMA34 仅作参考”或“忽略某周期缠论”，系统仍只提供数据，模型应服从策略正文。

会产生冲突的是自动注入交易方法，因此本方案明确禁止自动注入使用逻辑。

## 7. 数据与 API 合同

### 7.1 不新增第二套标签语言

继续使用现有持久化结构：

- `market_data_plan_json`：行情周期、K 线数量、主周期；
- `use_chan_analysis`：缠论总开关；
- `strategy_policy_json.indicators`：通用指标声明；
- `include_portfolio_context`：私有账户事实开关；
- `entry_methods_json`：允许的输出类型；
- `use_ema34_filter`：仅兼容镜像，不作为运行时真相。

### 7.2 增加通用的简单指标声明输入

创建和更新策略接口增加可选字段：

```json
{
  "indicator_declarations": [
    {
      "id": "ema34",
      "kind": "ema",
      "enabled": true,
      "source": {
        "timeframe": "M5",
        "field": "close",
        "bar_scope": "closed_only"
      },
      "params": {
        "period": 34,
        "minimum_bars": 34,
        "warmup_target_bars": 60,
        "evidence_window": 5
      }
    }
  ]
}
```

该字段是 `strategy_policy_json.indicators` 的普通用户适配层，不新增数据库列。后端负责：

1. 读取现有 canonical policy；
2. 识别由简单界面管理的 `ema34` 声明；
3. 合并或移除该声明；
4. 保留未知指标、workflow、constraints、prompt_rules 和 ui 元数据；
5. 重新执行现有通用编译校验；
6. 写回 canonical `strategy_policy_json`；
7. 将 `use_ema34_filter` 同步为是否存在兼容 EMA34 声明的审计镜像。

Policy mode 处理必须明确：

- 策略原本没有 policy 时，首次开启简单指标，创建最小 canonical policy，并使用 `shadow` 模式承载“只计算并提供数据”的语义；
- 最小 policy 的 features、workflow stages、selectors、constraints 和 prompt_rules 均为空，不能附带任何交易规则；
- 策略已有 `shadow` 或 `enforce` policy 时，保持原 mode，不因简单开关改变高级规则模式；
- 策略已有显式 `off` policy 时，开启简单指标属于用户主动变更，应先在界面提示将启用数据计算，确认保存后才转为 `shadow`；
- 关闭最后一个简单指标时，只有 policy 确认是系统生成的空壳且没有其他高级内容，才可将 policy 清为 `null`；
- 只要仍有未知指标、features、workflow、constraints、prompt_rules 或 ui 高级配置，就保留原 policy 和 mode。

### 7.3 高级声明保护

以下情况简单开关不得直接覆盖：

- 已存在同 ID 但 `kind`、周期或参数不同的声明；
- 其他约束或 workflow 正在引用该 EMA34 声明；
- policy JSON 无法由当前编译器识别；
- 策略在用户打开编辑器后已被其他会话更新。

界面显示：

> 当前 EMA34 使用高级配置。简单开关不会覆盖它；请先查看配置或确认转换。

第一版不提供原始 JSON 编辑器，只保护和展示状态。

### 7.4 并发保护

策略更新接口增加 `expected_version`：

- SQL 更新必须带 `WHERE id = ? AND version = ?`；
- 影响行数为 0 时返回稳定的 `strategy_version_conflict`；
- 前端保留用户草稿，提示刷新对比，不关闭编辑器；
- 创建策略不需要 `expected_version`；
- 用户端和管理端行为一致。

### 7.5 能力目录

新增只读、版本化能力目录：

```text
GET /api/ai/strategy-data-capabilities
```

返回：

- 目录版本；
- 支持周期；
- 基础行情摘要说明；
- 缠论支持周期和中性说明；
- 通用指标种类与可用参数；
- EMA34 简单预设；
- 私有账户事实的范围限制；
- 用户可见中文文案和高级字段路径。

能力目录必须是通用工具元数据，不根据策略内容返回不同交易规则。用户端和管理端使用同一目录，避免说明文案和后端能力漂移。

## 8. EMA34 canonical 声明

简单开关生成的声明固定为：

```json
{
  "id": "ema34",
  "kind": "ema",
  "enabled": true,
  "source": {
    "timeframe": "M5",
    "field": "close",
    "bar_scope": "closed_only"
  },
  "params": {
    "period": 34,
    "minimum_bars": 34,
    "warmup_target_bars": 60,
    "evidence_window": 5
  }
}
```

其中 `timeframe` 由用户选择，其余参数为第一版预设。实现不得：

- 把 M5 写死为所有策略默认；
- 因字段名包含 `ema34` 就添加任何交易条件；
- 根据价格相对 EMA34 的关系改写模型结论；
- 在服务端执行某个具体策略的 EMA34 过滤规则。

模型可见证据继续使用通用指标结构：

- `ready`；
- `reason`；
- `value`；
- `bar`；
- `source`；
- `bars_used`；
- `analysis`；
- `algorithm_version`；
- `evidence_hash`。

这些是可追溯数据，不是交易结论。

## 9. 保存校验与友好提示

### 9.1 阻止保存

- 未选择任何行情周期；
- 主周期不在已启用周期中；
- 开启缠论但没有 M5、M15、H1、H4 中的任何一个周期；
- 开启 EMA34 但未选择计算周期；
- EMA34 周期不在行情数据方案中；
- 关闭某周期会破坏仍在使用的高级指标声明；
- 指标声明编译失败；
- 策略版本冲突。

### 9.2 只提醒、不阻止保存

- 策略正文提到 EMA34，但当前没有提供 EMA34 数据；
- 策略正文提到缠论、中枢或背驰，但缠论开关关闭；
- 已提供 EMA34 或缠论，但策略正文没有描述用途；
- 某项可选数据已开启但可能未被策略使用。

提醒必须使用“可能”“建议”等表述，避免把关键词检测伪装成语义理解。

### 9.3 禁止自动修复

- 不自动开启能力；
- 不自动选择周期；
- 不自动修改策略正文；
- 不自动删除高级声明；
- 不自动将旧 `use_ema34_filter=1` 转换为新声明。

## 10. 旧数据兼容策略

### 10.1 旧提示词标签

- 继续保留服务端只读回退解析，避免旧历史配置无法运行；
- 新建和编辑界面不展示、不生成旧标签；
- 保存仍通过 `stripStrategyControlTags()` 清理控制标签；
- 新文档和帮助中心不再推荐旧标签；
- 不批量改写历史策略和历史快照。

### 10.2 旧 EMA34 布尔字段

读取时分三类：

1. 有兼容 EMA34 指标声明：显示开关已开启并回填周期；
2. `use_ema34_filter=1` 但无声明：显示“旧配置未产生 EMA34 数据”，开关不伪装为已生效；
3. 有不兼容或高级 EMA34 声明：显示“高级配置”，禁止简单覆盖。

用户明确保存新配置后，才同步布尔镜像。无需数据库迁移或批量回填。

### 10.3 历史快照

- 新鲜任务冻结 `market_data_plan`、`use_chan_analysis`、`chan_timeframes`、canonical policy、policy hash、indicator algorithm version 和 evidence hash；
- 历史模型比较只读取冻结快照；
- 不用当前策略开关重算旧信号；
- 旧快照缺少新目录版本时按历史合同只读展示，不伪造新声明。

## 11. 完整调用链改造

### 11.1 用户端和管理端

```text
打开策略编辑器
  -> 读取策略 + 能力目录
  -> 将 canonical policy 映射为简单能力状态
  -> 用户修改开关/周期
  -> 实时生成数据摘要和非阻断提醒
  -> 提交 expected_version + indicator_declarations
  -> 服务端合并并编译 canonical policy
  -> CAS 保存并返回新版本
```

### 11.2 新鲜推理

```text
读取策略
  -> parseStrategyPolicy()
  -> 按 market_data_plan 取行情
  -> 按 use_chan_analysis 计算支持周期的缠论
  -> 按 indicators 计算 EMA/SMA
  -> 构建 strategy_context
  -> 生成仅包含实际存在能力的中性身份说明
  -> 模型按策略正文分析
  -> 冻结策略声明、数据证据和模型输入
```

### 11.3 历史回放

```text
读取历史冻结策略和输入
  -> 不读取当前开关
  -> 不读取当前能力目录结果替换历史字段
  -> 使用历史 system prompt / user prompt / strategy runtime
  -> 保持结果可复现
```

### 阶段 D：完整回归与真实模型对照

门禁：无策略逻辑被服务端新增，无旧策略被静默改写。

### 阶段 E：发布

- 单一职责提交到 `dev_codex`；

## 17. 第二轮复审：兼容性、数据、并发、恢复与连带风险

### 17.1 数据与迁移

- 现有列足够，默认不新增迁移；
- 不批量回填旧 EMA34 布尔值；
- 不改历史策略正文和历史快照；
- canonical policy 合并必须保留未知字段。

### 17.2 并发与幂等

- 增加 `expected_version` CAS，防止两个编辑器互相覆盖；
- 重复提交同一 canonical declaration 应得到稳定结果；
- 版本冲突保留草稿，不自动重试覆盖；
- 能力目录是只读版本化数据，不产生写入竞态。

### 17.3 异常恢复

- 指标数据不足时返回 `ready=false` 的中性证据，不补造数值；
- 行情缺失时沿用现有新鲜推理失败边界；
- 旧配置无法映射时显示高级/待确认，不伪装生效；
- 前端加载能力目录失败时禁止修改不认识的高级声明，但仍可安全取消编辑；
- 保存失败、目录重试和版本冲突都必须保留用户草稿；
- 用户切换策略或继续编辑后，旧请求响应不得回写当前表单；
- 异步状态必须有加载、成功、失败和恢复入口，不允许按钮无反馈；
- 发布失败时按 Git 提交回滚，不执行策略数据回滚脚本。

### 17.4 时间语义

- EMA34 第一版固定使用已收盘 K 线；
- 证据保留 UTC 时间和行情来源；
- 历史比较使用冻结证据时间；
- 不用当前墙钟重算历史指标。

### 17.5 安全与权限

- 私有持仓上下文权限不因指标开关变化；
- 平台策略不获得订阅用户账户数据；
- 能力目录不返回账户、密钥或策略正文；
- 管理员只能编辑平台策略，普通用户只能编辑自己的私有策略；
- 新接口复用现有鉴权和策略归属校验。

### 17.6 测试与部署

- 单测不能替代真实浏览器和真实模型输入检查；
- 全量测试失败时停止发布；
- 静态资源必须更新缓存键并验证公网实际响应；
- 公网部署不得执行手工 SQL；
- 发布后只验证新任务，不回填历史任务。

### 17.7 界面与可访问性

- 用户主任务被收敛为“选择模型收到的数据，并决定如何在策略中使用”；
- 单页渐进披露比多步骤向导更适合高频编辑和跨区对照；
- 页面只保留“保存策略”一个主操作，模板复制和插入为次级操作；
- 状态使用图标、中文和控件共同表达，不依赖红绿或金色；
- 桌面端允许配置与摘要双栏，移动端保持单列和正确 DOM 顺序；
- 44px 触控目标、16px 移动输入字号、清晰焦点、ARIA 和减少动画均进入门禁；
- 不采用会遮挡内容的悬浮操作区，不用多层卡片增加视觉噪声；
- 用户端和管理端可以适配不同容器，但能力名称、说明、状态和交互合同必须一致。

### 17.8 连带 Bug 检查

- 简单关闭 EMA34 可能破坏高级 constraint 引用：已改为阻止保存；
- 缠论支持周期子集可能造成快照和运行时不一致：要求冻结实际 `chan_timeframes`；
- 用户提示词提到关闭能力可能造成模型自行估算：加入非阻断提醒，不自动开启；
- 两端前端可能产生不同 policy：要求同一 API 适配层和 parity 测试；
- 旧标签可能复活新配置：结构化字段存在时继续优先于标签回退；
- 能力说明可能演变为策略规则：建立允许/禁止文本测试和代码审查门禁；
- 展开或异步摘要造成布局跳动：为加载态预留稳定空间并做真实浏览器检查；
- 状态只靠颜色导致误读：静态治理测试和浏览器验收同时检查图标与中文；
- 移动端字号过小触发浏览器自动缩放：输入控件强制不小于 16px；
- 双栏视觉顺序与键盘顺序不一致：保持配置先于摘要的 DOM 顺序。

### 17.9 第二轮调整

1. 增加高级声明引用保护，不能简单删除被 constraint/workflow 使用的指标；
2. 增加策略版本 CAS 和草稿保留；
3. 增加能力目录加载失败的 fail-closed 编辑行为；
4. 明确历史快照不受当前能力目录和当前开关影响；
5. 将真实模型四组合对照加入发布前门禁；
6. 将“信号数量、方向或置信度变化”排除为成功指标；
7. 合入 UI/UX 专项分析，形成单页渐进披露、状态矩阵和响应式合同；
8. 明确拒绝第二套颜色和不适合高频编辑的向导模式；
9. 将无障碍、异步竞态和草稿恢复纳入发布停止条件。

第二轮结论：兼容性、数据、并发、恢复、时间、安全、测试和回滚均有明确门禁；未发现需要继续修改方案的实质缺口。方案可实施。

## 18. 剩余风险

1. 关键词提醒不能真正理解策略语义，只能作为非阻断提示；
2. 已有高级 policy 的组合形式可能超出简单编辑器识别范围，必须优先保护而不是强行兼容；
3. 当前基础行情摘要仍包含多项未逐个声明的技术指标，完全按声明精简需要另一个版本化输入合同；
4. 真实模型对同一中性数据的理解仍受模型能力和策略正文质量影响；
5. `strategy_policy_json` 同时承载数据声明和历史高级规则，长期可考虑拆分，但本方案不提前扩表；
6. 公网当前策略数据是否都具备 canonical EMA34 声明，需要实施前只读审计，不能从布尔字段推断；
7. 静态 UI 分析不能代替真实浏览器视觉验收，尤其需要检查长中文、系统缩放和不同数据量；
8. 用户端与管理端若各自复制能力文案，后续可能漂移，实施时必须复用同一能力目录和前端格式化合同。

## 19. 最终验收定义

只有同时满足以下条件，才能宣布完成：

- 缠论与 EMA34 的运行时提示只有中性身份说明；
- 关闭能力后新请求中对应数据和说明均消失；
- 手动、自动和新鲜比较链路一致；
- 历史回放仍使用冻结旧合同；
- 高级 policy 未被覆盖；
- 并发版本冲突不丢草稿；
- 界面保持 AURUM 现有深色金色设计语言，没有引入第二套视觉体系；
- 单页渐进披露、一个主操作和完整控件状态符合本方案；

- 键盘、焦点、ARIA、44px 触控目标、16px 移动输入字号和减少动画验收通过；
- 用户端、管理端、全量测试、真实浏览器和真实模型输入验收全部通过；
- 未在服务端新增任何具体策略的交易判断。

## 20. 2026-08-14 补充修订：高级 EMA34 总开关与持仓摘要语义

### 20.1 需求修订

- EMA34 开关只控制服务端是否计算并向新鲜模型请求提供 EMA34 数据，不修改用户策略正文；
- 现有 `entry_ema34` 等高级声明也必须能够关闭和重新开启，切换时保留原 ID、周期和参数；
- 关闭后，用户负责自行删除策略正文中对 EMA34 的依赖，界面只做明确提醒；
- 平台策略继续禁止读取订阅用户私人账户，但编辑器必须正确显示其运行时自动获得的“平台策略参考持仓与挂单”；
- 私有策略仍按现有授权开关读取策略所有者自己的持仓与挂单，执行前账户校验不受影响。

### 20.2 第一轮复审：需求、边界与最小改动

检查结论：此前“高级声明完全锁死”保护过度，与用户明确要求冲突。最小修订是不删除、不改名、不改周期或参数，而是把现有 `use_ema34_filter` 作为 EMA34 数据总开关镜像，并只切换 `strategy_policy_json` 中 EMA34 类声明的 `enabled` 状态。运行时只有总开关和声明同时开启时才计算对应数据。这样无需新增迁移，也不会把服务端变成策略规则执行器。

第一轮调整：

1. 高级 EMA34 的周期和参数继续只读，但总开关始终可操作；
2. 关闭/开启只同步总开关与声明的 `enabled` 状态，保留高级声明 ID、周期、参数、其他字段和策略正文；
3. 简单声明首次开启仍可创建 canonical `ema34`，后续关闭不删除声明；
4. 关闭确认文案明确“策略正文不会自动修改”；
5. 平台策略摘要改为“运行时自动提供策略参考持仓与挂单”，不再误报“未提供”。

第一轮结论：覆盖用户需求，复用现有字段和通用指标工具，未新增任何策略专属判断，可进入兼容性复审。

### 20.3 第二轮复审：兼容性、数据与恢复

检查结论：总开关必须同时约束手动、自动和新鲜比较的统一 `prepareStrategyDataRuntime` 边界；历史回放继续读取冻结输入，不受当前开关影响。保存端必须让显式 `use_ema34_filter` 优先于声明派生值，且 CAS 版本控制、草稿保留和权限边界不变。平台参考组合只反映策略自身持仓/挂单，不能改成订阅用户账户。

第二轮调整与门禁：

1. `data_capabilities.ema34` 同时返回声明类型和总开关实际状态；
2. 关闭后模型输入不得出现任何 EMA34 类 indicator，也不得附加 EMA34 系统说明；
3. 重新开启必须恢复同一高级声明，不丢 ID、周期、参数；
4. 多个 EMA34 类声明统一受总开关约束并同步切换 `enabled`，其 ID、周期、参数及其他策略字段保持不变；
5. 平台摘要只改展示语义，不能扩大账户权限；私有策略现有开关和 Bridge fail-closed 行为保持；
6. 增加高级声明开关、运行时过滤、正文不变、平台摘要和真实模型输入回归；
7. 回滚只需回退代码提交，不需要数据回填或 SQL 修复。

第二轮结论：兼容性、并发、历史冻结、权限、恢复和回滚边界清楚，方案可实施。
