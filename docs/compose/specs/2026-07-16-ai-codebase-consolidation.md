# AI 推理与风控代码收敛说明

## 1. 本轮目标

本轮不是继续叠加一套配置，而是将模型、策略、订阅、推理偏好、调度与风控收敛到单一职责链路，移除已经被新系统替代的外部入口，同时保留调度器仍在使用的最小兼容镜像。

## 2. 收敛后的主链路

```text
前端设置页
  ├─ 模型配置 -> ai_model_profiles / user_model_defaults
  ├─ 策略管理 -> strategy_profiles
  ├─ 策略订阅 -> strategy_subscriptions
  └─ 手动推理偏好 -> ai_inference_preferences

推理请求
  -> 服务端校验用户与策略归属
  -> resolveAiTaskModel 解析用户模型或管理员共享模型
  -> 只向模型提供市场行情与策略上下文
  -> AI 返回方向、理由、止损止盈和建议手数
  -> executeOrderCore 统一进入静态与状态风控
  -> 风控约束价格偏差、平台手数上下限、持仓和挂单
  -> Python Bridge 执行 MT5 指令

自动推理
  -> strategy_subscriptions 为真实控制面
  -> 事务内同步 auto_scheduler 与 user_bridge_settings
  -> reconcileAutoSchedulers 刷新运行态
  -> scheduler 执行推理、持久化、投递和风控
```

## 3. 数据职责

| 数据 | 权威来源 | 可见性与修改权限 | 说明 |
| --- | --- | --- | --- |
| 模型档案 | `ai_model_profiles` | 用户管理自己的模型；管理员管理平台模型 | API Key 加密存储；统一供手动和自动推理解析 |
| 默认模型 | `user_model_defaults` | 用户选择自己的默认模型；管理员可配置平台默认 | 用户未配置时，仅在管理员允许共享后回退平台模型 |
| 策略 | `strategy_profiles` | 用户仅见自己的私有策略；管理员可见全部及所属用户 | 服务端执行归属校验，不能依赖前端隐藏 |
| 策略订阅 | `strategy_subscriptions` | 用户管理自己的订阅；管理员可审计全部 | 自动推理的真实开关和策略绑定来源 |
| 手动推理偏好 | `ai_inference_preferences` | 用户修改自己的提示词、风险等级、手数上限等 | 不再把普通推理设置与 API Key 混存在 `ai_configs` |
| 平台全局风控 | `global_auto_config` 及专用风控表 | 仅管理员修改 | 作为硬上限，用户设置只能进一步收紧 |
| 调度运行镜像 | `auto_scheduler`、`user_bridge_settings` | 不提供独立前端或 WS 写入口 | 由订阅事务同步，供现有调度器与桥接读取 |

## 4. 已删除的旧控制面

- 删除前端“自动配置覆盖”子页、旧提示词类型弹窗和对应脚本、样式。
- 删除 `save_config`、`get_auto_config`、`save_user_auto_config`、`save_auto` 等旧 WebSocket 配置动作。
- 删除旧的全局自动配置和提示词类型 WebSocket 管理动作。
- 删除 `upsertAutoConfig`、`saveUserAutoConfig`、`saveGlobalAutoConfig` 等直接写旧表的业务函数。
- 手动推理配置改用 `/api/ai/inference-preferences` REST 接口。
- 自动开关改为操作 `strategy_subscriptions`，再同步调度镜像，不再直接修改旧自动配置。

## 5. 暂时保留的兼容代码

以下内容仍有明确运行依赖，不能在同一版本直接物理删除：

- `auto_scheduler` 与 `user_bridge_settings`：当前 scheduler 和 Bridge 的运行态镜像。所有写入必须由订阅事务同步，禁止新增外部写入口。
- `global_auto_config`：仍承载管理员全局调度与部分硬风控参数，后续应按“调度参数”和“平台风控”拆表迁移。
- `ai_configs`：仅用于旧凭据迁移、清理和历史迁移脚本；正常手动推理不再读取。待线上数据确认全部迁移后，再通过独立迁移删除。
- `auto_prompt_types`：当前调度器仍读取历史提示词策略。新策略完全接管并完成数据迁移前，不物理删除。

兼容边界：这些表可以被迁移器、订阅同步器和现有调度器读取或写入，但前端、公开 REST 接口和普通 WebSocket 命令不得直接写入。

## 6. 风控与模型边界

- 共享市场信号不包含用户账户余额、仓位、持仓或挂单，避免管理员账户状态污染其他用户。
- AI 负责给出建议手数，但建议值必须先限制在交易平台品种的最小/最大手数和步进内。
- 用户可配置下单价格最大偏差和更严格的手数上限；管理员配置平台硬上限。
- 最终下单手数不能大于 AI 建议手数、用户上限、平台上限及账户风险预算中的最小值。
- 持仓、挂单、净敞口、频率、日损、价格偏差和交易时段全部由确定性风控校验，AI 无权绕过。
- 所有自动与手动订单最终都必须经过 `executeOrderCore`，不得从 scheduler 或 Bridge 旁路下单。

## 7. 后续结构拆分顺序

### 阶段 A：调度器内部解耦

在不改变行为的前提下，将 `runUnifiedAutoCycle` 拆为市场快照、模型推理、信号落库、用户投递和订单执行五个小单元。每个单元使用显式输入输出，禁止隐式读取用户全局状态。

### 阶段 B：Bridge 命令分发解耦

将 Python `BridgeWorker._process_command` 按账户查询、行情、订单、历史和系统控制拆为独立 handler；命令路由只负责协议校验和分发。该阶段必须同时验证源码运行和打包版本。

### 阶段 C：兼容表退役

先增加迁移完成率与读写审计，确认没有旧版本客户端和未迁移凭据，再按顺序停止读取 `ai_configs`、迁移 `auto_prompt_types`、替换调度镜像，最后执行物理删表。不得仅凭代码搜索直接删库表。

## 8. 发布验收

- 数据迁移可重复启动且失败会阻止迁移版本标记完成。
- 普通用户无法读取或修改其他用户的模型、策略、订阅和推理偏好。
- 管理员能看到策略所属用户，但不能让共享推理携带管理员账户状态。
- 用户没有模型时，仅在平台共享开启且配额允许时使用管理员模型。
- 订阅新增、修改、删除，策略删除和账户拒绝后，调度镜像立即同步。
- 手动与自动订单均经过同一订单意图和风控网关。
- 全量测试通过；`npm run dev` 启动无 `[FATAL]`；健康检查数据库与 Redis 正常。
