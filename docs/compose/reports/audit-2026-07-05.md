## CRITICAL — 必须修复

### 1. 路径穿越漏洞 `video.js:160`
`GET /video-file/:filename` 直接将 `req.params.filename` 传入 `path.join(uploadDir, filename)`，无 `..` 过滤。攻击者可通过 `../../etc/passwd` 读取服务器任意文件。
**修复**: 添加 `path.resolve()` 容器检查：
```js
const resolved = path.resolve(filePath)
if (!resolved.startsWith(path.resolve(uploadDir))) return res.status(403)
```

### 2. 存储型 XSS — 帖子内容
`public/src/main.js` 中帖子 `contentHtml` 通过 `innerHTML` 直接注入 DOM，未经过滤。任意认证用户可在帖子中注入恶意脚本。
**修复**: 前端使用 DOMPurify 过滤 `contentHtml`，或后端在存储时过滤。

### 3. `user_notices` 和 `broadcast_messages` 两张表从未使用
`db.js:363` 和 `db.js:583` 创建了两张表，但整个代码库中无任何 SELECT/INSERT/UPDATE/DELETE。是死代码，增加 schema 混乱。
**修复**: 新建迁移删除这两张表。

## HIGH — 应尽快修复

### 4. 错误信息泄露内部细节
以下端点向客户端暴露 MySQL 错误信息：
- `admin.js:258-261` — `err.sqlMessage` (PUT /admin-users)
- `admin.js:296` — `err.sqlMessage` (DELETE /admin-users/:id)
- `config.js` 多处 — `err.message` (所有配置 CRUD)
- `auth.js:364` — `err.message` (send-code 公开端点)

**修复**: 用固定字符串替代，内部 log 详情。

### 5. 管理员端点缺少输入校验
`admin.js:215-262` PUT/POST /admin-users 接受任意 `plan`、`role` 值，无白名单校验。
**修复**: 校验 `plan ∈ {free, plus, pro}`、`role ∈ {user, admin}`。

### 6. `bridge_connection_status.user_id` BIGINT vs `users.id` INT
Migration 016 用 BIGINT，其余所有表用 INT。隐式转换可工作，但浪费内存且妨碍未来外键约束。
**修复**: 迁移中 ALTER 为 INT。

### 7. 数据库缺失关键索引
以下列被频繁用于 WHERE/JOIN 但无索引：
- `comments(episode_id)` — 每次课程加载
- `post_replies(post_id)` — 每次帖子详情
- `quiz_questions(episode_id)` — 每次测验加载
- `course_resources(episode_id)` — 每次资源加载
- `verification_codes(phone)` — 验证码查询（已有 email UNIQUE 但 phone 无）

**修复**: 添加迁移创建索引。

### 8. 重复索引 `auto_scheduler`
`idx_auto_scheduler_prompt_enabled(prompt_type_id, enabled)` 和 `idx_auto_scheduler_enabled_prompt(enabled, prompt_type_id)` 互为反转，功能重复。
**修复**: 删除其中一个。
