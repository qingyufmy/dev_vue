# 项目全面审查与分阶段整改报告

日期：2026-07-24<br>
项目：`wall-street-skill-local`<br>
结论：高风险代码问题已完成分阶段整改，通过全量自动化回归、当前环境真实 MySQL 迁移、数据库结构核验和运行健康检查；仍需反向代理、浏览器、桌面桥接和链上小额支付验证后才能签署生产可用结论。

## 1. 审查范围

本轮沿以下主链路检查功能、代码与数据语义：

- 注册、验证码、登录、改密、重置密码、JWT、HTTP 与 WebSocket 会话；
- 社区帖子、回复、评论、富文本及用户隐私；
- USDT 订单创建、推荐金抵扣、取消、过期、确认及会员激活；
- 后台订单收入、返佣汇总和用户端奖励展示；
- 课程视频和附件访问控制；
- 服务启动、后台任务、迁移、HTTP 超时和安全响应头；
- 依赖版本、漏洞、调试输出、临时文件、孤立源码和历史注释。

审查方法包括入口调用图、SQL 与 API 字段追踪、权限边界复核、语法检查、定向测试、全量测试、Python 桥接测试和 npm 生产依赖审计。

## 2. 已修复问题

### 2.1 支付与推荐金一致性

- 新增订单级 `referral_credit_applied` 台账，创建订单时锁定用户余额并持久化实际抵扣额；
- 取消或过期只退回该订单真实使用的推荐金，避免重复计算、错退或并发超扣；
- 支付确认适配真实 MySQL 事务返回的 `[result, fields]` 与 `affectedRows` 语义；
- 统一月付、年付周期映射和 DECIMAL 数值转换。

### 2.2 注册、会话和全设备退出

- 邮箱注册必须提交已核验且未使用的验证令牌；
- 用户新增 `token_version`，HTTP 鉴权、可选鉴权、在线心跳、普通浏览器 WebSocket、桥接 WebSocket 和管理 WebSocket 均校验版本；
- 修改密码、重置密码和“退出所有设备”会递增版本、撤销桥接刷新会话并主动断开现有套接字；
- 旧令牌仅在用户版本仍为 `0` 时兼容，迁移后不会无条件强制所有用户退出。

### 2.3 社区隐私和富文本安全

- 帖子、回复和课程评论响应不再返回用户邮箱；
- 前端编辑/删除归属判断改为稳定的用户 ID；
- 服务端由正则替换升级为 `sanitize-html` 解析型白名单，并在写入和读取历史内容时净化；
- 浏览器端增加 DOMParser 白名单作为第二道防线；
- 阻断脚本、SVG、MathML、事件属性、编码后的 `javascript:` URL、危险协议和任意 data 属性；新窗口链接自动加 `noopener noreferrer`。

### 2.4 金额与返佣语义

- 当前订单与返佣存储值的实际单位是美元金额，不是美分；后台此前再次除以 100，导致显示缩小 100 倍；
- 后台 API 改为 `amount`、`confirmed_amount`、`revenue`、`commission_amount` 等单位明确的字段；
- 用户端 `pending_credit` 改为汇总 `commission`，不再错误汇总来源订单金额；
- 后台待确认返佣改为真实 `SUM(commission)`，删除“待审核数量 × 500”的伪金额计算；
- 账户中心不再把美元奖励再次除以 100。

迁移 138 已把 `referrals.amount_cents` 在线改名为 `cash_amount`，并将用户奖励、订单金额、已确认金额、订单抵扣、返佣来源金额和返佣金额统一为 `DECIMAL(20,8)`；返佣记录新增唯一 `order_id`，后台不再事后猜测来源订单。

### 2.5 视频、启动和基础设施

- 私有视频改为短期签名访问地址，静态 `/uploads/videos` 直出被阻断；
- 服务只有在数据库、迁移和治理结构初始化成功后才监听端口；端口冲突和未捕获异常会失败退出，不再留下半启动后台任务；
- HTTP `headersTimeout` 为 15 秒、`requestTimeout` 为 120 秒，不再允许请求无限占用连接；
- 数据库迁移使用独占连接持有 MySQL 命名锁，多实例并发启动时只允许一个实例执行 DDL；
- MySQL 命名锁修复为恰好不超过 64 字符；连接池下限为 2，避免单连接池被命名锁占满后启动死锁；
- 增加 CSP、同源嵌入、MIME、防引用泄露、权限策略、COOP 和 HTTPS 条件 HSTS；移除 `unsafe-eval`。

### 2.6 上传、会员日期与支付后置任务

- 帖子图片改为内存接收后检查 JPEG、PNG、GIF、WebP 文件签名，不再相信客户端 MIME 或原始扩展名；保存名使用随机值和服务端固定扩展名；
- `/uploads` 响应增加 `sandbox` CSP、同源资源策略和 `nosniff`，实际静态图片 HEAD 请求已验证响应头；
- 所有公开上传路径统一由绝对 `PUBLIC_UPLOAD_DIR` 解析，默认仍是 `server/uploads`，绝对路径覆盖也不会让帖子、视频、封面和课程资源写入不同目录；
- 会员期限按 `Asia/Shanghai` 日历计算，修复 Date/ISO 输入偏移 8 小时及 1 月 31 日加月滚入 3 月等月末问题；目标月份不存在的日期会钳制到月末；
- 支付确认先在事务内锁定用户，再完成会员激活；通知和返佣改为 `payment_side_effects` 持久队列，进程中断后可重试，订单级去重避免重复通知和重复返佣。

### 2.7 验证码与会话原子性

- 注册、验证码登录、密码重置、修改密码、邮箱/手机更换和账号绑定均以条件更新或 `FOR UPDATE` 锁定一次性验证码；并发请求只有一个可以成功消费；
- 密码或账号更新、JWT 版本递增、桥接刷新会话吊销和验证码消费在同一 MySQL 事务中提交或回滚；
- WebSocket 断开只在数据库事务提交后触发，避免数据库失败但客户端已被踢下线；
- 后台重置用户密码也复用同一事务边界。

### 2.8 依赖、日志和无用文件

- 新增并锁定 `sanitize-html@2.17.6`；
- 升级 `express-rate-limit`、`mysql2`、`ws`、`vitest` 和直接依赖 `uuid`；
- 使用 npm override 将所有传递依赖的 `ws` 统一到 `8.21.1`，并把 `body-parser` 固定到已修复的 `1.20.6`；
- npm 审计从 1 高危、5 中危、1 低危降为 0 高危、3 中危、0 低危；
- 高频 LLM 和 WebSocket 握手诊断日志改由 `DEBUG_LLM`、`DEBUG_LLM_PAYLOAD`、`DEBUG_BRIDGE_WS` 显式开启；
- 删除受版本控制的 `test_output.txt`、`test_stderr.txt`，以及根目录调试脚本、Mimo 数据库查询脚本和误生成的 pnpm 锁/工作区文件；增加精确忽略规则；
- 明确只使用 npm，写入 `packageManager`，并声明 `sanitize-html@2.17.6` 所需的 Node `>=22.12.0`；
- Vitest 强制 `NODE_ENV=test` 和专用测试 JWT 密钥，不再读取真实 `server/.env`、真实 Redis 或其他生产配置；
- `depcheck` 未发现未使用或缺失依赖；服务端 104 个模块未发现孤立源码；
- Bridge 启动不再静态导入重量级 AI scheduler/config，通过轻量状态注册表和常量模块降低初始化顺序耦合；
- 删除不再被生产入口引用、最近提交也已标记退出的历史模型基准模块及其专属测试；迁移历史保留。

## 4. 尚未关闭的风险

### 4.1 必须在生产前验证

1. 当前环境已经执行到迁移 139；上线前仍需在生产同版本 MySQL 备份副本上重放 136—139，记录 DDL 耗时、锁等待和备份恢复时间；
2. 使用真实 MySQL 事务回放一笔低价值 TRC-20 订单，覆盖创建、推荐金抵扣、链上确认、会员激活和重复回调；
3. 回放取消与超时路径，核对推荐金只退一次且数值精确；
4. 通过实际反向代理验证 HTTPS/HSTS、CSP、WebSocket upgrade 和 120 秒请求边界；
5. 用桌面桥接程序验证改密和全设备退出后 HTTP、浏览器 WS、管理 WS、桥接刷新令牌全部失效；
6. 浏览器人工检查后台订单、累计收入、今日收入、返佣和账户中心金额；
7. 检查私有视频无令牌、过期令牌、越权会员和合法会员四种访问结果。

### 4.2 已知技术债

- CSP 仍包含 `unsafe-inline`，因为多个 HTML 页面还有内联启动脚本、样式和事件；后续应迁移到外部脚本或 nonce/hash，再移除该权限；
- npm 剩余 3 个中危来自同一条 `@solana/web3.js@1.98.4 → jayson@4.3.0 → uuid@8.3.2` 链。当前业务只使用 UUID v4 路径，而公告影响 v3/v5/v6 的 buffer 参数；不应采用 npm 建议的异常降级。应等待 Solana SDK 上游修复或单独评估 SDK 主版本迁移；
- `madge` 仍能看到由按需 `import()` 形成的 Bridge ↔ AI 路由、Bridge ↔ 周末清仓和行情 ↔ 平台行情闭环；关键静态 scheduler/config 环已拆除，剩余按需环当前可运行，但后续仍应把 Bridge 命令端口抽成独立基础模块；
- `sanitize-html@2.17.6` 的依赖链要求 Node `>=22.12.0`；部署环境必须跟随 `package.json#engines`，不能继续使用旧文档中的 Node 18/20；
- 本轮连接的是当前开发环境真实 MySQL/Redis，不是生产数据库；没有验证真实 SMTP/SMS、真实反向代理或真实链上资金，因此自动化和本机健康检查不等于生产签字；
- 当前工作树原本已有大量用户改动和未跟踪源码，本轮没有自动提交或推送，以免把不同范围的工作混进一个提交。
