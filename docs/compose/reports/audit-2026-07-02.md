## HIGH (8 项)

### HIGH #1: `verification_codes.email` NOT NULL 与 SMS 插入冲突
- **文件**: `server/db.js:313` vs `server/sms.js:89`
- **问题**: `verification_codes` 表 `email VARCHAR(255) NOT NULL` 无 DEFAULT。`sms.js:89` 插入时只传 `(phone, code, purpose, expires_at)`，不含 email。MySQL strict mode 下报 `Field 'email' doesn't have a default value`，手机验证码发送失败。
- **修复**: 迁移将 `email` 改为 `DEFAULT NULL`。

### HIGH #2: `cacheDel` 函数缺失
- **文件**: `server/redis.js`
- **问题**: AGENTS.md 文档声称导出 `cacheDel`，但实际不存在。全项目 grep 0 结果。需要缓存失效时无法实现。
- **修复**: 添加 `export async function cacheDel(key) { ... }`。

### HIGH #3: `admin.js` INSERT 包含已删除的 `answer` 列
- **文件**: `server/routes/admin.js:582,667,726,741`
- **问题**: 迁移 023 已 `DROP COLUMN answer`（quiz_questions 表），但 admin.js 的 4 处 INSERT/UPDATE 语句仍包含 `answer` 列。新数据库上运行会报列不存在错误。
- **修复**: 从 INSERT/UPDATE 语句中移除 `answer` 列。

### HIGH #4: bridge-ws.js (2000+ 行) 零测试
- **文件**: `server/bridge-ws.js`
- **问题**: 核心 WebSocket 桥接模块，2000+ 行，0 测试。包含消息路由、命令队列、桥接状态管理等关键逻辑。
- **修复**: 至少为核心消息处理函数编写单元测试。

### HIGH #5: middleware/auth.js 零测试
- **文件**: `server/middleware/auth.js`
- **问题**: JWT 认证中间件，安全基础设施无测试。
- **修复**: 编写认证中间件单元测试。

### HIGH #6: Bilibili API fetch 重复 4 次
- **文件**: `server/index.js:146`, `server/routes/admin.js:460`, `server/routes/video.js:237`, `server/routes/courses.js:103`
- **问题**: 4 处完全相同的 `fetch(bilibiliApiUrl, { headers: {...} })` 调用。
- **修复**: 提取为共享 helper。

### HIGH #7: `.env` 双重加载可能覆盖
- **文件**: `server/config.js:7` vs `server/index.js:38-48`
- **问题**: dotenv 先加载，然后 `index.js` 用 `readFileSync` 手动解析同一文件并 `process.env[key] = val` 无条件覆盖。对含 `=` 的值处理可能不同。
- **修复**: 删除 `index.js:38-48` 的手动解析。

### HIGH #8: `.env` 文件存在于文件系统
- **文件**: `server/.env`
- **问题**: `.env` 文件存在。虽然 `.gitignore` 应忽略它，但需确认未被提交到 git。如果包含生产密钥，泄露风险极高。
- **修复**: 运行 `git ls-files server/.env` 确认未被追踪。如已提交需从 git 历史中清除。

## MEDIUM (18 项)

### MEDIUM #1: `err.message` 泄露到支付 API 响应
- **文件**: `server/routes/payment.js:85,406,417,428,439,483`
- **问题**: 6 处返回 `err.message` 给客户端，可能泄露 DB 错误、文件路径等内部信息。
- **修复**: 替换为通用中文错误提示。

### MEDIUM #2: 密码策略过弱
- **文件**: `server/routes/auth.js:91,139`
- **问题**: 最低 6 字符，无复杂度要求。金融交易平台应更强。
- **修复**: 提升为 8 字符 + 至少包含数字和字母。

### MEDIUM #3: 验证码暴力破解风险
- **文件**: `server/routes/auth.js:383-393`
- **问题**: 6 位验证码，无 per-code 失败计数。authLimiter 20 次/15min 提供有限保护。
- **修复**: 添加 per-code 失败计数，5 次后锁定。

### MEDIUM #4: SSE 端点无认证无限流
- **文件**: `server/routes/video.js:352-357`
- **问题**: `/stream` SSE 端点无 auth 无 rate limit，可被大量连接消耗资源（DoS 向量）。
- **修复**: 添加连接数限制或认证。

### MEDIUM #5: 无 Content-Security-Policy 头
- **文件**: `server/index.js`
- **问题**: 未设置 CSP 头。成功 XSS 注入将有完全能力（内联脚本、外部脚本等）。
- **修复**: 添加适当的 CSP 头。

### MEDIUM #6: 注册自动赠送 Pro 会员
- **文件**: `server/routes/auth.js:115-116,155-157`
- **问题**: 新用户自动获得 1 个月 Pro 会员。可被滥用获取免费 Pro 访问。
- **修复**: 业务决策 — 确认是否为预期行为。

### MEDIUM #7: Bridge 下载 URL 硬编码版本号
- **文件**: `server/routes/ai/index.js:34-35`
- **问题**: `'https://qiniu.acadfx.com/AURUM_Bridge_v2.2.0.exe'` 版本号硬编码。
- **修复**: 从 system_config 动态获取。

### MEDIUM #8: `DEFAULT_API_BASE_URL` 定义在 4 处
- **文件**: `server/config.js:16`, `server/db.js:547,599`, `server/migrations.js:86`
- **问题**: `'https://api.deepseek.com'` 硬编码 4 处。修改需改 4 个文件。
- **修复**: 代码引用统一用 config.js 导出常量。

### MEDIUM #9: `calculatePlanExpiry` 重复实现有功能偏差
- **文件**: `server/crypto/monitor.js:120-130` vs `server/routes/payment.js:226`
- **问题**: monitor.js 用 `setFullYear/setMonth`（日历感知），payment.js 用毫秒加法（跨月边界可能出错）。同一逻辑两种实现，行为不同。
- **修复**: 统一使用 monitor.js 的日历感知版本。

### MEDIUM #10: 推荐返佣逻辑重复
- **文件**: `server/crypto/monitor.js:92-114` vs `server/routes/payment.js:236-258`
- **问题**: 相同的推荐查询、佣金计算、UPDATE referrals、INSERT notifications 代码块重复。
- **修复**: 提取为共享函数。

### MEDIUM #11: `auto_scheduler.symbols` 死列
- **文件**: `server/db.js:511`
- **问题**: `symbols VARCHAR(1000)` 只在 INSERT/UPDATE 时写入，从未 SELECT。统一调度器用 `auto_prompt_types.symbols_json`。
- **修复**: 迁移 DROP COLUMN。

### MEDIUM #12: `global_auto_config.symbols` 和 `system_prompt` 死列
- **文件**: `server/db.js:542,554`
- **问题**: 这两列在 CREATE TABLE 中定义，但除 db.js 外无任何 SQL 引用。统一调度器已迁移到 `auto_prompt_types`。
- **修复**: 迁移 DROP COLUMN。

### MEDIUM #13: `notifications` 表 CREATE TABLE 仍定义已删除的 `` `read` `` 列
- **文件**: `server/db.js:307`
- **问题**: 迁移 023 已 DROP `` `read` `` 列，但 CREATE TABLE 仍定义 `` `read` TINYINT DEFAULT 0 ``。新库会创建该列再删除，浪费迁移时间。
- **修复**: 从 CREATE TABLE 中删除 `` `read` `` 列。

### MEDIUM #14: `quiz_questions` CREATE TABLE 仍定义已删除的 `answer` 列
- **文件**: `server/db.js:327`
- **问题**: 迁移 023 已 DROP `answer`，但 CREATE TABLE 仍定义。且 admin.js 的 INSERT 仍引用该列（HIGH #3）。
- **修复**: 从 CREATE TABLE 和 admin.js INSERT 中删除 `answer` 列。

### MEDIUM #15: `notifications` 的 `actor_id` 列从未使用
- **文件**: `server/db.js:299`
- **问题**: `actor_id INT` 在 CREATE TABLE 中定义，但 INSERT 语句均不包含该列（只传 user_id, type, title, message）。
- **修复**: 确认是否需要，如不需要则迁移 DROP。

### MEDIUM #16: `notifications` 的 `post_id` 和 `meta` 列未在 SELECT 中使用
- **文件**: `server/db.js:304-305`
- **问题**: `post_id` 只在 INSERT 时写入，从未在 SELECT 中读取。`meta` 同样只写不读。
- **修复**: 确认前端是否需要，如不需要则标记为待清理。

### MEDIUM #17: `ai_configs.auto_config_override` / `auto_symbols` / `auto_interval_minutes` 功能已废弃
- **文件**: `server/db.js:428-429`（CREATE TABLE 中未定义这些列，但 migration 005 添加了它们）
- **问题**: 这些列是旧"应用当前配置给自动推理"功能的遗留。该功能已移除（AGENTS.md 记录），但列仍存在于旧数据库中。bridge-ws.js 仍在 INSERT/UPDATE 中引用它们。
- **修复**: 清理 bridge-ws.js 中对这些列的引用。

### MEDIUM #18: `.gitignore` 缺少 `*.pem`/`*.key` 模式
- **文件**: `.gitignore`
- **问题**: 无 SSL 证书/密钥文件忽略规则。
- **修复**: 添加 `*.pem`、`*.key`。
