# 模型保存时验证流式响应能力方案

- 日期：2026-08-24
- 状态：已实施，待虚拟机部署与真实链路验收
- 范围：模型配置保存、重新验证、能力持久化、模型管理前端展示
- 不包含：本次不修改业务代码、不部署、不重试复盘任务、不调整 Cloudflare 配置

## 1. 背景与问题

2026-08-21 日复盘在主请求阶段约 126 秒收到 HTTP 524。模型后台显示请求完成，只能证明上游模型最终完成，不能证明调用方在 Cloudflare 等待窗口内收到首字节。当前目标模型使用自定义 OpenAI-compatible 地址，能力记录为 `supports_stream=false`、`verification_status=unverified`，因此运行时走非流式请求，必须等完整响应体返回。

现有实现有四个缺口：

1. 保存模型时只发送一次非流式 JSON 连通性请求，没有验证 SSE 流式响应。
2. `saveModelProfileWithValidation` 调用验证器后丢弃验证结果，没有将传输能力与模型配置原子保存。
3. 能力表已有 `supports_stream`、验证状态和验证时间等字段，但模型管理 API 没有完整返回这些安全字段。
4. 前端只有“连接正常”和 Token 能力状态，用户无法判断模型是否适合日复盘、月复盘等长响应任务。

## 2. 目标

1. 每次新增或保存模型时，由服务端实际验证连接和流式响应能力。
2. 只把可证明的结果写入能力表，并绑定到准确的模型传输身份。
3. 前端明确展示“已验证支持 / 已验证不支持 / 尚未验证”三种状态。
4. 已验证支持流式后，现有运行时自动使用 SSE，使长响应能够持续产生首字节和活动数据。
5. 验证失败时不破坏已有可用模型配置，也不把临时故障误判为“不支持流式”。

## 3. 核心决策

### 3.1 流式能力不是必选项

不要求所有模型必须支持流式才能保存。连接正常但确认不支持流式的模型可以保存，前端显示风险提示；日复盘、月复盘等长任务绑定该模型时给出明确警告。本批次不全局禁止非流式模型，避免影响短任务或合法的非流式供应商。

### 3.2 能力必须由服务端实测

前端不得提交或覆盖 `supports_stream`。验证请求、结果分类和能力写入全部由服务端控制，防止客户端伪造能力或把“接受 `stream=true` 参数”误当作真正的流式传输。

### 3.3 必须区分“不支持”和“无法确认”

| 状态 | 判定 | 保存行为 |
| --- | --- | --- |
| `supported` | 收到有效 SSE，并在终止事件前收到有意义的增量内容 | 保存模型并记录 `supports_stream=true` |
| `unsupported` | 连接验证通过，且供应商明确拒绝流式参数，或忽略流式并返回完整的普通 JSON | 保存模型并记录 `supports_stream=false`，前端警告 |
| `unverified` | 超时、524、网络错误、429、5xx、畸形 SSE、结果矛盾或无法可靠分类 | 新建时不保存；编辑时保留原配置和原能力，不写入 `false` |

### 3.4 验证结果绑定准确身份

传输能力至少绑定以下身份：

- provider
- model
- normalized base URL
- protocol

其中任一项变化，都不得复用旧的流式验证结论。API Key 变化不改变传输身份，但每次保存仍重新验证连接和流式能力，并刷新验证时间。

## 4. 后端设计

### 4.1 新增服务端流式探测器

在 LLM 服务层增加仅供服务端调用的 transport probe，复用现有 Chat Completions 和 Responses SSE 解析能力，不向前端开放 `forceStream` 一类参数。

保存验证按以下顺序执行：

1. 发送最小非流式 JSON 请求，验证地址、凭证、模型名和基本响应格式。
2. 非流式验证成功后，发送由服务端构造的最小流式请求：`stream=true`、低输出上限、关闭或降低思考、禁止后续补请求。
3. 记录首个响应字节、首个有效增量、终止事件、总耗时、事件数量和安全错误分类。
4. 按三态规则分类，不保存提示词、响应正文、API Key 或上游原始错误体。

“支持流式”的最低证据：

- HTTP 请求成功；
- 响应是可解析的 SSE；
- 在终止事件前出现至少一个有意义的内容增量；
- 最终存在合法终止；
- 首个有效增量在探测预算内到达。

建议初始探测预算：首个有效增量不超过 30 秒、总时长不超过 60 秒，并限制最大字节数、事件数和输出 Token。预算应为服务端常量或受控配置，不能由浏览器任意放大。

### 4.2 修正保存服务的验证结果合同

`saveModelProfileWithValidation` 不再丢弃 `verify` 返回值。验证器返回结构化结果，保存服务在同一事务内写入模型配置和能力记录：

```json
{
  "connection": {
    "status": "passed",
    "latency_ms": 420
  },
  "streaming": {
    "status": "supported",
    "first_byte_ms": 510,
    "first_delta_ms": 680,
    "total_latency_ms": 1930,
    "event_count": 8,
    "source": "save_probe"
  }
}
```

事务要求：

- 新建：任一必需连接验证失败时，不产生模型或能力记录。
- 编辑：先完成全部探测，再校验乐观锁和传输身份；失败或冲突时保留旧模型及旧能力。
- 成功：模型配置、传输身份、`supports_stream`、`verification_status`、验证人和验证时间一起提交。
- 不确定：不得把既有 `true` 或 `false` 覆盖成错误结论。

现有能力表已包含所需字段，本方案默认不新增迁移。探测指标写入安全审计日志，不为一次展示扩张数据库结构。

### 4.3 API 返回安全的传输能力

模型配置的脱敏返回增加：

```json
{
  "transport_capabilities": {
    "streaming": {
      "status": "supported",
      "verified_at_utc_msc": 1787540000000,
      "source": "save_probe"
    }
  }
}
```

可由现有字段推导三态：

- `verification_status !== verified`：`unverified`
- `verification_status === verified && supports_stream === true`：`supported`
- `verification_status === verified && supports_stream === false`：`unsupported`

API 不返回 API Key、探测响应正文、原始错误体或提示词。若需要排障，只返回稳定的错误码和可公开的短说明。

### 4.4 “测试连接”升级为“重新验证”

独立测试接口复用同一套连接和流式探测器，并在模型传输身份未变化、乐观锁仍成立时刷新能力记录。前端操作名称改为“重新验证”，完成后重新加载模型列表。

如果验证期间模型被其他请求修改，返回冲突，不得把旧地址的探测结果写到新配置上。

### 4.5 运行时接入

运行时继续遵循已存在的规则：仅当持久化能力为“已验证支持”时使用 SSE；未验证或已验证不支持时走非流式。无需在复盘业务中写供应商特例。

这能让日复盘请求在模型生成期间持续收到数据，但前提是模型网关和 Cloudflare 链路确实透传、且不缓冲 SSE。探测器因此必须验证“增量及时到达”，不能只验证响应头或参数被接受。

## 5. 前端设计

### 5.1 模型卡片

模型卡片增加“流式响应”状态，使用文本和图标共同表达，不只依赖颜色：

- 已验证支持
- 已验证不支持
- 尚未验证

详情区显示最近验证时间和来源；连接状态与流式能力分开，不能用“运行中”代替“支持流式”。

### 5.2 保存交互

- 按钮等待文案：`正在验证连接与流式能力…`
- 支持时：`模型已保存 · 流式响应已验证`
- 不支持时：`模型已保存 · 已验证为非流式；长响应可能超时`
- 无法确认时：不关闭编辑框，展示稳定错误说明；编辑已有模型时明确告知旧配置未被覆盖。

验证结果需要进入可访问的 live region，移动端不能因状态字段增加而挤压操作按钮。

### 5.3 长任务绑定提示

在日复盘、月复盘等长响应用途旁显示所选模型的流式状态：

- 已验证支持：正常展示。
- 已验证不支持：提示“长响应可能在代理等待窗口内超时”。
- 尚未验证：提示先到模型管理执行重新验证。

本批次只警告、不禁止绑定，也不自动替换用户已选择的模型。

## 6. 观测与安全

安全审计事件记录：模型配置 ID、传输身份摘要、连接结果、流式三态、首字节/首增量/总耗时、事件数和稳定错误码。

禁止记录：API Key、Authorization 头、完整 URL 查询参数、请求提示词、模型输出、上游原始响应体。

429、5xx、524 和网络超时属于临时或链路故障，不得据此永久判定供应商不支持流式。

## 7. 实施批次

### 批次 A：探测器与分类

- 实现 Chat Completions 和 Responses 两种协议的最小流式探测。
- 复用并加强 SSE 限制、终止判断和错误归类。
- 增加首增量指标及审计字段。

### 批次 B：原子持久化与 API 合同

- 让保存服务消费结构化验证结果。
- 原子写入模型配置及传输能力。
- 增加身份/并发保护和脱敏返回字段。
- 将独立测试接口升级为重新验证。

### 批次 C：模型管理前端

- 模型卡片和用途绑定展示三态。
- 更新保存、重新验证的进度、成功、警告和失败文案。
- 同步前端构建标识和静态资源缓存键。

### 批次 D：发布后验证

- 另行获得发布授权后部署到虚拟机。
- 在真实 Cloudflare 路径重新保存目标模型，确认显示“已验证支持”。
- 另行获得重试授权后重试一条复盘，核对 SSE 首增量、无 524、复盘完成和无重复版本。

## 8. 测试矩阵

1. Chat Completions 有效 SSE：判定支持并持久化。
2. Responses 有效 SSE：判定支持并持久化。
3. 有早期增量且有合法终止：记录首增量和事件数。
4. 接受 `stream=true` 但返回完整 JSON：判定不支持，不误报支持。
5. 明确拒绝流式参数但非流式连接通过：允许保存为已验证不支持。
6. 401、403、404、429、5xx、524、网络超时、畸形 SSE：不保存新配置，不覆盖旧配置，不写入 `false`。
7. provider、model、base URL 或 protocol 变化：旧能力失效。
8. 并发修改：旧探测结果无法覆盖新身份。
9. 模型配置与能力记录在同一事务成功或回滚。
10. 重新验证只更新身份未变化的模型，完成后前端刷新。
11. 脱敏 API 包含三态、时间和来源，不泄露密钥或正文。
12. 运行时仅对已验证支持的模型启用 SSE。
13. 历史模型无验证证据时展示“尚未验证”。
14. 前端三态、提示文案、可访问性和移动端布局均有回归覆盖。
15. 前端构建标识、缓存键和 HTML 引用保持一致。
16. 发布后通过真实网关验证长响应能在代理超时前持续收到增量。

## 9. 验收标准

1. 保存模型必定执行连接和流式能力验证，前端不能自行声明结果。
2. 流式支持只有在真实增量及时到达时才能标记为已验证支持。
3. 临时故障不会变成永久“不支持”，编辑失败不会损坏旧配置。
4. 能力结论与准确的 provider/model/base URL/protocol 身份绑定，并与模型原子保存。
5. 前端在模型卡片和长任务用途处清晰展示三态及风险。
6. 已验证支持后，运行时自动走现有 SSE 路径，无复盘供应商特例。
7. 目标虚拟机真实链路验证后，长响应在 125 秒前持续产生可见上游活动，不再复现同类 524。

## 10. 第一轮复审：正确性与安全

### 发现

初稿若把任意流式探测失败都保存为 `supports_stream=false`，会将 429、524、网络波动和上游故障误判为永久不支持；若先写模型再探测，也会在编辑失败时破坏已有可用配置。

### 调整

- 明确增加 `unverified` 状态，仅在证据确凿时保存 `false`。
- 验证全部完成后再进入事务，并在事务中原子写入配置和能力。
- 增加传输身份与乐观锁复核，防止并发和身份错配。
- 禁止前端提交能力字段，审计日志只保留安全指标。

### 结论

方案满足失败关闭、旧配置保护、身份隔离和敏感信息保护要求。

## 11. 第二轮复审：体验、兼容性与运维

### 发现

仅验证 `stream=true` 被接受不能证明网关不缓冲；全局禁止非流式模型会破坏短任务兼容性；只在模型卡片显示状态，也不足以提醒复盘配置风险。

### 调整

- 支持判定要求终止前收到有意义的早期增量。
- 保留非流式模型，长任务用途采用明确警告而非硬阻断。
- 模型卡片、保存反馈和用途绑定三处统一展示状态。
- 发布验收必须经过真实 Cloudflare 路径，不能只用本地 mock 或直连供应商证明。

### 结论

方案兼顾现有模型兼容性、长任务可理解性和真实代理链路验证。

## 12. 剩余风险

- 小输出探测成功不能完全保证超长复盘在所有时段都持续透传。
- 支持 SSE 也不保证思考型模型能在 125 秒内产生第一个有效内容增量。
- 供应商或网关可能在验证后改变行为；本批次通过每次保存和手动重新验证刷新结论，自动过期策略暂缓。
- Cloudflare、反向代理或网关任一层缓冲，都可能让模型后台成功但调用方仍超时。
- 不同 OpenAI-compatible 实现的 SSE 事件格式存在差异，必须以严格且兼容的解析测试覆盖，不能通过宽松吞错误报支持。
- 若真实链路仍无法及时产生增量，需要另行评估绕开代理的 API 域名、DNS-only 路径或异步任务协议；这些不属于本批次。
