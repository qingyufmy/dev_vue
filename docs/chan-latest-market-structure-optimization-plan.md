# 缠论最新行情结构优先优化方案

## 1. 方案状态

- 文档状态：实施前正式方案。
- 编写日期：2026-08-27。
- 目标分支：`dev_codex`。
- 基线提交：`a2e97bd21943df4cc246d6aba1f5700626ef2dde`。
- 优先级：高。当前问题会让旧中枢和旧线段长期主导 H1 方向，导致最新反转结构无法进入策略确认链。
- 本文只定义算法、模型数据合同、策略衔接和验收标准；不授权修改、提交、推送、部署或历史数据回填。

## 2. 核心原则

缠论计算必须使用足够的历史 K 线构造包含关系、分型、笔、线段和中枢；但是：

> 历史 K 线是计算上下文，历史判断不是当前结论。

最终交给模型的当前判断只能来自“截至本轮最后一根已闭合 K 线的最新活动结构链”。已经脱离活动结构链的旧线段、旧中枢和旧突破结论只能用于审计、回放和解释结构来源，不能继续覆盖最新分型、最新笔和当前候选线段。

本次不采用“超过固定根数自动过期”。不同周期、不同波动环境的结构持续时间差异很大，固定时效会制造新的误判。结构是否退役必须由后续结构关系决定。

## 3. 已确认的问题

以本地 MT5 的 `XAUUSD.s` H1 行情做闭合 K 线因果回放：

1. 2026-08-19 红框区域：
   - 系统能确认底分型和结束于 4327.25 的向下笔；
   - 随后能看到形成中的向上笔；
   - 但没有明确输出“最新局部结构已经转为向上观察”，也没有买点候选。
2. 2026-08-25 箭头区域：
   - 系统能确认 4696.65 顶分型；
   - 能确认向上笔结束，并看到形成中的向下笔；
   - 后续 4696.65→4620.16 的向下笔已经确认，系统仍输出 `upward_breakout`、`reversal_bias=none`、`entry_candidates=[]`。
3. 当前确认线段仍停留在 8 月 14–17 日；形成中的向下线段仍从 4428.85 指向 4327.25，但其观察范围内已经出现 4696.65 的更高价格。
4. 当前趋势归约器优先返回旧中枢的历史突破方向，只有无法从中枢得出结论时才考虑形成中的反向线段。因此最新反转证据被旧判断遮蔽。
5. 模型载荷没有明确的“最新已确认分型”对象，只能从 `current_bi` 和 `developing_bi` 间接理解，容易造成模型对分型状态、方向和确认时间理解不一致。

## 4. 目标与非目标

### 4.1 目标

1. 每轮计算结果明确回答“最新行情现在处于什么结构状态”。
2. 旧结构不得覆盖已经出现的最新反向分型、反向笔或活动候选线段。
3. 宏观背景和最新局部方向分离输出，禁止压缩成一个相互矛盾的方向字段。
4. 系统提供已经计算好的客观缠论结构，模型不重新计算分型、笔、线段、中枢或背驰。
5. 顶/底分型能够及时进入 M15/M5 确认路径，但分型本身不直接升级为下单许可。
6. 保持闭合 K 线、非重绘、包含关系、笔间距、线段确认和数据完整性门禁。

### 4.2 非目标

- 不把“顶分型”直接等同于做空订单。
- 不把“底分型”直接等同于做多订单。
- 不删除历史 K 线或缩短到只看最近几根。
- 不让模型使用公式重新计算系统已经提供的结构。
- 不在服务端增加针对某一策略的强制开仓或拦截规则。
- 不在本批次修改谐波、裸 K、EMA34、通用交易输出合同或仓位风控。

## 5. 新的结构分层合同

### 5.1 历史拓扑层

保留完整目标窗口，用于稳定计算：

- 包含关系处理；
- 已确认分型和笔；
- 线段特征序列；
- 中枢、背驰和三类买卖点；
- 跨窗口一致性和结构锚点。

该层可以保留旧结构，但不得直接生成本轮交易方向。完整结果继续进入内部市场快照，供审计和复盘使用。

### 5.2 当前活动结构层

新增一个由系统确定性生成的 `latest_structure`，只描述与最新闭合 K 线相连的结构：

```json
{
  "as_of_time_utc_msc": 0,
  "latest_confirmed_fractal": {
    "type": "top|bottom",
    "price": 0,
    "time_utc_msc": 0,
    "confirmed_at_utc_msc": 0
  },
  "latest_confirmed_bi": {
    "dir": "up|down",
    "start_price": 0,
    "end_price": 0
  },
  "developing_bi": {
    "dir": "up|down",
    "start_price": 0,
    "end_price": 0,
    "confirmed": false
  },
  "active_segment": {
    "dir": "up|down",
    "lifecycle_state": "forming|confirmed|invalidated",
    "connected_to_latest_bi": true
  },
  "local_state": "continuation|reversal_watch|reversal_confirmed|range|unavailable",
  "local_bias": "up|down|neutral",
  "background_bias": "up|down|neutral",
  "basis": []
}
```

约束：

- `latest_confirmed_fractal` 必须由系统直接输出，模型不得从 K 线重新寻找。
- `active_segment` 必须包含最新已确认笔，或明确与最新笔共享有效端点；否则不能称为活动线段。
- `local_bias` 只反映最新结构，不能从旧中枢突破方向复制。
- `background_bias` 可以保留较高级别的历史趋势背景，但不得充当本轮局部方向。
- `basis` 只使用稳定原因码，不写策略化自然语言。

### 5.3 当前决策状态层

重构 `trend_state` 的语义：

- `direction`：最新已确认结构的方向，不再等同于旧中枢历史突破方向。
- `reversal_bias`：最新确认分型之后已经出现相反方向的形成笔或确认笔时，必须如实输出。
- `background_direction`：旧中枢和较早确认线段提供的背景方向。
- `state`：允许出现 `up_reversal_watch`、`down_reversal_watch`、`up_transition_confirmed`、`down_transition_confirmed` 等过渡状态。
- `reason`：必须引用本轮活动结构，不得只引用已经脱离活动链的旧中枢。

示例：4696.65 顶分型确认、向下笔形成时，允许输出：

```json
{
  "state": "up_reversal_watch",
  "direction": "up",
  "reversal_bias": "down",
  "background_direction": "up",
  "reason": "latest_top_fractal_with_developing_down_bi"
}
```

向下笔确认后应升级为局部向下过渡，而不能继续输出 `reversal_bias=none`。是否已经构成完整下跌趋势，仍由后续线段、中枢和背驰结构决定。

## 6. 历史结构退役规则

### 6.1 可以继续参与当前判断

旧结构只有同时满足以下条件时才能参与当前判断：

1. 属于当前活动 `bi_run`，没有跨越结构不连续边界；
2. 与最新已确认笔或活动候选线段存在连续端点关系；
3. 尚未被后续更高高点、更低低点或反向确认结构否定其当前语义；
4. 对应中枢仍是活动中枢，或其离开段仍属于当前活动结构链；
5. 窗口一致性和时间定位证据仍可用。

### 6.2 必须退役为历史背景

满足任一项即不得继续主导 `trend_state`：

- 旧线段不包含最新已确认笔，且后续已经形成新的反向确认笔；
- 形成中的候选线段价格范围已经越过其原始起点，却仍长期停留在旧方向和旧端点；
- 旧中枢已经关闭，且当前活动结构不再以该中枢的离开段为直接组成部分；
- 当前价格方向仅能通过旧中枢历史突破解释，但最新分型、笔或活动线段已经给出相反结构；
- 结构锚点与当前窗口身份不一致，或连续性、闭合状态不可证明。

退役不删除数据，只将其移入内部 `historical_context`。模型侧默认不再收到这些旧判断字段。

## 7. 线段生命周期修正

### 7.1 保留确认线段的非重绘历史

已经确认的线段仍保留，不因后续行情而改写其历史端点。这是审计和非重绘要求。

### 7.2 活动候选必须随最新结构推进

当前 `candidate_segment` 需要增加以下不变量：

- `observation_end` 必须推进到最新参与计算的确认笔；
- 候选方向、起点、方向极值与所含笔必须自洽；
- 后续价格否定候选原始方向时，候选必须标记为 `invalidated`，并从最新有效分型/笔重新生成活动候选；
- 不允许一个“向下候选”长期保留旧低点端点，同时内部价格已经远高于候选起点，却仍被当成当前向下结构；
- 严格线段尚不能确认时，应输出 `forming` 或 `reversal_watch`，不能回退为旧中枢方向确定。

这里需要保留两个概念：

- `historical_confirmed_segment`：非重绘的历史线段；
- `active_segment_candidate`：服务于最新行情判断、允许被明确失效并重新锚定的活动候选。

两者不得再共用一个模糊的“current segment”语义。

## 8. 趋势归约优先级

新的归约顺序如下：

1. 数据质量、闭合状态、时间定位或连续性不可靠：`unavailable`。
2. 最新活动结构上的已确认背驰或有效买卖点：输出确认结构及反转方向。
3. 最新确认线段：作为已确认结构方向。
4. 最新确认分型加反向形成笔/确认笔：输出 `reversal_watch` 或 `transition_confirmed`。
5. 活动中枢及其当前离开段：用于补充趋势阶段。
6. 已关闭且脱离活动链的旧中枢：只写入 `background_direction`，不得覆盖第 2–5 项。

这一顺序不把未确认反转伪装成完整趋势，也不会让旧突破结论压住最新反转。

## 9. 模型载荷与策略提示词衔接

### 9.1 模型载荷

模型侧只保留当前决策所需的紧凑结构：

- `latest_structure`；
- 最新确认笔和形成笔；
- 当前活动线段/候选线段；
- 当前活动中枢；
- 当前背驰和买卖点候选；
- 必要的证据能力字段。

以下内容默认只留在内部快照：

- 多个已经脱离活动链的旧线段；
- 已退役旧中枢；
- 旧突破方向；
- 仅用于算法诊断的窗口投票明细。

### 9.2 策略提示词

算法修复并验收后，再对策略提示词做最小修改：

1. 只读取系统提供的 `latest_structure`、`trend_state` 和 `entry_candidates`，不要求 AI 重算缠论。
2. H1 出现 `reversal_watch` 时，可以进入相反方向的 M15 确认流程，不再被 `background_direction` 一票否决。
3. 顶/底分型单独出现只代表反转观察，不得直接下单。
4. M15、M5 的原确认链保持不变；只有满足策略原有确认标准后才能开仓。
5. `background_direction` 只用于降低逆背景反转单的置信度和加强确认要求，不作为绝对禁止条件。

## 11. 实施阶段

### 阶段 A：冻结真实行情回放

1. 固定 2026-08-18 至 2026-08-27 的 H1 闭合行情样本和关键检查点。
2. 每个检查点严格裁掉未来 K 线。
3. 记录分型、笔、活动候选、趋势状态和买卖点输出。

验收门：能够稳定复现红框转多观察和箭头处分高后向下观察，重复运行结果一致。

### 阶段 B：修正活动结构与退役机制

1. 保持包含、分型和笔算法不变。
2. 实现活动候选失效、推进和重新锚定。
3. 将旧结构移出当前方向归约。

验收门：8 月 25 日顶部之后，系统不能继续输出 `reversal_bias=none`；旧中枢只能作为背景。

### 阶段 C：调整模型数据合同

1. 输出紧凑 `latest_structure`。
2. 保留内部完整审计快照。
3. 验证提示词输入没有旧判断混入当前方向。

验收门：模型无需查看原始 K 线或自己计算公式，即可知道最新分型、笔和局部方向状态。

### 阶段 D：策略最小衔接与复测

1. 只修改提示词中的 H1 反转观察入口。
2. 保留 M15/M5 原确认标准和风险规则。
3. 使用正式自动分析相同数据结构、模型和流式请求复测。

验收门：能够进入正确的买卖点确认流程，同时不把普通顶/底分型批量转成反转订单。

## 13. 回滚标准

出现以下任一情况，应停止上线并回滚本批算法改动：

- 已确认分型或线段在相同闭合历史上重复运行结果不一致；
- 活动候选重新锚定导致历史确认线段被改写；
- 反转观察被直接映射成下单许可；
- 模型载荷仍同时出现互相矛盾的“当前多头”和“最新向下结构”，且没有背景/当前语义区分；
- M5/M15/H1/H4 任一周期出现结构数量大面积归零或异常激增；
- 请求体因重复保留完整历史结构而显著膨胀。

## 14. 第一轮复审：避免把“最新”误解为“只看最近几根”

### 复审结论

最初可以考虑缩短窗口或给旧结构设置固定 K 线寿命，但这会破坏缠论拓扑和不同周期的一致性。问题不在历史 K 线太多，而在历史结论与当前结论没有分层。

### 已调整

- 保留正式目标窗口和跨窗口稳定性验证。
- 放弃固定根数过期方案，改为结构连接、失效和退役。
- 内部快照保留完整历史结构，模型载荷只保留活动结构。

### 剩余风险

- 不同缠论实现对未确认线段的重新锚定语义可能存在差异，实施前必须先冻结本项目采用的唯一规则并加入黄金样本。
- 活动结构过度敏感可能增加反转观察次数，需要用真实行情统计而不是只看两个成功案例。

## 15. 第二轮复审：避免把“最新反转”直接变成反转订单

### 复审结论

用户指出的两处行情证明当前系统没有及时表达最新反转，但不能据此把所有顶/底分型直接升级为买卖点。正确边界是让系统及时输出最新反转观察，由原策略的 M15/M5 确认链决定是否下单。

### 已调整

- 将“顶/底分型直接做单”改为 `reversal_watch`。
- 保留严格的一、二、三类买卖点定义和 `entry_candidates` 合同。
- 宏观背景不再一票否决最新反转，但逆背景交易需要原有下级周期确认。
- 提示词只消费系统客观字段，不加入缠论计算公式。

### 剩余风险

- 真实模型是否能稳定区分 `background_direction`、`direction` 和 `reversal_bias`，仍需使用正式自动分析载荷做流式回放。
- 最新结构字段会改变模型输入合同，需要同步检查历史复盘、手动分析、自动分析和模型对比路径，防止其中某一路仍使用旧字段。
- 旧结构退出模型载荷可能改变部分策略对长期中枢的引用；上线前必须对现有启用缠论的策略做兼容性扫描。

## 16. 最终实施判定

建议先实施阶段 A 和 B，只修缠论活动结构与趋势归约；确认 H1、H4、M15、M5 的因果回放均正确后，再实施模型载荷和提示词的最小调整。

不得先靠提示词绕过当前算法问题。只有系统能够稳定提供“最新活动结构”和“历史背景”的明确区分后，模型才有可能在正常自动分析中既抓住反转机会，又避免大量假反转订单。

## 17. 实施结果（2026-08-27）

本方案已在本地 `dev_codex` 工作区完成实现，未提交、未推送、未部署。

### 17.1 缠论结构

- 保持 K 线包含、分型、笔和已确认线段的既有计算规则不变。
- 新增 `latest_structure`，只描述截至最新闭合 K 线的已接受分型、已确认笔、发展中笔、活动线段和局部方向。
- 最新分型采用笔构建器实际接受的活动端点，不采用尚不能组成合法笔的原始分型，避免“最新分型”和“当前笔”互相矛盾。
- 新增线段候选生命周期。达到完整双侧观察长度后，如果后续笔越过候选起点，则候选退出当前方向判断，但保留在内部审计字段 `historical_candidate_segment`。
- 趋势结论分为 `local_bias` 与 `background_direction`。旧中枢、旧线段仍可描述背景，但不能覆盖最新闭合结构。
- 算法版本升级为 `chan_structure_v7`，防止新版逻辑复用 v6 的持久化锚点。

### 17.2 模型数据合同

- 模型载荷加入 `latest_structure` 和 `local_structure_usable`。
- v7 载荷不再同时发送已经退役的旧候选、旧线段和旧中枢作为当前结构。
- 内部完整结果仍保留历史诊断字段，便于审计，不要求模型根据旧结构自行重算。
- 旧版、没有 `latest_structure` 的快照继续沿用原投影方式，避免无条件破坏历史回放兼容性。

### 17.3 策略提示词

- H1 最新结构处于 `reversal_watch` 时，可以进入原有 M15 路径 A；当 `local_structure_usable=true`、`local_bias` 方向唯一，且 M5 已完成反向突破回收的完整生命周期并且确认年龄严格为 1 根闭合 K 线时，也可以进入严格路径 C。
- `reversal_watch` 不是已确认反转趋势，不能直接下单，也不能使用路径 B 绕过确认；路径 C 仍是独立的反转回收确认链，不把单一分型或形成笔当作订单许可。
- 路径 A 的 M15 至少 2 项证据保持不变；路径 C 的完整 M5 生命周期、M1 EMA34、止损、盈亏比和通用风控条件均保持不变。
- 明确系统字段是客观计算结果，模型不得使用原始 K 线重新计算或混用另一套缠论公式。

## 20. 上线边界与剩余风险

- v7 不复用 v6 锚点。部署后的首轮可能处于新锚点启动阶段，部分依赖跨窗口稳定锚点的高级入场证据会暂时不可用；这是防止新旧算法状态串用的预期行为。
- `reversal_watch` 会比完整趋势反转更早出现，因此只能作为路径 A 或严格路径 C 的确认链入口，不能当作订单许可。
- 正式载荷回放表明，路径 C 的机械候选可以被识别，但同一检查点的模型重复推理仍可能在下单与观望之间波动；因此本轮只证明数据合同和提示词允许正确进入确认链，不宣称模型已经能稳定抓住所有买卖点。
- 本轮证明了算法输出、模型数据合同和提示词约束一致，但尚未在部署后的真实自动分析进程中验证模型最终订单。部署后应只读检查若干新推理，确认模型采用 `local_bias`，且没有把 `background_direction` 当成一票否决或直接下单依据。
- 提示词 Markdown 已修改；若运行环境中的策略提示词存储在数据库或配置中，仍需单独同步该文本，代码部署不会自动替换已保存的策略内容。
