# 后端模块交付模板

新增功能先确定所属业务域；只有出现独立职责和数据所有权时才新增模块。复用现有模块化单体，不为每个功能增加进程。此模板适用于新模块，也用于现有模块收口。

## 模块说明（写入模块 README）

- 职责：面向用户提供什么能力；由哪些用例完成。
- 公开入口：`index.ts` 中的业务端口、DTO 和领域合同；`composition.ts` 中仅供运行组装使用的工厂。
- 依赖：消费哪些其它域的公开能力，哪个调用者负责事务；禁止跨域内部导入和反向依赖。
- 数据所有权：逐表列出唯一写入者、跨域读取端口、事务拥有者、历史 ID 映射、查询和索引依据。没有持久数据时明确写“无”。
- 合同与事件：HTTP operationId、实时消息或 outbox 事件及消费者；没有则明确写“无”。
- 验证入口：相关行为/合同测试、实际依赖验证记录及未验证边界。

## 实现顺序

1. 确定需求和数据归属，设计公开端口；不先建立空目录或通用万能服务。
2. 领域规则置于 domain，用例置于 application，SQL/Redis/外部 SDK 置于 infrastructure，HTTP/消息适配置于 transport。bootstrap/entrypoints 只组装和管理生命周期。
3. 有数据变更时追加迁移，在当前 dev_vue 结构上演练升级和数据对账；UTC、金额精度、旧数据和已执行迁移保持既定约束。
4. HTTP 合同登记在域源和 manifest，生成 OpenAPI、运行校验及消费者类型；同时更新实际组装。HTTP 写入必须处理认证授权、CSRF、幂等、版本冲突和提交未知。
5. 关键副作用采用短事务/outbox/幂等消费者。测试覆盖成功、权限隔离和重复/故障恢复，不能只验证函数存在或复制实现断言。

## 收口记录

| 项目 | 应填写的证据 |
|---|---|
| 需求与用例 | 原需求条目、实现位置、剩余缺项 |
| 模块边界 | 公开端口、消费方、数据所有权及事务约定 |
| 数据升级 | 迁移和真实开发依赖验证记录；未涉及则写明 |
| API | operationId → 实际路由 → 消费者 → 正反例测试 |
| 完整流程 | 输入到持久结果及回读，标注所有替身和未验证环境 |
| 后续工作 | 前端/Bridge 联调、上线验收与核心阻断项分别列明 |

必要命令为 `pnpm run verify:server-boundary-delta`、`pnpm run typecheck:server`、相关行为测试；涉及 HTTP 时运行 `pnpm run verify:api-contracts` 和 `pnpm run verify:api-runtime`。不得以生成一致、路由数量相等或零静态发现替代完整业务验收。

没有前端实现的后端能力应明确标记消费者待接入，不为通过清单伪造前端完成。前端接入时继续按相同的公开入口、数据归属和合同标准验收。
