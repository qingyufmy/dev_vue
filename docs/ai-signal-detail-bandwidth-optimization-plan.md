# AI 分析师信号详情带宽优化方案

## 目标与证据

线上实测一次 `signal_detail` 响应约 1.87 MB，其中 `inference_snapshot.klines` 约 1.75 MB，包含 M5、M15、H1、H4 各 2,000 根冻结 K 线；前端每个周期实际只保留最后 500 根。普通历史记录跳转还默认强制刷新，因此重复点击和新信号自动跟随都会重复下载整份四周期证据。

目标是在不改变推理结论、冻结证据、信号权限和执行状态语义的前提下：

- `signal_detail` 只返回文字结论、执行状态、展示元数据和冻结快照概要；
- K 线证据按 `signal_id + timeframe` 延迟读取，每次最多返回冻结快照中的最后 500 根；
- 普通重复点击复用详情与证据缓存，显式刷新只刷新轻量详情；
- 新信号自动跟随只加载轻量详情和当前展示周期，不预取四个周期；
- 不修改 Bridge、不增加数据库表或迁移、不从实时行情重建历史推理证据。

## 实施范围

1. `server/routes/ai/inference-snapshots.js`
   - 将快照概要与单周期证据读取拆分；所有压缩/普通 JSON 仍统一使用 `parseSnapshotJson()`。
   - 概要只暴露可用周期、各周期条数、市场快照和审计元数据，不返回完整 `klines`。
   - 单周期证据严格限制周期白名单与 500 根上限，数据只来自该信号已保存的冻结快照。
2. `server/bridge-ws.js`
   - `signal_detail` 改用轻量快照概要，并避免重复返回同一份 `market_data`。
   - 新增只读 `signal_evidence` 动作；复用 `signal_detail` 的用户、交付、观摩源与策略可见性校验。
3. `server/routes/ai/observer-access.js`
   - 将 `signal_evidence` 纳入与 `signal_detail` 相同的只读观摩动作集合。
4. `public/ai/app.js`
   - 详情缓存按 signal ID；证据缓存与 in-flight 去重按 signal ID + timeframe。
   - 默认周期异步加载，切换周期时再加载对应证据；过期响应不得覆盖当前信号。
   - 普通导航默认不强制刷新；执行状态推送只刷新轻量详情。
5. 测试
   - 覆盖授权一致性、错误边界、冻结证据来源、500 根上限、压缩快照、重复请求去重、切换周期、过期响应保护和响应体预算。

## 第一轮复核：需求、边界与最小改动

- 需求覆盖：解决历史详情点击和推理触发时的带宽峰值，同时保留四周期证据的可查看能力。
- 业务边界：不改变信号结论、执行状态、用户归属、观摩权限和策略经验限制；不把冻结证据替换成当前行情。
- 复用能力：复用现有 `getInferenceVisualizationSnapshot`、`parseSnapshotJson`、`signal_detail` 授权分支和前端图表组件。
- 调整：不引入 HTTP 新路由或数据库迁移，使用现有 WebSocket 请求/响应合同增加一个只读动作；信号列表投影优化暂不扩大到本批，避免改变多个页面共用的列表字段合同。
- 剩余风险：旧页面缓存可能继续请求旧合同，需要更新 `app.js` 静态版本号；本地测试无法替代线上真实带宽验收。

## 第二轮复核：兼容、并发、安全与回滚

- 兼容：轻量快照保留原有市场快照与审计字段，新增 `available_timeframes`；前端同时接受旧版内嵌 `klines`，便于服务和静态资源短暂版本错位时降级。
- 数据：不改表结构；单周期读取只查询已有 `inference_snapshots`，不得读取当前市场数据。
- 并发与幂等：同一 signal/timeframe 共用一个 in-flight Promise；响应绑定请求版本和当前选中信号，防止快速切换时串图。
- 异常恢复：证据读取失败只显示图表局部错误，不影响文字结论和执行状态；再次切换或显式重试可恢复。
- 安全：`signal_evidence` 必须先完成与 `signal_detail` 等价的信号可见性检查，再读取快照；未知周期、缺少 signal ID 和不存在快照均使用稳定错误响应。
- 性能门槛：测试构造四周期 2,000 根样本，轻量详情不包含 K 线；单周期证据最多 500 根。预算以序列化字节为回归线，不依赖 WebSocket 压缩。
- 回滚：回退上述网站文件即可恢复旧合同，无数据库回滚、Bridge 回滚或数据修复。
- 最终结论：方案可实施。实现后仍需浏览器网络面板验证真实详情响应、重复点击和新信号自动跟随三条路径；未部署前不得声明线上已解决。
