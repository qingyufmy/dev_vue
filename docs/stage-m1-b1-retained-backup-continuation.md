## 2. 实施与验收步骤

1. 将 DEFAULT/生成表达式的合法语法与函数调用区分。生成列只能从冻结 CREATE DDL 识别，不能仅靠列名、INVISIBLE 或默认表达式推断。
2. 普通列仍要求完整、按顺序出现；生成列省略符合 dump 语义。未知/跨库函数、活动对象、客户端命令、表达式 INSERT 继续拒绝。
3. 在新目录完整重新解密和解压已保留加密包，原始 SQL hash 必须匹配；对全部 SQL 审查，不仅检查 DDL 样本。
4. SQL 通过后再次确认实例、版本、目标不存在和可用空间。只创建精确新库，随后以不可重放的客户端导入。
5. 恢复库 SHOW CREATE 完整指纹与冻结观测一致；再导出恢复库，以全部有序普通列 INSERT、逐表行数和真实 COUNT 对比冻结 dump。生成列由同一 DDL 表达式重算，不宣称 dump 保存了原生成列的独立物化字节。
6. 复核原证据未改；记录源码提交、工具 hash、阶段时间、对账结果和未验证边界。任何失败保留现场，没有删除/自动续跑。

MySQL 将生成列与普通不可见列区分；表达式默认值也不等于生成列。参考 [生成列](https://dev.mysql.com/doc/refman/8.4/en/create-table-generated-columns.html)、[不可见列](https://dev.mysql.com/doc/refman/8.4/en/invisible-columns.html)、[默认值](https://dev.mysql.com/doc/refman/8.4/en/data-type-defaults.html)。

## 3. 执行前两轮复审

第一轮（需求/职责）：仅修复备份恢复工具，不做 V4 字段映射或业务回填；沿用现有 GPG/MySQL/gzip，无新服务、新加密体系或通用数据库重试框架。生成列适配由独立编码子任务完成，主代理审查差异后才准入实际 SQL。

第二轮（安全/异常）：续接入口不是原执行器的“跳过检查”。冻结文件钉 hash、新目录独占、完整解密审查先于 CREATE，最终仅允许恢复目标。凭据仍为匿名 memfd；原 source 不再次 dump。CREATE 超时或导入中断后目标视为可能存在，保留现场并停止，不自动重放。禁止扩大函数白名单来强行通过，未支持语法宁可提前失败。

剩余风险：同机备份非异机容灾；hash 不能防御已控制 root 的攻击者；SQL 白名单只支持本次实际需要的 MySQL dump 子集。源冻结观测前后结构一致是观察证据，不等价于证明期间从未发生瞬时 DDL。恢复一致也不等价于 V4 全量业务迁移完成。
