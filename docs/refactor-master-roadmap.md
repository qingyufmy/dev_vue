## 2. 逐阶段确认规则

每个阶段开始前，主 Agent 必须先向用户介绍：

1. 本阶段为什么现在做。
2. 范围与明确不做的内容。
3. 将检查、设计或修改哪些模块。
4. 交付物和验收条件。
5. 可能影响的数据、接口、用户或客户端。

介绍完成后必须停下并等待用户明确确认，未确认不得开始该阶段。上一个阶段的确认不能自动延续到下一个阶段。

阶段按一个可验收的用户流程组织。同一已确认范围内的合同细化、实现、缺陷修复和必要验证连续完成，不为每个内部工作包重复增加确认门；新增业务范围仍先说明并确认。

提交是保存进度，不是停工条件；同一已授权流程持续推进到目标完成、实际阻塞或需要新增授权。两轮正式复审用于架构、迁移、身份权限、交易执行或重大跨模块方案；已批准方案内的普通修复做定向复核，不因提交或内部工作包切分而重走两轮流程。

即使用户已确认某个阶段，下列动作仍需在执行前再次取得针对该动作的明确授权：

- 数据库 DDL、DML、回填、修数或删除。
- 删除旧代码、旧表、旧接口、旧安装包或用户数据。
- 真实 MT4/MT5 下单、挂单、改单、撤单或平仓。
- 部署、重启、发布 Bridge 更新或切换生产流量。

提交、推送遵循用户后续长期授权及根 `AGENTS.md` §10：本次改动验证通过后，按单一职责提交并推送当前 `dev_vue`；不重复询问，不包含部署、强推、合并或无关文件。

用户在任意阶段补充新要求时，先更新需求基线、迁移矩阵和本路线图，再判断是否影响当前阶段或后续顺序。

### 3.1 当前优先顺序与最小交付范围（2026-09-06 修订）

本节覆盖历史进度记录中的“下一步 P5B”安排，不重排已执行迁移或否定既有离线成果。后续只在本路线图更新总体状态，专项文档保留具体合同和证据，不为每个内部步骤新建一层计划。

| 顺序 | 用户流程 | 本阶段完成判据 |
| --- | --- | --- |
| 1 | 普通用户首次连接、重连与换号 | 不手工粘贴 refresh token；从已登录用户配对到终端只读数据形成完整生产者/消费者调用链；覆盖新增、删除、换号与失败恢复 |
| 2 | 真实依赖的有限只读联调 | 获准后，在指定测试环境验证实际 MySQL/Redis、Bridge 只读会话与数据；不发送交易命令；记录实际依赖及迁移版本 |
| 3 | P5B 观摩发布和 Pro 无桥接订阅 | 先明确合法平台行情来源，再贯通各自权限与数据路径；观摩切换、用户分析订阅、账户执行关联互不代替 |
| 4 | 其余 B2、B3 与前端业务迁移 | 按既有阶段补齐；全量回填、最终非功能验收、切流与清理保留各自边界 |

**首次连接阶段的源码核查与待办：**

- `BridgeCredentialService` 当前只提供旧凭据兑换和会话票据；`.NET ProfileEditorForm` 新档案仍要求输入 refresh token。复用 auth 身份和 Bridge 凭据仓储，补一次性配对签发/领取，不新建第二套登录体系，不把长期凭据放 URL 或日志。
- 配对证明系统用户授权，不单独证明账户归属。补首次账户认领合同：精确 platform/server/login、已认证档案与终端事实、既有 owner 冲突处理、并发唯一性与历史区间；不得凭任意客户端账号字符串自动接管他人账户。合同须在接通自动登记前明确。
- 当前客户端变更路线生成新 profile；明确本地档案、服务端身份及凭据的一致生命周期，旧 `default` 使用稳定唯一映射，不合并不同用户。SQLite 与 uncertain 命令不得因换号混用或直接复制到新账户。
- 新连接采用准备、额度领取、激活和失败补偿的明确步骤；不能将 MySQL 与 Redis 伪装成一个事务。额度读取、领取、激活和 welcome 失败都纳入清理路径；同路线重连失败不应无故销毁可用旧连接。终端实际换号时旧路由必须失效，保留配置/历史不等于继续在线，也不允许客户端自动登录回旧账户。
- 删除档案撤销相应凭据、释放当前连接，保留服务端账户历史和交易证据；额度只计算当前有效 WebSocket，不计算保存的档案或历史账户数量。
- 开始新增事务前统一配对、账户归属、档案、凭据和网关激活的实际锁序；高频消息鉴权记录 SQL 次数与耗时，验证后再决定批量触达或缓存，不盲目减少授权校验。

**验收与状态：**

- 离线覆盖首次配对/超时/重复领取、跨用户拒绝、身份映射、并发认领、额度失败、同路线重连、实际换号、档案删除和晚返回；服务端合同与 .NET 消费者共同验证。前端只接入必要配对流程，使用已有 shadcn-vue 组件，不在本阶段重做全站样式。
- 获准的真实联调前移，但不自动授权连接或写入真实依赖。即使终端只读，服务端登记仍会写测试数据库，因此启动、迁移、数据范围须先明确。当前真实使用的 MT5 禁止交易测试；MT4 账户/环境未就绪就明确保留未验项。
- 后续统一区分“源码/离线完成”“真实集成通过”“可交付”；未满足最后一项不写成完整完成。阶段 16 仍做全系统验收，不能替代每个关键流程的早期集成。

**第一轮复审——需求与复杂度：**先完成普通用户入口，P5B 后移；无桥接订阅不依赖进入观摩；不增加万能 RPC、插件平台、数据库或无独立故障边界的新进程。退役技术记录默认保留备份、定位与迁移对账，不强制建设逐行在线解密查询平台；活动业务历史不能因此只留备份。宏观首版仍只交付客观因子与日历，预测模型不是上线前置条件。

**第二轮复审——异常与数据：**补新连接失败、真实换号和旧配置保留的区别；配对与账户所有权分开；未知执行结果继续精确对账，不重放。旧迁移、冻结清单和用户数据不改；退役记录缩减须在后续新版映射中提供处置证据，不能凭文档解除阻断。真实锁序、性能、Win7 更新与 MT4/MT5 验收仍待相应环境验证。

**首次连接阶段实施记录：**2026-09-06 开始。首个基础修复是网关失败清理，不代表首次配对完成。第一轮复审确认只复用现有会话、租约和关闭端口，不增表、队列或通用补偿服务。第二轮确认额度查询应进入 pending 失败清理范围；Redis claim 可能已经生效但响应丢失，须按精确 connection ID 尝试释放；Redis/SQL 清理互不阻断，错误保留可诊断，关闭失败可再次清理且不得再次接收业务消息。该修复不恢复旧账户在线状态，不调整 owner/epoch/换号授权或重放交易。

本批结果：网关连接失败/关闭清理源码完成，新增 7 项回归（额度、claim 响应丢失、激活、welcome 失败、清理双失败、新连接保护、关闭重试）。服务端 57 files / 426 tests、类型检查和 V4 构建通过；测试仅使用 fake/Mock 及本机测试用回环 WebSocket，不连接实际 MySQL/Redis/Bridge/MT。无迁移文件、客户端或页面修改，无运行服务启动/部署。后续仍需配对签发与领取、首次账户认领、档案身份映射和完整换号链路；不能把本批结果称为普通用户首次连接已经可用。
