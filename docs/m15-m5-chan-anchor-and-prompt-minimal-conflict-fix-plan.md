## 2. 目标与硬边界

### 2.1 目标

1. 修复 M5、M15、H1、H4 共用的可信锚点滑出固定窗口后回退失真的问题；
2. 修复锚点失败回退通过对象展开丢失内部确认线段、中枢和时间证据的问题；
3. 评估四个受支持周期的固定窗口是否足以稳定产生线段和中枢，并把窗口容量问题与锚点代码缺陷分开处理；
4. 恢复旧版 M15“六项候选、至少两项独立确认”的策略语义；
5. 保留当前 v1.7 已经补齐的数据安全、已收盘证据、M1 EMA34、订单合法性、重复订单和风险控制规则；
6. 消除 H1 趋势判定、买卖点、谐波状态、ATR、风险收益和未来条件表达中的歧义；
7. 让每轮推理能够审计六项 M15 条件及最终计数；
8. 将锚点修复、窗口策略、模型能力投影和提示词修改分批发布，分别衡量对结构能力与信号数量的影响。

### 2.2 必须保留的交易流程

```text
H1 趋势主判
→ H4 仅在 H1 不明确时降级备判
→ H1 同向机会定位
→ M15 六项候选中至少两项独立确认
→ M5 至少一项已收盘触发
→ M1 EMA34 新入场方向过滤
→ 止损、净风险收益、订单合法性和重复订单检查
```

### 2.3 必须保留的业务边界

- M1 EMA34 不参与 H1/H4 趋势、M15 计数或 M5 计数；
- 缠论只有一个计算权威：系统提供的 Chan 结构；模型不得根据原始 K 线重新计算或覆盖分型、笔、线段、中枢、背驰和买卖点；
- M5 触发、M1 EMA34、评分或置信度不得补足 M15 的两项确认；
- 只使用已收盘证据确认结构和入场；
- 模型只选择“不建仓、试探仓、轻仓、标准仓”，不得给出绝对手数；
- 风控、执行资格、幂等和 Bridge 继续由通用服务端链路负责；
- 服务端不得按策略 ID 添加当前策略专用交易规则或改写模型原始方向；
- 不降低止损、净风险收益、订单方向关系或重复订单检查标准。

## 3. 已核实问题与责任划分

### 3.1 M15 计数语义被改变

旧版 M15 包含六个候选确认项：

1. 缠论背驰确认；
2. 谐波 PRZ 触达；
3. 第三类买卖点成立；
4. 关键裸 K 形态；
5. 假突破确认；
6. 支撑阻力 K 线反应。

当前 v1.7 把它们压缩为 A 缠论、B 谐波、C 裸 K 三组，并按 2/3 计数。该变化虽然意在防止重复计票，但改变了投票单位：同组多个独立条件最多只计一票。

当 A 因数据问题不可用时，当前规则必然退化为 B 与 C 同时通过，使 PRZ 从可选确认项变成事实上的必要条件。这是提示词规则导致的收紧。

### 3.2 Chan 计算存在两个必须分开的故障面

生产 Chan v6 只支持 `M5`、`M15`、`H1`、`H4`。`M1`、`M30`、`D1` 当前不走这套锚点和固定窗口路径，因此本方案不把它们误列为同类故障周期。

#### 3.2.1 旧锚点失败回退缺陷

生产当前只有 M5、M15 存在 `chan_structure_v6` 持久化锚点，两者都早于当前固定窗口起点；H1、H4 当前没有持久化锚点。2026-08-26 使用生产代码和生产 XAUUSD 缓存执行只读回放，结果如下：

| 周期 | 固定窗口 | 当前持久化锚点 | 同窗口无锚点 | 带生产锚点 |
|---|---:|---|---|---|
| M5 | 800 根 | 已滑出窗口 | 6 线段、0 中枢、窗口稳定 | 0 线段、0 中枢、`segment_history_unresolved` |
| M15 | 1000 根 | 已滑出窗口 | 4 线段、0 中枢、窗口稳定 | 2 线段、0 中枢；附带 `structure_anchor_not_found` |
| H1 | 1200 根 | 无 | 6 线段、0 中枢、窗口稳定 | 当前不触发旧锚点回退 |
| H4 | 800 根 | 无 | 5 线段、0 中枢、窗口稳定 | 当前不触发旧锚点回退 |

M5 是当前最明确的生产级反例：同一批 K 线只因携带已经滑出窗口的旧锚点，稳定的 6 条线段被回退路径重新归零。M15 当前快照没有完全归零，但同样被旧锚点改变了选择结果；历史回放还出现过“带锚点 0 线段、同窗口无锚点 6 线段”。这证明“行情没有结构”不是完整解释。

代码根因位于四周期共用的 `computeChan()`，没有 M5/M15 专用分支。因此：

- M5、M15 是当前已经触发的故障；
- H1、H4 当前没有锚点，所以没有触发；
- H1、H4 将来一旦保存锚点并发生滑窗、身份失败或末端回归，会进入同一缺陷路径；
- 修复和回归测试必须覆盖全部四个受支持周期，不能只修 M15/M5。

#### 3.2.2 固定窗口容量不足风险

去掉锚点因素后，四周期仍频繁出现 `center_cross_window_unstable`。将窗口扩大到现有普通缓存上限内作诊断回放，最近观察点的中枢可见率明显变化：

| 周期 | 当前策略窗口 | 诊断候选窗口 | 当前窗口中枢可见 | 候选窗口中枢可见 | 其他变化 |
|---|---:|---:|---:|---:|---|
| M5 | 800 | 1600 | 2/10 | 6/10 | unresolved 从 3/10 降到 1/10 |
| M15 | 1000 | 2000 | 2/10 | 8/10 | 两组均有线段，但候选窗口平均线段更多 |
| H1 | 1200 | 2000 | 0/10 | 10/10 | 候选窗口稳定保留 1 个中枢，仍为 entry 未确认 |
| H4 | 800 | 1600 | 0/10 | 7/10 | 最近 3 个观察点两个窗口都无确认中枢 |

这些数字只来自生产 XAUUSD、source 1 的只读滚动回放，不代表扩大窗口一定更正确，也不授权直接修改窗口。窗口改变会影响结构起点、stable ID、计算耗时和后续锚点身份，必须作为独立问题验证。

同机纯计算基准显示候选窗口有明显成本：M5 中位数约 24ms→208ms，M15 约 20ms→493ms，H1 约 37ms→186ms，H4 约 18ms→368ms。该结果证明不能把“永久扩大所有窗口”混入锚点最小修复。

### 3.3 直接代码根因

`computeChanWindow()` 在 `server/routes/ai/market-data.js` 中使用不可枚举属性保存内部选择证据：

```js
_confirmed_segments
_confirmed_centers
_closed_rate_times_utc_msc
```

锚点匹配失败后，当前代码重新计算 `unanchored`，随后通过对象展开生成新的 `primary`：

```js
primary = {
  ...unanchored,
  // diagnostics
}
```

对象展开只复制可枚举属性，三个内部字段全部丢失。后续跨窗口选择仍依赖这些字段，所以可能把有效的无锚点候选重新判为 unresolved。

### 3.4 现有测试没有覆盖生产失败路径

锚点身份错误和线段回归测试传入 `fractalsForTest`。生产代码在该选项存在时提前返回，因此测试没有经过真实的无锚点跨窗口选择。现有定向测试全部通过，只能证明已覆盖路径稳定，不能否定该缺陷。

### 3.5 提示词输出与服务端合同不一致

当前提示词要求输出 A/B/C 和 `X/3`，但服务端通用 JSON 合同没有对应字段，主要只保存 `decision_summary`、`key_reasons`、`analysis` 和 `reasoning`。因此当前无法稳定统计每个 M15 拦截项，也无法证明交易信号确实满足门槛。

### 3.6 模型看不到系统 Chan 的可用能力状态

系统内部已经计算 `evidence_capabilities`，包括：

- `segment_direction_usable`；
- `center_structure_usable`；
- `entry_structure_usable`；
- `divergence_usable`；
- 数据完整性和内部稳定原因码。

但 `server/routes/ai/chan-model-payload.js` 当前只投影结构对象，明确删除了 `evidence_capabilities`。模型因此无法可靠区分：

- 系统具备判断能力但本轮没有背驰/买卖点；
- 系统结构本身 unresolved，根本没有资格判断。

在禁止模型自行计算 Chan 后，这个能力状态必须由系统以脱敏、只读形式提供，否则“未通过”和“不可用”仍无法稳定区分。

## 4. Chan 计算最小修复设计

### 4.1 计算前识别窗口外锚点

在第一次调用 `computeChanWindow()` 前，比较：

- 可信锚点 `anchor_time_utc_msc`；
- 当前 calculation window 第一根和最后一根已收盘 K 线 UTC 时间；
- 锚点身份字段是否完整。

若锚点时间早于窗口第一根 K 线：

1. 不再用该锚点执行必然失败的 anchored 计算；
2. 直接按无锚点窗口计算；
3. 对外保留诊断 `structure_anchor_outside_window`；
4. `requested_time_utc_msc` 和请求身份仍保留在诊断中；
5. 不把窗口外锚点错误解释为身份不匹配或线段回归。

若锚点时间晚于窗口最后一根已收盘 K 线，按异常未来锚点失败关闭，不自动接受。

### 4.2 失败回退保留同一对象和内部证据

对窗口内但身份缺失、身份不匹配、末端线段回归等失败路径：

1. 仍重新执行一次无锚点 `computeChanWindow()`；
2. 复用同一个 `unanchored` 结果对象；
3. 在该对象上更新公开的 `status`、`reliability`、`warnings` 和 `structure_anchor` 诊断；
4. 禁止通过 `{ ...unanchored }` 创建新对象；
5. 若实现需要克隆，必须使用完整 property descriptors，并增加不可枚举性测试；
6. `_confirmed_segments`、`_confirmed_centers`、`_closed_rate_times_utc_msc` 继续保持不可枚举，避免泄漏到模型载荷或 API。

推荐优先复用同一对象，避免引入新的克隆工具和维护成本。

### 4.3 保持跨窗口稳定性规则不变

批次 A 的锚点修复只恢复已经存在的内部证据，不修改以下规则：

- validation window 数量；
- 线段身份匹配；
- 中枢一致性；
- 末端链确认；
- 最小历史数量；
- `segment_direction_usable`、`center_usable`、`divergence_usable` 和 `entry_candidates_usable` 的能力分层。

没有跨窗口稳定证据时仍应 unresolved；没有确认中枢时不得开放背驰或买卖点能力。窗口容量调整必须进入后续独立批次，不能借锚点修复顺手修改。

### 4.4 锚点更新与数据边界

- 不删除数据库中的 M5/M15 锚点；H1/H4 当前无锚点，不人工补写；
- 不手工修改锚点时间或 stable ID；
- 不在批次 A 中通过永久扩大历史窗口掩盖问题；
- 不新增数据库迁移；
- 让现有正常持久化流程在结构稳定后自然保存新的可信锚点；
- 所有比较使用 UTC 毫秒，不使用北京时间、终端墙钟字符串或固定 UTC 偏移。

### 4.6 向模型投影脱敏的系统 Chan 能力

在 `summary.chan` 中保留现有结构对象，并新增经过白名单复制的 `evidence_capabilities`：

```text
history_complete
continuity_complete
topology_input_complete
data_complete
segment_direction_usable
center_structure_usable
entry_structure_usable
divergence_usable
```

投影规则：

- 只允许上述布尔字段；内部 `reason_codes` 继续用于服务端诊断，不进入模型载荷；
- 不投影 `structure_anchor`、内部窗口、缓存身份、不可枚举证据数组或完整 warnings；
- 使用深拷贝，禁止模型载荷持有内部快照引用；
- `divergence_usable=true` 只表示系统有资格判断，不表示本轮一定存在背驰；是否通过仍看系统 `divergence.confirmed/type`；
- `entry_structure_usable=true` 只表示系统有资格判断买卖点；是否通过仍看 `entry_candidates[].usable_for_entry`、方向和类型；
- 能力为 false 时，提示词标记对应 Chan 项不可用，不从原始 K 线补算。

### 4.7 四周期窗口策略的独立修复候选

窗口容量问题进入独立批次 W。先对下面两种方案做离线比较，再选择其一；本方案不预先把诊断窗口写死为生产结论。

方案一：扩大固定窗口。

- 候选上限：M5 1600、M15 2000、H1 2000、H4 1600；
- 上限不得超过普通平台行情缓存 `CACHE_LIMIT=2000`；
- validation windows 必须按新目标重新选取，不能机械沿用原来的 100 根间隔；
- 优点是路径简单、每次结果一致；缺点是每轮都承担更高 CPU、内存和 Bridge/缓存取数成本。

方案二：保留基础窗口，仅在无匹配锚点且基础窗口出现边界型结构不稳定时运行扩展 bootstrap 窗口。

- 扩展窗口只允许产生“推荐锚点”，不能在同一轮直接开放背驰或买卖点入场证据；
- 下一轮必须用持久化锚点在基础窗口内重新匹配并通过现有能力门槛；
- 若推荐锚点位于基础窗口之外，或下一轮无法复现，则该方案不成立，改用方案一或继续失败关闭；
- 优点是正常路径成本低；缺点是状态机和测试复杂度更高。

选择门槛：

1. 对生产允许的全部 source/symbol 组合做至少 30 个滚动观察点回放；
2. 同时统计线段可见率、中枢可见率、stable ID 变更率、背驰/买卖点开放率和不一致率；
3. 对比固定前缀不变性，禁止仅因无关更早 K 线前缀改变当前结构；
4. 候选窗口不得把 `forming`、单窗口中枢或未确认 entry 升级为可交易证据；
5. 在生产同规格主机测量单周期 P50/P95、四周期整轮耗时和并发任务下的事件循环延迟；
6. 先离线冻结新的 policy version，再单独发布和观察；不得与锚点代码、能力投影或提示词同窗上线。

若上述门槛不能证明收益大于结构漂移和性能成本，批次 W 不上线；H1/H4 无中枢继续按“Chan 证据不可用”处理，而不是让模型自行补算。

## 5. 提示词 v1.7.1 最小修订设计

### 5.1 以当前 v1.7 为底稿，不整体回滚旧版

继续保留当前版已经修复的内容：

- 已收盘 K 线和数据完整性检查；
- 系统 Chan 是唯一缠论来源，模型不得自行重算或覆盖；
- M1 EMA34 路径、ready、M1、close、closed_only 和数据缺口检查；
- H1 明确时跳过 H4，跳过不构成否决；
- PRZ 必须实际触达，未来 D 点不能提前计票；
- M5 必须有已收盘触发；
- 止损、订单类型、Bid/Ask、重复订单和风险控制；
- EMA34 不用于退出、撤单或补足前置证据；
- 禁止固定手数和提示词内仓位倍数。

旧版中的直接入场旁路、`X/4`、S 级裸 K 独立入场、PRZ 单比例、固定仓位倍数等问题不得恢复。

### 5.2 恢复六项候选计数

M15 固定为以下六项：

| 编号 | 候选项 | 通过要求 |
|---|---|---|
| M15-1 | 缠论背驰 | 系统 `divergence_usable=true`，且 `divergence.confirmed=true`、类型与最终方向一致；形成中或候选背驰不通过 |
| M15-2 | 谐波 PRZ 触达 | 形态状态允许计票、PRZ 合格、价格已实际触达，不是未来 D 点 |
| M15-3 | 第一/第二/第三类买卖点 | 系统 `entry_structure_usable=true`，且存在方向一致、`usable_for_entry=true` 的具体候选；未完成或过期候选不通过 |
| M15-4 | 关键裸 K | 已收盘的 Pin Bar、吞没、晨星或黄昏星，并位于有效关键位 |
| M15-5 | 假突破 | 已收盘价格突破关键位后重新回到安全侧，关键位和极值可复核 |
| M15-6 | 支撑阻力 K 线反应 | 关键位首次测试或独立复测出现明确拒绝，时间和价位可复核 |

进入 M5 前：

```text
M15 独立通过数量 >= 2
```

分母固定为六项，不因证据不可用缩小；门槛固定为两项，不因证据缺失降低。

### 5.3 证据状态统一

每项只允许：

- `通过`：全部必要条件由已收盘证据满足；
- `未通过`：数据可用，但必要条件不成立；
- `不可用`：来源缺失、结构能力关闭、历史不足、未收盘或内部缺口；
- `未检查`：被更早的流程门槛阻止，未进入 M15 检查。

不得把“接近”“形成中”“候选”“预计进入”写成通过。

### 5.4 去重按底层证据，不按三大组投票

A/B/C 仅作为来源标签，不作为计票单位。

允许分别计票的情形：

- PRZ 的几何汇聚和实际触达通过 M15-2；随后已收盘 Pin Bar 以独立 K 线事实通过 M15-4；
- MACD 背驰满足量化比较通过 M15-1；买卖点同时完整满足中枢离开与回抽规则时通过 M15-3；两项必须分别展示证据，不能用同一句“出现背驰”代替买卖点结构；
- 假突破完成后，另一根或另一段独立复测 K 线出现拒绝，可分别通过 M15-5 与 M15-6。

只计一票的情形：

- 同一根假突破 Pin Bar 同时被命名为裸 K、假突破和支撑反应；
- 仅因价格位于 PRZ，同时声称谐波、关键位和裸 K 均成立；
- 同一个未完成结构同时被描述成背驰、线段破坏和买卖点；
- 同一 K 线换不同名称重复计数。

每个通过项必须提供最短证据引用：周期、已收盘时间、关键价格或结构 ID/端点。若两个通过项的证据完全相同且没有独立判定条件，只保留一票。

### 5.5 Chan 不可用时的语义

- Chan 能力不可用时，只把 M15-1 和 M15-3 标记为不可用；
- M15-2、M15-4、M15-5、M15-6 仍必须逐项检查；
- PRZ 不因 Chan 不可用而自动成为必要条件；
- 其余四项中仍需至少两个独立通过；
- 不得使用 M5、M1 EMA34、评分或原始主观描述补足两项。

### 5.6 系统 Chan 是唯一缠论计算权威

提示词不得包含任何“根据原始 K 线辅助计算缠论”或“系统结构不可用时自行重算”的分支。统一规则为：

1. 系统 Chan `usable/ok`：只使用系统提供的分型、笔、线段、中枢、背驰、买卖点和能力状态；
2. 系统 Chan `partial/unresolved/unavailable`：对应缠论证据标记不可用，不用原始 K 线重建或升级；
3. 系统完全未提供 Chan：所有依赖 Chan 的证据标记不可用，不启动模型侧 Chan 计算；
4. 原始 K 线仍可用于谐波、裸 K、假突破、支撑阻力和普通 HH/HL、LH/LL 价格序列，但不得把这些分析命名为分型、笔、线段、中枢、背驰或买卖点；
5. H1/H4 的 Chan 证据不可用时，趋势仍可基于非 Chan 的已收盘价格结构判断，但输出不得虚构 Chan 结构；
6. M15 Chan 不可用时，只关闭 M15-1 和 M15-3，继续检查其余四项；
7. M5 Chan 不可用时，只关闭“缠论最小级别触发”分支，突破或假突破触发仍可按原规则检查。

当前生产由系统提供 Chan。批次 A 的代码修复就是恢复这一唯一权威的数据能力，提示词不承担算法兜底。

### 5.7 H1 趋势判定顺序

改为确定性顺序：

1. 先检查数据不足、中枢粘连、结构多解、高低点混乱和方向冲突；
2. 存在任一未解决否决项时，H1 判为不明确并启用 H4；
3. 没有否决项后，再以已确认线段/中枢离开和 HH/HL 或 LH/LL 为主；
4. MACD 只能确认结构方向，不能单独定义 H1 趋势；
5. H1 与 H4 都不明确时返回 hold，不继续生成新入场。

### 5.8 补齐买卖点使用语义，不重述系统算法

系统已经提供 `entry_candidates`，最终提示词不再解释如何从原始 K 线、中枢或 MACD 重新推导第一、第二、第三类买卖点。正文只规定如何消费系统结果：

- 将 `first_buy/second_buy/third_buy` 和对应 sell 类型映射为明确中文名称；
- 方向必须与最终交易方向一致；
- 只有系统标记 `usable_for_entry=true`、结构已确认且证据时间属于已收盘 K 线的候选可以计票；
- forming、candidate、过期、失效或能力不可用的候选不计票；
- 使用系统给出的结构 ID、端点、关键位和失效位作证据，不从可见 K 线重建；
- 正文不得再用“三类买卖点”同时表示“三种类型”和“第三类买卖点”。

这些定义只用于校验和解释系统候选项的 `type`、`state`、`usable_for_entry`、结构引用与失效价，不授权模型根据原始 K 线自行构造新的买卖点。

### 5.9 统一谐波状态

统一为：

```text
严格合格：B/D 关键点偏差在 ±3% 内
宽松合格：偏差超过 ±3% 且不超过 ±8%，并满足其余必要比例
候选：点位或已收盘确认不足
无效：关键点偏差超过 ±8% 或摆动点不成立
```

只有严格合格或明确允许的宽松合格形态，在价格实际触达由至少两个比例汇聚形成的 PRZ 后，M15-2 才能通过。候选和未来 D 点不计票。

### 5.10 趋势重分类而非直接逆势

保留“逆势信号不得直接入场”。补充：若 H1 已收盘结构出现明确破坏、回抽确认和方向重建，先把原趋势重新分类为不明确或新趋势，再重新执行完整流程。背驰、谐波反转或单根裸 K 不能单独翻转 H1 趋势。

### 5.11 固定 ATR 和净风险收益

- 止损校验的 ATR 输入固定取系统 M15 `summary.atr_14_closed`；
- 止损必须位于结构失效点之外，且距离不得小于 `1.5 × summary.atr_14_closed`；
- 若 ATR 不可用，不得自行用其他周期冒充；
- 被推荐的实际执行 TP 档位，其净风险收益比必须至少为 `1:1.5`；
- TP1 可以作为管理参考，但低于 1:1.5 时不能成为新入场的推荐执行档位；
- 扩大止损后净风险收益不合格则放弃交易。

### 5.12 澄清未来条件表达

改为：禁止把未来价格路径描述成必然事实；允许基于当前已形成结构输出条件式挂单、止损、目标和失效方案。所有未来内容必须使用“若……则……”或明确的触发条件表达。

### 5.14 提示词制作验收标准（不写入最终策略正文）

本节是修改人员必须遵守的编辑规则，不是给模型看的策略规则。生成最终 `.md` 时不得把本节原文、类似“系统提供客观数据时不要复算”的元说明或编辑过程写入策略正文。

## 11. 第一轮方案复审：需求与最小改动

### 11.1 复审检查

- 需求覆盖：同时覆盖提示词逻辑和 M5/M15/H1/H4 全部受支持 Chan 周期；
- 核心策略：确认旧版核心是六项候选至少两项，而不是三组取二；
- 业务边界：保留 H1/H4、M5、M1 EMA34、风险和 Bridge 权威；
- 现有能力复用：复用 `computeChanWindow()`、跨窗口选择、现有策略 API 和通用 JSON 合同；
- 最小改动：锚点批次仅修改 market-data 与 Chan 测试；窗口策略、能力投影和提示词分别独立；
- 设计复杂度：不引入第二套 Chan 算法、迁移或新表。

### 11.2 第一轮发现与调整

发现一：原方案把 v1.7 的三组结构误当成策略核心，会继续造成 A 不可用时 B+C 强制成立。

调整：恢复六项候选计数；A/B/C 只用于来源分类和去重，不参与投票。

发现二：直接恢复六项可能重新引入同一根 K 线三次计票。

调整：增加底层证据去重、最短证据时间/价格要求和可分别计票示例。

发现三：为审计新增策略专用后端字段会违反策略唯一分析权威边界。

调整：第一阶段复用 `reasoning`；通用 trace 单独立项，不作为本次前置依赖。

发现四：允许提示词在系统 Chan 不可用时根据原始 K 线自行重建，会产生两套分型、线段、中枢和买卖点口径。

调整：系统 Chan 固定为唯一缠论计算权威；模型只消费系统结果，系统不可用时对应缠论项失败关闭，不做算法兜底。

发现五：“系统提供客观数据时不让 AI 复算”是提示词制作标准，不是要写给模型看的策略条款。

调整：把它放在 5.14 的文件验收中；最终正文通过删除重复算法、直接引用系统字段来落实，但不复制这段元规则。

发现六：锚点根因位于四周期共用函数，只测试 M15/M5 会让 H1/H4 的未来锚点失败路径继续无覆盖。

调整：所有锚点失败测试参数化覆盖 M5、M15、H1、H4；M1/M30/D1 因 v6 policy 明确不支持，不制造伪覆盖。

第一轮结论：需求已覆盖，核心逻辑得到纠正，计算与策略分层清晰，没有引入平行交易权威或过度设计。

## 12. 第二轮方案复审：兼容、安全、测试与回滚

### 12.1 兼容性与数据

- 不修改数据库结构和公开 API；
- 正常锚点路径保持不变；
- 内部字段继续不可枚举，不进入模型载荷；
- M5、M15、H1、H4 使用同一通用修复，不按周期复制算法；
- UTC 窗口判断与现有时间语义一致。

### 12.2 并发、幂等与恢复

- Chan 计算是单快照纯计算，不增加共享写锁；
- 锚点仍由现有流程自然更新，不增加并发写入口；
- 重复执行同一快照应得到相同窗口选择和结构状态；
- 失败仍返回能力分层，不自动重试模型或补跑任务。

### 12.3 第二轮发现与调整

发现一：只预判窗口外锚点不足以覆盖窗口内身份错误和末端回归，后者仍会经过对象展开丢证据。

调整：明确所有失败回退均复用同一个 unanchored 对象，并为三类失败分别增加不使用 `fractalsForTest` 的测试。

发现二：简单恢复内部线段可能错误开放背驰和买卖点。

调整：明确只恢复既有跨窗口证据，能力分层和中枢要求不变；真正不稳定仍失败关闭。

发现三：允许 PRZ 与裸 K 分别计票可能被模型用同一句“价格在 PRZ”重复证明。

调整：PRZ 必须展示几何比例与触达，裸 K 必须展示已收盘 OHLC/时间和形态；缺少独立判定事实时只计一票。

发现四：当前提示词的 TP1 允许 1:1，但最低合格风险收益未定义，会让策略在恢复信号时同时放宽风险。

调整：固定推荐执行档位净风险收益至少 1:1.5；TP1 低于该值只作为管理参考。

发现五：系统内部虽然计算了 Chan 可用能力，但模型投影明确删除该对象。在禁止模型自行重算后，模型无法区分“未出现”和“不可用”。

调整：把通用、脱敏的 `evidence_capabilities` 模型投影纳入方案，只暴露能力布尔值，不暴露原因码、锚点、窗口或内部证据数组；发布批次在下一项继续拆分。

发现六：若能力投影与计算修复同时上线，即使提示词保持 v14 不变，模型输入变化也会污染计算修复的观察窗口。

调整：将能力投影从批次 A 拆成独立批次 B；批次 A 只修计算，批次 B 只改模型输入，批次 C/D 再生成并保存 v1.7.1。

发现七：直接投影内部 `reason_codes` 可能把实现细节带入模型理由和用户可见文本，并扩大模型输入变化。

调整：模型只接收能力布尔值；具体原因码保留在内部快照、决策诊断和运维观测中。

发现八：生产回放显示 H1/H4 即使没有旧锚点，也会因当前固定窗口边界长期缺少确认中枢；但扩大窗口显著增加计算成本，且会改变结构身份。

调整：新增条件批次 W，把窗口策略从锚点修复中拆开；先比较扩大固定窗口和扩展 bootstrap 两种方案，未通过稳定性、前缀不变性与性能门槛则不上线。

发现九：普通行情取数受 `CACHE_LIMIT=2000` 限制，H1 全历史 2286 根回放虽然能显示中枢，但不能作为可直接上线的窗口目标。

调整：生产候选上限不超过 2000；H1 使用 2000 根复核后，最近 10 个观察点仍为固定窗口 0/10 有中枢、候选窗口 10/10 有中枢，因此容量风险成立，但最终实现仍待批次 W 验证。

### 12.4 剩余风险

- 修复后当前行情仍可能没有确认中枢，背驰和买卖点继续不可用，这是正确失败关闭；
- 六项恢复会提高组合空间，若去重遵循不足，可能重新出现重复计票；
- `reasoning` 是文本合同，审计稳定性弱于结构化字段；
- 新增系统 Chan 能力字段本身可能影响 v14 的模型判断，因此必须单独观察并可独立回滚；
- 模型自主谐波识别仍可能不稳定，生产没有独立谐波扫描器；
- 扩大窗口会显著增加 CPU 与取数成本，扩展 bootstrap 则增加状态机复杂度；两种方案都可能造成 stable ID 迁移；
- 当前回放主要基于 XAUUSD source 1，不能在缺少其他获准 source/symbol 样本时把比例外推为全市场结论；
- 当前生产 v1.7 完整正文未由一个 Git 跟踪文件唯一对应，v1.7.1 必须补齐版本治理；
- 信号数量受行情、M1 EMA34、M5触发、风险收益和账户状态共同影响，不能保证恢复到某个固定数量。

第二轮结论：方案覆盖四个受支持周期的锚点失败路径，并把固定窗口容量风险拆成条件批次；提示词恢复原六项核心、删除系统已有客观计算的重复算法，并增加可复核去重。代码实施、部署和生产策略保存仍需分别获得授权。
