# Bridge MT5 重新检测与 3.0.0 打包计划

## 1. 目标与边界

本批次修复量见智桥在当前 Profile 已存在一个 MT5 绑定后，点击“重新检测”无法发现新增 MT5 终端的问题，并构建新的 3.0.0 全量安装包。

本批次授权边界：

- 允许修改 Bridge Native Core 及其聚焦测试；
- 允许构建、签名和本地验证 3.0.0 模块包及全量安装包；
- 允许执行隔离的首次安装和同版本修复演练；
- 不上传七牛，不修改网站下载元数据，不部署服务器，不发布 current/bootstrap 清单，不激活灰度；
- 不删除或重置现有用户 Profile、SQLite 绑定、偏好、持仓或挂单；
- 不自动启动、关闭或切换任何 MT4/MT5 终端。

## 2. 已确认问题

当前流程只在 Profile 不含任何 MT5 绑定时进入终端发现。已有任意 MT5 绑定时，`provision_mt5_bindings_if_missing()` 直接返回；“重新检测”仅触发生命周期重载，重载后仍命中同一提前返回。

此外，普通启动流程若已有 `mt5_terminal_path`，只解析该保存路径；它不适合作为用户明确点击“重新检测”时的发现范围。

Windows 进程发现目前对 `terminal64.exe` 直接接纳，但 `terminal.exe` 只有同目录存在 `MQL5` 时才作为 MT5 候选。对于用户直接复制并启动、目录结构不完整的 MT5，可由精确路径 MT5 Worker 探测做最终类型判定，不应在进程枚举阶段过早丢弃。

## 3. 设计

### 3.1 显式重新检测信号

为当前 Profile 的运行生命周期增加一次性“强制重新检测”信号：

1. 本地 UI 收到 `Redetect` 时设置该信号并触发生命周期重载；
2. 生命周期下一轮原子消费信号；
3. 普通启动、设置变更和运行恢复仍保持“仅在缺少绑定时发现”的现有行为；
4. 强制重新检测只执行一次，不形成持续轮询或探测循环；
5. 请求在异步重载期间不得丢失；多个尚未消费的重复请求允许安全合并为一次扫描。

### 3.2 MT5 发现模式

`provision_mt5_bindings_if_missing()` 增加显式模式或等价参数：

- 普通模式：已有 MT5 绑定即返回；没有绑定时保留当前选择路径优先逻辑；
- 强制重新检测模式：忽略已有绑定和已保存单一路径，调用完整 Windows 发现，逐个处理当前运行候选。

### 3.3 探测与绑定安全性

强制重新检测时：

- 先取消并等待当前 Bridge 连接与 MT5 Worker 退出，再开始新一轮探测；
- 只探测当前确实运行、路径仍存在的终端；
- 使用精确可执行文件路径调用受控 MT5 Worker；
- 必须取得合法 Broker、登录号和已连接状态才写入；
- 已有终端 ID按当前账户身份更新，新终端 ID增量写入；
- 某一候选失败不阻止其他候选继续探测；
- 不删除未运行或本次失败的历史绑定；
- 不自动改变 `selected_terminal_instance_id`；
- 不打印账户、路径以外的敏感信息。

### 3.4 `terminal.exe` 候选

运行进程名为 `terminal64.exe` 或 `terminal.exe` 时均进入 MT5候选解析；最终是否为可用 MT5 由精确路径 Worker 初始化、账户身份和连接状态验证决定。注册表和 MetaQuotes 数据目录候选仍要求存在有效终端文件，不扩大到任意 exe。

### 3.5 列表语义

“切换账户”继续展示当前 Profile SQLite 中已知、已验证过身份的终端绑定。重新检测完成并重载后，新绑定进入 `terminal_candidates`。本批次不改变历史离线账户保留语义，也不自动切换主账户。

## 4. 测试与验收

聚焦验收：

- 已有 MT5 绑定且未请求重新检测：不执行全量发现；
- 已有 MT5 绑定且请求重新检测：执行全量发现；
- 强制信号只消费一次；
- 强制信号能安全跨越本地控制请求与异步生命周期重载；
- 探测开始前当前连接与 Worker 已完成停止，不与活动会话争用终端 IPC；
- 强制重新检测不受保存的 `mt5_terminal_path` 限制；
- 不同完整路径保持不同终端实例 ID，同路径仍去重；
- 运行中的 `terminal.exe` 不因缺少同目录 `MQL5` 而在预筛选阶段丢失；
- 单个候选探测失败不阻止其他候选；
- 当前选择不被自动改写；
- 现有 MT5、账户切换和本地控制测试继续通过。

发布验收：

1. `cargo fmt --check`；
2. `cargo clippy --workspace --all-targets -- -D warnings`；
3. `cargo test --workspace`；
4. `scripts/bridge-release/test-release.ps1`；
5. 形成只含本批次代码、测试和计划文档的本地窄提交，使生产构建工作树干净；不推送远端；
6. 版本面核验：公共版本、Native PE、MT5 Worker、MT4 EA、MT4适配器/协议、清单和安装器均按合同记录；
7. 使用唯一 ReleaseId 构建 3.0.0，签名并验证模块包/清单；
8. 构建全量安装包；若生产 Authenticode 证书不可用且未获得“允许未签名安装器”授权，则停止在安装器签名门前，不绕过；
9. 执行 loopback 首次安装和同版本修复演练；
10. 输出产物路径、大小、SHA-256、签名状态和跳过项。

## 5. 回滚

- 源码回滚：本批次使用独立分支和独立工作树，回滚为不合并该提交；
- 本地产物回滚：不使用本次新 ReleaseId 的输出目录；
- 因未上传、未部署、未激活，不涉及生产 current/bootstrap 指针回滚；
- 不删除旧产物，避免影响既有安装器和审计证据。

## 6. 剩余风险

- 当前无法直接在用户那台含 5 个真实终端的电脑上执行端到端探测；本地测试和隔离安装演练不能替代该设备验证；
- MetaTrader5 Python 包能否连接某个仅复制 exe 的终端，仍取决于该终端自身是否完整、已登录并已连接；
- `terminal.exe` 同时可能是 MT4，强制重新检测时会产生一次失败的 MT5只读探测，但不会写入绑定；
- 同版本号 3.0.0 无法仅凭 UI 版本区分旧包和新包，必须同时记录唯一 ReleaseId、源提交和 SHA-256。

## 7. 计划审查记录

### 第一次审查

结论：修复边界和数据安全约束正确，但初稿未明确异步请求不丢失及生产构建的干净提交要求。

调整：

- 增加重新检测信号跨异步生命周期传递、一次消费和重复请求合并约束；
- 增加本地窄提交作为生产构建前置门，明确不推送远端；
- 保留不删除历史绑定、不自动切换账户、不改变终端生命周期的安全边界。

剩余风险：真实用户设备上的 MetaTrader5 Python IPC 行为仍需安装后现场验证。

### 第二次审查

结论：运行时控制流会在偏好变更后先取消并等待活动连接结束，再继续生命周期下一轮，适合承载一次性强制探测；发布模式已明确为本地全量安装包，未越过上传和激活边界。

调整：

- 将“先停止并等待当前连接/Worker，再探测”加入设计和验收；
- 确认同版本构建用唯一 ReleaseId，并以提交和 SHA-256 区分产物；
- 确认未获授权时不以 `AllowUnsignedInstaller` 绕过生产 Authenticode 门。

剩余风险：需要在受影响电脑上用最终安装包验证五个进程中每个终端的实际 MT5 IPC可用性；本地发布演练只能验证安装、修复和打包闭环。

## 8. 第二轮现场反馈优化（2026-08-10）

### 8.1 新证据与问题修正

客户机截图证明运行进程和账户菜单仍不完全对应：3 个 `terminal64.exe` 只有 2 个形成 MT5 账户条目。第一轮实现已经完整枚举运行路径，但菜单只展示探测成功并写入 SQLite 的账户绑定，探测失败的运行终端完全不可见；同时探针丢弃 Python 标准错误并把多数失败折叠为 `mt5_probe_failed`，无法区分初始化失败、未登录和未连接。

点击“重新检测”还会对已经识别的 MT5 路径再次执行 `MetaTrader5.initialize(path=...)`。该调用建立终端 IPC，可能让已有 MT5 窗口前置；`CREATE_NO_WINDOW` 只隐藏 Python 子进程控制台，不能抑制 MT5 窗口行为。

### 8.2 优化设计

1. 强制重新检测仍完整枚举当前运行的 `terminal.exe` / `terminal64.exe` 路径，但先按终端实例 ID 和规范化路径匹配现有 MT5 绑定。
2. 已绑定、路径一致且仍运行的终端直接复用账户绑定，不再调用 Python 探针；不得增加连接代数、删除历史或改变当前选择。
3. 只有没有可复用绑定的新增路径才调用 `MetaTrader5.initialize()`；一个新增候选失败不阻止其余候选。
4. 探针必须返回结构化成功或失败结果，至少保留稳定错误码，并在本地日志中按终端 ID记录；不得记录密码、令牌或私钥。
5. 对当前运行但未形成账户绑定的 MT5 候选，向账户菜单发布不可选择的安装条目，以目录名称和安全失败原因说明“已发现但未登录/未连接/探测失败”，使进程数量和账户数量的差异可解释。
6. 探针前记录当前前台窗口，探针完成后尽力恢复；不得主动关闭、最小化、登录或切换 MT5 账户。此措施是 Windows/MetaQuotes IPC 副作用的缓解，不承诺底层终端绝不短暂闪动。
7. “重新检测”仍异步执行，但 UI 状态重载后必须包含新账户或失败占位条目；不得把请求已接受表述为所有终端已成功识别。

### 8.3 第二轮验收

- 两个已绑定运行终端加一个新增运行终端时，只探测新增终端；
- 现有绑定的账户和连接代数保持不变；
- 新增终端成功时进入可选择账户列表；
- 新增终端未登录、未连接、初始化失败或超时时，进入不可选择的说明条目并记录稳定错误码；
- 同一路径的注册表、数据目录和进程来源仍只形成一个候选；
- 探针执行后调用前台窗口恢复逻辑，且没有显式终端启动、关闭、最小化或账户切换；
- MT4 候选和现有账户切换语义不回归；
- 重新执行 Rust 聚焦测试、格式、Clippy、Workspace 测试和 Node 全量测试；
- 使用新的唯一 `ReleaseId` 构建、签名、验签、执行 loopback 首次安装和同版本修复演练，并生成经用户授权的未签名 3.0.0 正式安装器；
- 仍然不上传七牛、不更新下载元数据、不推送、不部署、不激活。

### 8.4 第三次计划审查

结论：第一轮“对所有运行路径重新探测”扩大了发现范围，但错误地把已知账户也置于有 UI 副作用的 IPC 探测中；列表也缺少失败占位语义。

调整：将强制扫描拆为“复用已知绑定”和“仅探测新增路径”，增加结构化失败、不可选择条目及前台窗口恢复。保留路径级终端身份，不按账户去重，以支持同账户在不同终端实例中独立存在。

剩余风险：MetaTrader5 官方接口没有“禁止窗口激活”参数；前台恢复只能缓解新增终端首次 IPC 连接的可见副作用，最终仍需客户机验证。

### 8.5 第四次计划审查

结论：方案未改变账户、命令、交易权限、终端生命周期或更新信任链；失败条目复用现有不可选择候选合同，不需要扩大本地控制 API 权限。

调整：明确不重新激活已有绑定、不增加连接代数、不删除历史；把现场验收拆分为数量解释、焦点恢复和新增账户发现三项，发布继续使用新 `ReleaseId` 与 SHA-256 区分同版本产物。

剩余风险：客户机使用“只复制 EXE”的非标准终端布局，Python IPC 是否能连接仍由 MetaTrader5 自身决定；新日志和灰色条目将使失败原因可观察，但不能替代完整终端文件和有效登录连接。
