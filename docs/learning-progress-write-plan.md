# 学习进度写入实施方案

## 范围与用户结果

承接新表读取和主站课程登录链路。当前课程提供外部媒体导航，没有可验证的播放器时间事件；首个写入流程是当前用户显式“标记已学完”或取消标记。保留已有 watched_ms、reported_duration_ms、quiz_passed，不推算、归零或截断历史观看时间，也不把完成标记当作考试通过。

写入只针对 dev_vue 的 learning_* 新表，追加迁移与学习域代码；旧课程、旧进度和迁移来源证据保持不变。所有新增时间以 UTC DATETIME(3) 保存，主站按北京时间显示。

## 数据与接口

1. GET 课节进度增加十进制文本 revision；有行返回真实正整数，没有进度以 null 表示，由命令使用 expected_revision="0"。新字段同步 OpenAPI、共享 Zod、MySQL reader 和前端消费者。
2. `PUT /api/v4/learning/courses/:courseId/lessons/:lessonId/completion` 只接受 completed 布尔值、expected_revision 文本和 UUID 幂等键（遵循现有 Idempotency-Key 头）。拒绝额外字段，不接受用户 ID、观看时长、考试状态或客户端更新时间。
3. 响应只返回 lesson_id、completed、revision、updated_at 与 replayed；时间与版本取事务结果，重放使用原回执，不能返回后续写入的新版本冒充原结果。
4. 追加 learning_progress_changes 审计兼幂等表：用户/请求唯一、进度/结果版本唯一，保存请求摘要、课节、修改前后完成状态、前后版本和 UTC 时间。外键关联 users、learning_lessons、learning_progress；正整数版本、严格 UUID/SHA256 和状态约束在应用及数据库两层校验。
5. 原行不存在时创建 native 进度，观看/报告时长与考试状态保持 null；原行存在时只改 completed、revision、updated_at_utc。legacy_import 行保留原来源标识与 source_sha256，新增审计明确记录原值之后的业务变化。

## 权限、并发和异常

- 路由复用 WWW 会话、精确 Host、Origin 和 CSRF；服务端身份进入应用命令。发布状态、课节所属课程和会员权益必须在写事务内再判断，不能仅凭旧页面的 allowed 状态。
- 固定锁序：用户 → 课程/课节 → 权益 → 当前进度/请求回执。权益经 commerce 的事务读取端口获取，不跨域导入内部文件。新增行同样由用户锁串行化，同用户多页面不会双创建；不同用户互不串进度。
- 相同请求 ID 和完全相同命令返回原回执，不再改记录；同键不同正文返回幂等冲突。重放先校验当前访问权限，不能借旧回执绕过已失效权限。
- 版本不符返回 409，页面重新读取后由用户决定；禁止自动用新版本覆盖。BIGINT 按文本/BigInt 比较，不能转 Number。
- 更新与审计在同一个短 MySQL 事务提交。提交确认丢失返回明确未知结果，销毁连接，不自动生成新请求键；用户重试沿用原键和原正文，靠持久回执确认。
- 前端保存请求期间禁用重复操作；不乐观宣告成功。切换课程、退出、权限变化和晚返回不得覆盖新页面状态。未知结果保留重试上下文，明确提示确认状态。

## 验收和推进顺序

先完成合同、事务 repository 与故障行为测试；再在恢复副本演练追加 DDL 的约束、重复执行、中断恢复和结构指纹。沿现有 62 步 coordinator 追加新步骤，验证原表逐项不变后升级当前 dev_vue。禁止手工改升级日志或改写已执行 SQL。

真实 MySQL 验证包括同键重放、同键不同内容、并发同版本只能成功一次、首次创建竞争、权限失效、提交后确认丢失及独立 SQL 回读。测试工具在本地执行，虚拟机只承担数据库。实际业务接口接入和前端按钮应在目标结构就绪后装配。

数据库回滚通过关闭新写入口保留新增审计和既有数据，不删除表或把已发生业务修改恢复成迁移快照。迁移导入验收属于首次切换基线，不能在已有用户修改后再次按源覆盖目标。

## 第一轮复审：需求与职责

采用显式完成标记，避免在外部播放器没有回调时伪造观看进度；合并审计与幂等回执为一张用途明确的追加表，避免引入无必要队列。学习域拥有进度，commerce 提供权益端口，auth 提供会话与 CSRF。没有新增播放器、课程管理或认证机制。

## 第二轮复审：数据与并发

历史两条超时长记录与所有原始时间、来源标识保持；新写只改变命令明示字段。用版本冲突避免多页面覆盖，用同事务回执处理确认丢失，重放重新授权；新增 DDL 必须走恢复副本和原有 coordinator。剩余风险是实际 MySQL 锁序及权限变动竞争尚未演练、浏览器真实登录尚未验收；这些是写入提升前的验证门，不能用 Mock 代替。

## 实施结果（2026-09-08）

已完成事务实现、真实恢复副本演练、当前 dev_vue 的 62→64 步升级、保存接口、主站按钮与浏览器验收。GET 详情额外返回 viewer_user_id，保存前用新会话核对页面所属用户；账号或权限变化时清空旧快照。字段兼容采用先后端后前端：旧客户端忽略新增字段，新客户端缺少 revision/viewer_user_id 时拒绝解析，不猜测身份或版本。

真实 MySQL 的首次创建竞争、已有行版本竞争、权益过期/下架后的重放拒绝、精确大整数和提交确认丢失恢复均通过。发现 CHAR 请求键会裁剪尾部换行，已保留执行过的 023 原文件并追加 024 纠正。恢复副本的四个已知 ASCII 正则字面量表达差异通过精确指纹限定适配，当前 dev_vue 不放宽检查。

源码 API 入口已装配业务写服务，实际完整运行进程未启用；当前 dev_vue 只做结构升级，没有改写 5 条真实个人进度。浏览器使用本地验收上游，真实账号/Redis 的完整 SSO 仍待验收。详见 [阶段188](migration/dev-vue-inplace-stage188-20260908.md)。
