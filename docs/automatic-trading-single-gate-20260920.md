# 自动交易单一开关实施记录（2026-09-20）

## 目标

首页与订阅设置只保留“AI 交易员”开关。启用后，模型提出的动作在通过账户权限、行情状态、确定性风控、订阅时段、版本一致性与 Bridge 校验后直接进入发送链路；不再存在独立的“允许发送交易”开关或拒绝原因。

本次只改源码与测试，不发送真实订单，不修改运行库数据，不重启或部署服务。

## 复核一：职责、范围与过度设计

- 单一业务状态源为订阅 `trader_enabled`。关闭表示只分析，开启表示允许 AI 交易员评估并发送通过风控的动作。
- 不新增状态、数据表或迁移。现有 `trade_send_enabled` 数据库列与 HTTP 字段暂留作兼容别名，服务端写入时与 `trader_enabled` 同步，执行链路不再读取它作为门槛。
- 移除订阅编辑、订阅列表和账户风控中的独立发送开关及状态文案。
- 不放宽账户 `trade_permission`、平台/账户暂停、风险额度、行情新鲜度、订阅时段、版本一致性和 Bridge 侧校验。
- 首页运行状态按每个订阅的品种聚合，不再用当前图表品种代表全部订阅。

结论：采用兼容字段保留、业务门槛删除的最小改法，避免一次无必要的破坏性合同与数据库迁移。

## 复核二：兼容、数据、并发、异常与回滚

- 旧记录即使 `trade_send_enabled=0`，只要 `trader_enabled=1`，发布后也会进入正常自动交易链路；这是用户要求的核心行为变化。
- 旧客户端仍可读取或提交兼容字段，但服务端忽略其独立含义并按 `trader_enabled` 归一化，避免重新制造双状态。
- 不批量更新历史记录；后续订阅写入自然同步兼容列。回滚代码后旧列仍存在，但回滚版本可能重新采用旧值，因此回滚前需先评估已更新订阅。
- 账户权限、风险快照、风控规则、行情与 Bridge 失败均继续 fail-closed；测试必须证明移除的只有发送许可门槛。
- 定向回归发现 `user_command` 曾把风控拒绝强制改为通过，并在 Bridge 派发策略中跳过检查；该旁路一并移除，确保手动与自动动作都服从确定性风控。
- 多品种状态按订阅逐项计算：全部休市显示“休市暂停”，无可运行品种且存在未知/受限显示“行情待确认”，部分品种可运行显示“部分运行”。

结论：无需迁移；用服务端归一化、查询条件移除和定向回归覆盖兼容风险。
