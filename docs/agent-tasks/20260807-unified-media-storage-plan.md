目标范围：管理后台、网站视频、课程附件、图片及后续需要上传保存的文件

- 阶段 5：已完成 provider/用途/状态汇总、本地磁盘健康、过期会话清理、待删除有界重试和运维手册。

## 一、结论

本项目应建立一层统一的文件存储服务，由管理后台决定不同文件类型使用“本地存储”还是“七牛对象存储”。第一阶段只正式支持两种存储后端：

1. 本地存储：文件保存在网站服务器的数据目录，通过现有权限接口读取。
2. 七牛对象存储：浏览器使用服务端签发的短期上传凭证直传私有空间，读取时由网站验证用户权限后签发短期访问地址。

上传式视频首期明确使用七牛私有对象存储：原始文件统一为 `MP4 + H.264 + AAC + 1920×1080`，上传前或服务端确认阶段验证 MP4 Fast Start，网页通过 HTTPS CDN、短期私有地址和 Range 请求边下边播。不启用七牛实时转码、不生成 M3U8、不接入腾讯云点播。现有哔哩哔哩、YouTube 等外部视频来源继续兼容，但不是新上传视频的默认路径。

第一阶段不同时接入阿里云 OSS、腾讯云 COS、S3、Cloudflare R2 等多家对象存储，也不自动搬迁已有文件。代码保留清晰的 provider 接口，等确有使用需求时再增加提供商。

## 二、需求确认

本方案覆盖以下需求：

- 管理后台“系统设置”增加网站媒体存储配置，能够维护七牛配置。
- 视频、附件、图片以及后续其他上传文件均可选择本地存储或七牛对象存储；当前推荐默认均使用七牛，新上传视频的云端实现固定为七牛。
- 不因切换默认存储方式导致旧文件失效、权限绕过或错误删除。
- 视频上传、播放，附件上传、下载，图片展示继续遵守原有会员和管理员权限。
- 配置切换只影响新上传文件，不隐式迁移、覆盖或删除已有文件。
- 上传失败、配置不可用、云服务异常时明确失败，不把云文件误记为本地文件，也不静默切换存储位置。

## 三、现状审查

### 3.1 已存在但后台不可见的七牛配置

`server/db.js` 初始化数据已经包含 `qiniu.access_key`、`secret_key`、`bucket`、`domain`、`region`。但是 `server/routes/config.js` 的 `ADMIN_CONFIG_SCHEMA` 没有开放 `qiniu` 分类，系统设置接口只序列化白名单中的分类，因此后台不会显示这些数据库记录。

管理后台前端已经有七牛字段的中文标签和区域选项，但 `systemCategoryMeta` 与 `systemCategoryOrder` 同样没有 `qiniu`。这说明当前问题不是单纯缺一张页面，而是后端白名单和实际网站存储能力都尚未接通。

### 3.2 当前上传链路彼此独立

| 文件类别 | 当前保存方式 | 当前记录方式 | 主要问题 |
| --- | --- | --- | --- |
| 课程视频 | `public/uploads/videos` 本地磁盘 | `video_streams.local_path`、`courses.local_video_path` | 上传流量和播放流量都经过网站服务器；只输出固定 MP4 类型；删除路径存在旧实现差异 |
| 课程附件 | `server/private-uploads/course-attachments` | `course_resources.url` 使用私有 URI | 权限链路较完整，但只能本地保存，单机磁盘是唯一副本 |
| 帖子图片 | `public/uploads` | `post_assets.url` | 使用公开静态路径，不适合统一私有访问策略 |
| 课程导图、信息图等 | `public/uploads/resources` | `course_resources.url` | 直接写本地磁盘，与附件使用两套实现 |
| 七牛视频字段 | 数据库仅有 `qiniu_key` | `video_streams.qiniu_key` | 没有完整直传、鉴权播放和可靠删除链路 |
| Bridge 发布包 | 独立发布脚本上传七牛 | 签名发布清单 | 属于软件发布系统，不应与网站媒体资产生命周期合并 |

### 3.3 现有七牛视频接口不应直接扩展使用

- `/api/qiniu-callback` 要求管理员登录令牌，不能作为七牛服务器到服务器的真实回调鉴权机制。
- `/api/stream` 仍只返回本地上传地址，并没有生成对象存储上传凭证。
- 前端根据 `bilibiliId -> localPath -> qiniuKey` 的隐式优先级选播放源；多个旧字段并存时可能播放错误来源。
- `qiniu` SDK 当前位于 `devDependencies`。网站运行时若使用它，应移入 `dependencies`，否则生产环境执行 `npm install --production` 后不能依赖该包存在。
- 当前 `qiniu_key` 只是键名，缺少存储提供商、可见性、状态、哈希、MIME、对象删除状态等统一元数据。

### 3.4 当前可保留并复用的能力

- 系统设置已经支持敏感字段加密、脱敏回显、管理员权限和审计日志。
- 课程附件下载已经先校验课程状态和会员权限，再由服务端返回文件。
- 本地视频已经具备 Range 请求支持和会员权限判断。
- 图片上传已经具备文件签名识别，不能退回只相信扩展名或浏览器 MIME。
- 课程内容、视频和附件后台已经有上传进度、关联课程和删除入口，可在原界面升级，无需新建第二套内容后台。

### 3.5 当前前端基线与必须替换的行为

- `public/admin/app.js` 的系统设置已经具备分类导航、敏感字段“已配置”状态、脏数据标记、统一保存反馈和中文错误处理，新增存储设置应复用这套交互。
- 当前课程视频上传仍使用单次 XHR 上传到网站服务器，只展示 0–100% 和“正在处理视频”两个阶段；网络中断后不能恢复，也无法表达“七牛上传完成但服务端尚未确认”。七牛直传不能只替换请求地址，必须同步升级上传任务状态。
- 当前上传控件允许 MP4、WebM、MOV 和 MKV，而新方案明确只接收可直接播放的 H.264/AAC 1080p MP4；前端提示、`accept` 属性和服务端规则必须同时收紧，避免管理员上传结束后才发现格式不合格。
- 当前主站的七牛播放器最终复用原生 MP4 播放器，并已使用 `preload="metadata"`。这部分方向正确，应保留；新增工作主要是签名地址获取、过期恢复、错误解释和布局稳定性，而不是更换播放器框架。

## 四、视频除了存储桶之外的方案

### 4.1 方案对比

| 方案 | 适合场景 | 优点 | 主要限制 | 本项目建议 |
| --- | --- | --- | --- | --- |
| 本地服务器托管 | 测试、少量低并发视频 | 成本直观、控制简单 | 占服务器磁盘和出口带宽；备份、扩容、Range 并发均由自己承担 | 保留为可选项和回退路径，不作为大量付费课程的长期首选 |
| 对象存储 + CDN | 图片、附件、原始视频和低复杂度视频 | 存储与网站服务器解耦，直传可减少网站入口带宽 | 普通存储桶不自动提供完善的转码、自适应码率和播放分析 | 第一阶段云存储实现采用七牛私有空间 |
| 专业云点播 | 大量课程、移动网络、多清晰度和付费内容 | 自动转码、HLS/DASH、自适应码率、封面、播放鉴权和统计 | 费用结构和接入明显更复杂 | 当前明确不实施；未来只有需求改变时才另立方案 |
| 第三方视频平台嵌入 | 公开内容、引流内容 | 网站几乎不承担存储和播放带宽 | 平台策略、广告、地区和登录限制不可控，付费内容保护较弱 | 保留哔哩哔哩/YouTube 作为外部来源，不作为私有课程唯一方案 |
| 自建 MinIO/流媒体集群 | 有专职运维、跨节点和私有基础设施 | 数据和协议自主 | 高可用、备份、CDN、转码和监控都需自行运维 | 当前阶段不采用，明显超出项目规模 |

七牛私有空间必须使用临时下载凭证，不能向付费课程返回永久公开链接：<https://developer.qiniu.com/kodo/manual/1656/download-private>。

### 4.2 推荐选择

最终选择“七牛私有对象存储 + HTTPS CDN + 短期签名地址”，统一覆盖视频、附件、图片和其他文件。本地存储保留为后台可选项和回退路径。

视频直接保存原始1080p MP4。当前平均每个视频15分钟、每天新增1个，不需要为单一1080p清晰度重复转码；播放器依靠 MP4 Fast Start 和 HTTP Range 实现边下边播。若未来需要多清晰度或自适应码率，必须重新评估并形成独立方案，不能在本次实现中预埋未使用的云点播流程。

## 五、目标架构

### 5.1 配置层

系统设置新增“文件与媒体存储”分类，使用新的 `media_storage` 配置类别；已有 `qiniu` 凭证分类作为该页面内的“七牛连接配置”展示。不要直接把 Bridge 发布行为绑定到这些开关。

建议配置项：

| 配置项 | 可选值 | 说明 |
| --- | --- | --- |
| `default_provider` | `local` / `qiniu` | 未单独指定类型时，新上传文件的默认存储 |
| `video_provider` | `inherit` / `local` / `qiniu` | 上传式视频的存储位置；默认 `qiniu`，外部视频不受此项影响 |
| `attachment_provider` | `inherit` / `local` / `qiniu` | 课程附件和其他私有下载文件 |
| `image_provider` | `inherit` / `local` / `qiniu` | 帖子图片、封面、信息图等 |
| `resource_provider` | `inherit` / `local` / `qiniu` | 其他上传资源 |
| `local_root` | 只读或环境变量控制 | 展示实际数据目录，不允许后台随意写绝对路径 |
| `qiniu.access_key` | 敏感 | 加密保存，不回显原值 |
| `qiniu.secret_key` | 敏感 | 加密保存，不回显原值 |
| `qiniu.bucket` | 普通 | 七牛空间名称 |
| `qiniu.domain` | 普通 | HTTPS 自定义访问域名 |
| `qiniu.region` | 枚举 | 存储区域提示，实际上传端点仍由 SDK 查询 |
| `qiniu.private_bucket` | 固定为 `true` | 第一阶段为权限安全锁定，不允许后台切成公开 |

管理后台提供“测试连接”按钮，只执行只读的空间访问和临时测试对象上传/删除闭环；测试结果不得回显 AK、SK、上传令牌或签名地址。

配置保存规则：

- 新配置未通过字段校验时不得保存。
- 把任一文件类型切换到七牛前，必须先通过七牛连接检查。
- 配置切换只影响后续上传，不修改已有资产的 `storage_provider`。
- 七牛暂时不可用时上传明确失败，不自动落到本地，以免管理员以为文件已存云端。
- 本地路径由环境变量或服务器固定配置决定，后台只能看到状态和磁盘空间，不能填写任意目录。

### 5.2 统一存储接口

新增 `server/storage/`，首期只包含：

- `storage-service.js`：按文件类型解析配置并选择 provider。
- `local-storage-provider.js`：安全保存、读取、删除本地文件。
- `qiniu-storage-provider.js`：签发上传凭证、查询对象、生成私有下载地址、删除对象。
- `storage-config.js`：读取并短时缓存经过解密的配置；保存后主动失效缓存。
- `storage-policy.js`：文件类别、大小、扩展名、文件签名、可见性和对象键规则。

统一接口只需要以下最小能力：

```text
put(file/context) -> stored object
createDirectUpload(context) -> short-lived upload session
confirmDirectUpload(session/result) -> verified stored object
createReadUrl(object/viewer) -> local protected route or short-lived cloud URL
delete(object) -> idempotent result
stat(object) -> existence/size/hash metadata
```

第一阶段不实现跨云复制、自动故障切换、版本化对象、去重存储或通用工作流引擎。

### 5.3 统一文件元数据

新增 `stored_files` 表，作为新上传文件的统一存储事实：

```text
id
purpose                 video / attachment / image / resource
storage_provider        local / qiniu
object_key              provider 内部相对键，禁止保存密钥和临时签名 URL
original_name
mime_type
extension
size_bytes              BIGINT
sha256                   可为空；服务端直传必须记录，云直传确认后按能力核验
visibility              public / authenticated / membership
owner_type              course / post / system 等
owner_id
status                  uploading / ready / deleting / deleted / failed
created_by
created_at / updated_at / deleted_at
```

现有业务表增加可空的 `stored_file_id` 或对应外键。旧字段继续读取，不做一次性强制回填：

- 新上传优先写 `stored_files`，业务关联成功后才标记 `ready`。
- 读取时优先使用 `stored_file_id`；为空时走现有 `local_path`、私有 URI 或 URL 兼容逻辑。
- 删除时先解除业务关联，再通过 `stored_files` 执行幂等删除；失败记录为 `deleting`，允许管理员重试。
- 后续可按批次登记旧文件，但迁移前后都必须保持可访问。

不在数据库保存七牛临时下载 URL，因为它会过期；只保存 provider 和对象键。

### 5.4 上传流程

#### 本地文件

1. 管理员发起上传，服务端验证身份、用途、大小上限和文件数量。
2. 使用临时文件或内存接收，验证文件签名、扩展名和 MIME 的一致性。
3. 写入最终目录前生成不可预测的对象键，禁止使用原文件名作为磁盘路径。
4. 文件落盘成功后写入 `stored_files`，再写业务关联。
5. 任一步失败，清理本次临时文件；不得删除已有旧文件。

#### 七牛文件

1. 管理员请求直传会话，服务端根据用途生成限定 bucket、对象键、大小、MIME 和短有效期的上传凭证。
2. 浏览器直接上传七牛，视频和大附件不再经过网站服务器入口带宽。
3. 浏览器把上传结果提交给确认接口。
4. 服务端使用七牛管理接口核验对象键、大小等信息，确认无误后把 `stored_files.status` 从 `uploading` 改为 `ready` 并建立业务关联。
5. 未确认会话超时后由清理任务标记失败；仅删除属于该会话前缀且能够证明归属的孤立对象。

七牛官方推荐由业务服务器签发上传、下载和管理凭证，客户端不接触 AK/SK：<https://developer.qiniu.com/kodo/12019/security-upload-download-manage-data>。

#### 七牛1080p MP4视频

1. 管理员选择视频后，前端先检查扩展名和大小；服务端创建仅允许本次对象键的分片直传会话。
2. 浏览器把原始MP4直接上传七牛，不经过网站服务器，也不触发实时转码、多媒体样式或M3U8任务。
3. 上传完成后服务端查询七牛对象信息，并解析或抽检媒体元数据；只有 `MP4 + H.264 + AAC + 1920×1080` 才进入可播放状态。
4. 服务端必须确认 MP4 的 `moov` 索引适合 Fast Start。若不符合，上传状态标记为“需要优化”，不得把不确定的文件直接发布；管理员在本地无损执行 `-c copy -movflags +faststart` 后重新上传。
5. 业务关联成功后，播放器取得由网站会员鉴权后签发的短期私有URL；浏览器通过 Range 请求分段读取。
6. 对象键使用不可变随机名称。替换视频时上传新对象并切换关联，不覆盖原键，避免 CDN 旧缓存和误删。

七牛 CDN 应开启 Range 回源。官方说明该功能可以减少大文件分发时的回源消耗并缩短响应时间：<https://developer.qiniu.com/fusion/4943/back-to-the-source-configuration>。

### 5.5 读取与权限

- 公开图片：可返回稳定 CDN 地址，但必须使用专用公开前缀，不能与会员视频、私有附件共用公开权限。
- 会员视频：网站先校验登录状态、会员等级和课程状态，再返回短期签名MP4播放地址；响应必须允许浏览器发起 Range 请求，不返回永久URL。
- 课程附件：继续通过现有下载 API 校验课程和会员权限；本地文件由服务端下载，七牛文件则返回或 302 到短期私有地址。
- 管理员预览：同样使用短期地址，不返回永久管理凭证。
- 哔哩哔哩/YouTube：作为明确的 `external` 视频来源处理，不伪装成 `storage_provider`。
- 视频播放来源增加显式字段，不再根据多个非空旧字段隐式猜测优先级；新增上传式视频来源只允许 `local_mp4` 或 `qiniu_mp4`。

### 5.6 删除、替换和异常恢复

- 替换文件采用“新文件上传并确认成功 -> 事务切换业务关联 -> 异步或重试删除旧对象”，避免先删旧文件导致内容中断。
- 删除接口必须幂等；数据库已标记删除但云端暂时失败时保留待重试状态。
- 不允许根据管理员提交的任意 URL 或对象键删除云文件，只能删除数据库中归属明确的对象。
- 对象键按环境和用途隔离，例如 `website/prod/video/...`，Bridge 发布仍使用自己现有的不可变发布前缀。
- 本地磁盘需纳入虚拟机备份和空间告警；云存储需配置生命周期规则，但不能自动清理仍被数据库引用的对象。

## 六、前端设计

### 6.1 系统设置

在现有“系统设置”中增加“文件与媒体存储”，包含：

- 当前默认存储位置。
- 视频、附件、图片、其他资源四类选择器。
- 本地存储状态：目录、可写状态、可用空间；目录只读。
- 七牛配置：AK、SK、空间、HTTPS 域名、区域、连接测试。
- 生效说明：“仅影响新上传文件，已有文件不会自动迁移”。
- 最近一次连接测试时间和结果，不记录敏感响应。

保存配置后不自动上传测试文件；“测试连接”是独立显式操作，避免每次编辑配置都产生云端对象和费用。

前端交互补充要求：

- 复用现有系统设置的分类导航、表单、敏感字段脱敏、保存按钮和审计反馈，不另建一套“云存储控制台”。页面层级最多两层，避免为四类文件各套一张重复配置卡片。
- “全局默认”和四类覆盖值必须同时显示最终生效结果。例如选择 `inherit` 时，旁边直接显示“当前继承：七牛云”，不能要求管理员自行推算。
- 七牛凭证、空间、域名或区域被修改后，旧连接测试结果立即标记为“配置已变更，需要重新测试”；不能继续显示绿色可用状态。
- 七牛配置允许先保存但不启用。将任一文件类型切到七牛时，如果当前配置版本没有通过连接测试，保存按钮必须阻止切换，并给出“先测试连接”的就地提示。
- 测试连接展示明确阶段和结果：检查凭证、空间访问、测试对象上传、读取、删除。失败信息转换为中文原因和下一步，不直接暴露 SDK 错误、请求签名或内部错误码。
- 修改未保存时，切换设置分类、刷新或离开页面要提示存在未保存内容；保存过程中禁用重复提交，但不能清空管理员刚输入的新密钥。
- 本地目录与七牛空间均显示状态摘要；“可用”必须带最后检查时间，过期结果使用中性提示，避免把历史检查误当作当前事实。

### 6.2 内容上传页面

- 上传区域显示本次实际目标，例如“保存到：七牛云（由系统设置决定）”。
- 第一阶段不提供每次上传临时改 provider 的下拉框，防止资产分布失控；管理员应在系统设置按文件类型配置。
- 视频列表明确显示“本地MP4 / 七牛MP4 / 哔哩哔哩 / YouTube”，不显示尚未实现的专业云点播选项。
- 文件详情显示大小、来源、上传状态和创建时间，不显示内部签名信息。
- 云上传使用真实分片/直传进度；完成上传不等于关联成功，必须等待服务端确认后才显示成功。
- 视频上传区明确提示只支持 `MP4 / H.264 / AAC / 1920×1080`，并显示“原文件直传，不进行云端转码”。不合格视频给出可执行的本地转换提示，不在网站服务器同步转码。

上传任务必须使用统一状态模型，而不是只显示一个百分比：

1. `待上传`：已选择文件，显示文件名、大小、目标存储和关联课程。
2. `正在上传`：显示真实字节进度、百分比和取消操作；不可用估算值冒充实际进度。
3. `正在校验`：上传已到 100%，服务端正在核验对象、媒体规格和业务关联，进度条保持完成但状态不能写“上传成功”。
4. `可以发布`：服务端确认 `stored_files.status=ready` 且业务关联成功后才显示成功，并提供“预览”和“查看课程”。
5. `失败`：保留文件名、目标和失败阶段，提供针对本次会话的“重试”或“重新选择”；不得自动新建重复业务关联。
6. `已取消`：停止继续上传并清理或等待服务端清理本次孤立会话，不影响课程已有文件。

大文件交互采用七牛分片上传的断点续传能力，但首期只保证同一浏览器、同一管理员和未过期上传会话内恢复；不建设跨设备后台上传中心。网络中断时暂停并提示恢复，不能从 0% 静默重传整段视频。

七牛官方将分片上传定义为多个独立 HTTP 分块请求并支持断点续传，同时提示其会增加实现复杂度，因此本方案仅对视频和超过阈值的大附件启用：<https://developer.qiniu.com/kodo/manual/upload-types>。

替换已有视频或附件时，提交前显示旧文件来源和“新文件确认成功前旧文件继续可用”；新文件进入 `ready` 后再切换。上传任务进行中禁止对同一课程重复提交第二个替换任务，其他课程上传不受影响。

前端预检只用于尽早提示扩展名、大小以及浏览器能够可靠读取的时长和分辨率，服务端校验仍是最终结论。音视频编码和 Fast Start 不依赖浏览器猜测；服务端确认不合格时，前端按结构化结果指出具体项目，例如“音频编码不是 AAC”或“不是 1920×1080”，并给出本地 Fast Start 处理提示，避免只显示“格式错误”。

### 6.3 视频播放前端

- 主站继续使用原生 `<video>` 播放器能力，`preload="metadata"`，不自动播放、不预取完整视频；保持现有学习进度、续播和权限语义。
- 播放器只向网站请求“当前可播放地址”，不持久化七牛签名 URL。首次播放、拖动进度或连接恢复时再按需获取，避免页面加载阶段批量签发所有课程地址。
- 若签名地址在播放或后续拖动时过期，前端重新向网站做一次权限校验并取得新地址，在允许误差内恢复 `currentTime` 和播放/暂停状态；失败时显示“播放地址已过期，请重试”，禁止无限自动刷新。
- 加载状态区分“正在验证观看权限”“正在加载视频信息”“网络较慢”；401/403、404、Range 不可用和媒体解码失败分别给出中文操作建议，不直接显示七牛地址或内部错误码。
- 管理员“预览”必须走与会员播放相同的签名和 Range 链路，只提高授权身份，不能使用永久公开地址；这样预览结果才能代表真实播放可用性。
- 播放区域保持稳定的 16:9 占位，错误、加载和重试切换不得引起页面上下跳动。窄屏下播放器宽度随容器缩放，控制区不产生横向滚动。

### 6.4 可访问性、响应式与前端性能

- 文件选择区必须可点击、可键盘聚焦并有明确标签；拖拽只是增强能力，不能成为唯一上传方式。
- 上传阶段使用原生 `<progress>` 或等价的 `role="progressbar"`；状态文本用节制的 `aria-live` 通知阶段变化，不播报每 1% 的变化。
- 所有状态同时使用图标/中文文字，不能只依赖红、绿或金色；按钮具备默认、悬停、键盘焦点、禁用、加载和错误状态。
- 在 820px 以下将配置和上传双列布局收敛为单列；主要按钮和图标操作目标不小于 44px，长文件名可换行或中部省略，不能挤出视口。
- 列表按页或按需加载，不因打开内容后台一次请求全部文件；仅对非终态上传任务做有上限的状态轮询，进入成功、失败或取消后立即停止。
- 新界面沿用 `DESIGN.md` 的色彩、字号、圆角和控件组件，不复制现有页面中的散落硬编码样式，也不新增渐变文字、宽阴影卡片或装饰性动画。状态切换只使用 150–250ms 的透明度/位移动效，并支持 `prefers-reduced-motion`。

## 八、迁移与兼容策略

- 新增迁移而不是修改已发布迁移。
- `stored_files.size_bytes` 使用 `BIGINT`，避免视频大小超过 `INT` 上限。
- 旧字段和旧文件路径保持只读兼容，第一阶段不批量搬迁。
- 每个资产记录自己的 provider；全局配置变更不影响已存资产。
- 迁移脚本只创建表、列和默认配置，不扫描磁盘、不上传文件、不删除数据。
- 如后续迁移旧文件，使用独立可暂停批处理：复制 -> 校验大小/哈希 -> 切换引用 -> 观察 -> 再删除旧副本。
- 回滚应用版本时，新表和新列保留；旧代码仍可读取旧字段。实施阶段必须确保新上传记录在回滚窗口内仍写入兼容字段，或在发布前明确禁止回滚到不识别新资产的版本。

## 九、安全要求

- AK/SK 只能在服务端解密，前端永远只看到“已配置”。
- 七牛空间按用途区分公开和私有权限；若只使用一个空间，第一阶段按私有空间处理，公开图片也由经过控制的地址生成策略提供。
- 上传凭证必须限定对象键、大小、MIME、有效期和不可覆盖策略。
- 对象键不可由用户完整指定，且必须包含环境、用途和随机 ID。
- 云上传确认不能只相信浏览器返回值，必须由服务端查询对象元数据。
- 下载/播放签名必须在会员权限校验之后生成，TTL 应短且由服务器时间计算。
- 文件校验以内容签名和允许列表为主，不只信任扩展名和 `Content-Type`。
- 视频私有URL不得进入数据库、长期缓存、日志、审计详情或前端持久存储；只保存七牛对象键。
- 视频上传确认必须验证容器、视频编码、音频编码、分辨率和 Fast Start；不能因为文件名为 `.mp4` 就判定可播放。
- HTML/SVG 等可执行内容默认不作为普通图片公开直出；下载附件使用 `nosniff` 和安全的下载头。
- 配置变更、连接测试、文件上传、替换和删除都写管理员审计，但敏感值及临时签名必须脱敏。
- 限制上传请求频率、并发会话数、单文件大小和单次文件数量。

## 十、测试与验证

### 10.1 单元与接口测试

- provider 选择：全局默认、分类覆盖、`inherit`、未知 provider 拒绝。
- 配置：字段白名单、加密、脱敏、空值保留、连接失败、缓存失效。
- 上传策略：文件类型、签名、大小、对象键、过期时间、不可覆盖。
- 本地 provider：路径穿越、原子写入、Range、重复删除、磁盘写入失败。
- 七牛 provider：凭证范围、对象核验、签名 URL、404、超时、删除重试。
- 七牛MP4：H.264/AAC/1080p允许，H.265、错误音频编码、非MP4、非1080p和非Fast Start拒绝发布。
- 业务权限：公开、登录、Plus/Pro、仅 Pro、草稿课程、管理员预览。
- 兼容：所有旧路径、旧附件 URI、旧视频字段仍能读取。

### 10.2 集成与浏览器测试

- 管理后台配置保存、脱敏回显、重新加载、测试连接；验证 `inherit` 的最终生效位置、配置改变后测试结果失效、未保存离开提示和重复提交保护。
- 四种文件类别在本地和七牛模式下各完成上传、查看/播放、下载、替换和删除。
- 验证上传状态依次为待上传、上传中、校验中、可发布或失败；100% 但尚未确认时不得显示成功。
- 上传中断、同浏览器恢复、主动取消、页面刷新、重复确认、令牌过期和云端对象缺失；恢复不能生成重复课程关联。
- 视频首播、暂停、拖动、续播、签名过期后单次换址恢复、移动端和不同网络速度；网络面板确认首播和拖动产生合理的分段请求，而不是下载完整文件后才播放。
- 使用带签名测试URL发送 `Range: bytes=0-1023`，确认返回 `206 Partial Content`、`Accept-Ranges: bytes` 和正确 `Content-Range`。
- 切换 provider 后验证旧文件仍从原位置读取，新文件进入新位置。
- 浏览器控制台、网络错误、进度状态和中文错误文案。
- 使用键盘完成配置、文件选择、上传、取消、重试和预览；状态不只依赖颜色，焦点清晰，阶段变化可由读屏软件理解。
- 在桌面、平板和窄屏验证单列收敛、44px 操作目标、长文件名、16:9 播放占位、200% 文本缩放和无横向滚动。
- 验证页面只对活动上传任务轮询，任务终态后停止；打开内容后台不批量签发视频地址，也不一次加载全部文件记录。

### 10.3 上线验证

- 数据库迁移 ID 与表结构。
- 生产环境加密密钥可用，七牛凭证未明文落库。
- 本地目录可写、容量和备份正常。
- 七牛空间、HTTPS 域名、私有访问、上传和删除闭环正常。
- 七牛 CDN 的私有空间回源鉴权和 Range 回源生效，短期URL过期后确实拒绝访问。
- 服务重启后配置和 provider 选择一致。
- 小文件、小附件和测试视频灰度通过后，再开放正式上传。
- 观察错误率、上传耗时、播放失败、待删除数量和服务器出口带宽。

## 十一、回滚方案

- 配置回滚：把各文件类型 provider 改回 `local`，只影响新上传文件。
- 代码回滚：保留新表、新列和云端对象，不执行破坏性数据库回退。
- 内容回滚：新对象未确认前不替换旧关联；切换失败直接继续使用旧文件。
- 云端异常：暂停新的七牛上传，已有云资产继续通过短期签名读取；不能静默把同一资产切到不存在的本地路径。
- 严重播放故障：单门课程显式切回其已有旧来源，而不是修改全局字段覆盖全部课程。

## 十二、两轮方案复审

### 第一轮：需求覆盖、复用、最小改动和过度设计检查

检查结论：

- 已覆盖后台七牛配置、本地/云存储选择、视频、附件、图片和其他文件。
- 复用了现有系统配置加密、附件权限、本地视频 Range、图片签名校验和内容后台，没有另建管理系统。
- 原草案曾考虑第一阶段同时支持“任意 S3 兼容存储”和上传时逐文件选择 provider。复审认为这会扩大配置、测试和运维组合，且用户当前明确缺的是本地与云桶选择，因此删除这两项。
- 原草案曾考虑自动把已有本地文件迁移到七牛。复审认为自动迁移会带来内容中断和误删风险，改为“旧文件原地保留，新上传按新配置，迁移另行授权”。
- 已将“视频也存七牛”落实为确定需求：新上传视频使用七牛私有对象存储，保存标准 `MP4 + H.264 + AAC + 1920×1080` 原文件，通过 HTTPS CDN 和短期签名 URL 播放。
- 原草案保留了腾讯云点播、实时转码和 M3U8 的后续实施阶段。按当前“只需存储和播放”的需求复审后，认为这些内容会引入额外供应商、转码费用、状态机和播放链路，属于过度设计，已从本方案实施范围删除。
- 视频来源仍与通用文件 provider 分开表达：新上传来源只允许 `local_mp4` 或 `qiniu_mp4`，既有哔哩哔哩、YouTube 等外部来源仅保留兼容读取，播放器不再依靠字段是否为空来猜测来源。
- 前端复审没有新增独立云存储页面、全站上传中心、自定义视频播放器或复杂动效；系统设置、内容后台和原生 `<video>` 均复用现有界面。断点续传只限定为同浏览器有效会话，避免把一天一个视频的需求扩展成跨设备上传平台。

第一轮调整后，实施范围收敛为本地 + 七牛、统一元数据、四类文件逐步接入。视频采用七牛原始 MP4 直传和按需分段播放，不建设转码、M3U8、多码率或专业云点播链路。

### 第二轮：兼容性、迁移、并发、异常、安全、测试和回滚检查

检查结论：

- 兼容性：采用可空新关联和旧字段 fallback，配置切换不重写旧资产，符合不中断要求。
- 数据与迁移：只新增迁移；视频大小采用 `BIGINT`；不在迁移中扫描磁盘或调用云接口。
- 并发与幂等：直传会话有状态；确认和删除幂等；替换先确认新对象再切换关联。
- 异常恢复：禁止云失败时静默落本地；保留 `uploading/failed/deleting` 状态并允许安全重试。
- 时间语义：上传凭证和下载签名由服务器时间生成，要求服务器校时；数据库不持久化临时 URL。
- 安全：AK/SK 服务端加密；私有内容先做业务权限判断；对象键、大小、MIME 和覆盖权限受到约束。
- 视频可播放性：对象上传成功不等于可直接播放。确认阶段必须校验封装、视频编码、音频编码、分辨率和 Fast Start；不合格文件不得标记为可发布。
- 按需播放：必须用真实私有域名验证 `Range: bytes=0-1023` 返回 `206`、`Accept-Ranges` 和正确的 `Content-Range`，浏览器播放时不得先下载整个对象。
- 缓存与替换：视频使用不可变随机对象键；替换视频时创建新对象并切换关联，避免 CDN 继续返回同键旧内容。
- 前端状态：上传 100% 与可发布严格区分；签名过期最多自动换址一次；连接测试与配置版本绑定；活动任务停止后不继续轮询。
- 可访问性与响应式：上传可由键盘完成，阶段状态有文字和读屏提示，窄屏收敛为单列，播放器占位固定，状态切换不引发布局跳动。
- 测试：覆盖 provider 切换、旧数据兼容、权限、Range、过期签名、媒体规格拒绝、重复确认和浏览器流程。
- 回滚：新旧路径并存，回滚不删除新表或云对象；但旧版本无法识别只存在于 `stored_files` 的新资产。

第二轮发现四个实质问题：一是“代码回滚后，新上传云资产可能无法被旧代码读取”；二是“七牛对象存在，但编码或 `moov` 位置不合格，仍可能导致网页无法及时起播”；三是“前端显示上传 100% 会被误解为已经发布”；四是“短期签名在后续拖动时过期会导致看似随机的播放失败”。方案已分别增加发布窗口兼容写入、上传后媒体校验、分阶段上传状态、真实 `206` 播放冒烟测试和单次换址恢复。媒体检查应使用可信元数据或有限范围的文件头/尾读取，不得为校验而把整段视频下载回网站服务器。

第二轮重新核对后，当前方案符合“视频存七牛、按需播放、可切本地、不因优化导致数据或文件引用错误”的需求；未保留多云、自动迁移、实时转码、M3U8、腾讯云点播或自建视频集群等过度设计。

## 十三、实施边界与剩余风险

本方案的本地代码与追加迁移已实施；本次没有修改线上配置、上传生产云对象或部署生产服务。

上线前仍需确认：

- 网站媒体是否与 Bridge 发布包使用同一七牛账号；即使同账号，也建议使用不同 bucket 或严格隔离的前缀和权限策略。
- 七牛目标空间是否为私有空间、是否已绑定生产 HTTPS 域名。
- 七牛域名是否已启用并验证 Range 回源、私有空间鉴权和签名 URL 过期行为。
- 本地上传目录的实际备份策略和磁盘容量告警阈值。
- 单个视频和附件的期望上限、预计文件数量与播放并发，用于确定七牛直传分片参数、上传超时和 CDN 监控阈值；这些参数不改变已确定的七牛对象存储方案。

剩余风险：

- 普通对象存储播放大视频虽能减轻网站服务器带宽，但不等于自动获得多清晰度和最佳弱网体验。
- 仅提供原始 1080p 时，用户播放带宽主要由源文件码率决定；弱网环境不会自动降到较低清晰度。
- 私有签名 URL 能降低长期盗链，不能完全阻止已授权用户录屏或二次分发。
- 七牛存储、CDN 下行和请求费用会随视频数量与播放量增长，必须配置用量告警、防盗链和异常流量监控。
- 旧数据路径较多，分阶段迁移时必须为每类文件单独建立回归清单，不能一次性机械替换。
- 本地与云端删除无法参与同一个数据库事务，因此必须依赖状态和幂等重试保持最终一致。

## 十四、最终可实施判定

方案已按“视频也存七牛”的决定完成实施与代码复审。当前可进入本地全量回归和真实七牛环境验收；本批仍不加入第二家云存储、云端实时转码、M3U8 或专业云点播。
