# 自动推理融合持仓管理完整方案

## 1. 方案结论

将挂单管理、持仓管理和新信号判断融合进同一次自动推理是正确方向。它可以复用同一份行情、K 线、缠论结构、策略提示词和记忆，减少模型调用与结论冲突。

但本方案不是直接重新开启旧智能平仓。模型只能提出持仓处理候选，服务端必须验证原交易逻辑是否失效、行情证据是否确认、持仓是否属于当前策略以及 MT5 执行状态。任何信息缺失或结果矛盾都应保持持仓，不得猜测执行。

核心原则：

> AI 判断交易逻辑是否失效，系统验证证据和归属，MT5 止损继续承担即时保护。

## 2. 当前实现现状

### 2.1 自动平仓仍被明确禁用

当前模型输出中的持仓动作只支持开仓、持有、不加仓和观望，提示词明确禁止自动平仓；调度器中的旧智能平仓总开关也保持关闭。因此不能简单打开旧开关，而应按本文建立新的统一推理合同与安全执行链。

### 2.2 当前止盈止损传递情况

| 场景 | 是否传持仓 | 是否传止盈止损 | 说明 |
| --- | --- | --- | --- |
| 平台策略 | 是 | 是 | 只传观摩源中归属于该策略的参考持仓，不传每个订阅用户的真实持仓 |
| 私有策略且开启“传入持仓与挂单” | 是 | 是 | 传用户账户实际持仓、`sl` 和 `tp` |
| 私有策略且关闭该开关 | 否 | 否 | 模型不参与账户持仓判断 |

平台参考持仓当前会优先使用 MT5 的止盈止损，在缺失时回退到原信号止损和 TP1。该做法会混淆“实际保护”和“原始建议”，启用持仓管理前必须拆分为：

- `actual_stop_loss`、`actual_take_profit`：MT5 当前真实值；
- `original_stop_loss`、`original_take_profits`：原始信号建议值；
- `take_profit_tier`：实际选择的止盈档位；
- `protection_status`：是否真实设置保护；
- `protection_modified`：是否被用户或后续流程修改。

## 3. 统一推理职责

每次自动推理生成三个相互独立但一致的计划：

1. **行情计划**：做多、做空或观望，并说明行情状态；
2. **挂单计划**：保留、取消或替换当前策略挂单；
3. **持仓计划**：继续持有、退出，或退出确认后反手。

仅在当前策略存在相关持仓或挂单时计算后两项。没有账户上下文时，不允许模型输出账户动作。

推荐协议：

```json
{
  "market_regime": "bullish | bearish | range | uncertain",
  "trade_thesis": "continuation | reversal | mean_reversion | breakout",
  "market_decision": {},
  "pending_order_plan": {
    "action": "none | keep | cancel | replace",
    "reason": "中文具体依据"
  },
  "position_plan": {
    "action": "none | hold | exit | reverse",
    "managed_direction": "buy | sell | none",
    "reason": "原交易逻辑是否失效的中文结论",
    "evidence": ["M15 已收盘K线跌破 4120"],
    "invalidation": {
      "timeframe": "M15",
      "price": 4120,
      "confirmation": "closed_below | closed_above",
      "required_closed_bars": 2
    }
  }
}
```

输出缺失、枚举错误、价格无效、证据与动作冲突时，统一降级为 `hold`，不得根据自然语言猜测动作。

## 4. 防止震荡误平仓

### 4.1 提示词强约束

提示词必须规定“默认继续持有，退出需要举证”。模型不得仅因以下情况建议自动退出：

- 当前持仓浮亏或接近止损；
- 单根未收盘 K 线、盘中影线或瞬时突破；
- 单个指标金叉、死叉或短周期方向变化；
- 最新行情不再满足开仓条件；
- 多空概率轻微翻转；
- 普通回调、区间震荡或均值回归信号；
- 缠论结构不可靠、数据不完整或周期相互冲突。

“现在不适合新开多单”不等于“原多单应该平仓”。模型必须对照原信号的入场理由与失效条件，证明原交易逻辑已经失效。

### 4.2 服务端安全闸门

提示词不是安全边界。自动退出必须依次通过：

1. **候选闸门**：模型结构化输出 `exit` 或 `reverse`；
2. **证据闸门**：服务端使用已收盘 K 线验证失效价格、周期和方向；
3. **持续闸门**：软反转必须跨越新的已收盘决策周期 K 线，连续两次得到相同结论；
4. **归属闸门**：持仓必须精确属于当前用户、策略、品种和来源信号；
5. **执行闸门**：Bridge、报价、账户模式和 MT5 状态均正常，并通过退出专用风控。

硬失效可在一根已收盘 K 线确认后退出；软反转默认需要两次确认。原止损一旦触发，仍由 MT5 立即执行，不等待下一轮 AI 推理。

### 4.3 原交易论点必须结构化保存

每个开仓信号应保存：

- 主分析周期与决策周期；
- 入场类型、方向和核心依据；
- 关键支撑、阻力及失效价格；
- K 线收盘确认方式；
- 缠论笔、线段、中枢或背驰证据；
- 原始止损、多个止盈候选及实际止盈档位；
- 策略、信号、交付记录和 MT5 ticket。

后续持仓管理判断的是“原论点是否失效”，而不是重新独立预测一次涨跌。

## 5. 平台策略与私有策略

### 5.1 平台策略

平台模型继续只读取观摩源中当前策略的参考持仓，不读取余额、净值、手数、盈亏或订阅用户的私有订单。模型输出通用的市场和持仓意图，分发阶段再根据每个用户的真实账户进行适配：

- 有当前策略对应持仓：进入退出验证；
- 没有对应持仓：不执行持仓动作；
- 只有人工或其他策略持仓：不自动处理；
- 用户持仓与观摩源不一致：以用户真实账户为准；
- 数据不完整或归属不清：仅提示，不执行。

这样可以继续保持一次推理、多用户共享，避免隐私泄露和调用成本成倍增加。

### 5.2 私有策略

开启账户上下文后，可以按用户真实持仓进行个性化判断；关闭时只能输出行情和新信号，不能管理挂单或持仓。该开关应明确提示会增加个人化推理数据和模型调用成本。

## 6. 可管理持仓边界

自动退出只能作用于当前策略产生的系统持仓，并同时满足：

- MT5 Magic 符合系统订单标记；
- ticket 可匹配 `auto_signal_deliveries.trade_ticket`；
- `user_id`、策略 ID、品种和原信号一致；
- 持仓方向和原信号方向一致；
- 账户支持精确关闭该持仓。

仅凭 Magic 不足以证明归属。人工仓、其他策略仓、缺少交付记录的历史仓一律不得自动关闭。

套期保值账户可以按 ticket 精确处理。净持仓账户若混合了人工和系统成交量，必须失败关闭并提示人工处理；只有证明净持仓全部来自当前策略时，后续阶段才可开放自动退出。

## 7. 退出与反手状态机

平仓和反向开仓不得同时发送：

```text
CANDIDATE
  → CONFIRMED
  → CLOSE_INTENT_CREATED
  → CLOSE_SENT
  → CLOSE_CONFIRMED
  → REENTRY_RISK_APPROVED
  → REENTRY_SENT
  → COMPLETED
```

- 平仓失败、超时或结果未知：禁止反手，等待 MT5 对账；
- 部分平仓：禁止反手；
- 平仓成功后：重新读取账户、报价和信号有效期；
- 新方向风控拒绝：保持空仓，不回滚已完成平仓；
- 新方向价格偏离：重新评估或放弃，不追价；
- 每一步使用幂等键，防止服务重启、WebSocket 重连或重复调度造成二次操作。

## 8. 产品配置建议

管理员设置平台最大边界，用户只能在允许范围内选择：

1. **仅展示建议**：默认，仅显示持仓判断；
2. **影子评估**：记录假设执行结果，但不发送 MT5 指令；
3. **自动退出策略持仓**：只平仓，不反手；
4. **退出后允许反手**：平仓确认后重新风控并建立反向仓。

建议初期只提供前两档。自动退出通过影子数据验收后灰度开放；自动反手最后开放，并要求用户单独确认。反手首期最高使用试探仓，不允许模型直接给出绝对手数。

## 9. 前端与审计

推理结果仅在涉及持仓时展示“持仓处理”区域：

- 当前策略持仓与实际止盈止损；
- 继续持有、建议退出或退出后反手；
- 原交易论点与本次失效证据；
- 当前确认阶段和下一步动作；
- 未执行、风控拒绝或 MT5 失败的具体中文原因。

挂单处理同样显示明确依据，如具体被破坏的价格结构、使用周期和已收盘 K 线，而不是只显示“原挂单逻辑失效”。没有挂单或未涉及处理时，不显示该区域。

审计必须串联原信号、交付记录、持仓 ticket、模型结论、证据校验、退出意图、MT5 返回和反向订单结果，禁止只记录“执行未完成”。所有用户可见状态和原因必须中文化，内部规则码仅作为隐藏诊断信息保留。

## 10. 性能与调度

- 复用自动推理现有行情快照，不增加独立智能平仓模型循环；
- 同一根已收盘决策周期 K 线只评估一次，不因轮询重复计数；
- 仅在当前策略存在持仓或挂单时附加账户管理上下文；
- 平台策略保持一次共享推理，不按订阅用户重复调用模型；
- MT5 即时止损、全局风控和账户保护不依赖 AI 调度周期；
- 只传模型判断必需的聚合数据，不传平台策略不需要的账户资金信息。

## 11. 实施阶段

### 阶段一：数据合同修正

- 拆分实际止盈止损与原始建议值；
- 保存结构化入场论点和失效条件；
- 补齐持仓来源与策略归属；
- 扩展模型输出协议和严格校验；
- 旧智能平仓继续保持关闭。

### 阶段二：影子评估

- 将持仓判断融合进自动推理；
- 记录候选、证据验证和假设退出结果；
- 前端展示建议，但不真实平仓；
- 统计误退出率、撤回率、避免损失和震荡反复率。

### 阶段三：自动退出

- 仅支持归属明确的策略持仓；
- 建立退出意图、专用风控、幂等执行和 MT5 对账；
- 优先支持可按 ticket 精确平仓的套期保值账户；
- 不允许自动反手。

### 阶段四：退出后反手

- 平仓确认后重新执行完整开仓风控；
- 首期限制为试探仓；
- 小范围灰度，设置每日自动退出和反手次数上限；
- 稳定后再评估净持仓、部分减仓、移动保护等高级能力。

## 12. 影子评估指标与验收

至少按策略和行情状态统计：

- 建议退出次数、证据确认次数和最终撤回次数；
- 假设退出后，价格先到原止盈还是先到原止损；
- 提前退出避免的进一步亏损；
- 提前退出损失的后续盈利空间；
- 同一持仓在若干根 K 线内反复改变方向的次数；
- 数据不完整、归属不明和 MT5 执行失败比例；
- 自动退出与原止损退出的平均 R 倍数差异。

建议至少覆盖足够数量的真实持仓及趋势、震荡、跳空和高波动场景后再开放真实执行。验收重点不是增加平仓次数，而是证明退出有明确证据、不会误伤非策略订单，并且长期结果优于只依赖原始止损。

## 13. 必测场景

- 接近止损但原逻辑未失效时继续持有；
- 影线刺破后收回时不得退出；
- 一根已收盘 K 线硬失效与两次软反转确认正确区分；
- 同一根 K 线重复推理不增加确认次数；
- 缠论结构不可靠或证据缺失时失败关闭；
- 人工仓、其他策略仓和归属不明仓不会被处理；
- 平台共享结论能按不同用户真实持仓正确适配；
- 平仓未确认、部分平仓或 Bridge 断线时绝不反手；
- 服务重启与消息重放不会重复平仓或重复开仓；
- 实际止盈止损缺失时不会误用原始建议冒充真实保护；
- 所有前端状态、拒绝原因和执行结果均显示自然中文。

## 14. 与反向持仓方案的关系

本文是 `20260723-opposite-position-reversal-execution-plan.md` 的上位统一方案。原文聚焦“遇到反向信号时如何退出并反手”，本文将其纳入每次自动推理的行情、挂单和持仓统一决策中。

最终推荐保持不变：先完成数据合同和影子评估，再开放自动退出，最后才评估自动反手。任何阶段都不能仅依赖提示词直接操作持仓。
