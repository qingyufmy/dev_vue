# 反向持仓与趋势翻转执行方案

## 1. 问题背景

信号 `#6256` 为 `XAUUSD SELL_LIMIT`，模型给出 67% 偏空判断和试探仓建议。信号分发到用户 `#1` 后，执行器实时读取到 1 个 XAUUSD 买入持仓，在进入订单意图和正式风控前，以 `opposite_position_exists` 跳过执行。

当前控制点位于 `server/routes/ai/scheduler.js` 的持仓与挂单对齐阶段：只要交易信号方向与任意同品种持仓相反，就无条件结束执行。因此该次记录中 `order_intent_id`、`risk_decision_id` 均为空，MT5 也没有收到下单命令。

这项保护能避免自动形成多空对锁，但存在明显缺口：当行情已经发生可靠的方向反转时，系统不会处理原方向持仓，新方向信号只能持续被跳过，原持仓只能等待止盈、止损或人工平仓。

## 2. 复审结论

### 2.1 不能直接删除反向持仓保护

直接允许反向开仓会产生以下风险：

- 在套期保值账户中形成无意义的多空对锁；
- 在净持仓账户中改变或冲销原仓位，实际结果难以预测；
- 误关人工订单、其他策略订单或无法追溯的历史仓位；
- 平仓失败但反向开仓成功，导致风险暴露翻倍；
- 普通回调信号被误认为趋势反转，造成频繁来回交易。

### 2.2 反向信号不一定代表趋势反转

`SELL` 可能是下跌趋势延续、顶部反转、区间高抛或短周期回调。仅凭信号方向、置信度或多空百分比，不能决定关闭原持仓。模型必须明确说明这是“趋势翻转”，并给出可核验的结构失效依据。

### 2.3 共享推理与用户账户执行必须分离

平台策略以统一市场行情和观摩源参考组合完成一次推理，但不同用户的持仓可能因接入时间、滑点、人工干预或历史执行失败而不同。共享模型只能输出市场层面的方向变化和通用持仓意图，不能直接指定某个用户的持仓票据。

执行阶段再根据每个用户的真实持仓、订单归属和风控设置，将同一市场结论转换成该账户的具体动作。

### 2.4 本方案不是重新启用完整智能平仓

现有 `SMART_CLOSE_FEATURE_ENABLED = false` 保持不变。本方案只增加由新一轮信号明确触发的“趋势翻转执行链”，不处理移动止损、利润保护、动态减仓、持仓巡检等完整智能平仓能力。

## 3. 目标行为

| 用户当前状态 | 新信号结论 | 系统行为 |
| --- | --- | --- |
| 无持仓 | 普通买卖信号 | 按现有风控开仓或挂单 |
| 已有同向持仓 | 不建议加仓 | 保持持仓，不新增 |
| 已有同向持仓 | 明确允许加仓 | 按加仓上限和风控执行 |
| 已有反向系统持仓 | 未确认趋势翻转 | 保持原仓，跳过新仓并说明原因 |
| 已有反向系统持仓 | 建议退出原方向 | 只平原仓，暂不反手 |
| 已有反向系统持仓 | 确认翻转并允许反手 | 先平原仓，确认成功后再独立风控新方向 |
| 反向仓为人工或其他策略 | 任意反向信号 | 不自动关闭，提示人工处理 |
| 净持仓账户且归属不纯 | 任意反向信号 | 禁止自动翻转，转人工复核 |

## 4. 模型输出协议调整

保留现有 `signal_type`、仓位档位和挂单处理字段，新增独立的市场翻转与持仓计划，避免继续滥用 `position_action=allow_add`：

```json
{
  "market_regime": "bullish | bearish | range | uncertain",
  "trade_thesis": "continuation | reversal | mean_reversion | breakout",
  "reversal": {
    "confirmed": true,
    "from_direction": "buy",
    "to_direction": "sell",
    "strength": "normal | strong",
    "evidence": ["H1 上涨结构失效", "M15 跌破关键支撑 4120"]
  },
  "position_plan": {
    "action": "none | hold | exit | reverse",
    "managed_direction": "buy | sell | none",
    "reason": "原多头结构在 4120 跌破后失效",
    "exit_timing": "immediate | before_new_entry"
  }
}
```

约束如下：

- `reverse` 必须同时满足 `reversal.confirmed=true`、方向相反、中文具体依据完整；
- 依据必须包含价格、周期、结构或指标变化，禁止只写“趋势反转”；
- `mean_reversion` 默认不得触发自动平仓反手；
- `hold` 信号不得要求反手；
- 模型只选择仓位档位，不输出用户最终手数；
- 输出缺失、矛盾或不符合枚举时失败关闭，不根据文本猜测动作。

## 5. 订单归属判定

自动退出只能作用于“当前用户、当前策略、当前品种”的系统持仓，必须同时满足：

1. MT5 `magic = 234000`；
2. 持仓 ticket 能匹配 `auto_signal_deliveries.trade_ticket`；
3. 交付记录的 `user_id`、`prompt_type_id` 与当前执行一致；
4. 原始信号方向与持仓方向一致；
5. 账户类型允许按 ticket 精确平仓。

仅有 Magic 不足以证明策略归属，因为多个策略共用系统 Magic。人工订单、其他策略订单、缺失交付记录的仓位一律不得自动关闭。

对于净持仓账户，如果同一净持仓可能混合人工与系统成交量，第一阶段直接转人工复核；只有能够证明仓位完全由当前策略形成时，才允许自动退出。

## 6. 两阶段翻转状态机

禁止“平仓和反向开仓并行发送”。建议新增可恢复的翻转任务：

```text
DETECTED
  → CLOSE_INTENT_CREATED
  → CLOSE_RISK_APPROVED
  → CLOSE_SENT
  → CLOSE_CONFIRMED
  → REENTRY_RISK_APPROVED
  → REENTRY_SENT
  → COMPLETED
```

任一步失败均停止后续动作：

- 平仓未确认：禁止发送新方向订单；
- 部分平仓：保持任务待处理，禁止反手；
- Bridge 断开或超时：状态记为不确定，等待对账，不自动重发；
- 平仓完成后行情已偏离：重新检查信号有效期、允许价格偏差和挂单方向；
- 新方向风控拒绝：保留“原仓已退出、新仓未建立”的真实状态，不回滚平仓。

幂等键建议使用 `用户 + 信号 + 原持仓 ticket + 动作阶段`，避免重启或重复消息造成二次平仓、重复开仓。

## 7. 风控与配置边界

新增“反向信号处理”设置，平台给出最大权限，用户只能在范围内选择：

- `仅提醒`：展示退出或翻转建议，不自动修改持仓；
- `自动退出原策略持仓`：确认翻转后只平仓；
- `退出后允许反手`：平仓确认后重新经过开仓风控。

上线初期默认值必须为“仅提醒”，先积累影子评估数据。只有影子结果达到验收标准后，管理员才可开放“自动退出原策略持仓”；反手能力始终需要用户单独主动开启。反手执行还必须满足：

- 模型明确输出 `position_plan.action=reverse`；
- 趋势翻转证据完整，且不是区间均值回归信号；
- 信号仍在有效期内；
- 原仓全部关闭并通过 MT5 二次查询确认；
- 新仓独立执行全部现有风控、仓位计算与价格偏差检查；
- 反手仓位最高限制为试探仓或轻仓，第一阶段建议固定为试探仓；
- 周末保护、全局暂停、账户暂停等硬规则仍具有最高优先级。

不建议只使用一个固定置信度阈值决定反手。置信度可作为辅助门槛，但必须与趋势类型、结构证据和账户状态共同判断。

## 8. 异常平仓风险与抑制机制

如果最新一次 AI 判断可以直接触发平仓，确实会产生较多异常退出，典型来源包括：

- 同一行情在相邻两次推理中结论来回变化；
- M5/M15 的普通回调被误判为 H1/H4 趋势反转；
- 使用尚未收盘的 K 线得出短暂结论；
- 模型置信度看似较高，但缺少原持仓逻辑失效证据；
- 平台参考组合与某个用户的真实入场价、止损和持仓状态不同；
- 模型升级、提示词变化或行情数据缺失造成输出漂移。

因此自动退出必须采用“三道闸门”，AI 只负责第一道候选判断：

### 8.1 原交易逻辑失效闸门

不能只判断“当前更偏空”，还必须对照原持仓对应信号的入场逻辑和失效条件。建议把自然语言失效条件升级为结构化字段：

```json
{
  "invalidation": {
    "direction": "buy",
    "timeframe": "M15",
    "price": 4120,
    "confirmation": "closed_below",
    "required_closed_bars": 1
  }
}
```

只有服务器使用已收盘 K 线验证条件成立，AI 的退出候选才可继续。若只是出现反向信号，但原持仓逻辑尚未失效，则保持原仓，不自动退出。

### 8.2 持续确认闸门

除止损、全局风控等硬退出外，软性趋势翻转不得在单次推理后执行。建议要求：

- 至少两次独立推理结论方向一致；
- 两次判断之间必须产生新的已收盘决策周期 K 线，禁止在同一根 K 线上重复计数；
- 高周期方向与决策周期不得明显冲突；
- 翻转后设置冷静期，避免短时间内多空来回切换；
- 同一持仓每日自动退出或翻转次数设置硬上限。

如果行情直接触发原订单止损，应继续由 MT5 止损和现有风控处理，不等待 AI 二次确认。

### 8.3 账户执行闸门

服务器必须再次验证持仓归属、账户模式、Bridge 状态、实时价格和信号有效期。任何数据缺失、部分匹配、净持仓混合归属或 MT5 状态不确定，都不得自动平仓。

### 8.4 影子评估与开放标准

第一阶段只记录“如果开启自动退出，本次会怎样处理”，不发送 MT5 命令。至少统计：

- 候选退出次数和最终确认次数；
- 候选出现后又被撤回的比例；
- 退出后价格继续原方向运行的误退出率；
- 退出避免的进一步亏损；
- 退出损失的后续盈利空间；
- 多空来回翻转次数；
- 不同策略、周期和行情状态下的结果。

只有误退出率、重复翻转率和数据完整率达到管理员设定标准，才允许按策略灰度开放自动退出。自动反手应在自动退出稳定运行后再单独评估，不能与自动退出同时首发。

## 9. 挂单场景处理

翻转前先处理当前策略的原方向挂单：

1. 查询实时挂单；
2. 只选择当前策略历史交付且 Magic 正确的挂单；
3. 根据模型的具体失效依据取消；
4. MT5 二次确认挂单已经消失；
5. 再进入持仓退出阶段。

对于新的反向限价或突破挂单，推荐先退出已确认失效的原仓，再挂新方向订单。系统接受一段时间保持空仓，不应为了追求同时完成而允许短暂对锁。

## 10. 前端与审计展示

推理结果新增“持仓处理”区域，仅在涉及现有仓位时显示：

- 市场判断：延续、回调、反转或不明确；
- 原仓方向、数量和归属；
- AI 建议：继续持有、退出或退出后反手；
- 具体判断依据；
- 当前执行阶段及每一步 MT5 结果；
- 未执行时的中文原因。

风控中心和审计记录应区分：

- `持仓对齐跳过`：没有进入风控；
- `退出风控拒绝`：禁止关闭；
- `退出执行失败`：MT5 平仓失败；
- `退出成功但新仓风控拒绝`；
- `翻转完成`。

必须记录原信号、原持仓 ticket、归属依据、模型翻转结论、关闭结果、新订单意图和最终 MT5 ticket，禁止只保存一句笼统状态。

## 11. 分阶段实施

### 阶段一：输出与可观测性

- 扩展模型输出协议和严格校验；
- 将普通反向信号与确认翻转信号分开；
- 前端展示具体持仓处理建议和依据；
- 保持自动平仓关闭，仅记录影子决策；
- 建立异常平仓指标和按策略统计看板。

### 阶段二：自动退出

- 增加策略持仓精确归属；
- 建立退出订单意图、风控、审计和 MT5 确认链；
- 只支持 hedging 账户完整平掉当前策略持仓；
- 不自动建立反向新仓。

### 阶段三：退出后反手

- 引入持久化状态机和幂等恢复；
- 平仓确认后重新校验行情与风控；
- 首期只允许试探仓反手；
- 小范围灰度并持续观察误反转率、平仓失败率和反手后收益。

### 阶段四：再评估高级能力

根据真实运行数据，再决定是否支持部分减仓、净持仓账户、移动保护和完整智能平仓。本阶段不属于当前改造范围。

## 12. 必测场景与验收标准

- 反向人工仓、其他策略仓、当前策略仓能够准确区分；
- 普通回调 SELL 不会错误关闭 BUY；
- 单次 AI 结论、同一根未收盘 K 线的重复推理不能触发自动退出；
- 原持仓结构化失效条件未成立时不能自动退出；
- 连续确认后行情结论撤回时能够安全取消候选任务；
- 确认翻转时先平仓，平仓未确认绝不反手；
- 重复调度、服务重启和 WebSocket 重连不会重复平仓；
- 部分平仓、拒单、超时、价格变化均失败关闭；
- 挂单取消、持仓退出、新仓风控和 MT5 结果都有中文审计；
- 共享信号在不同用户持仓状态下产生正确的个性化执行结果；
- 人工订单和其他策略订单在任何异常路径下都不会被自动修改；
- 完整智能平仓开关仍保持关闭。

最终验收目标不是“所有反向信号都能成交”，而是：系统能够识别可靠趋势翻转，安全退出可管理的旧方向持仓，并在确认账户已经适合后，才考虑建立新方向仓位。
