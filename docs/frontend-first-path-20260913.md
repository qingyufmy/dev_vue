# 前端第一条用户路径

范围：统一身份中心密码登录 → 应用 SSO 衔接 → trade 壳层 → 账户选择 → 概览。用户于 2026-09-13 明确授权正式开始前端。

## 实施依据

复用四应用、现有 API 和共享 shadcn-vue 组件。前端规范、MASTER 与实际设计令牌均采用默认品牌蓝；trade 深色、其它应用浅色。根 DESIGN 的旧黑金描述不作为新组件颜色来源。本批不改变全局令牌。

本批补齐密码登录已有链路与账户概览，不把注册、找回密码、MFA 产品扩展或旧策略语义验收混入第一条路径。其它认证功能、三种退出的完整产品入口、网站换号和会话撤销跨标签页联动继续保留为明确待办。

## 第一轮复审：用户任务与模块职责

- 认证中心 App 只组装登录 feature；应用各自拥有会话和 SSO 入口，不跨应用共享业务页面。
- 会话读取应区分未登录、权限拒绝与服务异常；已登录用户跨应用无需再次点击登录说明页。
- 自动 SSO 只在明确未认证时发起，并设短时循环保护；主动退出停留在明确退出页面，避免立刻自动登入。
- 概览复用真实 API、现有账户选择和实时投影，修复有证据的状态遗漏，不重写正常模块。
- 不新增组件库、不改后端策略、不启动业务调度或交易 Worker。

## 第二轮复审：兼容、并发与验证

- 会话请求用代次隔离，晚返回不能覆盖退出或更新后的身份；状态只从所属模块公开入口暴露。
- 回跳仅允许本应用内部路径；拒绝外部地址、反斜杠和控制字符，并避免回跳认证入口形成循环。服务端仍负责最终校验。
- 自动跳转标记只记录时间，不保存身份凭据；存储不可用时提供手动继续，不能无限跳转。
- 网络/服务故障不误报密码错误，也不视为成功认证；登录未知结果不自动重放写请求。
- 定向行为测试覆盖异常分类、重复提交、晚响应和自动跳转边界；验证受影响应用类型/构建和前端边界。
- 浏览器验证首先检查匿名登录与错误恢复，再用用户指定网站测试账号验证真实 SSO/概览；不以替身数据宣称真实账户通过。

## 实施前发现

- trade/admin 会话模块将所有读取异常转换为 null；路由把所有失败导向登录。
- auth App 集中业务及表单逻辑，所有登录错误都显示账号密码错误。
- trade 顶栏小屏隐藏全部运行状态，个人菜单有无行为的用户中心入口，退出无错误反馈。
- 当前没有监听 3010/3011/3100/4174/4175/4176 的开发服务，构建输出已由用户清理。

## 剩余风险与验收边界

真实网站测试账号尚待用户指定；公网 HTTPS/独立子域、管理员 MFA、真实终端交易均不作为本地源码验证的已完成结果。服务与数据配置沿用虚拟机 192.168.1.254，不迁移或重置数据库。

## 本批实现与验证结果

- auth 登录拆入独立 feature，支持明确错误分类、提交防重、销毁后晚响应隔离和可访问表单；trade/admin/www 分别管理自身登录衔接、退出停留、回跳校验与循环保护。
- trade 壳层在小屏保留运行状态；概览支持无个人账户时选择观察频道，区分未知状态与明确离线，行情切换先清理旧数据。金额按十进制文本格式化，避免浮点精度丢失。
- 修复真实联调暴露的两个入口问题：admin 开发服务器缺少 API/认证代理；www 原生 fetch 改写 Host 导致 `auth_surface_invalid`。www 固定使用保留已配置官网 Host 的服务端传输，并保持手动重定向及 Cookie 转发，未放宽后端 Host/CSRF 校验。
- 补齐设计令牌包自身导入的 CSS 依赖；使用 pnpm packageExtensions 为 Nuxt 4.5.2 声明与现有运行版本一致的 Vite 类型依赖，解决安装后错误解析到 Vite 6 的类型冲突。没有升级框架版本。

验证证据：

- `pnpm run test:frontend` 通过，四应用测试当时为 trade 215、admin 32、auth 13、www 30；之后 www 新增真实 HTTP 代理回归，定向重跑 31 项通过。
- `pnpm run build:frontend` 通过；最后代理修复后 www、admin 定向构建及 www 类型检查再次通过。
- `pnpm run verify:frontend-boundaries` 通过，检测到的越界与债务记录均为 0；不代表动态组件和 Nuxt 隐式依赖已经完整覆盖。
- `pnpm run build:server:v4` 通过，仅用于构建已有本地联调服务。
- 浏览器使用本地 API 及已有依赖：trade、www、admin 匿名入口均到达对应 client 的统一登录表单；trade 主动退出落页不立即自动登录；admin 服务异常落页可重试恢复。www 使用本次 Nuxt 生产构建在本地 3100 端口验证。
- 登录表单在 320、375、768、1024、1440 宽度检查无横向溢出，输入框高度 44px；交易概览登录后视觉与真实数据仍待账号验收。

本次没有执行迁移、重置数据、启动交易 Worker 或部署公网。当前可从 `http://localhost:4174` 继续网站账号登录验收；官网本地构建在 `http://localhost:3100`，管理端在 `http://localhost:4175`。

## 2026-09-14 网站账号联调

用户在浏览器完成登录后，使用同一浏览器验证：trade 登录状态有效，www 登录入口自动回到课程页，admin 自动进入运营概览，均未再次输入密码。仅退出 admin 后停留在明确退出页，刷新 trade 仍保持登录。本证据仅覆盖 localhost 不同端口，不代表生产独立子域和 HTTPS Cookie 配置已验收。

发现并修复图表运行错误：lightweight-charts 无法解析设计令牌中的 OKLCH，导致 mounted hook 抛错、页面更新中断。图表边界使用浏览器 Canvas 转换为 sRGB RGBA，保留透明度并缓存转换结果，不修改共享令牌。刷新后账户选择恢复响应，XAUUSD M5 K 线与成交量实际绘制正常；trade 类型检查与生产构建完成，差异格式检查通过。

当前真实依赖边界：账户选择只有一个选项，未完成多账户切换验收；页面缺少账户快照和报价，余额等保持未知值；本地 realtime 3011 未监听，页面明确显示实时断开。未启动终端或交易服务，未发送交易指令。官网仍使用静态导航，登录后导航仍显示“登录”，列入后续官网会话导航完善项。完整三种退出、跨标签页撤销和管理员 MFA 专项仍未验收。
