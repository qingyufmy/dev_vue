# V4 本地统一启停

从 `D:/dev_codex/dev_vue` 执行：

```powershell
# 开一个显式总控制台，复用健康的现有服务，只启动缺失角色
powershell -NoProfile -File scripts/local-v4.ps1 start

# 检查全部已登记角色的端口和健康状态
powershell -NoProfile -File scripts/local-v4.ps1 status

# 优雅停止由总控制台创建的进程
powershell -NoProfile -File scripts/local-v4.ps1 stop

# 只校验本地环境与构建文件，不启动服务
powershell -NoProfile -File scripts/local-v4.ps1 check
```

总控制台集中显示输出。默认使用 `full` 完整交易模式，包含 API、网页实时推送、Bridge 网关、公共行情、消息分发、历史同步、风控汇总、分析调度、AI 分析、交易评估、逐笔风控、订单执行、执行恢复调度、复盘，以及登录页、交易页，共 16 个角色。它不启动 MT4/MT5 或桥接 GUI，也不修改账户的自动交易开关。

只做分析与审核调试时，显式使用：

```powershell
powershell -NoProfile -File scripts/local-v4.ps1 start -Profile core
```

`core` 不启动订单执行、执行恢复调度和复盘，不能用于完整交易链路验收。`full` 会处理符合条件的现有队列任务。已有总控制台不能直接变更范围，应先 stop 再以所需范围 start；修改默认值不会自动升级当前运行实例。

status 显示实际运行模式，并单独检查逐笔风控、订单执行、执行恢复调度与 Bridge 网关；缺失或异常时明确提示执行链路未就绪。服务健康不等于终端成交证明。

通知发送 Worker 当前没有健康端点，尚未纳入此入口；管理员网站和展示官网也不属于本次交易工作区范围。生产部署仍使用 ecosystem.v4.config.cjs 与既有部署流程，本地入口不替代 PM2。

## 已运行进程与停止语义

- 已有健康服务标为外部实例并复用，不重复创建，不擅自接管。其他程序占用端口或服务不就绪时停止本次启动。
- stop 只停止总控制台自己创建的子进程；之前逐个启动的外部服务仍需在其原控制台停止。不会按端口扫杀或凭旧 PID 结束程序。
- 因而本次上线不强制迁移当前运行进程。以后从冷启动使用本入口，所有选中角色才都受同一控制台管理。
- 子进程退出后最多自动重启两次；5 分钟内第三次退出即停止重启并保留错误。仅健康检查失败时报告异常，不强杀正在处理任务的进程。
- 正常 stop 通过 IPC 调用既有 SIGTERM 关闭逻辑；15 秒仍未退出则终止该子进程。交易结果是否已完成仍以服务端幂等与回执核对为准。
- 操作系统强制关闭控制台不等于优雅停止，优先使用 stop。

## 配置与诊断

- 使用 `server/.env` 和 `D:/dev_codex/.local-runtime/dev-vue/account-api.env`；可通过 LOCAL_V4_ACCOUNT_ENV 指定账户 API 本地覆盖文件。
- 校验开发库地址/库名、既有本地覆盖合同及固定端口，不修改数据库、端口配置或策略。
- 启动前需要已存在 `server/dist-v4` 构建和前端依赖；入口不会隐式安装依赖、构建或执行迁移。
- 状态查询识别 IPv4 与前端 IPv6 回环监听；前端返回 HTTP 成功只证明页面可访问，不证明登录与业务完整。
- 总控制端口 3040 只监听回环，使用每次运行生成的随机令牌验证停止请求。状态文件与分角色追加日志在 `.local-runtime/dev-vue/unified/`；不要分享 controller.json。日志暂未轮转，长期运行使用正式进程管理配置。
- 业务代码仍各自运行在独立进程；此入口减少操作步骤和控制台数量，不声称降低这些角色的内存消耗。

## 2026-09-16 并发启动检查修复

统一冷启动时，多个只读结构检查共用 `aurum:inplace:<database>` 排他锁。原 `GET_LOCK(?,0)` 将正常检查竞争误判为结构未就绪，导致 API、Bridge、历史同步、交易评估启动退出；并行健康探测也会误报 503。开发库上 8 个并发检查复现为 1 成功、7 次锁竞争失败。

交易、执行工作流、Bridge 安装、历史及历史任务五处结构检查改为最多等待 2 秒。仍持有同一升级锁核对台账和表结构，超时或结构异常仍拒绝就绪；不改数据库结构，不跳过检查。构建后相同并发检查 8/8 成功、无锁失败，约 145 毫秒；76 项相关单元测试通过。随后 core 13 个角色重新启动均就绪，网页可重新检查连接恢复首页。本记录证明本机本次启动，不代表长期稳定或终端交易验收。

## 网页启动顺序

网页进程在 API 健康检查通过后才启动，避免网页代理先收到请求而接口尚未监听造成 ECONNREFUSED。所选角色全部通过启动检查后才报告检查完成；每个等待最多 30 秒，超时会停止本次管理器创建的进程并报告具体角色。已有外部实例不被停止。存活但尚未监听的子进程显示“进程运行，端口未就绪”，不误报为已停止。

5 项管理器测试通过，新增慢 API 就绪前不启动网页、API 超时不启动网页且回收子进程的验证。本机重新启动后的新增日志未发现 startup failed、ECONNREFUSED 或 EADDRINUSE。风控等角色的数据同步状态仍单独按业务健康报告，不因进程启动成功而隐藏。
