# 策略新建与编辑弹窗工作台重设计方案

> 状态：正式实施方案，尚未开始功能代码改造
>
> 适用范围：用户端“AI 策略师”新建/编辑策略、统一管理后台平台策略新建/编辑
>
> 设计基线：`PRODUCT.md`、`DESIGN.md`、`ui-ux-pro-max` 设计与可访问性准则
>
> 核心要求：策略正文是主展示；其他能力与运行设置进入侧栏；界面整体清晰明了；弹窗只能通过“关闭”或成功“保存策略”结束

## 1. 结论

本次不把策略编辑器改成多步骤向导，也不新建独立页面。保留现有单弹窗工作流，但把它重构为一个“策略文档工作台”：

1. 左侧主工作区只承载策略身份、策略正文和写法辅助；
2. 右侧设置栏承载行情周期、缠论、EMA34、持仓与挂单、入场方式、模型和运行频率；
3. 复杂技术信息默认收起，只在需要时展开；
4. 顶部只有明确的“关闭”入口，底部只有一个高强调“保存策略”主操作；
5. 点击遮罩和按 `Esc` 都不得关闭策略弹窗；
6. 有未保存修改时，“关闭”必须经过放弃修改确认；
7. 保存失败、版本冲突或校验失败时弹窗保持打开，正文和所有设置原样保留；
8. 用户端和管理端使用同一信息架构与交互合同，但继续保留各自现有权限、接口和数据边界。

## 2. 当前问题与验证依据

### 2.1 现场验证

在本地用户端以 `1280 × 720` 视口打开现有策略编辑弹窗，测得：

- 弹窗约为 `1180 × 672`；
- 弹窗内部内容滚动高度约为 `2629px`；
- 四个主要区块权重接近，均以大块表单展示；
- 策略正文输入框位于弹窗内容约 `1917px` 之后；
- 用户必须先穿过基础信息、行情周期、数据能力和入场方式，才能开始最核心的策略编辑。

这与“策略正文是主展示”的目标相反，也导致用户难以判断当前最重要的操作。

### 2.2 当前交互问题

现有用户端通用表单弹窗支持以下关闭方式：

- 点击“关闭”；
- 保存成功；
- 点击弹窗外遮罩；
- 按 `Esc`。

管理端实体弹窗也存在遮罩和 `Esc` 通用关闭行为。对于包含长策略正文、能力开关和多个运行参数的编辑器，后两种关闭方式容易造成误操作。

### 2.3 当前信息层级问题

- 策略正文和辅助设置处于相近视觉层级；
- “本策略将收到”的大摘要与设置内容重复，占用较多纵向空间；
- 技术字段对普通用户暴露过早；
- 缠论、EMA34、持仓与挂单等能力说明分散，用户需要来回比对开关与摘要；
- 管理端与用户端已经具备相似能力，但版式和部分交互实现不完全一致；
- 保存状态、未保存状态和校验错误没有形成稳定、持续可见的反馈区。

## 3. 设计目标

### 3.1 第一优先级：清晰明了

用户打开弹窗后，无需阅读说明即可识别：

- 正在编辑哪一个策略；
- 策略正文在哪里；
- 当前给模型提供哪些数据；
- 哪些设置会影响运行；
- 是否有未保存修改；
- 如何保存或关闭。

### 3.2 第二优先级：正文优先

策略正文是模型分析的权威业务逻辑，应获得最大的可视面积和最靠前的键盘焦点顺序。配置只负责声明系统提供的数据与运行方式，不能在视觉上压过策略正文。

### 3.3 第三优先级：防止误关闭

长表单必须采用显式退出：

- 遮罩点击无效果；
- `Esc` 不关闭；
- 只有“关闭”按钮可以发起退出；
- 只有服务端确认保存成功后，“保存策略”才可以结束弹窗。

### 3.4 保持 AURUM 设计体系

采用 `ui-ux-pro-max` 的内容优先、渐进披露、清晰焦点、44px 点击目标和减弱动效原则，但不采用其检索结果中的紫色、高饱和渐变或夸张大字号。视觉继续使用 AURUM 的深蓝黑背景、低频金色强调、语义状态色和现有字体体系。

## 4. 不做什么

- 不改成独立策略页面；
- 不改成多步骤向导；
- 不引入 React、Vue、Tailwind、shadcn 或新的前端框架；
- 不修改策略保存 API、数据库表、迁移或权限模型；
- 不自动修改用户策略正文；
- 不因为开关状态自动删除正文中的 EMA34、缠论或其他策略逻辑；
- 不改变缠论、EMA34、持仓与挂单、入场方式的后端业务语义；
- 不合并用户端和管理端的权限边界；
- 不把技术 JSON 提升为普通用户的主要编辑方式。

## 5. 新的信息架构

### 5.1 桌面端布局

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 编辑策略  ·  策略范围/版本状态                                      [关闭] │
├───────────────────────────────────────────────┬──────────────────────────────┤
│ 主工作区                                      │ 设置侧栏                     │
│                                               │                              │
│ 策略名称 / 品种 / 一句话说明                  │ 当前提供                     │
│                                               │ M5 · M15 · H1 · H4            │
│ 策略正文                                      │ 缠论 · EMA34 · 持仓与挂单      │
│ ┌───────────────────────────────────────────┐ │                              │
│ │                                           │ │ 行情数据                     │
│ │        大尺寸策略正文编辑区               │ │ 附加数据                     │
│ │                                           │ │ 执行能力                     │
│ │                                           │ │ 运行设置                     │
│ └───────────────────────────────────────────┘ │                              │
│ 写法辅助 / 模板（默认收起或紧凑展示）         │ 技术字段（默认收起）           │
├───────────────────────────────────────────────┴──────────────────────────────┤
│ ● 有未保存修改 / 校验错误摘要                              [保存策略]       │
└──────────────────────────────────────────────────────────────────────────────┘
```

建议桌面宽度：`min(94vw, 1360px)`；最大高度：`92dvh`。主体采用不对称两栏：

```css
grid-template-columns: minmax(0, 1fr) 360px;
```

侧栏在中等桌面可收窄到 `320px`，主工作区始终获得剩余空间。

### 5.2 主工作区

主工作区按以下顺序排列：

1. **策略身份区**
   - 策略名称；
   - 适用品种；
   - 一句话说明；
   - 平台/私有范围只在有权限时显示。

2. **策略正文区**
   - 明确标签：“策略正文”；
   - 辅助说明：“模型将以此处内容作为本策略的业务判断依据”；
   - 桌面最小高度建议 `440px`，并随视口扩展到约 `55dvh`；
   - 使用舒适行高和合理内边距，不做代码编辑器式高噪声装饰；
   - 正文内部滚动，不让整个弹窗因长正文无限增长。

3. **写法辅助区**
   - 紧邻正文，保持“辅助工具”身份；
   - 默认只展示简短入口，如“查看当前数据的写法说明”；
   - 展开后根据当前周期、缠论、EMA34、入场方式和策略范围动态生成说明；
   - “复制写法模板”和“插入到光标位置”保留；
   - 系统绝不自动覆盖、重写或保存策略正文。

### 5.3 设置侧栏

侧栏只承载辅助决策，采用分组和分隔线，不堆叠多层大卡片。

#### A. 当前提供

在侧栏顶部显示紧凑摘要：

- 基础行情周期；
- 缠论是否提供及周期；
- EMA34 是否提供及周期；
- 持仓与挂单是否按范围提供；
- 可用入场方式。

摘要必须来自当前表单实时状态，不另建第二份配置源。

#### B. 行情数据

- 周期启用；
- K 线数量；
- 主周期；
- 周期说明按需展开。

桌面侧栏不再使用横向大表格，改为紧凑行：周期名、数量、主周期标识和启用状态在同一视觉组内。

#### C. 附加数据

- 提供缠论结构；
- 提供 EMA34 数据；
- 持仓与挂单上下文。

每个开关包含：

- 清晰名称；
- 一句结果说明；
- 当前状态；
- 必要时展开周期、参数或高级配置。

开关关闭仅停止提供对应数据，不修改策略正文；若正文仍引用该能力，显示非阻断提醒，要求用户自行调整。

#### D. 执行能力

- 市价；
- 限价挂单；
- 突破挂单；
- 突破限价。

使用紧凑多选，不用大面积说明卡。危险或不可用组合由现有校验逻辑提示，不在前端另造策略判断。

#### E. 运行设置

- 分析模型；
- 自动分析频率；
- 可见性/范围；
- 私有策略账户数据开关。

#### F. 技术字段

放在侧栏最底部，默认收起：

- 只读展示当前能力声明和技术路径；
- 普通用户无需阅读即可完成新建或编辑；
- 不允许技术字段与普通开关形成两个可写真相源。

## 6. 顶部与底部操作区

### 6.1 固定顶部

顶部在弹窗滚动时保持可见，包含：

- 新建策略/编辑策略标题；
- 策略范围、版本或状态的轻量信息；
- 一个明确的“关闭”按钮。

“关闭”使用图标加文字或具有完整无障碍名称的按钮，点击区域不得小于 `44 × 44px`。

### 6.2 固定底部

底部只保留一个高强调主操作“保存策略”。左侧显示状态：

- 未修改；
- 有未保存修改；
- 正在校验；
- 正在保存；
- 保存失败；
- 版本已变化，请处理冲突。

状态区使用 `aria-live="polite"`；校验失败摘要使用 `role="alert"`。

### 6.3 主操作规则

- 编辑旧策略且无修改时，“保存策略”禁用；
- 新建策略在满足最小必填项后可保存；
- 保存过程中按钮禁用并显示加载状态；
- 保存成功后关闭弹窗并刷新列表；
- 保存失败不得关闭弹窗；
- 版本冲突不得覆盖服务器数据，也不得丢失本地草稿；
- 第一个错误字段自动获得焦点，并在底部显示简短错误摘要。

## 7. 明确的关闭合同

### 7.1 允许关闭的路径

普通新建/编辑流程只有两条：

1. 用户点击顶部“关闭”；
2. 用户点击“保存策略”，且服务端保存成功。

管理端删除策略属于对象已不存在的终态操作，不是普通关闭路径。为减少歧义，实施时优先将删除入口放到列表操作或侧栏底部独立危险区；删除成功后弹窗关闭属于明确的删除结果。

### 7.2 禁止关闭的路径

- 点击弹窗外遮罩：无效果；
- 按 `Esc`：无效果；
- 保存请求发出：不提前关闭；
- 保存校验失败：不关闭；
- 版本冲突：不关闭；
- 网络错误或超时：不关闭；
- 切换侧栏分组：不关闭。

### 7.3 未保存修改保护

弹窗打开时保存一份规范化基线快照，覆盖所有可编辑字段：

- 基础信息；
- 策略正文；
- 行情周期计划；
- 缠论和 EMA34 声明；
- 持仓与挂单；
- 入场方式；
- 模型和运行参数；
- 可见性与范围。

任何 `input` 或 `change` 后重新生成规范化快照，与基线比较得到 `dirty` 状态。

点击“关闭”时：

- 未修改：直接关闭；
- 有修改：显示“放弃未保存的修改？”确认；
- 选择继续编辑：保留全部内容和焦点；
- 确认放弃：关闭并恢复焦点到打开弹窗的按钮。

该确认是“关闭”动作的保护步骤，不构成新的第三种关闭入口。

## 8. 键盘与无障碍

- 使用 `role="dialog"`、`aria-modal="true"` 和明确的标题关联；
- 打开后焦点进入策略名称（新建）或策略正文（编辑）；
- `Tab` 焦点限制在弹窗内部；
- 关闭后焦点恢复到原触发按钮；
- `Esc` 被阻止时不弹出高频打扰，可通过一次性 `aria-live` 提示“请使用关闭按钮退出”；
- 所有开关必须具有可见标签，不能只依赖颜色；
- 点击目标最小 `44px`；
- 使用现有 `:focus-visible` 金色焦点环；
- 状态颜色满足 WCAG AA，对错误、成功、警告同时提供文字和图标；
- 动效限制为 `150–200ms` 的透明度或轻微位移；
- `prefers-reduced-motion: reduce` 下关闭非必要动效。

## 9. 响应式方案

### 9.1 大桌面：`≥ 1080px`

- 主工作区 + `360px` 设置侧栏；
- 侧栏随弹窗主体滚动，可在可用空间内保持设置摘要可见；
- 避免形成两个互相竞争的长滚动容器。

### 9.2 中等宽度：`820–1079px`

- 侧栏缩至约 `320px`；
- 主区保持至少 `520px` 的有效宽度；
- 过长能力说明自动折行，不压缩正文编辑器。

### 9.3 窄屏：`< 820px`

- 弹窗改为全屏单列；
- 顺序固定为：策略身份 → 策略正文 → 写法辅助 → 当前提供 → 其他设置；
- 设置分组采用单层折叠，默认展开“当前提供”和存在错误的分组；
- 顶部和底部操作区固定；
- 输入字号不低于 `16px`，避免移动端自动缩放；
- 在 `375px` 宽度下不得出现横向滚动。

## 10. 用户端与管理端一致性

### 10.1 必须一致

- 主次布局；
- 关闭合同；
- dirty 状态；
- 保存失败保留草稿；
- 缠论、EMA34、持仓与挂单、入场方式的展示语言；
- 写法辅助位置；
- 响应式断点；
- 焦点、键盘和无障碍行为；
- 加载、错误、空状态和版本冲突反馈。

### 10.2 保持差异

- 用户端私有策略与平台策略的权限边界；
- 管理端平台策略的发布、删除和运营字段；
- 用户端账户范围与私有持仓上下文；
- 各自现有 API、CAS 字段和错误码；
- 各自现有 DOM 标识，只在无法完成新布局时做最小兼容改名。

## 11. 前端实现边界

预计涉及：

- `public/ai/index.html`
- `public/ai/app.js`
- `public/ai/styles.css`
- `public/ai/responsive.css`
- `public/admin/index.html`
- `public/admin/app.js`
- `public/admin/styles.css`
- `tests/ai/frontend-governance.test.js`
- 必要的策略编辑器行为测试

实现原则：

- 优先重排现有 DOM 和复用现有数据绑定；
- 保留现有字段 ID、`data-*`、payload、`expected_version` 和错误映射；
- 为策略弹窗增加独立的关闭策略，不改变其他普通弹窗的遮罩和 `Esc` 行为；
- 用户端和管理端共享相同的设计 token 和状态命名，但不做高风险的大规模 JS 合并；
- 更新静态资源缓存键，避免部署后继续加载旧布局；
- 不在 CSS 中新增与 AURUM 设计体系冲突的独立颜色系统。

## 12. 实施阶段

### 阶段 A：结构和关闭合同

1. 建立主工作区/侧栏/固定头尾结构；
2. 将策略正文前置；
3. 为用户端策略弹窗禁用遮罩关闭和 `Esc` 关闭；
4. 为管理端策略实体弹窗增加局部关闭策略，其他实体弹窗保持原行为；
5. 增加 dirty 快照和关闭确认；
6. 保存成功才关闭，失败完整保留。

验收：核心交互正确，即使样式尚未精修也不会误关闭或丢草稿。

### 阶段 B：设置侧栏和信息压缩

1. 重组行情、附加数据、执行能力、运行设置；
2. 将“当前提供”改为紧凑实时摘要；
3. 技术字段下沉为默认收起；
4. 写法辅助移动到正文下方；
5. 用户端和管理端完成信息架构对齐。

验收：用户不展开技术字段也能完整新建和编辑策略。

### 阶段 C：视觉、响应式和无障碍

1. 应用 AURUM 间距、颜色、圆角和焦点 token；
2. 完成 1080、820 和 375 宽度适配；
3. 补齐键盘焦点、ARIA、状态反馈和减弱动效；
4. 更新缓存键；
5. 完成截图比对和视觉回归。

验收：桌面和窄屏均清晰，无横向滚动，无多层卡片堆叠。

## 13. 测试与验收

### 13.1 静态治理测试

- 用户端和管理端都有主工作区与设置侧栏；
- 策略正文位于数据设置之前；
- 策略弹窗禁止遮罩和 `Esc` 关闭；
- 其他普通弹窗维持现有关闭方式；
- 两端保留现有 API、CAS 和字段合同；
- 静态资源缓存键同步更新；
- 不出现新的硬编码策略逻辑或默认策略正文。

### 13.2 行为测试

- 打开旧策略后初始状态为“未修改”；
- 修改正文、开关、周期、模型等任一字段后标记 dirty；
- 改回原值后恢复“未修改”；
- 点击遮罩不关闭；
- 按 `Esc` 不关闭；
- clean 状态点击“关闭”直接退出；
- dirty 状态点击“关闭”出现放弃确认；
- 取消放弃后草稿和焦点保留；
- 保存校验失败、网络失败、超时和版本冲突均不关闭；
- 保存成功后关闭并刷新正确策略；
- 用户端与管理端行为一致。

## 15. 第一轮方案审查：需求、边界与最小性

### 15.1 审查结论

通过，但做以下收敛：

1. **不采用多步骤向导。** 策略编辑是反复局部修改，不应让用户在步骤间来回切换。
2. **不拆成独立页面。** 用户明确要求优化弹窗，且当前入口、权限与列表上下文都适合保留弹窗。
3. **不把侧栏做成多层卡片。** 改用分组标题、留白和分隔线，避免信息密度继续膨胀。
4. **不引入新框架。** 现有静态 HTML/CSS/JS 足以完成布局与交互，避免扩大回归面。
5. **不自动同步修改策略正文。** 开关只控制数据提供；正文是否引用对应能力由用户负责修改，界面只提醒。
6. **写法辅助继续内嵌在正文附近。** 它是复制/插入辅助，不是第二套策略生成器，也不自动保存。
7. **只有一个视觉主操作。** “保存策略”为唯一金色主按钮；“关闭”是明确但低强调的退出操作。

### 15.2 第一轮调整结果

- 将原本可能放在侧栏的写法辅助移回正文下方；
- 将大尺寸“本策略将收到”面板压缩为侧栏顶部摘要；
- 将技术字段移动到侧栏末尾并默认收起；
- 明确用户端与管理端只做视觉和行为对齐，不合并权限/API；
- 明确禁止遮罩和 `Esc` 关闭只作用于策略编辑弹窗，不影响其他弹窗。

## 16. 第二轮方案审查：兼容、异常、恢复与测试

### 16.1 数据与迁移

- 不新增数据库字段，不需要迁移；
- 不改变 payload 和服务端校验；
- 基线快照只存在当前前端会话，不写浏览器长期存储；
- 规范化 dirty 比较必须排除纯展示字段和临时状态，避免无意义地一直显示“有修改”。

### 16.2 并发与版本冲突

- 保存继续携带现有 `expected_version`/CAS 信息；
- 服务器版本变化时不得自动重试覆盖；
- 冲突响应保持弹窗打开，显示服务器已变化，同时保留本地正文与设置；
- 用户重新加载服务器版本前，应允许复制本地正文。

### 16.3 幂等与重复提交

- 保存过程中禁用主按钮；
- 同一保存 Promise 未结束前忽略重复点击；
- 请求超时后不推断保存成功，重新获取策略状态再决定提示；
- 不因为界面重排增加新的自动保存或后台保存。

### 16.4 恢复与意外情况

- 网络错误、认证失效、限流、超时和服务不可用都保留草稿；
- 弹窗内部重新渲染不得覆盖用户正在编辑的正文；
- 关闭确认取消后恢复到原操作位置；
- 保存成功刷新列表失败时，弹窗可以关闭，但列表需显示独立刷新错误并允许重试；
- 浏览器标签页直接关闭不属于应用内弹窗关闭合同，本次不增加 `beforeunload` 全局拦截，避免影响整个交易工作台。

### 16.5 时间、权限与安全

- 不改变分析频率的时区、单位和服务端语义；
- 用户端不能通过 DOM 操作获得管理端字段；
- 平台策略和私有策略继续由服务端权限校验；
- 技术 JSON 只显示经过现有净化的数据；
- 错误提示不得泄露密钥、内部 SQL、模型凭据或完整服务端堆栈。

### 16.6 第二轮发现并修正的问题

1. **删除成功会自然结束管理端编辑器。** 这不是普通关闭路径，方案已将删除定义为显式危险终态，并优先建议移至列表或侧栏危险区。
2. **`Esc` 完全无反馈可能让键盘用户困惑。** 增加一次性、非打扰式无障碍提示，但仍不关闭。
3. **两个独立长滚动区会造成操作迷失。** 方案改为弹窗主体单一滚动，正文输入框仅负责正文自身滚动，侧栏不建立独立永久滚动条。
4. **保存后列表刷新失败容易被误判为保存失败。** 方案区分“保存成功”和“列表刷新失败”，避免重复提交。
5. **管理端通用实体弹窗不能整体禁用遮罩/`Esc`。** 实施时必须使用策略类型或关闭策略标记做局部控制。

### 16.7 剩余风险

- 管理端策略编辑器当前由较长动态模板生成，重排时存在事件委托或字段 ID 遗漏风险；必须逐项对照 payload。
- 用户端和管理端并非共享组件，后续可能发生样式漂移；需用治理测试固定共同合同。
- 极长策略正文下的输入性能需在真实长度上验证，避免每次按键都做昂贵的全 DOM 重绘；dirty 快照应轻量、可节流。
- 移动端虚拟键盘会改变 `dvh`，需用真实浏览器验证固定头尾不会遮挡正文光标。

## 17. 最终验收标准

只有同时满足以下条件，才能认为改造完成：

- 打开弹窗后第一屏即可看到并编辑策略正文；
- 正文在视觉面积、焦点顺序和信息层级上均为主任务；
- 设置侧栏清楚展示“当前提供什么”和“如何运行”，没有重复大卡片；
- 普通用户不展开技术字段也能完成全部常用设置；
- 点击遮罩和按 `Esc` 均不会关闭策略弹窗；
- 只有显式“关闭”流程或保存成功可以结束普通编辑；
- 未保存草稿在关闭确认取消、保存失败和版本冲突后均完整保留；
- 用户端与管理端交互一致、权限与 API 不变；
- 桌面、平板和 `375px` 窄屏无横向滚动；
- 键盘、焦点、状态反馈、减弱动效和对比度满足设计要求；
- 定向测试、全量测试、浏览器行为验证和截图审查全部通过。
