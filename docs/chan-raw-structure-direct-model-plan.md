# 缠论原始结构直传模型实施方案

## 1. 目标

缠论计算完成后，后端仅按策略配置的周期把每个周期的原始结构放入
`strategy_context.timeframes[timeframe].summary.chan` 并传给模型。模型依据当前策略正文判断周期职责、方向关系和入场条件。

后端不再：

- 汇总多个周期为 `chan_timeframe_alignment`；
- 生成 `agreement`、`conflict`、`higher_timeframe_direction` 或 `alignment_with_higher`；
- 因通用跨周期汇总结果修改模型结论或压低仓位档位；
- 把通用跨周期汇总作为统一策略记忆库的检索条件。

本次不改变缠论算法、固定历史窗口、行情连续性检查、结构能力字段、推理快照、交易风险控制或订单执行校验。数据完整性与结构计算可信度属于原始证据质量，不属于策略方向校验，继续保留并随原始结构传给模型。

## 2. 现状与问题

当前 `buildStrategyContextFromTags()` 已经把每个周期的完整缠论结构放在
`timeframes[周期].summary.chan`，但随后又调用 `buildChanTimeframeAlignment()` 做一次通用跨周期裁决。

该裁决没有读取具体策略的周期职责。当可靠周期方向不一致时，它统一生成 `mixed/conflict`。全局模型规则要求据此降低结论强度或观望，输出归一化还会把 `mixed/insufficient` 的仓位证据上限压到试探仓。

这与“不同策略自行定义 H1、H4、M15、M5 的职责”冲突，也重复解释了模型已经收到的原始结构。

统一策略记忆库运行时直接注入完整库内容，不再按品种、周期或方向检索。因此当前推理链不需要跨周期汇总来驱动记忆调用。

## 3. 实施范围

### 3.1 策略上下文

- 删除 `buildChanTimeframeAlignment()` 及其测试导出。
- `buildStrategyContextFromTags()` 不再生成 `chan_timeframe_alignment`。
- 继续输出：
  - `required_timeframes`、`used_timeframes`、`missing_timeframes`、`context_status`；
  - 每个周期的普通指标、可见 K 线和 `summary.chan`；
  - 非枚举的快照可视化 K 线和政策指标源。
- 历史模型对比继续识别旧快照中的 `chan_timeframe_alignment`，只用于判断旧快照是否启用了缠论，不重新生成或解释该字段。

### 3.2 模型规则与输出归一化

- 删除全局提示词中对 `chan_timeframe_alignment`、`agreement=mixed` 和
  `alignment_with_higher=conflict` 的决策要求。
- 明确模型必须读取各周期原始缠论结构，并按当前策略正文定义的周期职责自行分析，不能假设所有周期需要同向。
- 保留结构字段语义说明，防止模型把候选结构、笔级中枢或不可靠时间定位误写成确认结构。
- 输出归一化不再读取跨周期汇总，也不再因该汇总压低仓位档位。
- 缺失周期和 `context_status=partial` 仍可限制仓位，因为这是输入数据完整性边界，不是缠论方向校验。

### 3.3 记忆与兼容

- 当前统一策略记忆库运行时保持完整文本注入，不增加方向检索。
- 旧分层记忆函数和旧快照字段只作历史兼容；本次不删除旧表、旧 API 或历史数据。
- 新生成的行情上下文和推理快照不得再包含 `chan_timeframe_alignment`。

### 3.4 文档与测试

- 更新缠论说明文档，删除跨周期汇总合同，记录原始结构直传合同。
- 策略测试验证启用缠论时各周期原始结构存在且无汇总字段。
- 模型测试验证提示词不再包含汇总裁决规则，并验证旧汇总字段不能影响新信号仓位归一化。
- 运行修改文件语法检查和定向 Vitest；再按共享文件影响范围运行相关策略、模型和记忆库测试。

## 4. 受保护行为

- 不改变 `market-data.js` 的缠论结构算法和字段语义。
- 不改变 v6 各周期固定目标窗口和验证窗口。
- 不改变策略是否启用缠论的开关及关闭时剥离 `chan` 的行为。
- 不改变策略记忆库全文注入、版本、哈希和审计归属。
- 不改变止损、止盈、入场方式、挂单价格、风险额度、账户权限和 Bridge 执行校验。
- 不修改或回退工作区现有的统一策略记忆库及模型 Token 上限相关改动。

## 5. 验收标准

1. 新构建的多周期策略上下文不含 `chan_timeframe_alignment`。
2. 每个已成功计算的周期仍含完整 `summary.chan`。
3. 模型系统提示词明确由当前策略解释周期关系，不含通用 mixed/conflict 观望规则。
4. 即使输入历史兼容的 `chan_timeframe_alignment.agreement=mixed`，输出归一化也不因此降低模型选择的仓位档位。
5. 缺失必要周期时的数据完整性降级仍有效。
6. 历史快照模型对比仍能识别旧缠论快照。
7. 所有定向测试通过，现有未提交改动未被覆盖或带入本任务提交。

## 6. 第一轮复审：需求与最小边界

### 检查结论

- 需求覆盖：原始结构已由现有 `timeframes[].summary.chan` 提供，不需要新建第二套 payload。
- 业务边界：删除的是跨周期解释和基于解释的归一化，不删除结构计算、行情质量或独立风险控制。
- 能力复用：复用现有策略正文、结构化策略配置和统一策略记忆库全文注入。
- 最小改动：无需修改数据库、迁移、前端、调度周期、Bridge 或缠论核心算法。
- 设计过度检查：不新增新的通用仲裁器、`effective_timeframe` 或后端缠论规则，周期关系完全交给具体策略和模型。

### 第一轮调整

- 原设想删除所有旧字段引用；复审后保留历史快照识别和旧文本本地化，避免历史模型对比及旧信号展示失去兼容性。
- 原设想取消全部证据降级；复审后保留缺失周期和 partial 上下文的输入完整性降级，因为这不是缠论方向判断。
- 明确统一记忆库无需改动，避免触碰正在进行的记忆库重构。

### 第一轮剩余风险

- 模型可能不完全遵守复杂策略中的周期职责；这是选择“由模型按策略分析”的固有风险，应通过策略提示词和信号回放评估，不在后端重新实现缠论仲裁。
- 删除通用仓位降级后，模型的仓位档位更依赖自身判断，但独立账户风险额度和订单风险控制仍然有效。

## 7. 第二轮复审：兼容性与回归风险

### 检查结论

- 兼容性：新信号不生成汇总字段；旧信号和旧快照仍可读取，历史重放继续使用冻结提示词和快照。
- 数据与迁移：不涉及数据库结构或数据写回。
- 并发与幂等：只改变纯上下文构建和纯输出归一化，无新增状态、锁或重试路径。
- 异常恢复：某周期获取失败仍由 `missing_timeframes/context_status` 表达，不伪造结构。
- 安全：记忆库仍作为不可信用户数据注入；策略、权限、风险和输出 Schema 优先级不变。
- 测试：覆盖新上下文、模型提示词、遗留字段不干预仓位及历史兼容识别。
- 回滚：代码回滚即可恢复旧汇总；无数据迁移回滚问题。

### 第二轮调整

- 增加“旧汇总字段不能影响新归一化”的回归测试，防止历史 payload 或外部兼容输入重新触发隐式后端裁决。
- 文档明确 `evidence_capabilities` 是随原始结构提供的事实描述，不是后端替策略做出的交易判断。
- 明确不删除旧记忆检索函数；它们已退出当前推理链，保留可避免扩大本次范围。

### 第二轮剩余风险与实施判定

- 策略正文若自身仍写有“所有周期必须一致”，模型仍会按该策略执行；这属于策略配置而非后端通用汇总。
- 真实模型输出可能在短期内仍沿用过去常见的“周期冲突”措辞，需要用冻结快照回放或上线后信号抽检验证。

方案已覆盖用户要求并通过两轮复审，可以实施。
