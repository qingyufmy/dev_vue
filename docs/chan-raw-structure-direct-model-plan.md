## 2. 最终需求

缠论结构由服务端通用计算器生成后，模型只接收计算结果中的结构对象本身。服务端只用一句中性文字说明“这是缠论结构”，不再追加字段字典、可靠性解释、周期职责、方向判断、观望条件或交易建议。

原则如下：

1. 策略是唯一分析权威；
2. 服务端负责获取行情、计算缠论和提供结构化数据；
3. 模型如何使用线段、中枢、背驰、买卖点和周期关系，只由当前策略正文决定；
4. 服务端不得根据缠论状态改写买卖方向、置信度或观望理由；
5. 完整诊断数据继续留在内部快照、复盘和审计链路，不进入模型输入；
6. 缠论算法、固定历史窗口、数据连续性核验、权限、独立风控和订单机械校验不因本方案放宽。

一句话目标：

> **模型只看到缠论结构；系统不替策略解释缠论结构。**

## 3. “原样传递”的精确定义

当前 `computeChan()` 的返回对象同时混合了两类数据：

- 结构结果：笔、线段、中枢、背驰、买卖点候选和结构趋势；
- 内部诊断：窗口、锚点、连续性、可靠性、支持票数、能力开关、警告和原因码。

因此，“把当前整个 `chan` 对象原样传给模型”实际上仍会传入 80–99 个顶层字段，无法满足“不传任何额外字段”。本方案将“原样”定义为：

- 不修改结构对象内部的价格、方向、时间、确认状态、ID、引用关系或枚举；
- 不翻译、不总结、不推导、不补造结构；
- 只从计算结果中取出已经存在的结构对象；
- 不把内部诊断字段混入模型可见结构；
- 不把重复对象改写成 `$ref`；
- 不改变完整内部计算结果和冻结快照。

### 3.1 模型可见的缠论结构字段

每个周期仅保留现有计算结果中的以下结构字段；字段不存在时不补造，字段为空时保留原有空值：

```text
current_bi
developing_bi
recent_bis
current_segment
prev_segment
candidate_segment
current_center
latest_center
latest_bi_center
active_center
divergence
forming_divergence
recent_divergences
entry_candidates
```

这些字段的值必须从 `computeChan()` 结果直接复制，不允许服务端二次重算或本地化。

### 3.2 不进入模型的内部字段

下列类别继续保存在完整内部快照中，但不得进入新的模型请求：

- `evidence_capabilities` 及全部 `*_usable`；
- `status`、`reliability`、`warnings`、`reason_codes`；
- `structure_topology_reliable`、`absolute_time_location_reliable`、`time_location_reliable`；
- `history_*`、`continuity_*`、`cache_*`、`clock_*`；
- `structure_anchor`、`window_*`、`validation_window_counts`；
- `cross_window_*`、`temporal_*`、`*_support_count`、`*_validator_count`；
- `raw_bar_count`、`processed_bar_count`、`requested_*`、`received_*`、`source_*`；
- 计数、规则版本和算法审计字段；
- 服务端生成的“结构可靠/不可靠”“锚定未完成”“必须观望”等解释。

### 3.3 目标模型输入

保留现有路径，避免新增第二份重复数据：

```json
{
  "strategy_context": {
    "timeframes": {
      "H1": {
        "summary": {
          "chan": {
            "current_segment": {},
            "prev_segment": {},
            "current_center": {},
            "divergence": {},
            "entry_candidates": []
          }
        }
      }
    }
  }
}
```

系统提示词只增加一句：

> `strategy_context.timeframes 各周期 summary.chan 为系统计算的缠论结构，请仅按当前策略正文自行分析。`

不再附加任何缠论字段说明。

## 15. 回滚

- 代码批次无数据库迁移，可按单一提交回滚；
- 新旧快照均保留冻结提示词和输入，不需重写；
- 回滚不得删除新信号、模型任务或快照；
- 策略更新通过版本历史单独恢复；
- 若精简输入导致结构字段缺失、历史对比被改写、复盘证据消失或执行资格异常，立即停止部署并回滚代码；
- 若只是模型仍选择观望，不构成回滚条件，应按策略和结构事实分析。

## 16. 第一轮复审：需求覆盖、边界与最小改动

### 16.1 独立检查项

- 是否真正做到“只传结构，不传解释”；
- 是否误把完整诊断和复盘证据删除；
- 是否修改缠论算法以迎合更多交易信号；
- 是否新增另一套 `chan_structures` 重复合同；
- 是否把某个策略的周期职责写进服务端；
- 是否把策略正文更新和通用代码修改混在一起。

### 16.2 第一轮发现

1. 原方案把整个 `summary.chan` 视为“原始结构”，但线上对象含 80–99 个混合字段，不符合“不传额外字段”。
2. 原方案保留 `evidence_capabilities` 给模型，仍会诱导模型用服务端资格替代策略判断。
3. 原方案允许 `$ref` 压缩，改变了“原样”结构表示。
4. 如果直接删除完整字段，会破坏复盘、冻结诊断和历史审计。
5. 线上实际策略与权威文件不一致，不能靠通用代码修复。

### 16.3 第一轮调整

- 增加固定结构字段投影，只精简模型副本；
- 将 `trend_state`、`price_vs_center` 等服务端汇总排除在结构投影之外，方向与位置关系由策略根据线段和中枢对象自行解释；
- 完整 `market` 快照和诊断保持不变；
- 停止模型可见 Chan `$ref`，K 线压缩继续保留；
- 只保留现有 `summary.chan` 路径，不新增平行字段；
- 明确不改 `computeChan()`、窗口、锚点和能力算法；
- 将策略正文和 EMA 配置纠正拆为独立人工确认批次。

### 16.4 第一轮结论

调整后的方案直接满足用户边界，复用现有快照和推理入口，不需要迁移，不为当前策略增加专用服务端逻辑，属于最小且可验证的改动。

## 17. 第二轮复审：兼容、数据、并发、异常、安全和连带 Bug

### 17.1 独立检查项

- 自动、手动、新鲜比较和历史回放是否一致；
- 精简模型输入后完整证据是否仍可恢复；
- 对象克隆是否修改共享 `market`；
- 旧 `$ref` 快照是否仍可读取；
- 空结构和计算失败是否被伪造成正常结构；
- token、超时和模型输出是否有新风险；
- 风控和订单执行是否受到影响；
- 策略并发保存与版本是否安全；
- 是否需要数据库迁移或历史回填。

### 17.2 第二轮发现与修订

1. **历史比较风险：**若在 replay 路径重新投影，会破坏冻结输入可重复性。

   **修订：**检测 `_comparison_replay_user_prompt`，历史 replay 完全旁路新投影。

2. **快照证据风险：**若把 `renderedEvidence.aiPayload` 当唯一市场快照，复盘会失去完整诊断。

   **修订：**继续以完整 `market` 保存 `market_snapshot_json`，实际模型输入仅保存在 `user_prompt`。

3. **共享对象污染风险：**浅拷贝后删除嵌套字段可能影响后续持久化和执行。

   **修订：**投影函数只处理模型边界的深克隆，不修改源对象。

4. **兼容风险：**旧冻结提示词和输出仍可能包含内部英文状态。

   **修订：**保留只读解析和展示本地化，不再把它们注入新模型提示词。

5. **输入增长风险：**移除 `$ref` 会增加字符数。

   **修订：**线上样本证明完整旧 Chan 仅增加约 7 KB；新结构投影同时删除大量诊断字段，最终输入预计净下降。上线前仍需记录实际 token。

6. **错误伪装风险：**计算失败若返回空对象，模型可能当成“无结构”。

   **修订：**模型只看到实际存在的结构字段；计算服务错误仍按现有数据准备错误路径处理，不额外生成“可靠/不可靠”结论。完整错误状态留在审计快照。

7. **交易安全风险：**删除服务端缠论解释不能删除输出和执行校验。

   **修订：**JSON Schema、价格机械关系、权限、独立风控、仓位精算、幂等和 Bridge 安全均保持不变。

8. **策略配置风险：**直接覆盖策略 #1 会混淆通用修复与业务规则变更。

   **修订：**策略修订使用独立版本和现有保存服务，需人工确认 EMA 决策，禁止手写 SQL。

9. **M5 结构风险：**精简输入不会自动让 M5 出现确认线段。

   **修订：**增加冻结 800 根 K 线重算验收，结构为空时如实传空，不修改算法门槛。

10. **验收偏差：**修复后仍可能全部观望。

    **修订：**成功标准是输入边界正确、策略权威、结论原样、执行安全，不以交易数量衡量。

11. **派生摘要风险：**`trend_state` 和 `price_vs_center` 虽位于当前 `chan` 对象内，但仍是服务端对结构的汇总解释，不是笔、线段、中枢、背驰或买卖点对象本身。

    **修订：**两者不进入模型投影，避免以另一种形式保留服务端方向判断；完整值继续保存在内部快照供审计。

### 17.3 第二轮结论

第二轮复审后，方案具备明确的新旧合同边界、完整快照兼容、无迁移路径、历史回放保护、独立策略更新、真实模型验证和按提交回滚方案。未发现必须在实施前解决的结构性阻塞。

## 18. 剩余风险

- 模型仍可能基于策略自身文字得出“结构不清晰”，这不属于服务端干扰；
- 权威策略正文很长，模型遵循度仍需真实 A/B 回放评估；
- 如果权威策略继续要求某些结构必须确认，连续观望可能是正确结果；
- 当前 M5 无确认线段需要冻结数据重算，不能仅凭状态字段判断算法错误；
- EMA34 是否属于策略 #1 仍需人工业务决策；
- 本方案不优化缠论算法正确性，只优化模型输入边界；
- 公网部署和策略数据修改均需要独立授权。

## 19. 最终实施判断

建议先实施批次 1，在本地完成自然任务和冻结输入验收，再决定是否更新策略正文。四条验收红线：

1. **模型只收到现有计算结果中的结构对象，不收到服务端诊断和解释；**
2. **完整内部快照、复盘与历史证据不能丢失；**
3. **不修改缠论算法，不用服务端替策略决定买卖或观望；**
4. **策略正文更新、EMA 决策和生产部署必须分别授权、分别验证。**
