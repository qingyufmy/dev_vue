## 1. 本阶段结论

分析师与交易员采用“市场共享分析、账户独立决策”的两级结构，但不再对每个账户无条件调用交易员：

- 同一系统用户、分析策略版本、标准品种和五分钟时间槽只登记一份分析；
- 分析输入显式冻结策略提示词、行情来源、报价、多周期 K 线和最新有效宏观快照；
- 每次模型请求保存稳定 task 和独立 attempt，最多三次；重试复用同一冻结快照；
- 更新的自动分析会使旧排队/运行自动分析及其模型任务过期，迟到写入由 run revision、task ID 和 fencing token 拒绝；手动分析不被例行调度静默取消；
- 分析师输出使用 `opportunity = none | long_setup | short_setup`，不再把“管理已有持仓”混在市场结论里；
- 每个账户根据机会与敞口生成 `entry | manage | both`，无机会且无持仓/挂单时不创建自动交易员任务；
- 手动“提交给当前账户评估”仍可显式创建一次账户任务。

该设计解决了“AI 交易员长时间不触发会失去持仓管理”的问题：只要账户仍有该品种的持仓或挂单，每轮新市场分析都会触发管理任务；空仓且无机会的账户则不浪费第二次模型调用。

## 2. 关键实现

### 2.1 调度与数据来源

- 调度器按 UTC 时间槽聚合多个账户订阅，并确定性选择一个在线行情来源账户；
- 首选账户离线时不会使用其旧投影，可回退到该用户其他在线账户；
- 分析策略可声明周期与 K 线数量，非法或缺失配置回退到统一默认值；
- 宏观研究作为独立的带版本快照读取，不在五分钟关键链路中临时执行宏观模型。

### 2.2 模型任务与失败

- 模型调用发生在数据库事务外；事务只负责冻结输入、任务领取、结果提交和状态转换；
- provider 可重试失败创建新 attempt，同一 snapshot/task 业务身份不变；
- 合同错误终止任务；运行版本冲突或新分析已替代当前任务时直接忽略迟到结果，不再次调用模型；
- 超时和普通调用失败有稳定错误类型，任务 deadline 阻止无限重试。

### 2.3 条件账户扇出

| opportunity | 当前敞口 | 自动任务 | 模式 |
| --- | --- | --- | --- |
| none | 无 | 不创建 | — |
| long_setup / short_setup | 无 | 创建 | entry |
| none | 有持仓或挂单 | 创建 | manage |
| long_setup / short_setup | 有持仓或挂单 | 创建 | both |

任务冻结订阅 revision、持仓 revision 和挂单 revision。Stage 12C 读取真实账户上下文时必须再次核对这些 revision，不能让旧账户状态生成新动作。

## 4. 两轮复审

### 第一轮：职责与最小设计

- 发现无条件账户扇出会使空仓、无机会账户每五分钟重复消耗模型；改为机会/敞口条件矩阵。
- 发现仅在有机会时调用交易员会遗漏存量持仓管理；将持仓或挂单作为独立管理触发条件。
- 没有增加交易员独立周期、第三个风控模型、工作流引擎或微服务。

### 第二轮：并发、数据与失败

- 发现模型调用失败与结果落库冲突不能共用重试路径；拆分后，provider 失败可重试，迟到结果只忽略。
- 发现更新分析只过期 run 会遗留运行中的 model task；现在同步关闭旧 task 和 attempt。
- 发现直接改 ENUM 可能损坏 Stage 12A 已有值；迁移改为新增列、明确映射、设为非空后再删除旧列。
- 发现首选行情账户可能已经离线；只允许在线账户成为新分析的数据源。
