## 结论与交付

最终保留两个 AI 策略：

1. [行情分析策略](01-market-analysis-prompt.md)：识别市场方向、有效机会、结构保护与目标，并输出供持仓管理使用的客观证据。
2. [AI 交易员策略](02-ai-trader-prompt.md)：结合分析、账户、持仓、挂单和执行状态，提出入场、退出、减仓、保护及挂单处理建议。

PivotGuard 是自动离场管理器，不是完整的开仓策略。将它融入 AI 交易员，不等于把每次报价处理交给模型。连续计时、盈利峰值、合法手数、风险校验和执行回执仍由程序承担；这不需要增加第三个 AI 策略。

两份提示词是配套评审稿。当前系统需要补足下文的数据合同才能完整运行，不能仅替换提示词就宣称已实现全部 PivotGuard 能力。

## EA 核心逻辑

### 行情与管理对象

`OnTick` 第 185 行开始处理，300ms 是报价回调节流，不是保证每 300ms 执行一次。没有图表报价，持仓管理循环就不会按这个频率运行。`OnTimer` 第 177 行主要做分钟级轴心更新与复盘调用。

`CalcPivots` 第 229 行读取当前图表品种上一根已收盘 D1。默认 Fibonacci 方法：P=(H+L+C)/3，R1/R2/R3=P+日振幅×0.382/0.618/1，S1/S2/S3 对称向下。普通方法也受支持：R1=2P−L，S1=2P−H，R2=P+振幅，S2=P−振幅，R3=H+2(P−L)，S3=L−2(H−P)。这些公式应由程序计算。

`IsManaged` 第 219 行只按魔术号筛选，魔术号为 0 时遍历全部账户持仓；没有按当前图表品种筛选。源码没有开仓或挂单管理逻辑。

### 持仓处理顺序与默认值

下表中的“价格距离”是报价数值差，不是 point，也不是账户盈亏金额。

| 顺序 | 规则 | 实际触发含义 | 源码默认值 |
|---|---|---|---|
| 1 | 最大亏损 | 持仓盈亏加隔夜费及已读取入场佣金达到亏损限额 | 50 账户币种单位 |
| 2 | P 反向穿越 | 默认多仓开在 P 上、空仓开在 P 下，反向越过距离线并持续观察 | 价格距离 8，3 秒 |
| 3 | 关键位回踩失败 | 多仓参考开仓价下方最近 R；空仓参考上方最近 S，越过保护线退出 | 价格距离 5 |
| 4 | 贴位反向突破 | 空仓贴近最近 R、多仓贴近最近 S，随后反向越线 | 贴近距离 10，突破距离 9 |
| 5 | 盈利回撤 | 历史正峰值回撤达标且当前仍正盈利 | 回撤 50% |
| 6 | 待处理移保本 | 已完成目标阶段后，按间隔尝试改单 | 5 秒 |
| 7 | P 止盈 | P 位于盈利方向、净盈利为正且进入到达容差 | 距离 3，默认减剩余仓位 50% |
| 8 | 最近目标止盈 | 七档轴心位中，开仓价盈利方向最近目标到达 | 距离 3，默认减剩余仓位 50% |

主体位于 `ProcessPosition` 第 405 行；目标处理见第 650、702 行。P 阶段移保本为开仓价向盈利方向移动 **2 point**；最近目标阶段为移动 **2.0 价格距离**，两者不可混用。

回踩规则按开仓价与关键位的关系直接判断，没有独立记录“先突破、后回踩”的完整历史过程。盈利回撤也没有最低盈利激活门槛，且当前跌为负盈利时不走该分支。

### 执行与状态

源码保存每张持仓的盈利峰值、目标完成和保本状态，部分运行中状态仅在内存。失败冷却默认 60 秒。全平请求有短暂等待；部分平仓以调用返回和返回码判断完成。

`IsTradeAccepted` 第 749 行接受 DONE、DONE_PARTIAL 和 PLACED。受理不等于全部成交；应结合实际成交、剩余手数及交易事件确认阶段完成。官方也明确 OrderSend 返回成功不代表交易已执行，参见 [MQL5 OrderSend 文档](https://www.mql5.com/en/docs/trading/ordersend)。

## 源码问题与 v1 建议（历史记录）

| 源码问题 | 影响 | 本次策略要求 / 后续程序处理 |
|---|---|---|
| 跨品种持仓使用当前图表 Pivot | 可能用错关键价位 | 每个持仓匹配实际品种、券商日线和日期 |
| 日线刷新失败仍保留旧 Pivot | 新交易日可能沿用旧线 | 标记适用日期；过期时停用依赖轴心的分支，其他保护独立运行 |
| 冷却和未决等待位于最大亏损检查之前 | 可能延迟紧急保护 | 持续评估风险；未决先对账，不能盲目重复平仓 |
| 已受理即标记减仓完成 | 后续减仓、保本可能基于错误手数 | 终端成交确认后推进阶段 |
| 移保本未检查现有止损是否更好 | 可能把止损改差 | 仅允许朝保护方向改善，保留有效 TP |
| 部分平仓后沿用旧金额峰值 | 减仓本身可能被误判成盈利回撤 | 明确剩余仓位可比峰值或成交后重建基准 |
| P 优先于最近目标 | 跳价可能先处理更远目标 | 建议最近未处理目标优先，单轮一个目标；P 与最近目标相同则去重 |
| 小仓位无法部分平仓时直接全平 | 动作超出原减仓比例 | 全平降级须有明确配置 |
| 手数精度仅按小数位推断 | 0.25 等步长可能不合法 | 按实际 volume step 量化并校验 |
| 止损仅按 digits 归一化 | 不一定符合 tick size | 校验 tick size、最小距离及冻结距离 |
| 状态键缺少服务器 / 品种上下文，跨日目标与旧完成标记混用 | 重连、跨日或不同终端可能歧义 | 状态按服务器、账户、持仓生命周期、规则和目标日期归属 |

源码入场佣金在添加跟踪时读取，并不能涵盖未来平仓费用。因此“保本”不等于扣除全部费用后的净收益保证。

这些是本次拆分提出的规则，不冒充旧策略原文：

## v1 接入分析（历史记录，不在当前工作范围）

本次查看了 `server/src/modules/inference/domain/inference.ts` 的分析和交易员结果合同，以及交易员仓位参数测试。现有交易员动作包含开仓、挂单、改单、平仓和撤单，能承载主要建议；但没有据此确认完整的 PivotGuard 实时状态已经实现。

落地前需逐项补齐：

1. **分析到交易员的数据**：H1/H4 路径、M15 依据、唯一 M5 事件及首次确认时间、M1 过滤、结构止损候选、目标和管理证据。结构化传递，不靠交易员从长正文猜价格。
2. **最终入场核对**：实际报价、入场方法、候选保护、目标和对应收益风险。若需要先形成候选再计算，应增加程序评估阶段，避免模型因缺少最终比值永久等待。
3. **持仓保护快照**：按实际品种计算的当日 Pivot、启用配置、触发线、持续计时、可比盈利峰值、目标阶段及未决动作。
4. **执行状态机**：部分平仓受理 → 成交确认 → 剩余仓位更新 → 合法保本候选 → 改单确认；重复轮次不得重复减仓。
5. **生命周期**：跨日采用“开仓日固定目标”还是“按新日线更新目标”须作为显式配置；目标事件身份跟随选定模式，不能混用新目标和旧完成标记。加减仓、净额账户及重启后的状态恢复也需要定义。
6. **秒级保护**：服务端或终端确定性模块负责，部署位置取决于断线保护要求；只靠定时 AI 请求不能等价替代原 EA 盯盘。
