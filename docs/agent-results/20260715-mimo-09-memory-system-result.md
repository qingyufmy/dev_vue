# Task 09 交付结果：个人经验记忆与压缩

## 结论

个人记忆仅由用户确认准确的复盘产生，并始终按用户隔离。检索、注入、撤销、重复项处理、压缩和摘要回滚均有可审计记录；平台共享策略不会直接混入用户账户经验。

## 已实现

- 确认复盘后创建 owner-scoped 记忆条目；相似内容被标记为重复候选，不静默覆盖历史。
- 检索按用户、策略、品种、周期、状态和 Token 预算筛选并排序；管理员无正文读取入口。
- 平台策略需要个人记忆时自动创建/复用用户私有派生策略，保证后续推理使用该用户的模型解析和记忆空间。
- 每次实际或影子检索写入注入日志，并可关联信号与推理快照；历史快照不会因记忆撤销而改写。
- 用户可全局关闭记忆、撤销单条经验或激活重复项；撤销会使相关摘要失效并排队重新压缩。
- 超过阈值后由统一模型 resolver 总结压缩；任务具备租约、重试、版本化摘要和回滚能力。
- 付费配对实验必须同时满足管理员授权和用户显式同意，额外运行一次无记忆对照；对照结果绝不下单，只保存脱敏决策摘要与 hash。

## 灰度与隐私

- 复盘生成、经验记忆、压缩默认关闭；用户开关只能进一步收紧管理员开关。
- `retrieval_shadow` 先记录候选而不注入，审核相关性和 Token 后才进入实际注入。
- 管理员只能查看活跃/撤销数量、Token 和队列年龄等聚合健康指标。

## 验证

- `tests/ai/memory-system.test.js` 覆盖 owner 隔离、候选排序、Token 预算、撤销重压缩、摘要回滚、配对实验脱敏与双层开关。
- 手动和自动推理均关联记忆注入日志与不可变推理快照。
