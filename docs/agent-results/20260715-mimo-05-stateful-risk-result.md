# Task 05 交付结果：L2/L3/L6 状态型风控与熔断治理

> 执行者：Codex。用户取消 Mimo 委派后，由 Codex 直接实现并复审。

## 账户身份与持久状态

- migration 060 为交易账户增加身份核验和观察期字段，并以 `user_id + broker_server + login_account` 建立唯一身份。升级前若已有重复账户，会先保留最新有效记录、迁移策略订阅，再删除冗余记录，避免唯一索引导致迁移中断。
- 新增数据库持久化的账户风险状态、恢复申请和全局风险控制。Redis 不参与正确性判断，服务重启或 Redis 不可用不会丢失熔断、冷静期或最近成功开仓时间。
- 检测到账户切换时暂停旧账户订阅，新账户回到待审核与观察状态；管理员审核后才允许自动开仓。

## L2 交易状态规则

- 在同一交易账户数据库锁内完成持仓/挂单统计、频率/去重判断和风险预占，阻止并发请求穿透。
- 同向敞口同时计算外部 MT5 持仓、挂单和本系统尚未释放的预占。
- 每日开仓计数口径为北京时间自然日内成功的新开仓/新挂单，加仍处于 active 或 uncertain 的预占；被拒绝、明确失败、平仓、减仓与撤单不计入。
- 实现最小开仓间隔、每日成功开仓上限、signal id 幂等，以及同品种同方向的价格/时间窗口去重。

## L3 账户熔断

- 日亏损使用北京时间日初权益作为分母；分子为当日已实现净损益（profit + commission + swap + fee）与当前浮动亏损之和。盈利浮盈不抵消已实现亏损。
- 连续亏损按完整 position 聚合后判断，不把同一仓位的分批成交 deal 当作多笔亏损。
- 回撤高水位按净入金、提款和信用变化同步平移，资金流本身不制造盈利或回撤。
- margin level、总名义敞口使用 Bridge 返回的真实合约参数；非账户币种敞口需要可验证汇率。
- 触发日亏损、连续亏损、回撤或保证金规则时，halt/cooldown 先持久化再拒绝订单，不会因业务异常回滚状态。

## L6 治理与失败关闭

- 支持全局和用户 Kill Switch、账户恢复申请、管理员审核恢复、规则冷静期与新账户观察期手数上限；所有治理操作记录原因和审计。
- 全局 Kill Switch 只能由管理员解除。用户不能绕过账户审核或持久熔断。
- 历史分页不完整、账户快照缺失、合约参数缺失、必要汇率缺失、账户待审核、全局/用户停机或已熔断时均 fail closed。
- 平仓、减仓、撤单和紧急清仓不经过新开仓闸门，在所有停机状态下保持可用。

## 同步修复：历史净损益

- Python Bridge 的历史行增加 `fee` 和 `net_profit`，账户统计中的总盈利改为汇总 profit、commission、swap、fee，避免手续费被漏算。
- 未设置日期筛选时仍查询完整账户历史，入金、提款、信用和早期交易不会再被 31 天窗口截断。
