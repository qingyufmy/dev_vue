# Task 08 交付结果：证据化复盘工作流

## 结论

复盘只对“已完成精确归因、订单已完全平仓、推理证据完整”的结果生成。用户可以修订正文并单独标记交易流程是否有问题；只有用户确认内容准确的版本才能进入个人记忆。

## 已实现

- `review-workflow.js` 以 `signal_outcomes`、原始信号、不可变推理快照、历史提示词、推理时 K 线和完整 deal 为证据源。
- 无 deal、部分平仓、Netting 多意图/INOUT 歧义、缺失快照或缺失原始提示词时拒绝生成，不用当前配置伪造历史。
- 复盘任务具备租约、重试、失败状态和幂等队列；模型响应经过严格结构校验。
- 结果明确区分“决策质量”和“最终盈亏”，避免把盈利机械等同于正确。
- 用户编辑采用期望版本号控制并发，每次修改产生新版本；证据保持只读。
- 确认接口将“交易流程问题”与“复盘内容确认”拆开；管理员健康接口只返回聚合队列指标，不返回正文。

## 权限边界

- 用户仅能读取、编辑、确认和重试自己的复盘。
- 管理员不能通过复盘或健康接口查看用户复盘正文、提示词、证据正文或个人记忆。
- 未确认、确认有问题或证据不完整的复盘不会生成记忆。

## 验证

- `tests/ai/review-workflow.test.js` 覆盖证据完整性、拒绝场景、严格模型输出、版本冲突、owner 隔离和确认状态。
- 与 Task 07 的 Hedging/Netting、费用稳定扫描和部分平仓测试联合验证，确保不提前生成复盘。
