# M1 / B2 / P3：离线账户与历史归属防护

> 2026-09-05；实施基线 `d5f33571`。P3 源码、主代理复审与离线验证完成；不执行迁移、回填、部署、服务启动或终端访问。下一确认门 P4。

## 1. 实施前两轮复审

第一轮（需求与职责）：账户实体不依赖档案存在；当前账户和历史账户列表分用途，历史列表不得成为交易授权。终端事实属于账户，不属于采集时连接用户；只有完整交易时间范围落在可靠归属区间，才能形成用户可见记录。前端仅适配 nullable 合同及历史列表参数，不改布局，不引入组件或依赖。

第二轮（安全、数据与并发）：现有 `account_trade_records_v4.user_id` 可能来自旧采集者，因此不能仅取消 ownsAccount 门。查询、详情、汇总、采集同时要求归属证据；未证明的记录保留但隔离。追加 nullable user_id/ownership_interval_id，不填虚拟用户，不批量修旧数据。旧记录须后续独立对账，不能自动改 owner。跨归属或不完整交易保留原始事实和未归属投影；不猜测按单一开/平仓时间分配。

账户/持仓/挂单投影增加来源证据，trusted writer 与投影同事务提交；缺失来源的旧缓存不可展示给新 owner。在线状态须 SQL 新鲜心跳与 Redis 当前租约精确一致，读取失败按离线处理。固定锁序账户主行→采集同步状态→事实→记录→日汇总→outbox，不在事务内请求终端。MySQL 的真实锁行为和 DDL 仍须单独演练。

## 2. 实施范围

- 追加 020：私有投影 provenance、交易记录 nullable owner 与 interval 关联；旧迁移、冻结 JSON 不动。
- current/history 账户读取分离；无设备返回 null 档案、offline、不可交易，保留真实账户身份。
- OpenAPI、服务端 DTO、前端合同和客户端同批支持 nullable terminal_profile_id；交易记录使用 history 账户列表。
- 采集按完整归属区间确定 user/interval；查询所有分支使用同一证据谓词；不依赖当前 owner。
- 历史实时订阅按历史权限鉴权，不能借此读取当前持仓；失效事件仅用于回读，不包含私有交易正文。
- HTTP workspace 与账户级 TraderContextBuilder 均显式传入所属系统用户读取私有投影；私有 getter 不保留“省略用户即当前 owner”的隐式授权。排队任务不因账户转移而读取新用户数据。
- 无可靠来源的持仓/挂单返回 revision 0，而不是“当前 revision 的空仓”。TraderContextBuilder 拒绝缺证据的零版本，避免把读取不到误解为无敞口。

## 3. 证据与尚未覆盖的边界

本批采用区间证明，不把旧 attribution 的 source_id、备注或连接用户当作不可变系统归属。跨区间交易即使有某条执行关联，也必须有完整生命周期的独立证明后才可解除隔离；此类精确拆分/回填仍在后续 B3 对账门。新归属区间登记/接管事务由 P5 对应流程完善，区间为空不回退旧 owner 猜测。

原始时间转换、旧记录重归属、真实 SQL/Redis、真实设备登记、观摩 P4 动态授权与上线迁移均不因本批通过而完成。

本批源码依赖 018–020 结构及有效的 owner interval/revision 数据。历史运行库和新接入流程尚未具备这些证据时会拒绝读取/投影写入，不设置兼容猜测分支。因此必须连同后续 P5 登记/接管、B3 回填对账完成后再做运行验收；不能单独部署本批并宣称原功能已无缝切换。当前真实 A/B schema 安装证据仍只到 017。

观摩私有快照暂不借 source owner 身份读取；发布投影、动态撤权与 source 切换由 P4 完成。设备档案列表及真实登记/接管生命周期仍属于 P5，不以本批账户列表的在线核验代替设备全链路验收。

历史 API 的 freshness 只根据本人已证明记录判断 empty/stale；不引用当前连接者的全局同步完成时间，freshThrough/lastSuccessAt 暂为 null，不把“已显示若干记录”冒充“全历史已同步”。旧记录的 interval 为空时继续隔离；常规增量窗口之外的旧记录须经 B3 专项对账，不能声称本批已自动恢复全部旧交易。

日汇总只重建指定账户的派生缓存，不删除事实或交易记录。同一用户/账户/业务日期若混入多个时区偏移（或偏移缺失），不生成该日缓存，避免唯一键导致分组互相覆盖；API 列表和日曲线仍从已证明的记录计算。

历史失效通知按历史 owner 分页分发，逐用户发送历史/audit 失效，不携带当前 owner 的同步时间或交易正文。仅订阅 trade_history 的 WS 目标允许 history 账户权限；混合持仓等资源不能借此绕过 current 权限。
