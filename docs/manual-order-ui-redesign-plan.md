# 手动下单界面重设计方案

## 目标

在不改变普通手动下单、管理员策略分发、订单预览、风控校验和 API 合同的前提下，将现有纵向堆叠表单重构为清晰、紧凑、可响应的交易票据。

## 现状审查

- 管理员分发面板位于所有交易字段之前，视觉权重过高，普通下单主路径被打断。
- 分发能力关闭时，`hidden` 会被组件的 `display: grid` 样式覆盖，导致不可用字段仍占据页面空间。
- 品种、报价、手数、订单类型、保护价和最终操作缺少清晰分组，用户需要从上到下逐项扫描。
- 可选说明与辅助文案占用过多纵向空间，核心价格和最终方向操作反而不够突出。
- 桌面端仍按窄表单排布，空间利用率低；移动端虽能收缩，但没有围绕交易操作重新排序。

## 设计基线

依据 `ui-ux-pro-max` 的金融交易深色界面建议：

- 保留现有深色与金色语义令牌，不引入新的品牌色、字体或依赖。
- 使用专业、低动效、信息密度适中的订单票据结构。
- 表单字段始终保留可见标签；关键状态不能只靠颜色表达。
- 交互目标最小 44px，焦点清晰，动效控制在 150–300ms，并支持 `prefers-reduced-motion`。
- 375px 无横向滚动，桌面端使用两列信息布局，窄屏按交易顺序自然堆叠。

## 信息架构

1. 票据标题与当前执行模式。
2. 品种与实时买卖报价。
3. 订单参数：手数、订单类型，以及按需展开的挂单参数。
4. 风控参数：止损、止盈。
5. 管理员专属策略分发：作为模式开关，只有能力可用且用户主动开启后才显示策略、有效期和选填原因。
6. 最终操作区：买入与卖出同时显示对应成交参考价。
7. 分发进度：仅有真实分发任务时显示，不打断新订单编辑。

## 不可改变的合同

- 保留现有元素 ID、事件入口、普通手动下单与管理员策略分发 payload。
- 策略分发仍只支持市价 BUY/SELL，交易手数直接使用 `volume`。
- 策略分发仍强制止损和至少一个止盈；原因仍为选填，填写时 2–500 字。
- 保留能力门控、管理员门控、报价校验、二次确认、逐目标进度和失败目标重试。
- 不新增后端接口、迁移、交易行为或自动下单行为。

## 验收

- 能力关闭时管理员分发面板完全隐藏；普通用户永不看到管理员字段。
- 切换订单类型仅展开相关字段；切换策略分发仍强制回到市价。
- 桌面、375px、横屏下均无横向滚动，按钮和字段不被遮挡。
- 键盘焦点顺序与视觉顺序一致，所有输入均有关联标签，图标按钮有可访问名称。
- reduced-motion 下没有依赖动画才能理解的状态变化。
- 相关静态合同、前端治理、普通下单和策略分发测试全部通过。

## 实施复审

### 第一轮：结构与业务隔离

- 保留所有既有字段 ID、事件入口和接口载荷；只新增票据分区、标签关联与 ARIA 状态同步。
- 桌面两列仅作用于手动票据内部，没有改动互斥标签页使用的外层 `trading-grid`，避免影响订单管理和 AI 持仓管理。
- 管理员分发能力关闭时，面板、展开字段和历史进度均按 `hidden` 强制隐藏；普通手动下单恢复为页面唯一主路径。

### 第二轮：真实页面与过度设计检查

- 本地已登录页面验证桌面、375px 和 667×375 横屏均无横向溢出；买入、卖出按钮完整可见。
- 市价与限价切换验证通过：挂单字段的可见状态与 `aria-hidden` 同步。
- reduced-motion 模拟环境中票据交互动效降为近零；控制台无新增警告或错误。
- 删除响应式文件中与基础样式重复的 reduced-motion 规则和横屏单列声明，避免重复维护。

## 剩余风险

- 本次没有发起真实订单或管理员策略分发；交易结果仍由既有二次确认、后端风控和 Bridge 流程保证。
- 管理员分发功能门控在当前本地环境关闭，因此本轮真实浏览器验证覆盖了“完全隐藏”的失败关闭路径；开启后的字段、预览与进度由静态合同和既有分发回归测试覆盖。
