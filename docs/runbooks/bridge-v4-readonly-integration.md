## 1. 验收范围

验证普通用户从网页配对到软件取得当前账户数据，再完成断线恢复、换号、移除档案与失败重试。MT4/MT5 仅使用已由用户启动并明确指定的终端，账户切换由用户操作。当前开发机 MT5 曾被明确声明为实际使用账户，不沿用早期模拟交易授权。

“只读”限定终端操作。配对、首次认领、连接、快照接收与撤销会写服务端数据库和 Redis，客户端会写 DPAPI 档案和 SQLite；必须在目标确定后逐项确认这些写入。不得发送任何下单、挂单、改单、撤单或平仓指令，包括用真实命令制造 `uncertain`。

准备批次编写本手册、读取源码、离线解析迁移计划，并读取本机进程/监听端口/服务及工具路径。随后用户指定使用 `.env` 连接，已在内存中读取凭据并进行只读依赖核对，未输出凭据、运行真实终端探针或启动窗口。

## 4. 迁移准备

本机只调用 `loadMigrationPlan` 与 `loadMigrationCorrections` 读取 SQL 文件，结果为 bootstrap + 001–024 共 25 个计划文件、159 条计划语句，另有 1 个 correction。该结果不代表目标库已经执行，也不是遗漏 checksum 校验的直接执行清单。

024 为配对请求表；019 为账户归属区间，023 为档案 epoch 范围。不得只补 024 后假定全部依赖齐全。目标确定后，按现有迁移 runner 核对完整计划、checksum、checkpoint 和 correction；记录待应用的具体差异，再申请迁移。已有共享迁移不改写、不重排。

`scripts/migrate-v4-schema.mjs` 即使不传 `--apply` 也会建立真实 MySQL 连接，不能当成本地离线检查。这里只使用纯文件解析模块，没有运行该 CLI。历史交接中的“018–024 未执行”是历史记录，目标现状待查。

## 5. 有界验收顺序与证据

所有行初始状态均为“未执行”。每行记录 UTC 开始/结束、精确 commit、脱敏身份关联、请求/连接 ID、结果及证据位置。成功配对、健康接口 200、hello accepted 都不能单独代表完整流程通过。

| 顺序 | 操作与范围 | 通过标准 |
| --- | --- | --- |
| 0 | 核对环境/隔离、迁移、版本、证书，检查已授权角色 `/health/live` 与 `/health/ready` | 实际主机/目录/commit 一致；依赖就绪；无非预期消费者及交易工作 |
| 1 | 测试用户在 trade 配对，客户端领取并保存 | 正常用户流程可用；profile/installation 精确对应；凭据不进入 URL、日志或明文目录 |
| 2 | 用户选择已运行终端，识别账户 A，连接 | 事实来自当前终端；币种无默认回填；新账户仅建立首次 owner，已有账户只能使用有效归属 |
| 3 | 对已有他人归属测试账户进行受控冲突检查 | 拒绝接管；账户、owner、绑定和会话无部分提交；不使用真实第三方账户 |
| 4 | 两个专用测试客户端竞争同一新测试账户 | 仅一个合法结果；失败无部分 owner/绑定；与离线重复键/死锁替身证据分开记录 |
| 5 | 读取账户快照，观察心跳和状态，保持 5 分钟 | 显示 server/login 对应当前 A，币种/时间一致；无交易命令生成/消费/终端执行证据 |
| 6 | 仅中断本测试连接网络 30 秒，再恢复 | UI 状态可解释；重连刷新事实、epoch 正确；无重复活动路线和迟到串号结果；不影响其它连接 |
| 7 | 用户在已指定终端手动由 A 换至 B，再编辑档案并连接 B | 旧路线失效；保留 profile 凭据；B 数据目录隔离；切回 A 时 epoch 不倒退，A 账本保留 |
| 8 | 软件关闭与重新打开；两进程竞争同一测试档案 | 成功清理后才释放锁；关闭失败能重试；同档案只有一个活动 Worker，其它档案不受影响 |
| 9 | 移除专用测试档案；对该请求模拟响应丢失后重启并重试 | 持久化待移除且不自动连接；同凭据幂等撤销；匹配回执后才移除；其它档案和历史保留 |
| 10 | WinForms 窗口与 Windows 7 分别验收 | 新增/编辑/失败反馈/重试/退出可用；Win10/11 成功不能代替 Win7 结论 |

用例 3/4/9 涉及测试身份准备和故障注入，必须在目标方案中先指定范围和实施方式；不直接复制生产数据或改客户端生产目录。网络中断仅作用于测试进程/连接，不关闭整机网络。无法有界注入时保留未执行，不使用交易指令或全局防火墙故障替代。

换号计时分别记录：终端变化时刻、最后源事实时间、本地判断失效、socket 关闭、远端 route/lease 不再有效。当前源码每 10 秒检查事实，25 秒为事实过期判断阈值；阻塞 I/O 和调度可延迟实际关闭。Redis lease 按最后有效心跳后 45 秒 TTL 清理，不把任意阈值当作实测关闭上限。将实测延迟与源码阈值并列报告。

## 6. 停止、保留与恢复

出现错误账户数据、其它用户状态变化、非预期交易命令、身份绕过、迁移差异、凭据泄露或异常重启循环时立即停止该用例及已授权测试连接，保留脱敏证据并诊断，不反复重启掩盖失败。

结束时仅关闭本轮启动的进程，不关闭用户终端；恢复本轮明确修改的测试配置。保留账本和 `uncertain`；撤销/移除用例不能通过删除历史或恢复旧有效 token 来回滚。数据库清理、测试账户删除、Redis 清空及生产配置变更均不作为自动收尾步骤。

## 7. 两轮复审与当前结论

第一轮（需求/职责）：复用现有网页、WinForms、探针、迁移 runner 与 Gateway，不新增独立诊断平台。补齐“终端只读仍写服务端”的范围说明，将完整用户流程与独立终端探针区分。P5B、交易、发布与安装器不纳入本轮。

第二轮（兼容/并发/异常）：核查发现 Gateway 自带 command consumer、入口加载 `.env`、迁移无 `--apply` 仍连接数据库，已据此补充独立依赖和有效配置核验。把响应丢失、两进程争锁、新账户竞争、Win7 与换号实际计时列为实机证据缺口；没有为缺少目标信息猜测数据库、账户或启动命令。

当前可审查产物为本手册、本地环境盘点、离线迁移计划解析及用户指定 `.env` 目标的只读连接结果。此前源码批次记录的 462 项服务端测试、77 组客户端烟雾和构建通过，本轮未重复运行，不能替代以上实机验收。用户已确定本地运行及远程依赖来源；下一步确认专用 V4 新库初始化，再补齐具体启动与迁移执行记录。
