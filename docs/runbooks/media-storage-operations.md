# AURUM 文件与媒体存储运维手册

## 1. 运行边界

- 新文件按管理后台的文件类型设置选择本地或七牛；切换 provider 不迁移、不改写旧文件。
- 每个文件由 `stored_files` 记录自己的 provider 和对象键，读取和删除始终按文件记录执行。
- 云端失败不会静默改存本地。系统不扫描整个 bucket，也不删除无数据库归属的对象。

## 2. 日常检查

1. 打开“管理后台 -> 系统设置 -> 文件与媒体存储”。
2. 确认本地目录可读写、剩余容量不低于 5 GiB 且不低于文件系统容量的 10%。
3. 检查“上传中 / 失败 / 待删除”数量。少量短时上传中属正常；连续两个 6 小时维护周期仍不归零需要检查日志和 provider 连通性。
4. 七牛配置变更后重新执行连接测试。测试必须完成上传、查询、HTTPS 读取和删除闭环。

## 3. 本地存储备份与恢复

- 默认根目录为 `server/private-uploads/media-storage`，生产可用 `MEDIA_STORAGE_LOCAL_ROOT` 改到独立数据盘。目录不得位于公开静态目录。
- 备份必须在同一恢复点包含 MySQL 和本地媒体根目录。先备份数据库，再快照或备份媒体目录，记录两者时间。
- 恢复时先停止新上传，恢复数据库和对应媒体目录，检查目录所有者/可读写权限，再启动服务。
- 恢复后抽查本地附件、图片和视频 Range 播放，不要用文件名批量重建数据库关联。

## 4. 七牛配置与密钥轮换

- 使用私有空间、生产 HTTPS 域名和正确 region；确认 CDN 支持 Range 并保留 `206`、`Accept-Ranges` 和 `Content-Range`。
- 轮换 AK/SK 时：新建最小权限凭证 -> 在后台替换 -> 重新连接测试 -> 抽查旧对象读取和新对象上传 -> 再停用旧凭证。
- 当仍有七牛资产时不允许直接更换 bucket。如需换 bucket，必须单独编制可暂停的迁移任务，不在系统设置中强行覆盖。
- 日志、工单和截图不得包含 AK、SK、上传令牌或私有下载签名地址。

## 5. Provider 切换

1. 切换前确认目标 provider 健康；七牛必须有当前配置版本的成功测试。
2. 仅修改需要的类型（视频、附件、图片或资源），保存后检查“当前生效”。
3. 上传一个小测试文件，完成读取/播放和删除。旧文件仍从原 provider 读取。
4. 若失败，将该类型的新上传路由切回原 provider；不要删除新表、旧对象或旧字段。

## 6. 异常恢复

- 过期直传会话和 `deleting` 文件每 6 小时有界重试，每轮最多 50 条。
- 维护任务只删除有 `stored_files` 记录、对象键合法且已无业务表引用的对象。仍被引用的记录会保留，需要查明状态来源。
- 连续失败时，先检查本地权限或七牛凭证/域名，修复后等待下一轮重试。不要直接把状态改为 `deleted`，除非已独立确认远程对象不存在。

## 7. 上线前必做的真实环境验证

- 用生产私有域名执行连接测试。
- 上传一个 `MP4 / H.264 / AAC / 1920×1080 / Fast Start` 测试视频，确认服务端 `avinfo` 和有界 Range 校验通过。
- 使用短期播放地址发送 `Range: bytes=0-1023`，必须返回 `206 Partial Content`、`Accept-Ranges: bytes` 及正确 `Content-Range`。
- 验证链接过期后失效，前端只自动换取一次新地址并恢复原播放位置。

本手册不包含生产凭证和签名 URL。真实七牛/CDN 验收需在配置完成后单独执行并记录无敏感证据。
