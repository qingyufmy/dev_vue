# 阶段 12L：交易实验室 AI 分析前端竖切验收记录

> 日期：2026-09-04
>
> 范围：AI 交易实验室首页最新分析、AI 分析师历史与详情、手动分析、用户级分析实时失效通知、共享 shadcn-vue Progress 与 Sheet 触控修正
> 边界：仅完成源码和离线验证；未启动服务、未读取真实 `.env`、未执行迁移、未连接真实 MySQL/Redis/provider/Bridge/MT，也未执行交易

## 1. 结果

本阶段把阶段 12K 已完成的用户级分析 HTTP 与 WebSocket 能力接入新版交易实验室，并保持“HTTP 权威快照 + WebSocket 小事件”的边界：

```text
首次进入 / 断线恢复
  -> HTTP 分析摘要列表
  -> 选择记录后 HTTP 完整推理
  -> WebSocket 仅订阅 analysis job 与 market analysis 小事件
  -> 新结果到达只失效并重拉分析列表
```

首页的“最新 AI 分析”不再使用占位数据，显示当前系统账号下最新一条行情判断的品种、市场偏向、交易机会、置信度、摘要、策略和分析时间。完整推理通过按需加载的全屏 Sheet 读取，不把大正文打入首页首屏，也不进入 WebSocket。

`/analyst` 已从占位页替换为真实页面。历史记录按系统账号归类，不随 MT4/MT5 交易账户切换；列表只显示品种、策略、机会类型、偏向和时间，不重复塞入长结论。右侧详情按“当前答案、关键价位与失效条件、正反证据、数据缺口、完整推理正文”展开，完整正文固定在结构化内容底部。

## 2. 手动分析

- 用户从 AI 分析师页打开 shadcn-vue Sheet，选择一条当前可用且已发布的 `analysis` 策略并输入品种。
- 请求固定为 `mode=manual`，不携带自动执行字段，不会直接下单。
- 每次提交生成独立 `Idempotency-Key`；提交中禁止重复点击。
- 服务端仍是 3 分钟冷却的唯一权威。前端在成功后同步进入 3 分钟禁用期，收到服务端 `retry_after_ms` 时按权威剩余时间禁用。
- 同页通过 `analysis.job.changed` 展示已排队、分析中、完成或失败状态；新 `market_analysis.created` 到达后仅刷新分析列表。

## 3. 组件与可换肤边界

本阶段通过官方 `shadcn-vue` CLI 检查工程并读取 Card、Badge、Button、Sheet、Tabs、Table、ScrollArea、Skeleton、Empty、Alert、Select 和 Progress 文档。新增 Progress 使用官方 `reka-nova` Registry 源；表单、状态、列表操作、抽屉、空状态和加载态均组合唯一共享组件源，没有新增第二套 UI 控件。

考虑后续可能随 Astra 方向重新设计，本阶段只冻结稳定的产品结构和交互，不把某套视觉写死：业务页面只使用语义令牌、共享组件 variant、响应式布局和少量模块内组合。未来可通过设计令牌和展示组件换肤，不需要改 API、实时协议、查询键或领域状态。

共享 Sheet 的关闭按钮由 28px 修正为 44px 触控区域；主要刷新、手动分析、关闭、提交和全屏操作同样使用至少 44px 的组件尺寸。全屏详情由 Sheet 自身管理层级，没有手写 z-index。动效仅用于加载反馈并尊重 `prefers-reduced-motion`。

## 4. 数据与实时行为

- 首页首屏并行读取账户工作区和最新分析，但分析读取失败不会清空账户、行情或持仓数据。
- 首页只在首次加载读取策略列表；后续新分析事件只重拉一条最新摘要，避免每次事件重复请求不变配置。
- 首页原实时连接追加用户级 `market_analyses` 目标，没有再创建第二条 WebSocket。
- 组合连接改用完整浏览器事件合同维护连接内 sequence，避免用户级分析事件夹在账户事件之间时被误判为序列缺口。
- 复审时修复了原首页恢复回调会再次停止/创建连接的问题：现在断线恢复只执行 `syncAccountSnapshot`，HTTP 成功后由原连接控制器建立唯一新连接。
- AI 分析师页离开时关闭自己的唯一连接；重连前先刷新 HTTP 列表，HTTP 失败不会带着未知快照直接恢复实时状态。
- 完整推理、输入哈希、证据对象和正文始终走授权 HTTP；WebSocket 不承载大载荷。

## 5. 第一轮复审：需求覆盖、职责和最小改动

第一轮逐项核对首页最新分析、系统账号归档、历史列表、完整推理、手动选择策略、3 分钟冷却和自动更新。现有 `/api/v4/strategies`、`/analysis-jobs`、`/market-analyses` 与阶段 12K 实时资源已经覆盖所需能力，因此删除了新增后端路由、数据库字段或另建前端事件总线的设想。

复审发现策略接口会同时返回草稿和退役记录，若全部放入手动分析选择器会形成必然失败请求；已收窄为仅显示有活动版本的 `active` 分析策略。另发现首页新结果事件若同时刷新策略会产生无意义请求，已改为首屏读取策略、事件只刷新最新摘要。

视觉复审没有追求一次性定稿：保留当前深色交易工作台和信息优先级，只建立组件化结构、语义色、触控面积、加载/空/错状态与 375/768/1024/1440 的布局断点，为后续 Astra 风格调整保留低成本替换边界。

## 6. 第二轮复审：并发、恢复、安全和连带 Bug

第二轮按连接时序检查首页账户事件与新增用户级事件。原连接只解析交易事件，如果分析事件占用 sequence，会让下一条交易事件被误判为缺口；现已改为先校验浏览器事件联合合同和系统用户，再按资源作用域分发。

同轮发现原断线恢复传入 `loadAccount` 会调用 `stopTradingRealtime()`、改变 generation 并创建连接，外层恢复器随后又尝试连接，存在无法恢复或重复连接的风险。现拆出不改变连接生命周期的 `syncAccountSnapshot()`，恢复顺序稳定为 HTTP 快照成功后单次连接。分析师连接同样在 HTTP resync 失败时继续退避，不能把失败的同步当成成功。

安全复审确认：客户端不提交用户 ID；事件必须匹配当前会话用户且用户级分析的交易账户作用域必须为空；详情 ID 仍由服务端按 owner user 授权；模型正文只以 Vue 文本插值呈现，不注入 HTML；手动写请求同时要求当前 CSRF 与幂等键。

## 8. 剩余风险与后续门

- 本阶段没有启动真实 API、浏览器实时网关或前端开发服务，因此真实登录态、MySQL 数据、Redis 事件、provider 输出和 375/768/1024/1440 浏览器视觉验收仍需阶段 15～16 联调。
- 当前 V4 只提供分析结果列表，没有“按用户查询仍在运行的 analysis job 列表”恢复端点。页面刷新后，已完成结果可以恢复，但提交中任务的即时状态只能等待新事件；后续若产品要求跨刷新显示队列进度，应新增窄 HTTP 查询，而不是把 WebSocket 当历史库。
- 顶栏自动分析倒计时、自动分析开关和订阅管理不属于本竖切，仍按后续交易实验室壳层阶段实施；AI 分析师页有意不重复显示自动分析倒计时。
- 市场分析只表达行情方向和机会，不代表账户可执行；AI 交易员、确定性风控、执行 intent、Bridge 与 MT 结果仍需在各自页面接入后才能形成完整用户链路。
- 本次没有迁移或删除任何数据库结构，也没有触发模型调用或交易操作。

因此，本阶段可以认定为“首页最新分析与 AI 分析师真实前端竖切已完成源码实现并通过离线验证”，不能据此宣称真实数据、浏览器视觉、模型或交易端到端已经验收。
