# 策略组合与效果展示实施方案（2026-09-20）

## 目标与用户流程

策略运行仍保留“行情分析策略”和“交易执行策略”两个独立版本及职责，但面向普通客户只呈现一个可选择的策略组合。客户在策略师页面选择组合、账户和品种后，即可配置分析时段并决定是否启用自动交易，不再单独选择交易执行策略。

策略详情展示当前用户在该组合下、由终端历史精确归因的实盘效果。首版指标包括净收益、最大回撤金额、已平仓做单数、盈亏比和胜率。只有 `closed + system + exact + complete` 的终端交易记录进入统计；按币种分组，币种混合或样本不足时不拼接金额，不用账户总收益冒充策略收益。收益率和回撤率需要可靠资金基线，首版缺少该证据时明确显示不可用。

## 最小数据模型

- 在分析策略上增加一个可空的 `paired_trader_strategy_id`，指向交易策略。交易策略本身不反向持有分析策略，允许一个成熟的执行策略服务多个分析策略。
- 绑定属于策略元数据，沿用现有鉴权、幂等键、`If-Match` 修订号和写入收据；绑定变化使策略修订号递增。
- 草稿分析策略可以暂未绑定。客户可用的组合必须已发布；启用自动交易时必须存在已发布且可访问的绑定交易策略。
- 新建或更新订阅时，服务端以分析策略上的当前绑定为权威，自动写入交易策略及其当前版本。旧客户端显式提交的交易策略只在与绑定一致时兼容接受，避免静默改用另一策略。

## 效果口径

- 从终端交易的 `bridge_command` 精确归因，沿 `bridge_commands_v4 → execution_intents → trade_decisions → market_analyses` 同时核对分析策略和交易策略，避免同一执行策略被多套分析策略复用时串算效果。
- 仅统计已平仓、系统来源、精确归因、证据完整且具有明确账户币种的记录。
- 净收益为纳入样本的 `net_profit` 之和；胜率为正收益交易数除以全部样本；盈亏比为总盈利除以总亏损绝对值；最大回撤金额由按平仓时间排列的累计净收益曲线计算。
- 返回样本起止时间、币种和证据状态。没有精确样本时返回 `insufficient`，界面显示原因而不是零绩效。

## UI 信息架构

- 页面主导航保留“策略组合 / 账户订阅”，移除客户侧的“分析策略 / 交易策略”双选择心智。
- 左侧目录只展示分析策略组合，卡片同时显示绑定执行策略、发布状态和紧凑效果摘要。
- 详情顶部给出组合名称、用途、可用状态与主操作；第二层展示五项指标及证据范围；第三层再渐进披露“分析引擎 / 执行引擎”和各自版本。
- 编辑订阅只选择一个策略组合。自动交易开关只表达是否启用，不再出现交易策略下拉框。
- 管理员和个人策略所有者在策略资料中配置绑定执行策略；内部提示词与版本仍可分别维护。

## 第一轮评审：产品边界与职责

结论：采用“分析策略作为客户可见组合根 + 单向绑定交易策略”，不新建套餐、产品、回测或排行榜系统。它满足一次选择，同时不破坏分析师/交易员的独立运行合同。策略效果明确为当前用户的精确实盘样本，不跨用户汇总，也不把 AI 复盘结论当财务事实。

调整：允许草稿暂未绑定，避免阻塞现有策略编辑；但自动交易必须绑定且交易策略已发布。列表中的未绑定项标为“待配置”，不伪装成完整组合。

## 第二轮评审：兼容、数据与失败边界

结论：保留订阅表里的两个策略及版本快照，历史订阅、复盘和执行归因不改语义。新服务端会从绑定派生交易策略；旧客户端显式值必须匹配绑定。绑定更新不追溯改写历史订阅，只影响以后新建或主动更新的订阅。

调整：绩效查询只读取精确终端证据；混合币种时返回分组不可合并状态，前端不展示误导性的合计金额。百分比收益和百分比回撤留空，直到资金基线链路提供可验证输入。数据库采用追加迁移并补升级登记与结构校验；接口合同、生成类型、运行校验和前端消费者同步更新。

## 验收与剩余风险

- 合同正反例、服务端绑定与订阅派生、精确绩效口径、前端单选流程和响应式页面均需定向验证。
- 历史分析策略不会自动猜测绑定，需要策略管理员或所有者设置一次。
- 当前效果是实盘已平仓结果，不是回测，也不代表未来收益；页面只需清晰标注数据来源，无需额外风险弹窗。
- 本轮不发送真实交易、不启动或部署生产服务。
