# 核心交易链路与自动交易调度分析

方案已按用户审查更新。账户并发控制及排队任务合并已实现；尚未对新策略完成真实终端执行验收。

## 推荐调度

以已持久化的自动行情分析完成事件为主触发。范围为当前账户内策略支持品种匹配的全部持仓和挂单，包括 MT5 手工订单；不按下单来源排除。标准品种匹配券商后缀，不能仅看账户是否存在任意持仓。

| 当前状态 | 无新机会 | 有新机会 |
|---|---|---|
| 无持仓、无挂单且无在途指令 | 不调用交易模型 | 入场评估 |
| 有可管理持仓或挂单 | 管理评估 | 管理优先，并评估是否允许入场 |
| 指令已发送、回执未确认 | 核对执行状态 | 核对执行状态，禁止重复入场 |
| 持仓快照缺失或过期 | 刷新数据 | 刷新数据，不能当作空仓 |

手动分析保持只分析，不隐式触发自动交易。管理模式禁止新开仓动作；同时存在新机会时是否加仓、反向入场等由交易策略与确定性风控决定。

## 补充触发与并发

- 成交、部分成交、撤单、平仓等结构变化只刷新库存、风险并核对执行状态，不触发额外 AI 评估；下一轮自动分析完成时统一评估。
- 断线恢复先完成账户、库存、在途指令同步；不补跑积压旧决策，不新增库存事件触发。
- 模型层每账户串行评估；新事件合并为最新待办，不能无限中断正在运行的任务。运行结果仍需按当前状态核验。
- 同一入场事件独立去重，不能因每轮生成了新的分析记录就重复进场。未知执行结果先查回执，禁止盲重发。
- AI不承担秒级硬保护。终端止损止盈、风险上限与指令限制由确定性逻辑负责。分析持续失败时不新增风险，现有保护继续运行并显示异常。

## 当前实现与缺口

1. inference/domain/inference.ts 的 traderTaskMode 已有上述四种基本分流。mysql-inference-repository.ts 在非手动分析完成时读取订阅与库存，创建交易任务并写出站事件。
2. 库存摘要使用快照是否存在推断持仓，缺少同处的时效/完整性判断；必须区分确认空仓和未知，补在途指令门禁及管理归属。
3. traderStaleReason 比较报价、账户、持仓、挂单、合约、风险版本；报价与风险汇总的普通更新会导致结果作废。需区分结构变化和动态估值变化：结构变化重新评估，动态估值变化在确定性执行前重算风险、价格条件与数量。不能简单删除所有过期检查或使用旧报价下单。
4. expireSupersededTraderRuns 会使同订阅排队及运行中的旧任务过期；需防持续替换导致管理任务无法完成。
5. 分析保存和订阅派发位于同一事务，单账户派发异常可能影响整条分析提交。应将分析可靠落库与账户派发隔离，通过现有 outbox 按账户幂等处理。
6. 本次默认端口检查：3023分析、3030风险汇总有监听；3021执行、3024交易员、3025风险、3028执行调度无监听。此结论不等于已排除自定义端口部署；启动前核对运行参数和实际任务积压。

## 第一轮复审：职责与需求

保留分析完成作为主触发，避免新增重复定时AI轮询。库存变化只更新数据及执行核对，避免连续平仓导致重复模型调用。风险汇总不等于交易风险执行；AI建议不等于已成交。用户已确认品种匹配的手工持仓与挂单也纳入管理。
