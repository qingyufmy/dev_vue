# 缠论算法外部实现核对与线段修复记录（2026-09-21）

## 1. 目标与边界

本次只修正当前 `chan_structure_v8` 的线段特征序列与形成中线段语义，不引入新的交易信号、买卖点、递归级别或另一套运行时。算法仍以已收盘 K 线为输入，保持现有的窗口共识、可信锚点、因果确认和已发布结构不重绘约束。

核对顺序为：缠论原始课程文字与图例、可读源码实现、当前源码、正反例与真实冻结样本。外部仓库只用于交叉核对规则，没有复制其源码。

## 3. 当前缺陷与修复

### 3.1 相等边界被错误吞并

旧实现用 `>=`/`<=` 判断特征序列包含。第 81 课边界相等时，这会把两个仍有独立结构意义的特征元素合并，导致反向分型消失，线段长期停留在“形成中”。

修复为只有高低两侧都严格包住时才合并。相等边界保留为独立元素。

### 3.2 特征分型要求了无关边界

旧实现判定向上线段顶分型时同时要求高点和低点都严格更高；判定向下线段底分型时同时要求低点和高点都严格更低。这比线段特征序列的极值侧定义更严格，会拒绝合法端点。

修复为向上线段只比较顶侧高点，向下线段只比较底侧低点；包含处理仍先执行，所以不会把未消除的普通包含误认成分型。

### 3.3 相等高点会错误翻转合并方向

相等边界保留后，旧方向推断会把“高点相等、低点变化”一律判成向下。后续若出现被包含元素，会沿错误方向合并。

修复为特征序列合并方向按高点顺序推断，相等高点延续向上侧顺序；对应回归验证了下一被包含元素的高低边界与来源索引。

### 3.4 第一段尚未确认时错误改起点

旧实现遇到反向笔越过形成中线段起点，会立即把候选段改锚到该反向笔。对第 78/81 课的“旧假设取消、A+B+C 仍为一段”场景，这会制造一个并不存在的新起点。

修复后，尚无已确认前段时保留原始形成中线段；只有前面已有确认链、当前候选确实有固定前驱时，才允许把失效候选保存为历史证据并重新锚定。真实 H1 的断链尾部仍保持 `awaiting_segment_chain_connection`，不会冒充已确认段。

## 4. 保留的项目约束

- 已确认段不因后续行情回收或改写；与部分教学实现的全历史重算不同，这是审计、AI 证据和交易复现所需的因果边界。
- 有缺口的第一特征序列分型仍必须由反向特征序列分型确认；新极值会使候选端点失效。
- 未确认候选、局部已确认但与主链断开的尾部、正式确认段继续使用不同状态。
- 滚动窗口起点不可信时，仍需多起点重同步和跨窗口多数共识；不能因本次图例修复降低窗口门槛。
- 中枢只使用正式确认的组件，不使用形成中段补足三段重叠。

- 有缺口端点：缺少反向分型时不确认，新极值时旧候选失效。

## 6. 两轮复审

### 第一轮：规则覆盖与过度设计

结论：改动覆盖了本次暴露的线段停滞、相等边界、形成中候选换起点三条冲突；没有引入第二套算法、递归级别或策略信号。笔、K 线包含、中枢与趋势投影未发现需要借本次任务改变的直接证据，因此保持现状。

调整：最初只准备修改包含和分型；复现第 81 课反例后发现候选仍被改锚，补充“仅在已有确认链后允许重锚”的显式条件与镜像测试。

### 第二轮：兼容、因果、异常与验证

结论：确认段仍不重绘；缺口二次确认、滚动窗口共识、可信锚点和断链保护没有被绕过。变更只影响特征序列边界语义和第一段形成期，不改变 HTTP 字段或前端图层合同。

调整：相等边界改为不合并后，进一步发现方向推断的等号分支会污染下一次包含合并，已单独修复并添加来源索引断言。

剩余风险：公开课程图例不能穷举所有行情；不同开源项目对“确认后是否允许回收前段”存在实现差异。本项目继续选择审计友好的不重绘语义，并通过 `historicalCandidate` 和断链状态保留无法发布的局部证据。完整实时表现仍需在本地运行链路重启后，用实际 H1/M15/M5 闭合 K 线观察，不能由离线测试替代。
