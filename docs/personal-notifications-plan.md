# 个人设置与消息中心

范围：交易端顶栏未读消息、深浅色切换、个人信息、分析和交易决策通知偏好、独立声音提醒、外部通知渠道。

第一轮复核（需求与职责）：主题属于浏览器显示偏好；个人资料和通知偏好持久化到服务端；通知归属独立 notifications 模块。分析与决策提供事实，不承担渠道发送。仅有效分析指发现机会，仅有效决策指包含实际交易动作，不把风控通过的观望当作有效动作。

第二轮复核（隔离与异常）：消息与偏好按用户隔离，交易决策保留账户归属。写入需认证、CSRF、版本和幂等；消息去重并保存已读状态。外部发送由独立 worker 处理，禁止阻塞交易或在 API 中启动轮询。声音必须由用户点击开启或试听后激活，不在首次加载历史消息时播放；多标签页需防重复。主题尊重用户选择，默认保持现有深色。

实施顺序：主题与入口；个人资料及偏好合同和迁移；消息存储及未读入口；按选定渠道投递；声音和端到端验证。

已确认渠道：飞书群机器人和邮件。外部真实投递待用户填写机器人配置、平台配置 SMTP 后验证。服务端未接通的设置不得显示保存成功，不能用本地缓存冒充跨设备消息状态。

## 部署接入与升级

保留 `server/db/migrations/20260916_033_personal_notifications.sql`，使用 `scripts/apply-personal-notifications.mjs`，禁止直接改已执行 SQL。开发库命令为 `node scripts/apply-personal-notifications.mjs --apply`。其它目标必须先配置该环境的 server/.env，并显式传入 `--host=<目标主机> --database=<目标数据库>`；脚本核对两者一致并取得升级锁、校验台账及字段。该补充迁移尚未合并到完整 278 步旧版部署流程，虚拟机新库真实升级模拟仍按用户安排另行验收。
