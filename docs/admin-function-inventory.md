## 1. 文档目的

本文记录当前管理后台已有页面、操作、权限、API、数据库、后台任务与外部依赖，并给出新版后台必须迁移、需要重塑和建议新增的能力。

本阶段只做只读审查和方案冻结，不修改业务代码、不执行数据库写入、不删除旧表或旧接口、不提交、不推送、不部署。

本轮已经由用户确认的新增要求是：

1. 管理后台可按公开页面或路由键设置 TDK。
2. 管理后台可配置平台主域名，以及主站、AI 交易实验室、管理后台和统一认证中心的域名或子域名。
3. 其它常见后台能力先形成候选清单，必须经用户确认后才能进入正式迁移矩阵或实现；用户已确认 A1–A5、B2–B7 加入，B1 暂缓。

本次检查了：

- `public/admin/index.html`、`public/admin/app.js`、`public/admin/styles.css`

当前管理后台仍是静态单页应用：

数据库行数来自 `information_schema.table_rows`，只用于证明数据和功能已存在，不作为迁移对账结果。

### 3.1 运营总览

当前已有运营指标、异常或待办提示、用户与商业摘要、AI 与 Bridge 健康摘要、快捷入口和 WebSocket 刷新。新版保留“今天最需要处理什么”的工作台定位，但按管理员角色过滤信息：内容编辑不需要看到交易全局停止入口，审计员不需要看到修改按钮。

### 3.2 用户、会员与交易接入

当前能力包括：

- 按关键词、状态和分页查找用户。
- 查看昵称、邮箱、手机号、计划、到期时间和用户详情。
- 修改资料、密码、用户/管理员角色、会员计划和有效期。
- 查看交易账户、Bridge、策略订阅、自动分析、交易发送和账户风控。
- 从用户页发送通知。
- 匿名化删除用户，同时保留订单、交易、风险和审计证据。
- 重置密码时使 Bridge 刷新会话失效。

新版必须保留这些业务结果，但禁止继续使用一个巨大用户弹窗承载所有编辑。建议拆为：用户档案、会员与订单、交易接入、权限与安全、通知记录、审计时间线六个独立子模块。

### 3.3 通知中心

当前能力包括：

- 指定用户、指定会员计划或全部用户。
- 固定站内信，可选邮件渠道。
- 预览命中人数和样本用户，再使用预览令牌发起发送。
- 普通/重要优先级和站内链接。
- 幂等键、投递记录、发送状态、取消和失败邮件重试。

新版保留收件人预览、幂等和投递结果。建议补充通知模板、变量预览、渠道健康和静默时段，但不引入通用营销自动化编排器。

### 3.4 商业运营

当前能力包括订单和营收筛选、会员到期通知及重试、返佣概览、返佣比例规则、返佣审批和作废。订单、支付、会员激活、返佣和通知存在真实数据，不可在迁移中静默丢失。

新版商业模块必须围绕已冻结的单地址 TRC20 支付目标重新设计；旧多链配置字段只作为迁移来源，不继续暴露给普通后台操作。

### 3.5 AI 运营

当前 AI 运营实际包含多个业务域：

- 运行总览：模型请求质量、延迟、错误、信号、Bridge、组件健康、告警和待复盘事项。
- 调度监控：自动分析运行状态、策略订阅者、下一次运行、等待原因和模型使用情况。
- 观摩频道：观摩源、交易账户、频道、分配和运行状态。
- 统一记忆：策略记忆库、修订、恢复、压缩、冲突和一致性任务。
- 模型评测：快照选择、对比任务、历史结果。
- 平台治理：平台策略、模型配置、用途路由、灰度健康、功能开关、风险规则和凭证轮换。

新版不删除这些功能，但应拆为独立路由和 API 领域，避免修改模型配置时影响策略、记忆或调度页面。

### 3.6 风控管理

当前能力包括账户风险状态、风险决策、平台规则、规则版本、允许范围、锁定值和全局停止。该模块关系真实交易安全，必须继续由服务端进行确定性校验；前端仅负责查看、输入、差异预览和确认。

全局停止、恢复、放宽规则等动作在新版中必须记录原因、前后差异、操作人、增强认证结果和关联审计编号。

### 3.7 内容运营

当前内容模块包括：

- 课程库：草稿、发布、归档、排序和访问等级。
- 课件与测验：附件、资源、题目、知识点和思维导图。
- 视频管理：本地/七牛等存储、上传会话和播放来源。
- 学习数据：完成情况和活动。
- 用户反馈。
- 版本与内容健康摘要。

新版内容发布采用草稿、预览、发布版本和回退，不让编辑表单直接覆盖线上版本。课程、文章、视频和公开页面可以拥有自身 SEO 字段，页面模板 TDK 作为兜底。

### 3.8 管理审计

当前可按操作人、动作、详情和目标类型检索管理日志，前端没有编辑入口。数据库现有 `audit_logs` 记录，但当前证据只能证明“后台只读展示”，不能证明日志具有密码学防篡改、外部归档或完整留存策略。

新版审计日志应记录结构化前后差异、关联请求、结果、IP、设备信息和脱敏后的目标信息；后台不能删除或编辑审计证据。

### 3.9 系统设置

当前可配置：

- 登录、注册和赠送会员开关。
- Plus/Pro 月付和年付价格。
- TRC20 固定收款地址。
- 短信、SMTP、七牛和媒体存储。
- 股票研究菜单、金融工具箱。
- 更新日志和发布说明。

当前优点：服务端有允许列表、类型校验、敏感值加密与脱敏、SMTP/SMS/存储连接测试，并记录配置变更审计。

当前缺口：大多数配置标记为 `apply_mode: immediate`，普通分类保存后立即生效；除部分存储校验和发布说明外，没有统一的草稿、差异、影响预览、版本、回退和增强认证流程。

## 5. 已冻结新增能力

### 5.1 SEO / TDK 中心

TDK 中心至少支持：

- 按公开路由键、页面模板或内容对象配置 `title`、`description`、`keywords`。
- 全站默认值、应用默认值、页面覆盖和动态内容自身 SEO 字段。
- Canonical URL、Open Graph 分享标题、描述和图片。
- 草稿、预览、发布版本、历史、回退、修改人和发布时间。
- 主站 Nuxt 在 SSR/SSG/Hybrid 结果中输出已发布配置；不能只在页面挂载后修改元数据。
- 字段长度、重复标题、空描述、非法 Canonical 和失效内容引用提示。

`keywords` 按用户要求保留，但 Google 官方说明其搜索排名不使用 `meta keywords`；因此它只作为兼容或内部分类元数据，不承诺 SEO 收益。标题、描述、Canonical、分享元信息和内容质量继续纳入本轮；robots、站点地图、重定向和失效链接检查随 B1 暂缓。

### 5.2 域名中心

域名中心至少支持：

- 平台根域名。
- `www` 主站、`trade` AI 交易实验室、`admin` 管理后台、`auth` 统一认证中心的完整 HTTPS 域名。
- 域名格式、协议、重复、保留域、环境和允许来源校验。
- 预览生成的站内链接、Canonical、登录回调、退出回调、邮件链接和公开配置。
- 草稿、影响范围、发布版本、操作审计和快速回退。
- 变更前检查登录 Cookie 边界、CORS/CSRF Origin、OIDC 回调、WebSocket、邮件链接和旧域名过渡方案。

管理后台只管理应用层域名配置。DNS、TLS 证书、反向代理、负载均衡和认证服务端受信回调白名单属于基础设施配置，不能由普通表单直接写入并立即切换。域名发布必须先完成基础设施检查，再激活应用配置。

## 6. 当前异常与重构风险

| 优先级 | 发现 | 风险 | 目标处理 |
| --- | --- | --- | --- |
| P0 | 只有 `admin/user` 两级角色 | 任一管理员都能改钱、风控、内容和凭证 | 增加最小可用 RBAC 与操作级权限 |
| P0 | 高风险配置多数立即生效 | 误操作可直接影响登录、支付、存储或交易 | 增加差异预览、版本、增强认证和回退 |
| P0 | 管理员个人中心仍嵌入通用账户 iframe | 跨应用耦合、会话和权限边界混乱 | 改为 `admin/me/*` 独立页面 |
| P0 | 单体 `app.js` 和 `styles.css` | 修改一个页面容易影响其它模块 | Vue 功能模块、路由懒加载和严格依赖边界 |
| P1 | 没有 TDK 与域名配置 | 无法集中管理 SEO 和多子域链接 | 按第 5 节新增 |
| P1 | 后台任务状态分散 | 失败、锁、重试和恢复缺少统一入口 | 增加受控任务中心 |
| P1 | 审计缺少已证明的防篡改与留存策略 | 高风险操作证据可能不完整 | 结构化、脱敏、归档、导出和访问审计 |
| P1 | 系统配置表仍有旧多链字段 | 容易把废弃支付能力重新暴露 | 迁移 TRC20 必要字段，旧字段候选删除 |
| P2 | 旧管理路由和控制台路由并存 | 合同重复、行为漂移 | API V4 统一后删除旧入口 |

### 7.3 建议暂缓或明确不做

| 候选 | 结论 | 原因 |
| --- | --- | --- |
| 通用无代码工作流编辑器 | 暂缓 | 复杂度高，当前通知、任务和发布可用固定流程解决 |
| 插件市场 | 不做 | 没有明确业务需求，会扩大供应链和权限风险 |
| 多租户组织系统 | 暂缓 | 当前是平台用户，不需要提前设计企业租户 |
| 大型多级审批引擎 | 暂缓 | 当前只有一个管理员；先做增强认证、版本和回退，未来多人后再加双人审批 |
| 后台 SQL / Shell / 文件管理器 | 不做 | 权限与破坏风险过高，不属于业务后台 |
| 通用 BI 报表搭建器 | 暂缓 | 先做固定运营指标和异步导出 |
| 全站 A/B 实验平台 | 暂缓 | 暂无明确实验流程与样本规模 |
| 一键修改 DNS、证书或恢复数据库 | 不做 | 属于基础设施高风险操作，应走独立运维流程 |
| B1 站点运营扩展 | 本轮暂缓 | 用户确认当前没有必要；不影响已冻结的页面 TDK、Canonical 和域名配置 |

## 8. 目标模块边界建议

├─ overview
├─ users
├─ memberships
├─ commerce
│  ├─ orders
│  ├─ payments
│  └─ referrals
├─ notifications
├─ content
├─ ai-operations
├─ bridge-operations
├─ risk
├─ jobs
├─ audit
├─ site-settings
│  ├─ seo
│  ├─ domains
│  ├─ redirects
│  └─ legal
├─ integrations
├─ system-settings
└─ me

每个模块拥有自己的路由、页面、query key、API 客户端、Schema、权限声明和测试。业务模块不得进入共享 UI 包；共享包只保存 shadcn-vue 基础组件、设计令牌和无业务语义工具。

## 11. 第一轮复审

复审范围：现有功能覆盖、用户要求、模块边界、最少代码和避免过度设计。

结论与调整：

- 当前后台能力覆盖用户、商业、内容、AI、风控、通知、审计和系统设置，不需要为了“重构”重新发明业务。
- 新增 TDK 和域名中心，但将 DNS、证书、代理和受信回调与普通业务配置分层，避免一个保存按钮破坏全站。
- 已确认功能优先解决权限、变更安全、任务恢复和管理员账号安全；没有加入低代码平台、插件市场或通用 BI。
- 当前只有一个管理员时不强制多级审批；先实现角色权限、增强认证、版本和回退，双人审批作为未来条件能力。
- 独立 `admin/me/*` 替代通用账户 iframe，符合三应用独立页面要求。

第一轮结论：功能盘点覆盖当前源码声明的后台主能力，候选新增项保持必要且可渐进实现。

## 12. 第二轮复审

复审范围：安全、异常恢复、权限绕过、数据迁移、时间、并发、审计和连带 Bug。

结论与调整：

- 所有后台权限仍由服务端判定；前端路由和按钮权限只改善体验，不能代替 API 鉴权。
- 高风险配置不能继续统一“立即生效”；域名、登录、支付、交易、风控和凭证变更需要差异、验证、发布和回退。
- 配置版本发布要使用并发版本或 CAS，防止两个管理员互相覆盖；实际表结构在数据库设计阶段冻结。
- 后台任务中心只允许经过合同定义的安全重试，重复提交仍必须由服务端幂等。
- TDK 发布不得让草稿污染线上 SSR/SSG；域名切换必须同时校验 OIDC、Cookie、CORS、CSRF、WebSocket 和邮件链接。
- 删除用户、订单修正、返佣、风险恢复和全局停止必须留下关联审计链；日志中不得记录密码、密钥、Token 或完整支付敏感信息。
- 当前行数仅为估算；正式迁移需要逐表、逐用户、逐业务主键对账和可重复迁移。

第二轮结论：本阶段方案可作为迁移矩阵输入；用户已确认 A1–A5、B2–B7 加入，B1 暂缓。任何实现仍按路线图逐阶段确认。
