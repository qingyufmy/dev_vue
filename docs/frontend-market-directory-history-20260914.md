# 账户品种目录与行情历史（2026-09-14）

> 后续用户需求已调整：公共行情统一由管理员指定账户采集，私有策略使用本人绑定账户。设计以 [公共与私有行情数据源方案](market-data-source-routing-20260914.md) 为准；本文账户目录缓存路径已被取代，相关草稿尚未迁移或部署。

范围：首页同步当前账户真实终端品种，默认黄金及经纪商后缀；通过 HTTP 获取有限历史窗口，补初次加载、重连缺口及向左翻页。保留已有实时小增量。

复审一：现有 history task 是交易订单/成交历史，不是行情 K 线，不能直接复用。Bridge 已有 symbols 和 market.candles 查询合同；按这两个固定只读资源扩展现有相关性校验与查询超时。HTTP 与 Gateway 之间用短期、有界 Redis 请求/响应传递，不新增数据库业务轮询或交易入口。网关只负责当前连接的查询转发。品种缓存采用追加表迁移，执行前单独核对本地目标。

复审二：HTTP 校验本人所有权；网关再校验 user/account/当前 route，响应回到 HTTP 后再次校验。每个连接最多一个在途查询，分页有上限，过期请求丢弃，错误不返回假空目录。前端请求按账户、品种、周期和窗口隔离，切换后忽略旧响应。

用户确认的品种规则：按正常账户只提供一种经纪商品种名称处理，不增加后缀配置界面。数据库以账户和不带后缀的基础品种为键，同时保留终端真实名称。请求 XAUUSD 时优先完整匹配，其次匹配任意后缀，如 .s、.c、m、pro；不维护后缀白名单。基础品种优先依据终端货币元数据，黄金别名 GOLD 归并到 XAUUSD；不能可靠识别的其它品种保持原名，不盲目截断。切换账户后使用该账户的目录。报价、K 线和订单中的真实品种不改写，避免丢失来源信息。缓存有效期五分钟，读取时检查所有权版本。

验收范围：本轮新增目录缓存及行情窗口入口；已有交易执行合同仍使用真实终端名称，不宣称已改写全部交易调用链。历史每次请求最多 500 根，前端保留最多 2000 根，不把有限窗口称为完整历史回填。

实现顺序：终端只读查询与目录事实 → 网关固定资源及短期请求/响应 → HTTP 合同/客户端 → 首页黄金默认与历史交互 → 定向测试、构建、MT5 实机和响应式检查。MT4 如未连接仅报告离线验证。
