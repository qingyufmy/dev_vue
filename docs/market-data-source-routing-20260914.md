# 公共与私有行情数据源方案（2026-09-14）

> 用户已确认进一步简化：公共/私有账户池自动选择在线可用来源，选定后保持，故障后自动切换。最新规则与复审以 [行情自动选源设计复审](market-data-auto-source-audit-20260914.md) 为准；本文手动指定来源及私有行情固定取执行账户的规则不再采用。

## 1. 用户确认的规则

- 管理员维护一份基础品种目录，例如 XAUUSD、EURUSD，不保存各券商后缀版本作为独立公共品种。
- 公共行情由管理员指定的交易账户通过桥接采集，缓存到数据库，普通用户读取同一份公共数据，不因增加浏览用户而重复向桥接采集。
- 使用本人私有策略时，策略所需终端行情来自该用户绑定交易账户的桥接，不回退到公共行情。
- MT4 和 MT5 桥接负责基础名称到真实终端名称的解析，完整匹配优先，其次任意后缀匹配；映射按终端身份和会话保存，重新登录、更换账户、重连或发现品种失效时重新解析。
- 管理员和普通用户都可以同时连接多个交易账户。在线状态不等于已被指定为数据源。

## 2. 必须分开的三个概念

1. 交易账户：余额、持仓、挂单、成交、交易权限及执行目标所属账户。
2. 行情数据源：给某次图表、分析或策略运行提供行情的指定终端。
3. 基础品种：公共目录中不带后缀的逻辑名称；桥接响应同时保留真实终端名称。

公共数据是平台选定的一份参考行情，不代表不同券商的价格、成交量、日线边界完全相同。公共缓存可包含收盘 K 线、对应成交量及基于该组 K 线计算的指标。用户实际买卖报价、点差、合约大小、最小手数、保证金、交易时段、账户权限和持仓仍来自执行账户；不能用公共账户规格做另一账户的交易校验。

## 3. 多账户的确定性选择

| 场景 | 来源选择 | 切换界面的交易账户是否改变来源 |
| --- | --- | --- |
| 公共图表、公共策略的通用行情 | 管理员设置的公共数据源 | 否 |
| 用户私有策略运行 | 该策略启用/订阅绑定的本人交易账户 | 否，按保存的绑定运行 |
| 私有策略图表 | 当前查看的私有策略及绑定账户 | 仅显式切换查看上下文后改变 |
| 用户实际交易报价、风控、订单管理 | 操作目标交易账户 | 是，需重新读取账户快照 |

管理员设置一个默认公共来源账户。仅在覆盖品种需要时，允许为基础品种指定覆盖来源；每个品种同一版本只允许一个生效来源。界面显示平台、交易账号及在线/同步状态；数据库和任务绑定稳定账户 ID，不能只用可能重复的 login。指定账户必须由被授权的公共数据提供者拥有，普通管理员角色本身不等于可以读取任意人的桥接。

私有策略沿用已有订阅的交易账户绑定，避免增加含糊的“优先在线账户”。用户有多个在线账户时，启用策略必须明确绑定目标账户；同一策略在 A、B 两个账户运行时分别建立运行与数据作用域。用户只有一个符合条件的账户时可预选，保存后仍是明确绑定。

后台任务冻结来源绑定版本，不能在执行中读取浏览器当前选择。拥有私有策略不会将用户所有公共页面自动切成私有数据；以当前页面或运行明确选用的策略为准。

## 4. 缓存与采集职责

- 公共目录全局一份；公共 K 线按公共数据源版本、基础品种、周期、UTC 开盘时间唯一保存，不按消费用户复制。
- 来源事实记录数据源 ID、来源版本、真实来源账户 ID、终端实例、券商、真实品种、时区可信信息、采集时间、覆盖区间和数据修订。对普通用户返回公开来源名称，不暴露管理员交易账号、余额、持仓或凭据。
- 私有行情按用户、来源绑定账户、来源版本、基础品种、周期、UTC 时间隔离。允许在该用户相同来源下合并重复采集并复用有界缓存；不得写入公共数据集。所谓“从用户桥接拉取”指采集来源，浏览器仍通过服务端授权的 HTTP/实时接口读取。
- 收盘 K 线和可复用的历史结果入 MySQL；最新报价和未收盘 K 线沿用内存/Redis实时增量，收盘后再持久化。指标缓存还需包含算法版本、参数及输入数据修订。
- 调度器登记按需采集；Worker 执行补缺口、去重和缓存；Gateway 仅转发必须访问当前连接的固定只读查询。不得在 HTTP 或 WebSocket 处理器里增加业务定时器。沿用持久请求 ID、outbox 与有界任务，不能将早期临时 Redis 请求/响应草稿直接视为最终采集架构。
- 多人请求相同公共窗口只产生一次在途采集；任务包含固定来源版本。响应到达时再次检查该版本与账户路由，拒绝旧连接和旧来源回写。

## 5. 断线、换源与缺口

- 来源离线时仍可展示已缓存历史，并明确最后同步时间、缺口与过期状态；缺少策略所需完整新鲜窗口时不启动依赖该窗口的分析。
- 不自动选择“另一个在线账户”，不把私人来源离线转换成公共行情。用户无需反复点击重试，连接恢复后按原绑定恢复有界补采集。
- 管理员更换公共来源时产生新来源版本。不得直接以基础品种覆盖另一来源历史；新版本完成所需连续窗口后再切换活动读指针，旧版本保留以支持冻结证据和回滚。
- 同一分析的多个周期使用同一冻结来源版本和一致参考时点。不得用 A 账户的 M5 和 B 账户的 H1 拼成同一次输入。
- 历史修正通过数据修订追踪，不篡改已经冻结的分析输入或把新数据伪装成当时已知信息。

## 6. 前端体验

- 顶栏仍仅在同时连接多个交易账户时显示账户选择器，选项保持“平台 + 交易账号”。
- 行情区域用轻量文字标明“公共行情”或“私有行情 · MT5 · 账号”，并显示同步状态。来源受策略上下文控制，不再加一个没有用途的账号下拉框。
- 公共图表品种显示基础名称；私有图表可显示桥接解析的真实名称。账户交易区域始终显示执行账户的真实品种。
- 公共图表旁若展示用户实际买卖报价，必须标明“当前交易账户报价”，避免误认为与公共 K 线来自同一终端。
- 浏览器缓存、历史窗口、实时订阅和请求失效键加入来源 ID/版本及私有授权作用域。切换账户或策略后取消旧订阅，忽略旧响应。

## 8. 两轮复审

第一轮（需求、职责、复杂度）：覆盖公共复用、私有例外、管理员与用户多账号。取消每个用户缓存整份品种目录；取消根据在线列表顺序挑源；沿用私有策略订阅账户绑定。仅公共默认源和必要品种覆盖配置，不为普通用户新增后缀设置。

第二轮（兼容、数据、并发、权限、验证）：发现现有缓存和调度把账户与来源绑定，需要显式来源版本而非只去除后缀。公共行情不能替代账户交易规格。私有访问、迟到响应、换源、重连、跨周期一致性及冻结证据均需要定向测试。旧历史保持原来源，不执行去账户化回填。

剩余风险与验收：跨券商价格/时区差异由明确参考来源和版本隔离处理；本阶段不做跨来源自动拼接。测试至少覆盖两个管理员来源、两个用户账户、公共并发去重、私有不串号、来源离线、重连、换源迟到响应、后缀解析、同一用户同时使用公共和私有策略。需要 MT4/MT5 实际只读验收，不能用 Mock 代替。迁移、重启和真实终端写操作按项目独立授权边界执行。
