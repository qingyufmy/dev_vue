# 模型接入配置编辑

当前范围：在交易端编辑已有模型的接入地址、密钥、模型名称、协议及输出上限。个人模型仅本人可编辑，平台模型仅管理员可编辑。保留默认模型选择。

密钥只输入不回显，留空保留旧密钥；更换地址时必须重新输入密钥，避免把旧凭据发送到新地址。保存时不调用外部模型，不自动认定验证通过；提供显式验证操作，通过小型结构化响应检查后启用当前配置。

新增仅存储请求摘要与结果的模型修改回执表，为并发修改、重复点击和审计提供证据；不存储明文密钥。数据库迁移单独授权。

第一轮审查：不复用策略回执表、不回显密钥、不修改用户默认模型、不发送交易。
第二轮审查：配置修改与验证结果必须按当前配置指纹校验；请求正文不写日志；平台配置修改需要服务端管理员校验。

验收：权限、并发、密钥保留/替换、保存反馈、配置失效与验证流程；真实配置由用户填写和保存。

## 完成与验证

- 模型列表提供编辑接入入口，支持名称、HTTPS 地址、密钥、接口协议和输出上限。保存后保留编辑面板，明确提示是否需要验证。
- 密钥使用现有 AES-GCM 信封格式加密；更换地址必须重新输入密钥。接口响应和回执没有密钥内容。
- 验证只发送一条固定的小型结构化请求，拒绝重定向与私网目标；必须解析出预期 JSON 后才通过。配置在验证期间变化则拒绝写入旧结果。
- 用户已授权，开发库已新增 model_configuration_receipts_v4 表。未修改任何现有模型或默认选择。
- 7 项服务端测试、3 项前端测试通过；服务端构建、合同生成检查和交易端类型检查通过。
- 本地 API 已重启。浏览器已验证管理员能看到编辑入口，当前默认模型正确回填，密钥栏为空，桌面排版已检查。
- 外部模型验证仅使用模拟响应测试，未代用户发起真实付费调用；需用户填写保存后按需点击验证连接。

## 保存异常修复

用户保存返回 503。只读检查确认实际升级库能力表使用 verified_at_utc_msc / updated_at_utc_msc，而首次实现按基础建库脚本使用 DATETIME 字段，SQL 报错触发事务回滚；回执表无成功保存记录。

保存与验证现在根据固定白名单检测两种时间字段格式。7 项定向测试通过；服务端构建通过；在实际开发库对保存链路的 3 条写语句执行 EXPLAIN，均通过，无真实数据写入。接口重启后由用户继续提交原表单，不刷新或丢弃已输入密钥。
