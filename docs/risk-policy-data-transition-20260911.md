## 实施及验收

1. 纯转换器严格拒绝未知字段、无效控制、重复版本、跨集当前指针、缺失用户/账户映射。候选包含源摘要、完整目标 JSON 和字段处置。
2. 同一事务写入 3 集、10 版本、源归档、ID 映射及回执；先插空当前版本指针，再写版本，最后绑定。目标已有不一致内容时拒绝覆盖。
3. 恢复库注入回滚、提交、独立重放及逐列对账。检查旧表和旧账本摘要不变，再用同一冻结候选处理当前库。
4. 真实风险读取解析平台及当前账户策略，历史所有者不可读取。发送与人工放行关闭；记录尚未完成的执行接线。

## 复核一：数据完整性

发现历史所有者的旧策略仍是 active，已调整为按当前所有权决定目标 retired，保留原状态和全部版本。配置 JSON 含小数，不能直接交给仅支持安全整数的迁移摘要函数；目标 JSON 按字符串冻结，回读先规范化 JSON 再比较。

## 复核二：运行语义

发现默认人工放行会使旧平台每日 50 次配置解析失败，已明确关闭新增人工放行权限。重复订单时间窗无旧执行消费者，归档并记录处置；不能假称新的执行链已经使用 ATR 配置。历史账户版本按当时原值保存，当前有效解析使用当前平台控制范围，不要求历史账户配置兼容所有历史平台版本。
