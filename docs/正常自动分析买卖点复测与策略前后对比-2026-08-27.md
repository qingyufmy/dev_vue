# 正常自动分析买卖点复测与策略前后对比

> 日期：2026-08-27
> 分支：`dev_codex`
> 模型：`deepseek-v4-flash-0731`（平台模型配置 ID 12，正常 `auto_platform` 调用链）
> 品种与数据源：本地 MT5 `DooTechnology-Demo`，`XAUUSD.s`
> 性质：历史时点模型决策复测，不是成交账户净值回测

## 1. 结论

本轮确认了两个彼此独立的问题：

1. 缠论结构没有在检查点伪造背驰或买卖点；M15、M5 的 `entry_candidates` 均为空，`divergence.confirmed=false`。当前主要缺陷不是缠论算错方向，而是确认严格、结构能力经常处于不可用状态，因此路径A中的缠论两项没有贡献。
2. 真正导致顺势信号漏失的是普通双K突破证据只有“当前最后两根K线”状态，没有已确认事件的生命周期。M15与M5确认不同步时，二者很难在同一轮同时为 `complete=true`。

修复后，系统会保留最近确认的双K突破事件、事件年龄和失效K线；策略仅在事件仍有效且年龄不超过3根对应周期已收盘K线时使用。该增强同时适用于M15和M5，不改变原来的双K确认标准，也不把交易决策写入服务端。

最终模型能够在 2026-08-19 16:00 UTC 的正常快照中输出一笔有效回踩买入：`buy_limit 4425`、止损 `4409`、模型报告净盈亏比 `1.83`。后续最低价 `4424.44`，挂单可成交；后续最高价 `4499.33`，止损未触及且推荐目标可达。因此“能够抓到买点”已经得到至少一次完整、可执行的正例。

但不能把它表述为稳定抓取：同一快照的另一次有效模型响应错误判断回踩价降低会让多单盈亏比变差，返回了 `hold`。提示词已增加方向单调性和最终归约自检，但后续两次验证分别遇到 `fetch failed` 和 HTTP 520，未取得新的有效响应。因此当前结论是“算法和策略门槛已允许抓取，模型输出仍有随机性”，不是“每次都能稳定出同一单”。

## 2. 复测方法

- 每个检查点只使用决策时已经形成的数据，不把未来K线放入模型输入。
- H1、H4、M15、M5、M1 全部来自同一个本地 MT5 终端和同一个品种，避免混合服务器缓存、截图或其他经纪商数据。
- 正常可见K线计划保持为 H1 80、H4 50、M15 100、M5 60、M1 60。
- 缠论后台历史按系统窗口策略准备：M5 1800、M15 2000、H1 1800、H4 1000。
- EMA34 使用已收盘K线，系统暖机目标170根；模型只消费系统指标结果，不重新计算EMA。
- 模型调用经过正常 `maybeAiSignal`、策略编译、共享行情快照和输出合约；未调用调度器、信号落库、风控、订单意图或Bridge。
- 未来18根M15（约4.5小时）仅用于事后评价，不参与模型决策。

## 4. 调整前后对比

| 项目 | 调整前 | 调整后 |
|---|---|---|
| M15顺势突破 | 只认当前最后两根K线的 `complete` | 当前事件或近期有效事件二选一；近期事件必须未失效且年龄不超过3根M15 |
| M5入场触发 | 只看当前窗口，容易与M15错开 | 同样消费近期有效事件，最多3根M5；不能替代M15门槛 |
| 事件失效 | 下一根K线到来后事件直接消失，无法区分“已确认仍有效”和“从未确认” | 系统提供 `found/age_closed_bars/still_valid/invalidation_bar` |
| H1 Chan不可用 | 模型容易把Chan不可用、RSI超买直接解释为趋势不明 | 只消费系统H1的close、SMA20、3/10动量、MACD方向执行非Chan直映射；不让模型重算指标 |
| 路径A/路径B | 模型可能把未采用路径写进硬失败 | 明确为或关系，采用路径通过后删除另一条路径失败项 |
| 路径B止损 | 容易优先使用远端M15/H1旧结构，导致止损过宽 | 优先使用实际M5触发事件两根确认K线极值，并用M5 ATR校验 |
| 市价盈亏比不足 | 模型可能直接观望 | 必须再审计一次合法M5回踩Limit方案 |
| 回踩盈亏比 | 模型出现“多单入场更低反而RR更差”的方向错误 | 增加方向单调性和最终归约自检；不在服务端增加策略硬拦截 |

## 5. 缠论结构复核

### 5.1 已确认没有出现的问题

- 没有把 `candidate_segment.confirmed=false` 当成已确认线段反转。
- 没有把形成中笔、候选背驰或空买卖点数组伪装成已确认买卖点。
- M15、M5 检查点均未产生虚假的 `entry_candidates` 或 `divergence.confirmed=true`。
- 突破生命周期增强没有修改分型、笔、线段、中枢、背驰或三类买卖点算法。

### 5.2 仍存在的可用性边界

- 多个检查点的 `topology_input_complete=false`、`segment_direction_usable=false`、`entry_structure_usable=false`、`divergence_usable=false`。这意味着系统能够输出部分结构对象，但这些对象不能作为入场权威。
- 本段强趋势中，缠论路径没有给出已确认背驰或三类买卖点；这可能是严格确认的正常结果，也说明仅依赖路径A会漏掉顺势加速段。
- 当前证据不足以证明背驰/买卖点数学本身错误；已发现并修复的是跨K线的普通突破确认生命周期，而不是Chan计算公式。
- H1、H4、M15、M5 使用同一套能力与生命周期边界，没有发现某个周期独有的伪确认；低周期更容易因窗口滚动和异步确认暴露事件消失问题，因此M15、M5都已统一增强。

## 6. EMA34：M1还是M5

结论：保留M1，不改回M5。

八个同源检查点中，M1与M5有七个方向和斜率一致；唯一分歧是 2026-08-26 00:00 UTC：

| 周期 | 价格关系 | 斜率 | 后续约4小时 |
|---|---|---|---|
| M1 EMA34 | below | falling | 收盘 -15.17，空头MFE 28.53 |
| M5 EMA34 | above | rising | 与后续短线下跌方向相反 |

选择M1的原因：

1. M5已经承担入场触发，再用M5 EMA34会重复同一周期信息，独立过滤价值较低。
2. M1在唯一分歧样本中更早识别了转弱，符合“最后入场方向过滤”的职责。
3. M1更敏感也更噪，但它不定义H1趋势、不补M15票、不生成M5触发，只是最后一道过滤，因此噪声风险受到前置门槛约束。
4. 2026-08-21两个检查点中，M1和M5都偏空而后续上涨，说明EMA34本身不是预测器，不能单独决定交易。

建议配置：注入M1已收盘K线60根供模型查看；EMA34由系统单独使用170根暖机历史计算。不要要求模型根据60根可见K线重算EMA34。

## 7. 两轮审查与调整记录

### 第一轮

发现：M15在13:30完成确认、M5在14:15完成确认，但当前窗口布尔值要求二者同一时刻成立，导致顺势路径误失效。

调整：服务端只增加中性的近期确认事件证据；策略定义M15/M5各自最多3根已收盘K线的使用寿命和失效条件。

复核：单根突破仍不成立；上下方向对称；事件在后续收盘回到参考区时标记失效。

### 第二轮

发现：模型正确读取近期事件后，仍可能用RSI或Chan不可用否定H1，或错误判断回踩价与净盈亏比的方向。

调整：增加H1系统字段直映射、实际数值引用、M5回踩审计、方向单调性和最终字段归约；不增加服务端策略硬限制。

复核：成功生成过可成交且止损未触发的 `buy_limit`；对称空头检查在空间不足时正确观望。相同买点仍出现一次模型算术误判，后续模型接口又连续失败，因此稳定性风险尚未消除。

## 8. 剩余风险与下一步

1. `deepseek-v4-flash-0731` 当前温度为0.30，同一冻结快照存在结果波动；单次成功不能代表稳定命中率。
2. 正常请求约129至130 KiB，提示词与五周期K线内容较长，模型对末端规则的遵循可能不稳定。继续追加重复文字的收益已经很低。
3. 两次最终复测分别遇到 `fetch failed` 和 HTTP 520，这是模型服务可用性问题，不应归入策略观望。
4. 未来评价使用M15 OHLC，不包含点差扩大和逐tick成交顺序；成功限价单的最低价低于入场且远高于止损，结论不依赖同K线高低顺序，但仍不等于真实账户成交证明。
5. 若要求同一冻结快照高一致性，下一阶段应先做多次重复性评估，并比较较低温度或更稳定模型；不要继续通过放宽交易门槛增加下单量。
6. 公网/虚拟机数据库当前策略内容不会被本地Markdown自动替换；部署时必须显式复制v1.7.7提示词并保持M1 EMA34数据计划一致。
