## 2. 统一目标与模块交付标准

继续采用模块化单体和 www/trade/admin/auth 四应用。模块按稳定业务职责划分，不按页面数或文件大小机械拆分，也不为每个功能增加微服务。

每个模块必须具备以下可审查交付物：

1. 模块说明：职责、公开能力、允许依赖、数据所有权、事件与测试入口。
2. 服务端：`domain/application/infrastructure/transport` 各负其责；跨域只使用业务 `index.ts`，`composition.ts` 仅供运行组装。公开入口不得泄漏 repository、SQL 连接或 SDK。
3. 数据：每张表唯一写入所有者；跨域读模型明确权限、一致性和索引。强一致流程由一个用例拥有事务，公开事务能力共享同一事务，禁止各域分别提交导致部分成功。
4. API：域合同为唯一源，同步生成类型和运行 schema；覆盖 method/path、Host、权限、输入输出、错误、分页及幂等/revision。认证重定向等协议例外逐项登记。
5. 前端：页面负责组装，feature 拥有业务组件、API、状态与转换；跨 feature 经公开入口。查询缓存与实时订阅具有账户作用域，账户切换后旧响应不能覆盖新状态。
6. 验证：该域越界债务清零，合同与生产者/消费者一致，相关行为、真实依赖和浏览器流程分别有证据。目录整理、类型通过或健康检查均不能单独作为完成证明。

## 4. 下一批：账户样板具体工作包

1. 收尾本地 trade 代理与成功 SSO。验证实际开发代理保留 Host、Origin、Cookie；密码登录、授权码交换、应用会话及登出符合合同。使用独立开发夹具，凭据置于仓库外，清理仅匹配夹具身份及其产生的数据。
2. 清点账户样板的 auth/trading/bridge/audit 依赖、SQL 表读取和事务关系。先定义必要公开业务端口，再替换调用；不搬运整个内部服务到公共入口。
3. 将跨域整表 DDL 摘要检查改为表所有者提供的版本化兼容能力检查。验证无关新增列不会迫使消费者改代码，缺少必需字段、约束或未完成迁移仍拒绝就绪。发布新验证工具，保留已冻结迁移与 proof 输入。
4. 验证真实 MySQL/Redis 与 HTTP 的账户选择、观摩进出、权限撤销、revision 冲突、同 key/body 重放、异 body 冲突及提交未知查询恢复。先只读，再仅对独立测试夹具执行必要写入。
5. 浏览器验证登录、切账户、刷新恢复、多标签页、断线重连和迟到响应隔离。若当前环境没有正向观摩事实，建立明确的合成夹具覆盖业务链路，并保留真实终端联调缺口，不以空列表通过代替。
6. 清理已解决的精确债务记录，更新功能矩阵和验收回执。账户样板退出后再扩大到 P2，不重复执行已经完成的账户/K 线回填。

## 5. 数据、时间与恢复约束

开发应用、Redis 和测试留在本地，虚拟机仅使用既有 MySQL。当前 `dev_vue` 继续增量升级，保留历史数据、旧 ID、映射和迁移账本；已执行迁移、proof 及其冻结工具不改写，只追加新版本。每次变更先核对冻结输入范围，避免修改共享配置使旧 proof 失效。

时间统一存 UTC，旧历史按 UTC 原值迁移、不平移。实验室显示终端时间，其余页面显示北京时间；休市不利用停滞 tick 重新校准，UTC+3 只作显示默认值，不作为交易时钟可信依据。

每个需要数据切换的域交付前后对账、唯一写入口、断点恢复和回退说明。回退必须处理切换后新增数据，不能简单恢复旧备份覆盖新记录。本方案不安排删除旧表、公网切换或终端交易；未来公网覆盖仍须单独验证实际服务器版本及数据升级链。

## 6. 后续新增功能的固定规则

新增功能先确定归属模块，再定义公开合同、数据写入者和权限/并发语义；同步实现服务端用例、API 与所属前端 feature。跨模块需求由流程拥有者编排，禁止直接改他域表或 Store。

验收运行现有 `verify:server-boundary-delta`、`verify:frontend-boundary-delta`、`verify:api-generated`、`verify:api-types`、`verify:api-runtime` 及受影响测试/类型/构建。合同变更同步生成；写操作验证权限、CSRF、幂等、revision、审计和未知结果恢复。仅运行已经存在且适用于该改动的命令，不把拟议汇总门禁当作已实现能力。

已覆盖的运行 schema 与未覆盖操作分别记录。模块 README、合同、迁移和行为证据缺任何必要项，该功能就不能标为模块化完成。

## 7. 两轮复审

第一轮：需求、职责与投入。确认前后端同一标准及未来开发规则全覆盖，保持现有技术栈与角色；调整为先账户完整流程，再逐域复制，删除旧接续入口中重复的 148–165 升级待办。避免新建通用业务平台、万能 shared 或仅转导出内部实现。

第二轮：兼容、数据、并发与异常。确认旧数据原值、唯一写入口和跨域事务不被拆分破坏；补入整表摘要耦合替换、冻结工具不可改、独立夹具清理、提交未知不换键，以及切换后新增数据的回退处理。将源码、合成夹具、本地真实依赖、浏览器和终端证据分开。

剩余风险：110 条服务端债务需按实际调用链逐条消除；API 覆盖计数需实施时刷新；前端扫描仍有盲点；账户整表就绪门禁尚为过渡实现；完整正向浏览器/终端链路未验收。各项已落到 P0/P1/P7 或对应业务阶段，不据此声明全局完成。
