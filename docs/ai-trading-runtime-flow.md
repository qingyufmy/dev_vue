# AI 交易实验室完整逻辑链路说明

> 适用版本：`dev_codex`，整理日期：2026-07-21。本文描述当前代码的实际行为，不是未来规划。数据库中的管理员配置会覆盖文中列出的代码默认值。

## 1. 总体架构

系统把“分析”和“真实交易”明确分开：策略决定模型看什么、如何分析以及允许输出哪些入场方式；模型只给出交易建议；风控根据用户账户、实时价格和 MT5 交易规格重新计算并决定是否允许执行；平仓后再将完整证据送入复盘，只有人工确认的结论才可能成为后续经验。

```mermaid
flowchart LR
  A[策略与订阅] --> B[统一自动调度器]
  B --> C[行情与结构证据]
  C --> D[模型解析与推理]
  D --> E[信号与推理快照]
  E --> F[用户级交付]
  F --> G[持久化订单意图]
  G --> H[静态核心风控]
  H --> I[账户状态风控]
  I --> J[用户 MT5 桥接执行]
  J --> K[成交归因]
  K --> L[日复盘与月复盘]
  L --> M[人工确认]
  M --> N[个人记忆或平台经验]
  N -. 条件匹配后注入 .-> D
```

核心入口：

- 策略与订阅：`server/routes/ai/strategy-ownership.js`
- 自动调度：`server/routes/ai/scheduler.js`
- 行情与缓存：`server/routes/ai/platform-market-data.js`
- 模型解析：`server/routes/ai/model-profiles.js`、`config.js`
- 推理与快照：`strategy.js`、`llm.js`、`inference-snapshots.js`
- 下单与风控：`order-intents.js`、`risk-policy.js`、`risk-state.js`
- 成交归因：`signal-outcomes.js`
- 复盘与记忆：`review-workflow.js`、`period-review.js`、`memory-system.js`、`platform-experience.js`

## 2. 角色、策略和数据边界

| 场景 | 平台策略 | 用户私有策略 |
|---|---|---|
| 创建与维护 | 仅管理员 | 仅普通 Pro 用户本人；管理员不建立私有策略 |
| 可见性 | 上线后所有有权限用户可见 | 仅所有者可见；管理员可从管理接口审查归属 |
| 自动推理模型 | 策略绑定的平台模型，或平台默认模型 | 绑定的本人模型；未绑定时依次解析本人默认模型、管理员允许共享的平台模型 |
| 行情来源 | 管理员当前活动桥接，形成共享行情 | 私有策略所有者自己的桥接 |
| 持仓和挂单 | 不传入模型，只分析市场 | 由策略开关决定；开启后数据不完整则本轮停止 |
| 信号 | 同一“策略 + 品种”只生成一次共享信号 | 只为策略所有者生成 |
| 真实执行 | 每个订阅用户分别用自己的 MT5、账户配置和风控执行 | 所有者自己的 MT5、账户配置和风控执行 |
| 复盘 | 只为管理员观摩账户生成，普通用户不生成平台策略复盘 | 只为普通用户本人生成；管理员私有复盘被禁用 |
| 经验 | 管理员审核发布为平台经验 | 用户确认后形成个人短期/长期记忆 |

策略记录保存在 `auto_prompt_types`。核心字段包括：范围与所有者、可见状态、版本、支持品种、行情数据方案、缠论开关、允许入场方式、系统提示词、模型绑定、推理间隔，以及私有策略的持仓/挂单上下文开关。

策略允许的入场方式为 `market`、`limit`、`stop`、`stop_limit`。系统会据此动态缩减模型输出枚举；不允许的入场类型即使被模型返回，也会在结构校验阶段拒绝。旧提示词里的 `{{ATF:...}}` 和 `{{USE_CHAN}}` 只用于兼容迁移，新策略以结构化配置为准。

## 3. 订阅与自动推理启动条件

订阅保存在 `strategy_subscriptions`，关联用户、交易账户、策略、品种、运行时段、止盈选择和记忆模式。当前版本明确限制：**每个用户同时只能启用一个自动推理订阅**。启用新订阅时可以选择替换旧订阅；同一账户、同一品种也不允许出现并行执行冲突。

有效品种始终是“用户勾选品种 ∩ 策略支持品种”。订阅状态会事务性同步到兼容表 `auto_scheduler` 和 `user_bridge_settings`，避免前端显示已开启但运行时仍读取旧策略。

调度器按“策略 ID + 标准品种”合并任务。启动一轮推理前依次检查：

1. 用户为管理员或有效 Pro 用户，策略处于上线状态；
2. 订阅已启用，品种仍在策略范围内；
3. 当前不处于周末强制保护窗口；
4. Redis、分布式锁和冷却状态正常；
5. 平台策略的管理员桥接，或私有策略所有者桥接在线；
6. MT5 `market_state` 判断品种已开市；
7. 订阅运行时段允许推理；
8. 模型和凭据解析成功。

运行时段默认采用 MT5 服务器时区 `UTC+3`。时段外选择“暂停全部”时不推理；选择“只生成信号”时仍推理，但不允许自动执行。跨午夜时段按所选时区正确归属前一交易日。

Redis 锁防止多进程重复推理，成功后按策略间隔进入冷却；失败按原因退避。前端进度来自调度状态和 WebSocket，阶段包括配置、桥接、行情、结构计算、AI 推理、保存、发布和交付。

## 4. 行情、K 线与缠论证据

策略的行情数据方案定义主周期、辅助周期和每个周期的 K 线数量。主周期决定信号的 `timeframe`、有效期和默认图表；开启缠论后，系统按周期固定政策目标窗口计算指标、笔、线段、中枢、背驰、趋势状态、买卖点候选和多周期一致性。指标若需要额外历史可以共用同一次行情请求，但 Chan 只计算该周期目标窗口的最后部分。

平台行情优先取管理员活动桥接：

- Redis 保存最近最多 2000 根已闭合 K 线，TTL 24 小时；Chan v6 每个周期只计算政策目标窗口（M5 800、M15 1000、H1 1200、H4 800），缓存上限不等于 Chan 计算数量；
- MySQL `market_candles` 持久化历史已闭合 K 线；
- 每轮仍从 MT5 拉取边界附近少量 K 线，检测断线缺口和内部异常缺口；
- 发现缺口时重新拉取完整窗口，无法补齐则返回错误，不把不连续数据交给缠论或模型；
- 线段需要同一批可观察历史窗口对完整连续后缀达成严格多数；中枢再按最初三条线段形成核心独立表决，最长完整窗口决定中枢相位，短截断窗口只能确认，禁止从不同窗口的局部证据拼接结构；
- 无可信结构锚点时使用当前周期的固定目标窗口，并在相邻政策验证窗口中回算连续三根已收盘 K 线；只有三次均非低可靠或过期、`core + entry` 时间稳定，且具备至少 150 根前置上下文的跨窗口严格多数时，才原子保存进入段起点、进入段 ID、三段核心 ID、最后确认线段和观察时间；目标窗口输出结构，验证窗口只确认；首次只提交锚点，下一轮完整身份精确命中且线段不回退后才开放进入段相关证据。没有中枢不会触发更大历史请求，`evidence_capabilities` 分层关闭中枢、进入段和背驰能力；圣诞节、元旦休市按确定性日历分类，未知工作日长缺口继续失败关闭；
- 背驰投票区分“明确无背驰”和“证据不可判”，MACD 暖机区或引用缺失只弃权，不会反向压过有效背驰证据；
- 当前未闭合 K 线只参与本次实时分析，不写入缓存；实时报价不缓存；
- 复盘按精确起止时间拉取，最多 5000 根，并补充持仓期间 K 线和缠论结构。

没有可用的平台桥接时，才回退到请求用户自己的桥接，且该回退数据不进入平台共享缓存。所有时间先标准化为 UTC 毫秒，同时保留管理员桥接校准出的 MT5 时区偏移。MT4 按当前服务器偏移换算的时间不声明为精确 UTC；只有 EA 最近 5 分钟内从新 tick 校准过合法偏移，且数据源已按账户、服务器和偏移隔离时，结构计算才使用该时间键。休市时 EA 冻结最近偏移而不随本机时钟漂移，但缓存样本不会用于新的结构确认。

平台策略会在构建模型输入前移除账户余额、持仓、挂单和其他用户私有数据。私有策略只有主动开启“向模型提供当前持仓与挂单”后才读取这些数据。

## 5. 模型解析与信号生成

所有用途共用 `ai_model_profiles`，但按 `manual`、`auto_platform`、`auto_private`、`review`、`memory_compression` 分别解析权限。

私有策略的解析顺序为：

1. 策略显式绑定的本人模型；绑定模型失效时直接停止，不静默切换；
2. 用户默认模型；
3. 管理员开启对应共享开关、用户套餐符合且配额未超限时，使用平台共享模型；
4. 均不可用则本轮停止。

平台策略使用策略绑定的平台模型或平台默认模型。API Key 只在服务端解密，模型用量先预留再结算；共享模型同时受每日请求数和 Token 配额限制。

手动推理以当前操作用户为模型使用主体：私有策略优先使用其绑定的本人模型；未绑定时使用用户默认模型，再按管理员共享策略回退。当前代码中，手动运行平台策略也使用当前用户的默认/共享解析链，不直接占用平台自动推理主模型。复盘优先沿用策略对应的模型解析规则；记忆压缩使用用户默认/共享模型解析链。

模型接收的主要内容包括：策略提示词、结构化行情、允许入场方式、手数允许范围、可选经验上下文和严格 JSON 输出格式。输出包含方向/信号类型、置信度、建议手数、入场方式和价格、止损、三档止盈、AI 推荐止盈档位、分析正文与执行结论。模型失败会转换为明确错误，不保存成伪正常信号；正常 `hold` 信号可以保存，但不会进入下单。

每条信号同时写入：

- `ai_signals`：用户展示和执行所需的标准结果；
- `inference_snapshots`：当时策略版本、完整提示词、模型来源、行情/K 线、结构证据、记忆模式和内容哈希；
- `auto_signal_deliveries`：共享信号面向每个用户的独立交付与执行状态。

平台共享信号只保存一次，但每个用户的是否自动执行、止盈模式、最大手数、运行时段、桥接状态和风控结果互相独立。

## 6. 从信号到真实下单

自动执行前还有一层交付资格检查：订阅仍有效、仍在运行时段、AI 交易员开关打开、账户允许交易、用户桥接在线、用户实时报价可用，且止损和选定止盈方向正确。启用 AI 交易员后，通过这些资格检查和确定性风控的动作直接进入发送链路，不再有独立的发送许可开关。挂单还会检查现有同品种同向挂单，先尝试替换旧挂单并再次查询确认；无法确认时拒绝继续。

所有手动或自动新开仓统一进入 `prepareAndExecuteOrderIntent()`：

1. 用用户、账户、信号或客户端请求号生成幂等键；
2. 创建 `order_intents` 并获取租约，重复请求直接返回原结果；
3. 从用户桥接读取账户、报价、品种规格和风险快照；
4. 解析有效风控策略并执行核心风控；
5. 在事务中执行账户状态风控和风险预留；
6. 标记为 `bridge_sending` 后才调用 MT5；
7. 根据桥接结果提交或释放预留，保存真实订单号；
8. 发送后状态不确定时标记 `uncertain`，后台通过 `order_lookup` 对账，不把英文错误误判成成功。

因此，“模型建议”“风控批准”“MT5 成功”是三个不同状态。只有 MT5 明确返回成功或后续对账找到订单，界面才能显示为已执行。

## 7. 风控策略的合并顺序

风控版本存放在 `risk_policy_sets` 和 `risk_policy_versions`。有效值按以下顺序解析：

1. 代码安全默认值；
2. 管理员平台默认值、用户允许范围和平台锁定值；
3. 用户账户级覆盖值；
4. 兼容配置中的用户最大手数等更严格限制；
5. 订阅绑定的风险档案，仅允许进一步收紧。

“平台默认值”是用户留空时继承的值；“用户可选最小/最大值”是真正可配置边界；“平台锁定值”优先级最高。账户级值可以在管理员允许范围内高于或低于平台默认值，但不能越过范围。所有改动立即生成新版本并保留审计记录。

当前核心规则及代码默认值：

| 类别 | 规则 | 默认值 |
|---|---|---:|
| 订单基本条件 | 允许品种、强制止损、必须有止盈 | 全部品种、开启、开启 |
| 手数与风险 | 单笔最大手数、单笔最大真实亏损 | 0.05 手、净值的 1% |
| 挂单 | 默认有效期、方向关系、异常价格、Stop Limit 关系 | 180 分钟、强制校验 |
| 时效与成交 | 信号有效期、报价最大年龄、最大点差、下单允许价格偏差 | 300 秒、15 秒、120 点、0.1% |
| 频率 | 最小开仓间隔、每日最大开仓次数、重复订单窗口 | 30 秒、20 次、180 秒 + 0.05 ATR |
| 账户损失 | 日亏损、连续亏损、冷却、最大回撤 | 3%、3 次、60 分钟、8% |
| 时间保护 | 周末收盘前停止新增风险 | 60 分钟 |

风控分两层执行：

- **核心无状态风控**：字段结构、品种、MT5 规格、交易模式、止损止盈方向、AI 手数范围、真实止损金额、挂单方向、报价时效、点差、信号时效、周末保护、下单价格偏差。风控只会缩小 AI 建议手数，绝不会放大；若缩小后低于 MT5 最小手数则拒绝。
- **账户状态风控**：平台/账户紧急停止、账户暂停或切换、数据完整性、日亏损、回撤、连续亏损冷却、每日开仓次数、最小间隔、短时间同方向同价重复订单。

真实亏损优先使用 MT5 `order_calc_profit`；只有该计算与最终订单参数完全匹配时才采用，否则使用品种 Tick 元数据计算。风险快照由桥接端提供增量成交统计、账户、持仓和挂单摘要，避免反复拉取全量历史。关键数据缺失时系统失败关闭，不猜测放行。

## 8. 成交归因与复盘证据

成功市价单、挂单成交和后续平仓会进入 `signal_outcomes`。后台按订单、持仓、成交和交付关系持续对账，把开仓、部分平仓、完全平仓、手续费、隔夜费、外部人工干预等归到原信号。只有完全平仓且归因明确的结果才具备完整复盘资格。

单笔复盘证据包包括：

- 推理时的信号、策略版本、模型、系统提示词和用户提示词；
- 推理时 K 线、指标、缠论结构和内容哈希；
- 原始订单、风控批准订单、命中的规则和策略版本；
- MT5 执行结果及全部关联成交；
- 从开仓到平仓的多周期 K 线、路径指标和缠论结构；
- 实际净收益、持仓量、外部干预和证据引用。

缺少推理快照、历史提示词、精确成交归因或持仓路径时，复盘标记为“证据不完整”，不会让模型编造结论。

## 9. 日复盘、月复盘与人工确认

周期复盘由独立 Worker 驱动，默认每 60 秒运行，也可以由“重试生成”立即唤醒，并非必须等下一个固定时间点。

### 日复盘

- 使用管理员桥接校准的 MT5 时区，按“用户 + 交易账户 + 策略 + 策略版本 + MT5 日期”分组；
- 只有该 MT5 日期结束后 30 分钟才创建，今天尚未结束时不应提前出现；
- 聚合当日全部已归因平仓交易，同时读取策略所需周期的整日行情、结构和缠论证据；
- 统计交易数、胜负、胜率、净收益、盈亏因子和外部干预；
- 日结束后的 24 小时沉淀期内定期补查迟到成交或行情证据；
- 已人工确认的版本保持冻结，但若出现真正遗漏的晚到平仓结果，会重新形成复盘版本并使旧派生经验失效。

### 月复盘

- 按“用户 + 策略 + 策略版本 + MT5 月份”聚合日复盘；
- 月份结束后 120 分钟才创建；
- 汇总交易日、交易数、胜负、净收益、盈亏因子、重复问题、风险观察、缠论问题和下月行动；
- 月复盘证据来源包含各日复盘状态与内容哈希，日复盘变化时月复盘会识别来源变化。

模型必须返回严格 JSON，并由服务端验证字段、枚举、置信度、证据引用和来源 ID。生成任务采用租约、最多 3 次重试、指数退避，并在 `period_review_job_events` 保存“排队、准备证据、AI 分析、校验、成功/失败”等进度。前端导航角标提示未读、待确认和失败记录。

用户可修改 AI 草稿，再选择“确认准确”“需要修改”或“稍后处理”。未经确认的内容不会进入任何记忆或平台经验。

## 10. 个人记忆与平台经验

### 私有策略个人记忆

普通用户确认私有策略日复盘后，系统生成有效期 30 天的短期记忆。月复盘确认后，会：

1. 确保月内已确认日复盘形成短期记忆；
2. 将这些来源压缩为月度摘要；
3. 对月复盘提出、且至少有两个日复盘支持的模式建立长期记忆候选；
4. 长期候选必须由用户再次确认才会启用。

此外，相似短期经验若来自至少 3 次独立复盘、跨度不少于 7 天，也会形成长期候选。撤销某条短期记忆会使依赖它的摘要失效，并将相关长期记忆置为重新验证。

推理检索严格绑定用户、策略 ID 和策略版本；再按品种、周期、方向、入场方式和行情状态匹配。存在明确不匹配时不注入。默认上下文预算 800 Token，最多 5 条短期记忆和 3 条长期记忆，长期记忆最多占预算的 60%。策略升级后旧短期记忆变为过期上下文，旧长期记忆进入重新验证。

“仅影子检索”会正常匹配并记录命中，但不给模型；“主动使用”才写入提示词。记忆效果评估不再追加第二次模型调用，每轮交易推理只执行一次。

短期记忆超过 20 条或合计超过 4000 Token 时进入 AI 压缩队列，摘要上限 1200 Token；压缩任务保留完整来源 ID 和哈希，来源变化后旧摘要自动失效。

### 平台策略经验

管理员观摩账户的已确认平台策略复盘会生成“候选经验”。系统先过滤账户、余额、持仓、手数、盈亏等账户专属内容；管理员审核发布后才成为平台经验。每个策略可设为：

- `off`：不检索；
- `shadow`：检索并记录匹配，不注入；
- `active`：匹配后注入平台策略推理。

匹配考虑策略版本、品种、周期、行情状态、趋势方向、波动等级、允许入场方式，以及缠论趋势、线段、中枢和背驰状态。平台经验只能辅助市场分析，不能覆盖输出格式、手数边界或任何风控规则。普通用户只能看到自己私有策略的记忆采用情况；平台经验细节仅管理员可见。

## 11. 前端页面与运维观察点

| 页面 | 用户重点 | 管理员重点 |
|---|---|---|
| 模型策略 | 私有策略、本人模型、订阅、品种、时段、个人记忆模式 | 平台策略、平台模型共享、平台经验策略 |
| 推理 | 手动选择策略和支持品种；查看执行建议、K 线结构证据和本人记忆采用情况 | 查看平台策略经验采用情况 |
| 风控中心 | 账户能否交易、本人可调规则、执行记录、账户紧急停止 | 所有账户状态、平台默认值、用户范围、锁定值和灰度规则 |
| 复盘与记忆 | 日/月复盘确认、短期/长期记忆、影子检索与正式记忆注入 | 管理平台经验候选、发布、撤销和效果评估 |
| 审计 | 本人信号、风控原因、订单意图和 MT5 结果 | 全局中文审计、异常账户和系统运行状态 |

主要可观察数据：调度状态在 Redis 与 WebSocket；信号和交付在 `ai_signals`、`auto_signal_deliveries`；完整推理证据在 `inference_snapshots`；下单状态在 `order_intents`；风控结论在 `risk_decisions`；账户风险在 `risk_account_state`；成交归因在 `signal_outcomes`；复盘任务进度在 `period_review_jobs/events`；记忆采用情况在 `memory_injection_logs` 和平台经验日志中。

## 12. 关键安全不变量

1. 平台策略不向模型暴露任何订阅用户的账户数据。
2. 私有策略、私有模型、个人记忆只属于创建用户，服务端校验所有权，不能依赖前端隐藏。
3. AI 建议手数必须位于模型输入允许范围；风控只能保持或缩小，不能放大。
4. 所有真实新订单必须经过订单意图、核心风控、状态风控和用户自己的 MT5 桥接。
5. 发送结果不确定时只能显示“不确定”，必须对账确认后才能显示成功。
6. 风控、权限、结构化输出和系统提示词优先级始终高于任何记忆或平台经验。
7. 未经用户/管理员确认的复盘不进入记忆；普通用户的平台策略交易不生成个人复盘和个人记忆。
8. K 线缺口、报价过期、账户快照缺失、模型凭据失效或桥接离线时失败关闭，不使用猜测数据继续交易。
