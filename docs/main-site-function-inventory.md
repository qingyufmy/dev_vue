## 1. 文档目的

本文只盘点当前主站已经存在或声明的用户能力，记录其页面入口、API、权限、数据和新版迁移去向。它不要求新版复制当前布局、原生 DOM 实现、通用账户 iframe 或旧支付链路。

本轮主站定位继续遵守以下要求：

- 主站是课程、品牌与企业展示网站，不做成交易工作台。
- 核心用户是普通外汇交易者，内容表达中文优先、简单直观。
- 当前有效功能必须有明确去向；重复入口可以合并，失效能力可以进入候选删除，但不能静默丢失。
- 主站、AI 交易实验室和管理后台拥有各自独立页面与业务模块，不嵌入一个通用用户中心前端。
- 统一的是用户身份、服务端数据合同和安全策略，不是页面实现。

## 4. 功能模块盘点

### 4.1 品牌与公开展示

当前能力包括品牌信息、课程体系与课程落地页、学习成果、大纲、适合人群、价格、FAQ、咨询二维码、跨产品入口和深浅色切换。

主要数据来自静态 HTML、`course-programs.js`、课程数据库和 `system_config`。新版使用 Nuxt 4 的 SSR、SSG 或 Hybrid 能力输出公开页面元数据，品牌、课程展示和付费转化成为首页主线，不采用交易工作台布局。

### 4.2 登录、注册和账号恢复

当前能力：

- 邮箱或手机号密码登录、验证码登录。
- 注册、图形验证码、发送和验证验证码。
- 忘记密码、重置密码和登录后返回原路径。
- 本地保存 JWT 和用户资料，并同步一个可读 Cookie。

主要接口：`/api/auth-methods`、`/api/captcha`、`/api/login`、`/api/register`、`/api/send-code`、`/api/verify-code`、`/api/reset-password`。

主要数据：`users`、`verification_codes`、`referrals`、`notifications`。

新版主站保留独立品牌登录入口，但凭据流统一进入 `auth.<domain>` 的 OIDC Authorization Code + PKCE；不在浏览器保存长期 JWT，不通过父域 Cookie 或 iframe 同步认证。

### 4.3 主站账户模块

当前能力分散在两套实现中：

1. `public/src/main.js` 内置“设置和账单”，包含个人资料、账号设置、通知、订阅、账单和返佣邀请。
2. `public/account/` 提供账户概览、个人资料、安全、通知、订阅、订单和邀请奖励，并通过 `embed=main|ai|admin` 被三个应用 iframe 嵌入。

主要接口：`/api/profile`、`/api/change-password`、`/api/change-email`、`/api/change-phone`、`/api/bind-email`、`/api/bind-phone`、`/api/notifications`、`/api/orders`、`/api/referrals/me`、`/api/telegram-entry`。

主要数据：`users`、`notifications`、`notification_deliveries`、`orders`、`referrals`。

新版取消通用账户前端和 iframe 嵌入，改为“共享身份与数据合同、每个应用独立页面”，详见第 6 节。

### 4.4 会员、订单与 USDT 支付

当前能力包括体验版、Plus、Pro、月付/年付、当前会员、到期提醒、创建/取消订单、二维码、地址、精确金额、倒计时、确认数、订单状态、订单历史、返佣抵扣和邀请记录。后端还保留 HD 地址、固定地址、四条链、归集和支付副作用任务。

主要接口：`/api/plans`、`/api/payment/mode`、`/api/payment`、`/api/payment/status/:orderId`、`/api/payment/cancel/:orderId`、`/api/orders`、`/api/referrals/me`、`/api/referrals/track`、会员到期提醒接口。

主要数据：`users`、`orders`、`crypto_watch_list`、`referrals`、`membership_expiry_notifications`、`system_config`。

新版已冻结要求：

- 用户只使用 TRC20 USDT。
- 所有用户使用一个收款地址。
- 通过订单创建时间、支付时间和订单唯一金额差匹配。
- 页面不再显示 ETH、BSC、SOL 或其它链选择。
- 重新定义重复金额、少付、多付、超时到账、重复交易、补单、会员激活、幂等和人工对账；旧四链实现不原样迁入 V4。

### 4.5 课程目录与内容消费

当前能力：

- 课程分类：早盘解读、技术指标、形态分析、交易策略、经济指标。
- 数据库课程优先，静态 `episodes.js` 作为回退来源。
- 无限加载课程卡片、会员徽标、学习进度、最近更新和观看历史。
- 文章、视频、附件、测验、知识点、思维导图和下一课导航。
- 视频支持 YouTube、Bilibili、本地私有文件和七牛私有对象。
- 课程权限按访问等级判断。

主要接口：`/api/course-items`、课程附件/下载、测验/资源、`/api/video-stream`、私有视频文件和 Bilibili 信息接口。

主要数据：`courses`、`course_resources`、`quiz_questions`、`video_streams`、`stored_files`、`storage_upload_sessions`。

迁移注意：

- 静态清单和数据库双来源收敛为一个权威内容模型，离线或构建期回退另行设计。
- `episodes.js` 声明了多条 `/indicators`、`/patterns`、`/strategies`、`/models` 静态文章路径，但当前仓库没有对应 HTML；需在浏览器与部署资源中确认后再决定迁移或删除。
- 课程内容、会员权限、附件和视频访问必须使用服务端授权，不能只依赖前端隐藏。

### 4.6 学习进度与互动

当前有本地进度缓存、服务端同步、视频进度、课程完成、测验通过、观看历史、学习统计、课程评论、回复、删除和点赞。主要接口是 `/api/progress`、`/api/comments`、`/api/comments-like`，主要数据为 `progress`、`comments`、`comment_likes`、`users`。

新版服务端数据是权威状态；本地缓存只用于离线体验和待同步状态，必须有用户、课程、版本和冲突边界。

### 4.7 社区论坛

当前有帖子筛选、发帖、编辑、删除、楼层回复、引用、分页、图片上传、举报、置顶、精选、锁定和通知。主要接口为 `/api/posts`、`/api/post-replies`、`/api/post-reports`、`/api/post-images*`、`/api/notifications`；主要数据为 `posts`、`post_replies`、`post_reports`、`post_tags`、`post_assets`、`stored_files`、`notifications`、`users`。

普通社区操作保留在 `www`；置顶、精选、举报处理和平台内容管理移到 `admin`，主站只按权限显示必要的就地快捷操作。

### 4.8 通知、提醒和在线状态

当前有论坛回复/引用、系统和会员到期通知、未读数、重要通知确认、指定通知定位、到期弹层、页面在线心跳、短信到期通知和通知中心 Worker。

新版主站通知只显示会员、订单、课程、社区和系统公告；交易信号、Bridge、风控和订单执行通知属于 `trade`。共享通知服务按 audience、domain、resource 和 severity 返回，各应用独立实现页面。

### 4.9 金融工具与市场信息

当前有量见晴雨表、交易所/看盘/数据外链、后台可配置工具箱与股票研究菜单、量见语录。主要接口为 `/api/sentiment`、`/api/system-config-public/toolbox`、`/api/system-config-public/market_menu`。

这些能力保留为主站内容/工具模块；宏观和实时专业行情若服务于交易决策，应进入 `trade` 的市场行情模块。

### 4.10 公开交易记录与案例

当前展示公开交易观点、盈亏统计、时间线和 MT5 报告截图，管理员可在主站新增和删除记录。主要接口 `/api/trades`，主要数据 `trades`、`users`。

公开案例继续在 `www` 展示；创建、编辑、排序、发布和删除移到 `admin` 内容模块。

### 4.11 反馈、更新日志和 Telegram

后端存在用户反馈、反馈历史、站点更新、更新日志确认和 Telegram 入口。新版把反馈作为帮助模块；更新日志按应用分别发布；Telegram 作为通知渠道配置，不与个人资料混为一个字段组。

### 4.12 法律与风险文本

当前 `/tos` 把服务协议、投资免责声明、付费退款、用户规范、知识产权、隐私和争议处理混在一个页面，而且受登录门保护。新版拆为公开、可版本化、可留存同意证据的独立文档；交易风险揭示与课程付费条款分别管理。

## 5. 当前主站 API 与数据边界

当前主站源码直接引用约 47 个 `/api` 路径。新版不按旧路径逐个复制，而按业务域归并：

| V4 领域 | 当前主要能力 | 目标边界 |
| --- | --- | --- |
| identity | 登录、注册、验证码、密码、联系方式 | 统一身份中心与每应用 BFF |
| profile | 昵称、头像、Telegram 渠道 | 用户核心资料服务；应用各自展示 |
| membership | 方案、权益、过期提醒 | 主站商业域权威，trade 只读必要权益 |
| commerce | 订单、TRC20 支付、返佣 | 主站购买域，后台管理独立权限 |
| learning | 课程、内容、附件、进度、测验 | 主站课程域 |
| community | 帖子、回复、图片、举报、通知 | 主站社区域；后台管理分离 |
| content | 公开战绩、工具、语录、更新、法律文本 | 主站内容域 |
| notifications | 分域通知、确认和渠道 | 后端共享投递，应用独立视图 |

路由组件不直接写 SQL；V4 由各领域 service/repository 读取数据库，并由 OpenAPI 合同定义精确字段。

## 6. 新版用户中心架构

### 6.1 冻结结论

不再创建一个通用“用户中心前端”供主站、AI 交易实验室和管理后台 iframe 嵌入，也不在三个应用间共享账户业务页面组件。

| 所属应用 | 独立页面 | 应展示的能力 |
| --- | --- | --- |
| `auth.<domain>` | 登录、安全挑战和会话流程 | 登录、注册、找回、MFA、敏感操作挑战、全设备退出；顶层跳转，不嵌入 |
| `www.<domain>/account/*` | 主站账户与会员 | 个人资料、会员、续费、TRC20 支付、订单、邀请奖励、课程进度、社区通知、通知渠道 |
| `trade.<domain>/settings/*` | 交易实验室设置 | 交易账户、Bridge、策略订阅、模型、交易偏好、交易通知、观摩模式；只显示必要会员状态 |
| `admin.<domain>/me/*` | 管理员个人设置 | 管理员资料、安全、MFA、会话和通知；平台用户管理不属于个人中心 |

### 6.2 共享与不共享

允许共享：

- 用户、会话、联系方式和角色的服务端权威数据。
- OpenAPI/TypeScript 合同、验证 Schema、错误码和权限枚举。
- 无业务语义的 shadcn-vue 基础组件、设计令牌和纯工具函数。
- 无界面 composable，例如资料查询、头像上传、敏感操作挑战和缓存失效协议。

禁止共享：

- 整个账户页面或 iframe。
- 主站会员/订单页面嵌入交易实验室。
- 交易账户、Bridge、模型和策略设置进入主站账户页。
- 管理员用户管理界面进入普通用户设置。
- 通过 `postMessage` 同步用户、主题、通知或退出状态。

### 6.3 跨应用体验

- `trade` 点击“管理会员”时顶层跳转 `www.<domain>/account/membership`，SSO 避免重复输入密码。
- 支付完成后返回原应用的明确路径，由原应用重新获取会员摘要，不携带访问令牌。
- 修改资料后服务端更新用户版本；各应用进入前台或收到安全失效事件后刷新自己的缓存。
- 全网站退出和全设备撤销由身份中心处理；普通退出只清理当前应用 Host-only 会话。
- 主题和布局属于各应用自己的偏好，不通过账户页跨应用强制同步。

### 6.4 设计理由

- 主站用户关心课程、会员、支付和社区，交易实验室用户关心账户、Bridge、模型和策略，任务不同。
- iframe 会复杂化焦点、弹窗、滚动、响应式、主题、浏览器历史和错误处理。
- 通用业务页面会让主站改支付布局时影响交易实验室，违背模块隔离要求。
- 共享服务端合同而非页面，既避免数据分叉，也允许各产品按自身任务优化体验。

## 7. 后台任务与外部依赖

主站相关后台任务包括 USDT 确认、订单过期、备用扫描、支付副作用、会员到期短信、通知中心和存储清理。

外部依赖包括 TRON/TronGrid、阿里云短信、SMTP、七牛、本地私有文件、Bilibili、YouTube、Telegram 和工具箱第三方网站。V4 迁移矩阵必须记录超时、重试、幂等、密钥边界、失败提示、数据保留和人工恢复方式。

## 8. 状态和异常场景

新版至少覆盖：

- 游客、已登录、会员有效、会员过期、管理员。
- 课程为空、无权限、内容未发布、视频缺失、链接过期、附件不存在。
- 学习进度首次加载、后台同步、离线修改、冲突和失败重试。
- 社区空列表、加载失败、帖子被锁、无权编辑、上传失败和举报成功。
- 订单创建失败、等待、确认中、成功、取消、过期、超时到账、金额不符和人工处理。
- 通知为空、未读、重要待确认、链接失效。
- 外部服务不可用、请求超时和受限网络环境。
- 手机、平板和桌面的加载、空、错误、成功和危险操作确认。

## 9. 已确认的结构性问题和迁移候选

### 高优先级

1. 通用账户 iframe 与主站内置设置重复，取消嵌入并按应用拆分。
2. 浏览器长期 JWT、`localStorage` 用户态和可读认证 Cookie 不符合新版 SSO。
3. 旧支付仍有四链和多地址能力，与 TRC20 共用地址要求冲突。
4. `main.js` 同时承担路由、视图、状态、支付、社区、认证和后台快捷操作，无法模块隔离。
5. 课程静态数据与数据库双来源可能产生标题、权限、媒体和分类差异。

### 中优先级

1. 主站包含论坛置顶、精选、锁定和公开战绩维护等管理员功能，目标入口应移到 `admin`。
2. 通知未按主站和交易实验室明确分域。
3. `/tos` 混合多个法律文本且需要登录。
4. 股票研究菜单和若干保护路径仍有配置与源码入口，但当前仓库缺少对应页面。
5. 多个静态文章 URL 在当前仓库没有目标文件，需要运行态核对。

### 保留但重塑

- 课程、会员、支付、社区、通知、公开案例和金融工具属于有效业务能力。
- 产品导航保留，但改为子域顶层跳转。
- 个人资料和安全能力保留，但不复用通用前端页面。
- 七牛、本地私有文件及视频多来源能力先进入迁移矩阵，不在盘点阶段删除。

## 11. 迁移验收门

- 本文每个页面与功能进入全项目迁移总矩阵。
- 主站不再引用 `/account/?embed=`，不存在账户 iframe 或账户 `postMessage` 协议。
- 三应用分别拥有独立账户/设置页面和独立路由。
- 主站没有交易账户、Bridge、模型或策略配置业务。
- TRC20 支付只展示一条网络和共用地址匹配流程。
- 课程、会员、订单、社区和通知完成真实 MySQL 权限与数据回归。
- 公开页面完成 SEO、结构化元数据、性能和无登录访问验收。
- 手机、平板和桌面均能完成注册、学习、支付、社区和账户核心操作。
- 原始用户、课程、进度、订单、支付、帖子、通知和文件逐用户对账无未解释差异。

## 12. 第一轮盘点复审

复审范围：需求覆盖、业务边界、现有能力复用、最小迁移和是否设计过度。

结论与调整：

- 补齐课程之外的会员、支付、社区、通知、公开案例、工具、法律和帮助能力。
- 没有把当前接口逐个复制为 V4，先按业务域归并，具体路径留到 API V4 阶段。
- 用户中心不再作为第四个通用业务前端；统一身份和合同，各应用独立页面。
- 管理员快捷操作迁往后台但能力不删除。
- 股票研究、静态文章和外部媒体只标记运行态待核对，不在盘点阶段删除。

第一轮结论：主站功能覆盖完整，可进入后续总迁移矩阵。

## 13. 第二轮盘点复审

复审范围：数据、权限、兼容性、时间、并发与幂等、异常恢复、安全、测试和回滚。

结论与调整：

- 旧四链实现与新版 TRC20 单地址目标明确分开，并补充金额冲突、延迟到账、重复交易和人工对账状态。
- 课程双来源、视频多来源和私有文件权限列为迁移风险，禁止只验证前端隐藏。
- 用户中心跨应用同步改为服务端版本和缓存失效，不使用 iframe、`postMessage` 或跨应用 Token。
- 增加分域通知，避免交易风险和主站社区通知混杂。
- 数据库行数只作为模块存在证据，正式迁移仍要求精确逐表、逐用户对账。
- 真实浏览器、支付链、短信、七牛和视频播放未验证，不把源码入口标记为运行正常。

第二轮结论：盘点可作为主站迁移输入。剩余运行态验证放入相应实现阶段，不阻塞进入阶段 2。
