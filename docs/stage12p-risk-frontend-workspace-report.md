# 阶段 12P：AI 风控师前端工作区验收记录

> 日期：2026-09-04
>
> 范围：账户风险概览、账户规则编辑、服务端手动解除可用性、风控评审记录与浏览器实时失效通知
>
> 边界：仅完成源码和离线验证；未执行 011 迁移，未启动 V4 业务服务，未连接真实 MySQL、Redis、Bridge、MT4/MT5，也未发送交易命令

## 1. 结果

阶段 12P 将 `/risk` 从占位页替换为当前账户的真实 AI 风控师工作区。页面首屏先回答普通交易者最关心的三个问题：

1. 当前是否存在风险限制；
2. 哪些指标已接近或达到上限；
3. 账户规则能否修改，以及当前限制能否由用户手动解除。

风险状态不会把“达到持仓上限”误写成所有操作均被禁止。页面明确说明平仓、撤单和收紧保护价仍按动作类型单独评审；真正的交易许可仍由服务端确定性风险域决定。

## 2. HTTP 合同与数据边界

公共 V4 合同新增并严格解析：

- 账户有效风险策略与可编辑字段；
- 当前账户风险摘要；
- 手动解除记录与服务端可用性；
- 风控决定列表和逐规则详情；
- 账户规则 PATCH/PUT 请求与手动解除请求。

金额、比例、点差和手数继续在 HTTP wire 中使用十进制字符串；明确为整数的次数、分钟和 revision 才转换为 number。规则修改使用 `If-Match`，手动解除同时使用风险摘要 `If-Match`、独立 `Idempotency-Key` 与当前 trade 会话 CSRF。

浏览器不会根据页面上看到的阈值自行推断“可以解除”。`GET /api/v4/risk-accounts/{account_id}/manual-release` 现在返回：

```text
release + availability
```

其中 availability 由服务端复用和 POST 完全相同的 `assessManualRelease` 规则计算，包含可用状态、拒绝代码、可解除规则、有效期、策略 revision 和风险摘要 revision。风险基线指纹与内部计算细节不暴露给浏览器。

## 3. shadcn-vue 页面结构

页面只组合共享 `@aurum/ui` 的 shadcn-vue/Reka 组件：

- `Card + Badge + Progress`：风险状态和六项实时额度；
- `Select + Button`：交易账户快速切换与刷新；
- `Sheet + Field + Input + Tabs + Switch`：按亏损、敞口、频率、行情和挂单保护分组编辑账户规则；
- `AlertDialog + Checkbox`：高风险手动解除确认；
- `Table + Card + Sheet`：桌面风控记录、移动记录卡片和逐规则详情；
- `Alert + Empty + Skeleton`：缺账户、观摩、加载和局部失败状态。

复杂配置默认收进右侧 Sheet，首屏不堆叠整张参数表。所有主要交互维持至少 44 px 触控目标；数值采用等宽数字，所有颜色使用语义令牌，未引入渐变、玻璃、衬线字体或另一套组件体系。

## 4. 权限、账户切换与局部失败

观摩模式不读取来源账户的所有者风控资源，也不允许修改规则或解除限制。页面仍列出当前用户自己的交易账户；选择后通过已有 trading context CAS 切回本人账户。

账户切换会停止旧账户风险 WebSocket、递增 generation、清空旧详情，再读取新账户。迟到响应不能覆盖新账户。风险规则是工作区的必要资源；风险摘要、手动解除状态和决定列表为相互独立的局部资源。某一局部资源失败不会把整页规则编辑能力一起清空，例如尚未生成风险摘要时仍可查看和收紧账户规则。

## 5. 浏览器实时策略

页面对当前本人账户订阅单个 `kind=risk, resource_id=all` 目标：

- `risk.policy.changed`：重拉策略和解除可用性；
- `risk.summary.changed`：重拉风险摘要和解除可用性；
- `risk.decision.created`：重拉决定列表；
- `risk.manual_release.changed`：重拉解除记录和可用性。

WebSocket 只传小型失效事件，不承载完整策略、风险摘要、规则详情或解除基线。序列断档会关闭连接，先用 HTTP 重拉权威状态，再按 1/2/5/10/20/30 秒抖动退避重新订阅。

## 6. 第一轮复审：解除按钮不能由浏览器猜测

第一轮复审发现，旧 GET 手动解除接口只返回最新记录或 null。若前端仅用策略和摘要拼接按钮条件，就会复制服务端关于终端时钟、业务日期、数据完整性、平台硬上限、可恢复规则和有效 release 的业务逻辑，后续很容易漂移。

调整：把精确 availability 放到风险应用服务，由服务端复用同一个 `assessManualRelease`；GET 返回窄读模型。POST 仍重新读取并校验当前 revision，因此读模型只用于解释和引导，不构成授权，也没有削弱并发保护。

第一轮结论：手动解除入口只在服务端明确返回 available 时启用，active release、平台停机、账户暂停、关闭交易发送、数据不完整、时钟未校准和平台硬上限均有确定原因。

## 7. 第二轮复审：动作语义与容错

第二轮复审发现两项问题：

1. 把持仓数量达到上限概括为“账户交易受限”会让用户误以为不能平仓或撤单；
2. 初始四资源 `Promise.all` 会让一个尚未生成的风险摘要遮住仍可使用的账户规则。

调整：状态文案改为“部分交易动作受限”，明确保护性操作仍逐动作评审；初始读取改为独立 settled 结果，只把风险策略视为页面必要资源。风险摘要、解除状态和决定历史分别展示局部错误，实时重同步也不会因长期缺少摘要而进入无意义的重连循环。

第二轮结论：页面信息层级、账户权限、局部失败、实时恢复和移动端表格降级符合当前 V4 边界；未在前端实现任何风控放行逻辑。

## 9. 剩余风险与下一步

本阶段没有启动 V4 API、Realtime 和数据库，因此没有伪造登录后的真实浏览器数据证据。375/768/1024/1440 px 的响应式结构已按静态组件和构建检查收口，但真实数据长度、焦点回退、Sheet 滚动和 WebSocket 恢复仍需在阶段 15～16 启动旁路环境后完成浏览器验收。

阶段 12Q 建议进入 AI 策略师真实前端竖切：只围绕分析策略与交易员策略的列表、版本、提示词编辑、编译校验、发布/退役和账户订阅关系接入现有 V4 合同。开始前仍需单独介绍范围并由用户确认。
